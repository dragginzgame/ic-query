# Query 0.86 release notes

## 0.86.0

### ⚠️ Breaking

Catalog loading has one failure contract. `load_cached_subnet_catalog`,
`load_subnet_catalog`, `load_subnet_catalog_with_source`, and
`load_subnet_catalog_with_source_and_progress` return
`Box<SubnetCatalogLoadFailure>`. Replace the former parallel `_detailed`
loader names with these names; replace `_detailed_with_progress` with
`_with_source_and_progress`. Inspect the retained request, stage, cache
disposition and typed failure evidence, then `failure.source` for the original
host error. Call `into_source()` only when deliberately consuming that evidence.
Cache-only loads remain synchronous and never fetch. Source traits, policy,
assurance checks and report-builder error contracts retain their boundaries.

Canic's inspected `canic-host` catalog acquisition/cache wrappers and
`canic-testing-internal` fleet-growth helper use the former detailed names.
Update those callers and their fixtures when adopting 0.86. Their existing
failure-evidence matching remains applicable. This Query change does not update
or qualify the Canic checkout, and its current 0.84 dependency stays unchanged.

Report origins are `ReportProvenance::Live` or
`ReportProvenance::Cache { cache_path }`. Rust consumers can match the origin or
use `data_source()`, `cache_path()` and `cache_complete()`. Shared report JSON
retains `data_source`, emits `cache_path` only for cached origins, and no longer
emits the independently nullable `cache_complete` field. A cache origin denotes
an admitted complete snapshot. Human-facing provenance text keeps its existing
source/path/completeness lines. Coordinate JSON report consumers before adopting;
this does not authenticate cached content or add a point-in-time guarantee.

Complete ICRC account-history snapshots, refreshes and list reports expose
identity and collection metadata through `context`. Update Rust field access
and fixtures, for example `report.context.index_canister_id` and
`snapshot.context.collection_started_at`. Their existing flat JSON fields,
cache identities, transaction rows, completeness evidence and schema-1 snapshot
shapes retain their contract; existing complete-history caches need no reset.
ICRC cache-status summaries distinguish `Valid { data }` from
`Invalid { cache_path, cache_error }`. Valid summaries contain admitted metadata;
invalid summaries no longer invent zero counts, false completeness or placeholder
timestamps. JSON consumers branch on `cache_status`; a valid summary implies
completeness and carries a required index canister. Human text omits invented
metadata for invalid files while retaining their original error and path.

SNS catalog/list rows use `SnsLifecycleOutcome` under `lifecycle`: JSON carries
`{"status":"value","code":3}`, `{"status":"failed","error":"…"}` or
`{"status":"not_collected"}`. Raw unknown codes and bounded query failures
remain visible. Direct lookups may leave lifecycle uncollected; complete catalog
admission rejects that outcome. Update Rust/JSON consumers of the previous raw
optional lifecycle and separate error fields. SNS cache-status expected and
refresh-attempt paths are required strings; update Rust callers using `Option`.

SNS reward-diff rows group each side's observations under optional `before` and
`after` records. Each present record carries combined maturity, creation time,
both local policy observations and pending-disbursement count together. Derive
new-neuron and missing-after facts from side presence. Update consumers of the
former prefixed fields and boolean flags. Raw signed deltas, allocation checks,
policy-change findings and invalid-reason evidence remain intact. Checkpoint
inputs retain their existing format; regenerate diffs from retained checkpoints
when needed, preserving older reports for any consumers that still require them.

Portable NNS proposal and neuron continuation JSON no longer stores an independent
`status`. Rust `status()` and `is_complete()` derive lifecycle from page/cursor
facts. Start/update times, requested source, concrete provenance, cursor direction,
page ceilings, row accounting and family-specific exhaustion checks remain
mandatory. A page ceiling still means incomplete collection, and pages must be
retained before their continuation is advanced.

### 🧭 Migration Notes

All current schema identifiers remain `1`. Before adopting the new binary or
library, coordinate consumers of changed report and stored shapes:

- Preserve any deployed-SNS catalog files needed as evidence, then explicitly
  refresh the catalog with `icq sns refresh` using the intended cache root,
  network and endpoint. Earlier catalog payloads fail admission; cache-only reads
  do not repair them. The existing authorized invalid-content refresh policy can
  replace them atomically. Failed refreshes preserve the existing file.
- Finish older portable proposal/neuron walks with their original collector and
  retain their page evidence before upgrading. Alternatively archive their pages
  and state, then explicitly start a fresh walk; do not discard the sole evidence
  of a prior collection. Coordinate embedders that persist these continuations.
- Update report consumers and custom fixtures together. There is one current
  reader/writer, with no migration, fallback reader, automatic deletion or schema
  increment. Complete NNS caches, SNS neuron/proposal caches, reward checkpoints,
  ICRC caches and refresh-attempt/lock contracts need no reset for this batch.

### 🧹 Cleanup

SNS proposal/list and ICRC sort options use library-owned choice vocabularies
through the existing CLI parser. Exact spellings, defaults, leading-hyphen API
sorts, help ordering and live-versus-cache restrictions remain unchanged. Remove
the redundant CLI conversion enums and their macro. NNS/SNS source/cache text
uses one provenance renderer, and SNS cache-status rendering requires the paths
that every addressed status report already supplies. No new CLI surface or live
network behavior is introduced.

Report statistics are Query-owned code. Replace the direct Metrics dependency
with exact integer percentage rounding and a private checked count/sum accumulator
for neuron distributions. Preserve nearest-tenth half-up rounding, unavailable
denominators, missing-versus-zero observations, raw dimension ordering and typed
count-before-total overflow diagnostics. No instrumentation, report shape or
numeric policy is added or changed.

### ⬆️ Dependencies

Adopt published Platform 0.18.0 with canonical Types 0.17.0 and Runtime 0.18.0,
Host Tools 0.78.0, Foundation (Artifacts, FS, HTTP and Process) 0.74.1, Build
0.74.0, Text 0.74.0 and Testkit 0.80.0. Wire
0.15.0 serves development probes and fixtures without changing their codec bytes,
schemas or budgets. Its compiler minimum and optional Types 0.17 identity align
with Query's existing selections. Update consumers exchanging
Platform-owned Principal, certificate, ledger or runtime types, and align all
canister runtime users on Runtime 0.18. These dependency changes preserve raw
external protocol bytes, collection policies and existing cache formats; the
separate report/catalog/continuation changes above retain their own actions.
Rust 1.99.1 remains Query's existing minimum and selected compiler.

The unpublished native fixture selects the independently published
`ic-platform-pocket-ic` 0.18 client directly, sharing its identity with Testkit
0.80. Required external Candid parsing remains in Platform 0.18. Query, Host
Tools and Testkit select one current Platform/Types stack. Query has no direct
Metrics dependency; Testkit retains its supplier-selected arithmetic-only
Metrics 0.26 dependency, without exchanging those types with Query. Older Platform, Types, Runtime and
Foundation generations are removed from the lockfile. There is no client bridge, dependency override or
alternate runtime executor. Client 0.18 selects management DTOs 0.11 and retains
the existing PocketIC 16.1.0 server protocol. Native simulator and macOS acceptance
remain separate from source/graph checks and Wasm cross-compilation.

Adopt Shared Tooling 0.27.27 from committed revision
`651f5f7acb2e3055abd51ba5f835a2112801666a` through the canonical exporter. The
snapshot adds source-bound release-group plan support and its required companion;
Query retains its existing full release gate and native host matrix. No narrower validation plan,
hook, schedule, release or delivery effect is activated. Existing compiler and
common executable pins remain unchanged. Prepare the lock-selected Testkit 0.80
CLI and existing server for focused native fixtures, and admit the Build 0.74
metadata executable for the existing local release-adapter fixtures. Those
fixtures simulate Git effects and do not release Query. Their nested Make calls
select fixture groups explicitly, preserving missing-group refusal checks and
Query recovery scenarios under either parent release group's arguments.

## Presentation and release ownership

Report renderers and their human-facing helpers now belong to `ic-query-text`.
Update imports from `ic_query::<family>` to `ic_query_text::<family>` for text
functions. The library has no dependency or re-export back to presentation.
The extraction preserves JSON shapes and text output; the separate model changes
above retain their own consumer obligations. See the [CLI group notes](../cli/0.86.md).

Select the group explicitly for version inspection:

```bash
make version RELEASE_GROUP=query
```
