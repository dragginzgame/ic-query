# Query 0.93 release notes

## 0.93.4

### 🧹 Shared NNS operations and continuation bookkeeping

Give the eight Governance point, proposal and neuron operations one typed
implementation. Native and replicated adapters retain source admission,
transport errors and their existing response bounds. Preserve Candid argument
shapes, diagnostic labels and all public source capabilities.

The existing continuation owner now checks source continuity, advances page
and row counts together, and validates row bounds and lifecycle evidence.
Neuron and proposal owners retain their different cursor and exhaustion rules,
validation order, error types and schema-1 persisted states. Neurons still
require a short terminal page; proposals may finish on a full page.

Keep native Governance request admission, Agent selection and Candid query
execution together in the native adapter. Export SNS cache list/status reports
directly from their owners and build cached neuron views in the existing cache
module. Public report and source paths remain unchanged.
Keep the exact external Candid allowances aligned with the shared transport
capability and its adapters, retiring entries for removed helpers.

### 🩹 Tool setup and dependency updates

Run lifecycle-handler fixtures on an admitted historical date so an expired
security acceptance does not mask their intended failure and cleanup assertions.
Dependency-review fixtures continue to prove expiry refusal, and the production
dependency gate still uses the real UTC date.

Adopt Shared Tooling 0.31.3 at `d2a2f395`. Its checksum reader is outside quoted
command substitution so system Bash 3.2 can parse it during macOS bootstrap.
Keep strict NUL and malformed-output rejection and preserve a failing hash
backend's original exit status. Output owners create their scratch parents on
fresh runs; LOC reporting rejects scratch inputs removed during a run with a
clear diagnostic instead of emitting partial totals. Native consumer
qualification remains separate from this local adoption.

Select Build 0.77.0, Platform 0.23.5, Wire 0.17.6 and Testkit 0.90.0 in the shared
lockfile, with the compatible SmallVec 1.16.5 patch. Build continues to own probe
input resolution and the locked release-metadata executable. Host Tools and
Host Text retain their existing selections. Product APIs and schema-1 contracts
are unchanged.

Supply a five-minute request timeout when constructing the Governance fixture's
PocketIC client. Keep the separate one-minute startup deadline, NNS/application
topology, typed protocol limits, failure/provenance checks and explicit instance
close. This adopts Testkit's finite-budget contract without changing Query's
public APIs or adding product mutations.
[#116](https://github.com/dragginzgame/ic-query/issues/116).

## 0.93.3 - 2026-11-06

### 🔧 Frozen grouped delivery

Adopt Shared Tooling 0.31.0 at `7431394`. Select the complete affected roster once;
the shared runner captures clean source and runs Query's existing metadata,
validation, Git and publication adapters in its managed delivery checkout.
Subsequent normal-checkout source and lock updates remain deferred. Preserve
supplier-first publication, receipt checks and exact recovery semantics.
Consumer hook fixtures qualify interrupted validation, deferred locks, archive
identities, uncertain publication, completed resume and remote advancement.
Native host acceptance remains separate. Enable the supplying CBOR source check
alongside the existing dependency and Candid boundaries. Product commands,
package APIs and schema-1 contracts are unchanged. Shared owns candidate setup
and all batch commands: prepare host tools for a fresh group, admit them offline
during recovery, retain saved release/publication context, and provide guarded
status, fast-forward reconciliation and explicit scoped retirement. Single-group
releases capture automatically; an empty roster cannot select live delivery.
Use `RELEASE_GROUPS`, `RELEASE_PUBLISH_TARGET`, `RELEASE_SETUP_TARGET`,
`RELEASE_SETUP_MODE` and `RELEASE_BATCH_ACTIVE` with
`scripts/ci/run-release-batch.pl`; retired names refuse without aliases.
Shared's contributor recovery journals use schema 2 and require a recorded
publication commit. Existing pre-0.31 attempts retain their original tooling;
Query-owned product schemas remain 1. Include the supplying checksum fixes and
required annotations on newly exported snapshots.
Keep the exported default IC pin path relative to the selected checkout, and
prepare/admit the selected IC tools alongside the host parser tools. The real
plan-admission path is exercised in batch hook fixtures before simulated gates,
so a normal-checkout pin path or missing captured tool selection fails locally.

```bash
make release-patch RELEASE_GROUPS=query,cli
make release-batch-resume BATCH=batch-XXXXXXXX
make release-batch-status BATCH=batch-XXXXXXXX
IC_QUERY_RELEASE_BATCH_CASE=admission make release-batch-check
```

## 0.93.2 - 2026-11-06

### 🧹 Concrete cache ownership

Make SNS neuron storage, summaries and refresh paging concrete now that neurons
are the sole retained SNS collection. Remove the private family traits, marker
type and generic forwarding while preserving public entry points, snapshot and
attempt shapes, paths, validation, locks and read budgets. Continue measuring API
exhaustion before removing repeated page-boundary rows, and retain the previous
complete snapshot after an incomplete refresh.

Run SNS neuron refresh directly from its existing entry point with one private
context for paging, attempt evidence and publication. Remove the single-caller
callback layer while preserving lock scope, starting/running/failed attempts,
atomic replacement and finalization diagnostics. Share field-labelled canonical
principal validation for Governance targets and owner filters, retaining their
validation order and existing errors before any live call.

Share the mechanically identical NNS proposal/neuron progress, page-cap and
attempt-sidecar projections. Keep each family's cursor advancement, row admission,
collection evidence and final ordering with its existing collector.

Use the validated Registry snapshot directly for topology joins and exact node,
operator and data-centre lookups, without creating intermediate list reports.
Retain independent Governance metadata acquisition, source-call and error order,
component provenance rows and capacity calculations. Publish the existing SNS
cache entry points directly from their owners. Use a synchronous leaf cache
writer without changing refresh publication, locks or dry-run output.

Assemble neuron reports with the existing shared context and live/cache
provenance, removing a separate private wrapper and its conversions. Define
common neuron/proposal continuation accessors with their metadata owner while
retaining public method names, documentation, const access and serialized state.
Each family keeps its own cursor and row accounting.

Carry node-status freshness from cache admission into refresh selection using the
same caller-supplied clock. Retain the inclusive freshness threshold, future-time
rejection, missing-only policy and existing cache evidence.

### 🧹 Release-group Cargo selection

Split lint and archive stages along the existing release groups.
Selected Query plans run Query/private Testkit Cargo checks and package Query,
retaining CLI/Text tests and all feature/public-consumer boundaries. Selected
CLI/Text plans check and package their own members against the actual Query
dependency. Full CI and full-fallback releases run both sets of stages; standalone
workspace commands retain their existing coverage. All Cargo checks stay locked
and offline, and archive peers retain the real workspace versions.

Clippy already performs native compiler checks with the same selected packages,
all targets, all features and development profile. Remove the repeated native
check stages, retaining standalone `make check` for developers. Feature-isolated,
Wasm, public-consumer, runtime and archive checks remain independent obligations.
Query has no first-party Clippy-specific compilation branches or build scripts
requiring a separate native check.

The changed mapping invalidates prior host admission. Full release validation
remains in force until matching native comparisons are admitted; focused command
and selector fixtures do not establish a speedup or qualify native hosts.

### ⬆️ Native Testkit logging ownership

Adopt published Testkit 0.89.1 for the private Governance fixtures and managed
server CLI. Query does not use the retired logging environment variables or
automatic client subscriber, so its adapters need no replacement logging setup.
Retain the async client, explicit instance deletion, reply fixtures, Platform
identities and PocketIC 16.1.0 selection. Eleven unused logging-related packages
leave the lockfile. Public Query contracts and the compiler floor are unchanged;
the existing pending compatible release covers this test-tooling adoption.
The selected lockfile also carries Platform 0.23.3, Runtime 0.19.3, Types 0.18.2,
Wire 0.17.4 and flate2 1.1.11. Keep the existing public dependency requirements
and qualify these compatible patch selections with the release gate.

## 0.93.0 - 2026-11-05

### 🧹 Enforce the Candid source boundary

Adopt Shared Tooling 0.30.4 at committed revision `a08f03a`, including its
generic inherent-header fix, through the snapshot exporter. CI and both release
plans run `candid-boundary-check` once over all first-party Rust source, tests
and examples. Each necessary external IC DTO or codec helper has an exact named
declaration allowance with its protocol and reason; whole modules and owned
application models are not exempt. The lexical check rejects unreviewed trait
references and stale allowances without Cargo or network access. It complements
the released model separation in [#114](https://github.com/dragginzgame/ic-query/issues/114);
native CI acceptance remains separate. No CLI or report contract changes.

Shared Tooling now supplies `docs/supported-hosts.md`. Preserve Query's native
matrix and requirements in `docs/query-supported-hosts.md`, updating local guide
links without narrowing required hosts or changing qualification obligations.

### ⬆️ Host and simulator alignment

Adopt published Host Tools 0.83.0 and Testkit 0.87.0. Both select Platform 0.23,
removing the retained Platform 0.22 generation. Canonical Types/Runtime remain
shared. Query already uses Platform's strict certificate/hash-tree decoder;
replace stale feature guards with that capability's current name.

The compiled Governance fixture owns one Tokio runtime and awaits client startup,
network calls, installation and report assertions. It explicitly deletes its
instance before releasing server custody. Failed assertions also attempt deletion;
the original panic is retained and any secondary deletion failure is reported.
No blocking-client compatibility wrapper or private per-call runtime is added.

### ⚠️ Rust dependency identities

Host Tools 0.83 changes the Host-owned `LedgerTip` package identity returned by
`authenticate_ledger_tip` under `ledger-evidence-host`. Callers exchanging that
value with Host's chain verifier select Host Tools 0.83. Query report fields,
JSON/schema-1 contracts, authentication order and byte/nesting limits remain
unchanged. This public Rust boundary requires a Query minor release. Rust text
renderer callers adopt the corresponding Query model generation; command syntax
and text/JSON output do not change.
