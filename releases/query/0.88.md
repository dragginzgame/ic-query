# Query 0.88 release notes

## 0.88.0 - 2026-11-02

### ⚠️ Breaking

Registry-derived node, node-provider, node-operator and data-center operations
return `ic_query::nns::NnsInventoryError`. Replace the four family-specific
host error imports and matches with that shared type. Its variants retain
`NnsInventoryCollection`, original lookup input/ambiguous matches and Registry
source errors; cache failures retain their original component, path and source.
`NnsTopologyHostError::Inventory` replaces its four inventory wrapper variants.
No compatibility aliases are retained.

SNS reward checkpoints contain the raw parameter/event/version brackets,
collection timestamps, observed page count and neuron evidence. Call
`report.summary()?` for checked aggregates and policy observations. Use
`row.checked_combined_maturity()` and `row.derived_policy_observations()` for
row projections, and `report.row_count()`, `report.client_query_count()` and
`report.collection_row_ceiling()` for derived collection metadata. Human UTC
labels are produced by Text. The independently stored summaries, combined row
maturity/policy fields, display timestamps, fixed page size and redundant counters
are removed from checkpoint JSON.

Exact SNS neuron details also derive their two policy observations through
`detail.derived_policy_observations()`. Permission entries in details and reward
checkpoints expose `permission_types: Vec<i32>` directly. Use
`sns_neuron_permission_name(code)` when a display name is needed. Unknown codes
remain intact; principal, duplicate-code and disbursement admission still apply.

List reports no longer store counts that duplicate their returned vectors:
proposal counts, SNS neuron counts, NNS returned-neuron counts, ICRC
returned-transaction counts and cache/refresh-lock row counts. Use the matching
vector's `.len()`. Independent complete-collection totals and collection evidence
remain. NNS proposal rows likewise derive ballot counts from `ballots.len()`.

ICRC account-history snapshots retain canonical transaction rows without duplicate
newest/oldest transaction-id fields. List, refresh and cache-status views still
report bounds derived from the complete snapshot, independently of view limits
and sort order. Native index-page oldest-id observations remain source evidence.

Dashboard `IcNodeStatusSnapshot` contains only observation metadata and raw rows.
Status projections derive their totals; cache payloads already retained raw rows
and keep their existing shape. Exact Subnet topology retains provider membership
counts without duplicate Subnet or report totals. Use `report.subnets.len()` and
the checked `subnet.node_count()?` / `report.node_count()?` methods. Validation
retains canonical identities, ordering, nonzero provider counts and the native
`u32` membership ceiling. Count-mismatch variants are replaced by
`NnsSubnetTopologyValidationError::NodeCountOverflow`.

Registry certification retains raw nanoseconds, trusted-root identity, certificate
and hash-tree evidence without stored UTC text or byte lengths. Use
`certificate_bytes()` and `hash_tree_bytes()` on admitted canonical evidence;
Text derives UTC labels. Mutations retain raw `mutation_type`; use
`mutation_kind()` for its optional supported interpretation. Source and retained
report admission still reject unsupported operations.

Certified Registry batches contain raw versions, chunks and acquisition evidence
without independently stored summary fields. `report.summary()?` derives checked
version bounds, counts, value-byte totals, availability, total query calls and
response bytes. `validate_nns_certified_registry_delta_batch` returns that summary
after request and structural admission. It does not replace raw certificate
reauthentication. A sealed authenticated batch exposes `batch.summary()` bound to
its immutable report; replay and archive accounting reuse it. Observed chunk
queries, encoded response sizes, quotas and independent authentication remain.

### 🧭 Migration Notes

This replaces the owned schema-1 checkpoint, exact SNS detail, NNS proposal-row
and ICRC account-history snapshot shapes in place. Strict readers refuse former
permission objects and removed stored fields. Preserve historical checkpoints,
snapshots and their caller evidence before adoption, and coordinate Rust/JSON
consumers. New collection cannot recreate an earlier observation. Recollect
affected caches explicitly after preserving the original files; cache-only reads
remain strict, while existing read-through operations retain their established
visible repair policy. There is no fallback reader, conversion, migration or
implicit deletion of rejected files. Schema identifiers remain `1`.

The exact Subnet topology and Registry report/evidence shapes are also schema-1
hard cuts. Strict readers reject their former derived fields. Coordinate custom
sources, Rust matches, JSON/export consumers and retained-archive users before
adoption. Preserve complete earlier archives, manifests, object bytes and required
consumer tooling; their report digests and evidence-chain commitments describe
the original bytes. Do not rewrite objects, descriptors or hashes to make them
pass current readers. Use a new caller-selected archive root for current captures
after explicitly retiring the former capture root from current consumers. There
is no archive conversion or fallback reader; new collection cannot reproduce an
earlier authenticated observation.

Raw canister identities, complete brackets, permissions, pending disbursements,
unknown native values and maturity components remain evidence. Checked arithmetic,
source/restored-input validation, stable brackets, row ordering, strict exhaustion,
collection budgets and failed-refresh preservation remain enforced. Diff reports
continue to carry derived reconciliation/allocation results, including recomputed
summaries when header evidence is invalid and raw arithmetic can still be assessed.

### 🧹 Cleanup

Dashboard account/holder responses deserialize directly into existing untrusted
source records. Exact wire names, required fields, optional fee defaults and
lossless raw values are preserved; report normalization and source admission
remain separate.

Registry row projection no longer constructs three intermediate per-family list
envelopes. Rows and acquisition provenance pass directly to the existing NNS
report owner. Inventory caches, published report shapes, identities and refresh
policies remain unchanged.

Release and publish Query before the matching CLI/Text group.
