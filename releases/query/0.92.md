# Query 0.92 release notes

## 0.92.0 - 2026-11-05

### ⬆️ Development protocol alignment

Adopt Testkit 0.86.0 and Wire 0.17.2 together for the compiled Governance
probe, native simulator fixture and smoke harness. Testkit now selects the
same Wire minor line as those callers. The owned endpoints use Serde directly,
so Wire’s optional schema derive leaves this lockfile. Existing frame bytes,
method identities, decode budgets and malformed/trailing-frame rejection remain
the protocol contract. Report JSON remains at schema 1.

### ⚠️ Platform certificate error identity

The existing certificate decoder migration selects Platform 0.23.0's strict
certificate/hash-tree decoder. `CertificateVerificationError::Decode` now
contains `ic_platform::certification::cbor::strict::ParseError` instead of the
former Host type. Downstream code that names or downcasts that source adopts
the Platform type. Byte ceilings, exact-input admission, codec recursion limits,
authentication order and witness checks retain their existing contracts.
This public source identity change requires a minor Query release.

### 🧹 IC protocol fixtures

Resolve [Query #113](https://github.com/dragginzgame/ic-query/issues/113) using
published Platform 0.23.0. Native development dependencies alone select
`ic-protocol-fixtures`; typed IC query replies/rejections and captured-envelope
inspection replace generic CBOR maps. Platform's certificate/hash-tree encoders
and deliberate malformed-certificate fixtures preserve unknown-field,
duplicate-tree, trailing-data, oversized-input and deep-nesting coverage.

Remove Query's direct `serde_cbor` declarations/imports and forbid their return
through its dependency policy. Legitimate upstream transitive CBOR remains.
Owned application RPC stays on Wire; no application DTO protocol changes.

### ⬆️ Platform 0.23 alignment

Select published Platform 0.23.0 directly. Its optional subnet-metrics decoder
change has no direct Query caller. Host Tools 0.82.1 and Testkit 0.86 still
require Platform 0.22, so retain that supplying generation transitively instead
of overriding their contracts. The selected canonical Types and Runtime owners
remain shared; the two facade versions are not two executors. Keep native
supplier adoption separate from this direct Platform update.

### ⚠️ Application models are not Candid DTOs

Resolve [#114](https://github.com/dragginzgame/ic-query/issues/114) by removing
`CandidType` and conditional Candid derives from owned NNS economics/reward/
maturity data, the public SNS cursor, supported-standard rows, Cloud Engine
node classes and the CMC report rate. Their Serde fields, raw values and
validation semantics remain unchanged. Consumers that used these models as
external Candid DTOs must use the appropriate external protocol type; owned
application RPC uses Wire.

Private NNS/SNS/Cloud Engine records now own their external Candid shapes and
convert explicitly into report data. Ledger standards reuse Platform's
`icrc10::SupportedStandard`, and CMC certificate leaf comparison encodes
Platform's official `IcpXdrConversionRate` before report projection. Existing
external requests/replies and the certified CMC leaf keep their Candid bytes.
