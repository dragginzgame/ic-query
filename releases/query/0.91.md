# Query 0.91 release notes

## 0.91.0 - 2026-11-05

### ⚠️ One proposal cache inspection contract

Remove `NnsProposalCacheListReport` and
`build_nns_proposal_cache_list_report`. The proposal collection has one expected
complete snapshot per network and cache root; the list adapter only wrapped the
status report's optional summary in a vector.

Use `build_nns_proposal_cache_status_report` with the existing
`NnsGovernanceCacheRequest`. Inspect `found`, the optional `cache` summary,
`expected_cache_path`, `refresh_attempt_path` and `latest_attempt`. A missing
snapshot can still have retained failed-refresh evidence. Cache and sidecar
admission, error handling and refresh behavior are unchanged. SNS cache lists
continue to discover multiple instance snapshots and remain available.

### ⚠️ One owner for failure classifications

`SubnetCatalogLoadFailure` no longer stores copied `code`, `category` and
`retryability` fields. Read `failure.source.code()`,
`failure.source.category()` and `failure.source.retryability()` instead.
The typed original error remains the classification owner; request, stage,
cache disposition, Registry progress and offending-subject evidence remain.

Canic's current Subnet Catalog tests compare copied classifications with these
source accessors. Drop those equality checks when adopting this release, and
read the expected retry classification through `failure.source.retryability()`.
Keep its failure provenance assertions. Its runtime error forwarding does not
read the removed fields. This Query change does not update Canic's dependency.

These public API removals require a minor release. Registry collection, node,
operator, data-centre and topology functionality remain available. All current schema identifiers remain 1. The shared inventory cache hard
cut below requires new collection; legacy cache files are not read or migrated.

### 🔧 Topology aggregation

Build provider distributions directly from the retained inventory reports,
borrowing provider and location identifiers until output construction. Preserve
the distinction between registered providers without metadata, unregistered
references, and unused registered providers. Capacity remains the sum of each
operator's available and over-assigned slots; spare capacity on one operator
does not cancel another operator's over-assignment.

Subnet and node summaries share one subnet-kind counter, including unknown
kinds, while routing-range totals remain independent. These aggregation changes
retain distribution values and ordering. The collection/cache contract changes below are separate parts of this release.

### ⚠️ Shared Registry inventory

Replace independent node, operator and data-centre caches with one bounded
`nns/ic/inventory/snapshot.json` and `inventory/refresh.lock`. One Registry pin
and relation acquisition supply all three views. Node filters and identifier
lookups remain projections over complete data. A cold node read now also
collects referenced data-centre records; a failed collection preserves the
previous complete shared snapshot.

Custom sources implement `NnsRegistryInventorySource::fetch_registry_inventory`
and return `NnsRegistryInventorySnapshot`. Retire `NnsNodeSource`,
`NnsNodeOperatorSource`, `NnsDataCenterSource` and their per-view cache/refresh
APIs. Use `nns_registry_inventory_cache_path`,
`nns_registry_inventory_refresh_lock_path` and
`refresh_nns_registry_inventory[_with_source]`. Existing list/info builders
continue to return their view-specific reports. Cached rows and envelopes
reject unknown and duplicate fields.

Older `node/nodes.json`, `node-operator/operators.json`,
`data-center/data-centers.json` and `node-provider/providers.json` are ignored.
Preserve or explicitly retire those caller-owned files; no legacy reader,
migration or automatic deletion is added. First reads visibly collect the new
schema-1 inputs using the selected endpoint. The combined snapshot retains the
64 MiB inventory ceiling.

### ⚠️ Independent Governance provider metadata

`NnsNodeProviderSource` extends the shared Registry capability and returns
`NnsNodeProviderMetadata` from `fetch_node_provider_metadata`. It carries its
own `CollectionSourceRequest`, fixed Governance identity and provider rows.
Those rows must have `node_count: None`; Query derives counts from the captured
Registry snapshot. This replaces the former combined report-returning source
contract without a compatibility adapter.

Governance metadata is cached at `nns/ic/node-provider/metadata.json` with a
separate refresh lock. Provider list/info reports retain Registry provenance
and add `governance_source` for the independent endpoint/time/collector. A
Governance failure leaves Registry views usable. Older complete metadata can
be joined with a newer Registry snapshot with both acquisitions visible.

Provider refresh returns `NnsNodeProviderRefreshReport` containing `inventory`
and `metadata` publication outcomes. Its explicit output file contains only
Governance metadata; obtain joined counts through the list/info report builders.
Dry runs use freshly collected data while publishing neither managed snapshot.
Exports cannot alias either input snapshot or either coordination file.

Topology sources now supply the shared raw Registry/Governance capabilities,
plus their existing Subnet Catalog read or refresh capability. Topology refresh
publishes Subnet Catalog, shared Registry inventory and provider metadata as
three components. Governance's refresh row has `registry_version: None`; its
source endpoint, timestamp and collector describe the Governance acquisition.
A later failure retains earlier complete publications and previous metadata.

### ⚠️ Retired global cache overview

Remove the generic `CacheStatus*` models/builder, header/age/recovery/lock-view
models and the cross-family scanner. Keep `CacheCollectionCompleteness`,
`CacheValidationStatus`, refresh-attempt records and all family cache readers,
locking, confinement, bounded discovery and recovery behavior. This retirement
removes diagnostics rather than weakening cache admission.

Built-in canister execution and its dedicated qualification remain supported.

### 🧪 Canister CI lint scheduling

Each canister job runs the complete native Clippy target once and the dedicated
Wasm probe lint in one stage, before deterministic Testkit execution, local NNS
smoke and bundle construction. The three product checks use the already prepared
locked dependency cache and do not repeat lint or dependency preparation. Linux,
Apple Silicon macOS and Intel macOS coverage remain selected. Standalone
canister development commands retain their lint gates; lint failures stop product
execution even when Make runs with parallel jobs.


### ⚠️ Neuron stake evidence without the SNS platform

Retire SNS-W discovery, project list/info/catalog refresh, Root canister health,
Governance proposals/parameters/metrics, Swap, upgrade and SNS-specific token
wrappers. Keep generic ICRC token metadata, direct balance/transaction/burn reads
and paginated Dashboard holder enumeration. Registry and NNS infrastructure
reports remain available.

Neuron requests now use `SnsNeuronTargetRequest` and its explicit Governance
principal. Numeric project ids and Root lookup are removed. `SnsNeuronSource`
returns the same `SnsNeuronRow` used by list results and complete caches;
`SnsNeuronsSource` no longer inherits discovery and its methods receive the
Governance principal directly. Report context contains acquisition metadata and
that principal, without project ids, names or Root/SNS-W identity.

Every row includes required canonical permission principals and all native
permission codes, including unknown codes. Exact reports carry `neuron` instead
of the former `detail` policy/followee payload. Keep raw stake, fees, maturity,
staked maturity and dissolve/vesting values separate. Query does not infer
purchase eligibility or equate every permission holder with a controlling owner.
Toko owns gating policy, token mutations and idempotent credits.

Complete snapshots now live under
`sns-neuron/<network>/<governance>/neurons/full.json` with matching lock and
attempt paths. Schema identifiers remain 1. Old Root-based snapshots, attempts
and project catalogs stay untouched; there is no old reader or migration.
Explicitly refresh each Governance target before using cached stake ordering.
Capped or failed scans retain the last complete snapshot and attempt evidence.
Pagination can span state changes; completeness is not a point-in-time guarantee.

```bash
icq sns neuron list "$GOVERNANCE_CANISTER_ID" --owner "$USER_PRINCIPAL" --json
icq sns neuron refresh "$GOVERNANCE_CANISTER_ID"
icq sns neuron list "$GOVERNANCE_CANISTER_ID" --sort stake --json
```

The `sns-host` dependency selection drops ledger DTOs and concurrent discovery
helpers. Native neuron calls retain Platform Candid decoding, endpoint admission
and reply limits. Public API removals and the schema-1 replacement require this
minor release; adopt callers and refresh snapshots together.

### 🔧 Shared Tooling 0.30 and source hygiene

Adopt the committed 0.30.0 snapshot and its updated source layout, lint,
retained-state and validation ownership rules. The Governance smoke runner and Registry timing utility move
to their package's `tools/` directory and its deployable probe to `tests/fixtures/`.
Both retain their Cargo example names and existing commands. The private Testkit
package declares a tests-only LOC role; the root catalog distinguishes production,
mixed and development dependencies. Remove misleading workspace-member role
comments; Cargo target roles and explicit fixture metadata remain authoritative.

Remove the workspace-wide `needless_pass_by_value` allowance. Fix avoidable wire
cloning and scalar selector ownership; document deliberate owned conversion and
publication boundaries through scoped `expect` attributes. Keep documentation
and exported-name policies at workspace scope and enable unfulfilled-expectation
warnings explicitly.

Local shell and Rust test scratch uses workspace `target/tmp/`; shell adapters
retain explicit `TMPDIR` overrides. Persistent ICP identities remain under their
separate custody contract. The new shared release runner checks bounded Git-side
retention and keeps new reproducible validation trees under `target/`.
Committed-source manifest ordering also retains its extracts under `target/`,
keeping Git-side recovery state free of new source copies. Retire reviewed
legacy source/build copies with explicit cleanup approval, preserving historical
commits, qualification evidence and recovery metadata. This does not claim
native Linux/macOS release qualification.

Refresh the Shared snapshot to `4d09618` for the latest committed LOC reporter.
Workspace summaries use concise names, `???` identifies unclassified lines, and
classification details remain available through JSON diagnostics. A single
workspace has one summary row; subcrate rows remain explicitly selectable.
