# Query 0.87 release notes

## 0.87.0

### ⚠️ Breaking

Report acquisition and human-facing presentation have separate inputs. Remove
`verbose`, `show_ballots`, and their request builders from NNS proposal/neuron
and SNS list/proposal/neuron callers. Reports and JSON no longer carry those
display flags. Pass `ic_query_text::TextOptions` to the affected Text renderers;
raw retained ballots and other source evidence are collected as before.

SNS lookup construction is fallible. Handle `SnsLookupRequest::new(...)?` and
use `input()`, `id()`, and `root_canister_id()` to inspect the immutable selector.
The original caller text is retained while numeric positions and root principals
are parsed once. Invalid selectors fail before discovery. Numeric positions still
resolve against the full current SNS-W inventory; complete cache views still use
root principals and never scan local files to reinterpret a numeric position.

Build proposal list requests with `SnsProposalsRequest::new` for bounded live
acquisition or select `.with_cache_root(...)` before applying complete-cache
filters. `with_status(...)` now returns a result, and `status()` and `collection()`
expose the admitted choices. A live `decided` filter is rejected at request
construction. Cache hits, missing-only proposal refresh, explicit neuron refresh,
and detail lookup's cache-preferred live fallback retain their policies.

SNS proposal rows derive `decision_state()` from positive failure, execution,
and decision timestamps, in that order. Zero timestamps do not mark a transition.
`ballot_count()` derives the retained vector length. Stored and emitted row JSON
no longer has independently editable lifecycle or ballot-count fields. Raw status,
timestamps, action/vote codes, ballots, and unknown native values remain evidence.

SNS and NNS cache summaries carry typed admission outcomes. Match `admission`
or use `valid()`, `cache_status()`, and `cache_error()`. JSON uses
`cache_status: "valid"` or `"invalid"`; valid facts remain flat, while invalid
content carries only refusal evidence and its path, plus independently admitted
SNS attempt metadata. Invalid summaries no longer invent counts, identities,
timestamps, endpoints, or completeness. Valid summaries imply API exhaustion;
the redundant `complete` summary field is removed. Expected paths and latest
attempt evidence remain independent of snapshot validity.

NNS neuron reports carry `ReportProvenance` through `provenance`, flattened in
JSON as `data_source` and, for caches, `cache_path`. Replace `from_cache` with
matching that origin or `provenance.cache_path().is_some()`. Governance refresh,
cache-status and proposal-cache list reports use `NnsGovernanceCollection` for
the existing `neurons` and `proposals` labels.

ICRC account-transaction rows use `IcrcAccountRow::Structured { owner,
subaccount_hex }` or `Legacy { account_identifier }`. JSON discriminates them
with `account_kind: "structured"` or `"legacy"`. Mixed, missing-identity, and
former flat account shapes are rejected. Original index identifiers and the
lossless `raw_transaction` projection are unchanged; external Candid protocols
remain separate and unchanged.

Paged progress events carry `PagedQueryProgress` counters, collection identity,
optional target name, and lifecycle state. Update progress consumers that read
the former text field. CLI formatting owns the wording and escaping; library
callers can inspect counters without parsing human-facing strings.

### 🧭 Migration Notes

Schemas remain `1`, with one current reader and no migration or fallback format.
Before upgrading, coordinate Rust/JSON consumers and preserve any historical
snapshots or exported reports they still need. Explicitly refresh SNS proposal
snapshots containing the removed derived row fields. Cache-only and ordinary
missing-only reads reject them without modifying the original bytes.

ICRC account-history snapshots containing the former flat account objects also
require an explicit complete refresh. Preserve required prior evidence first;
cache-only inspection remains strict. The existing authorized read-through repair
policy can replace invalid ICRC content, so archive required evidence before
invoking it. Failed refreshes preserve the prior complete snapshot.

SNS neuron, deployed-SNS catalog, NNS neuron/proposal, reward-checkpoint, and
Subnet catalog snapshots retain their formats. Their caches need no reset for
this batch. Progress, report-only provenance and inspection-summary changes do
not change snapshot identity or collection budgets.

### 🧹 Cleanup

Classification evaluation and its fingerprint use the same typed Registry-kind
and curated-Subnet tables. The existing canonical policy bytes and digest are
preserved, including charging defaults, ordering, curated annotations and their
provenance. Certificate/cache admission, raw reply evidence and separate NNS/SNS
collection boundaries remain intact.

Release and publish Query before the matching CLI/Text group.
