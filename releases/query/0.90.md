# Query 0.90 release notes

## 0.90.0 - 2026-11-04

### ⚠️ Public dependency identities

Adopt published Platform 0.22.0 and Host Tools 0.82.0. Query's certificate
authentication helpers exchange upstream certificates and hash trees through
Platform's certification exports, shared directly with Agent;
certificate decode errors and ledger tips expose Host-owned types. Rust
consumers exchanging these values must align direct Platform dependencies to
0.22 and Host Tools to 0.82. These crate identities change even where fields
and wire behavior are unchanged, so this batch requires a Query minor release.

Canonical Types stays at 0.18.0 and Runtime at 0.19.1. Query retains its trust-root,
endpoint, quota, retry and error-projection policies. Report, cache and CLI
formats are unchanged, all schema identifiers remain 1, and no cache reset is
required for this dependency alignment.

### 🔧 Native fixture alignment

Adopt Testkit 0.85.1 and its owned `ic_testkit::pocket_ic` client for the private
Governance fixture. Remove the separate `ic-platform-pocket-ic` dependency;
client values and installation extensions now come from one Testkit owner.
PocketIC's response-size error remains typed. Query does not select the new
snapshot-transfer APIs. The client now requires an explicit server endpoint and
removes implicit binary discovery/download/startup. Query already supplies the
endpoint through `PocketIcStartupConfig::build_instance`; keep that managed
server/instance owner alive through the fixture. Prepare the matching CLI with
`make install-testkit`, then admit it offline with `make testkit-check`.
This changes development fixtures, not Query's public API or report/cache behavior.
The server remains PocketIC 16.1.0 and Wire remains 0.16.2; Foundation 0.74.3,
Text 0.74.2 and Build 0.74.3 remain selected. Rust stays pinned at 1.99.1.

### 🔧 Published Tooling and Runtime patches

Align the Foundation catalog requirements with the already locked Artifacts,
FS, HTTP and Process 0.74.3 packages, and Build with 0.74.3. Foundation's patch
separates upstream test helpers from production code. Build shares Wasm/generic
cache finalization while preserving published entries and cleanup error evidence;
its earlier dependency-free archive admission fix remains included.

Qualify the locked Platform 0.22.0 family with Runtime, macros and runtime guard
0.19.1. That patch reorganizes upstream tests while retaining runtime bodies
and identities. Platform 0.22 and Host Tools 0.82 replace the former certificate
and hash-tree identities with upstream types shared by Agent. Remove recursive
conversion calls; Host retains strict bounded decoding and Agent authentication.
Testkit 0.85.1 aligns its Candid/management DTO dependency with Platform 0.22,
removing the last Platform 0.21 lock entry. Native fixture, production native and
Wasm graphs share canonical Types/Runtime identities without a second facade. This cut requires the pending minor release;
report/cache schemas and CLI behavior remain unchanged.

### 🔧 Release-group validation

Adopt Shared Tooling 0.29.3's canonical roster, baseline observation, plan runner,
evidence verifier and receipt custody helpers. Full CI and release selection use
one declaration. Query changes retain Query/Testkit tests and CLI/Text reverse
consumers. Qualified CLI/Text-only changes omit unchanged Query engine and private
Testkit test execution while retaining real public report/schema integration,
feature/runtime boundaries, installed native lanes and every archive. Shared,
unknown or unqualified scope selects the full roster. Both groups may omit
unchanged automation regression suites; all omissions have explicit local reasons.

Preserve source/index admission and exact retained evidence during recovery.
Changed mappings select native full/selected comparisons; ordinary source changes
run full CI once. Unqualified hosts retain the full release gate. This addresses
[#112 — Query/CLI release plans](https://github.com/dragginzgame/ic-query/issues/112); see the [mapping contract](../../docs/query-release-validation.md).

### 🧪 Test source layout and tooling admission

Move inline unit test bodies and test-only fixtures into their owning test files,
using ordinary module discovery. Keep production module boundaries, test behavior,
feature gates and existing coverage. File-based source reports now distinguish
these tests from production code. Documentation debt follows relocated owners
without adding new exceptions.

Shared Tooling 0.29.3 transfers the native client dependency exception to Testkit,
preserves manifest-order failures during release admission and authenticates
UTF-8 selection reasons in retained evidence. A focused Query fixture exercises
its real selector, Shared runner and recovery receipt with a non-ASCII reason.

### ⚠️ Report payload and derived counts

`IcCanisterSourceData` and `IcCanisterReport` now contain `data: IcCanisterData`.
Custom sources and Rust callers construct/access the payload there; provenance
remains separate. JSON still flattens the payload. Canonical identity, duplicate
controller/upgrade, provenance and module-hash validation remain in projection.

Remove `IcCanisterReport.upgrade_count`, the three Node Status `returned_*_count`
fields, and `IcApiBoundaryNodeReport.node_count`. Derive these from `upgrades`,
`nodes`, `subnets`, `providers`, or `rows`; nullable upgrade history stays nullable.
Full-snapshot counts and cache integrity fields remain because they describe
independent evidence. These emitted report contracts replace schema 1 in place;
update consumers before adopting. No persisted snapshot shape changes or cache
reset is required, and no older reader/migration is retained.

Registry node-provider and Subnet-topology acquisition now constructs the report
owner's DTOs directly. Remove five private intermediate DTOs and their projection
copies; retain checked provider counts, relationship validation and final report
validation.

Node Status remains: its three CLI views share one bounded Dashboard snapshot
with a 60-second freshness policy. It reports off-chain observed health, separate
from authoritative Registry membership. See the investigation in
[reporting adapters](../../docs/design/ic-reporting-adapters.md#node-status-retention-review).

### ⚠️ Output-only derived analytics

Remove `validate_nns_proposal_activity_report`,
`validate_nns_neuron_distribution_report`, `NnsProposalActivityValidationError`
and `NnsNeuronDistributionValidationError`. Activity/distribution report DTOs,
their bucket/count rows and `NnsGovernanceAnalyticsContext` retain serialization
and lose deserialization. This explicitly retires the saved-summary read-back
contract, including its restoration-only tests and private validation helpers.
No production Rust consumers were found in this checkout or the inspected sibling
sources; external consumers must adopt the public API retirement before updating.

Portable and cache-only builders remain, as do source-provenance, collection-
state, row-identity/time/accounting checks and checked aggregation. Persisted
collection-state input contracts and analytics JSON output remain unchanged at
schema 1. Preserve existing caller-owned reports; there is no migration, reset,
compatibility reader or automatic deletion. Retain source collection state and
rows when recomputation is needed.

CloudEngine Type4 node-list reports remove only the redundant `node_count` field.
Use `nodes.len()`; source query scope and independent aggregate fields remain.
This emitted shape replaces schema 1 in place and does not affect a cache.

### ⚠️ Request configuration and remaining derived fields

Remove 62 assignment-only `with_*` methods on request/query types whose target
fields are already public. Constructors and their defaults remain. Configure
fields explicitly after construction; optional setters become `Some(value)`
assignments, retaining `.into()` when converting strings or paths. This is a
public API retirement without aliases or replacement setter wrappers.

For example, replace the SNS metrics window setter with:

```rust
let mut request = SnsMetricsRequest::new(lookup);
request.time_window_seconds = 90 * 24 * 60 * 60;
```

Do not mechanically replace every method with the same name. NNS/SNS proposal
`with_sort` still resets the direction to that sort's default;
`SnsProposalsRequest.with_status` still admits filters against the acquisition
route, and its `with_cache_root` still selects that route. These methods and their
order remain. `SnsListRequest.with_sort` was a plain assignment and is removed.
All source admission, quotas and cache policy still run in their existing owners.

Remove these emitted fields while retaining the underlying data:

| Report | Removed field | Consumer replacement |
| --- | --- | --- |
| `CloudEnginePricesReport` | `price_count` | `prices.len()` |
| `CloudEngineProviderListReport` | `cloud_engine_provider_count` | `providers.len()` |
| `CloudEngineOperatorReport` | `operator_binding_present` | `operator_canister_id.is_some()` |
| `CloudEngineOperatorReport` | `claimed_domain_count` | `claimed_domains.as_ref().map(Vec::len)` |
| `NnsTopologyRegionsReport` | `region_count` | `regions.len()` |
| `NnsTopologyProvidersReport` | `referenced_node_provider_count` | `providers.len()` |

Keep source-wide, registered-provider and aggregate totals that carry independent
evidence. Human text retains its existing labels and values. These report-only
shape changes replace schema 1 in place; consumers must adopt them. They do not
change persisted cache shapes, keys or schemas, and require no cache reset.

Retire the documentation-debt entries for deleted methods/fields; do not add new
exceptions. Existing caller-owned JSON and cache evidence is preserved.
