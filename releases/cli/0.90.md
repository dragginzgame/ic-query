# CLI and Text 0.90 release notes

## 0.90.0

### ⚠️ Public dependency identities

Align Query/Text consumers with the [Query 0.90 dependency family](../query/0.90.md):
Platform 0.22.0 and Host Tools 0.82.0. Rust embedders passing Query/Text report
types or Platform certificates and Host errors must align direct dependencies.
CLI commands, human-facing output, JSON and cache shapes are unchanged; schema
identifiers remain 1.

### 🔧 Native fixture alignment

Use Testkit 0.85.0's owned PocketIC client and remove the separate
`ic-platform-pocket-ic` dependency. The prepared PocketIC 16.1.0 server and
Wire 0.16.2 remain selected. Canonical Types 0.18.1, Runtime 0.19.1,
Foundation 0.74.3, Text 0.74.2, Build 0.74.3 and Rust 1.99.1 remain selected.
The Testkit client requires an explicit endpoint; Query's existing managed
startup supplies it. Prepare the matching CLI with `make install-testkit` and
admit it offline with `make testkit-check`. This development-only alignment adds
no Query CLI surface or output change.

### 🔧 Published Tooling and Runtime patches

Align the Foundation and Build catalog requirements with their existing locked
versions, and qualify native consumers and the Wasm probe against the published
[Query dependency family](../query/0.90.md). Runtime/macros/guard 0.19.1 retain
the canonical runtime implementation. Published Platform 0.22 and Host Tools
0.82 share upstream certificate/hash-tree identities directly with Agent. Commands,
output and schema identifiers remain unchanged by this dependency alignment.

### 🔧 Release-group validation

Qualified CLI/Text-only changes run CLI processes, Text presentation and real
Query report/schema integration without unrelated Query engine or private Testkit
test suites. Query changes retain CLI reverse consumers. Full CI and selected
plans share one roster through Shared Tooling 0.29.3, retaining feature/runtime
boundaries, installed native lanes, archive admission and recovery custody.
Shared, unknown or unqualified scope keeps the full gate. Native comparisons
qualify changed mappings instead of repeating every group gate on ordinary
changes. This addresses [#112 — Query/CLI release plans](https://github.com/dragginzgame/ic-query/issues/112); see the
[mapping contract](../../docs/query-release-validation.md).

### 🧪 Testing

Standalone Governance probe fixtures declare their own workspace so retained
temporary directories do not accidentally join the enclosing Query workspace.

### 🧪 Test source layout and tooling admission

Move inline unit test bodies and test-only fixtures into their owning test files,
using ordinary module discovery. Keep production module boundaries, test behavior,
feature gates and existing coverage. File-based source reports now distinguish
these tests from production code. Documentation debt follows relocated owners
without adding new exceptions.

Shared Tooling 0.29.3 transfers the native client dependency exception to Testkit,
preserves manifest-order failures during release admission and authenticates
UTF-8 selection reasons in retained evidence. A focused Query fixture exercises
its real selector, Shared runner and recovery receipt with a non-ASCII reason.

### ⚠️ Concise human reports

NNS node/operator/provider/data-center and Subnet Catalog list renderers now take
`TextOptions`. Replace calls to `*_list_report_verbose_text(report)` with
`*_list_report_text(report, TextOptions { verbose: true })`; ordinary calls pass
`TextOptions::default()`. Each collection has one row builder. Verbose retains
full identities and report-level provenance; exhaustive fields remain in JSON.

Proposal/neuron lists no longer append an exhaustive dump of every row. Neuron
info uses the same summary table as the list. NNS/SNS proposal info retains its
identity, state, title, creation time and summary. Proposal ballots and all raw
numeric/detail fields remain in the existing `--json` reports. Remove `--ballots`
and `TextOptions.show_ballots`; callers pass only `verbose`. Collection, filtering,
cache identity and JSON ballot acquisition are unchanged.

Query report consumers also adopt the shared canister payload and redundant-count
removal described in the [Query notes](../query/0.90.md). Schema identifiers remain 1.

### 🔧 Presentation ownership

Use small Query helpers for labelled fields and the standard report table style;
Host Text continues to own terminal escaping, alignment and layout. Query keeps
unit selection and token amounts. NNS/SNS refresh output shares publication,
finalization and coordination fragments, and SNS refresh uses its existing
collection-context owner. Publication failures remain explicit in human output.

### 🔧 Contract-test ownership and output-only analytics

Adopt Query's analytics read-back API retirement and CloudEngine node-count cut.
Analytics commands and their JSON/text output remain unchanged. CloudEngine text
still prints the derived count; JSON consumers count the retained `nodes` vector.

Keep cross-crate custom-source, valid portable paging/resume and rendering/JSON
contracts. Remove constructor-field mirrors and signature-only assertions already
exercised by real CLI callers; share existing typed NNS inventory fixtures.
Analytics renderer fixtures use typed output DTOs and still compare against the
same golden JSON and text, without requiring a production report reader.

### ⚠️ Explicit request fields and derived report counts

Adopt the [Query request and report cuts](../query/0.90.md).
Configure public request fields directly while preserving constructor defaults,
fallible status admission, cache-route selection and proposal sort-direction
resets. CLI flags, acquisition order and text output remain unchanged.

JSON consumers derive the retired price/provider/region counts and operator
binding/domain summaries from the retained vectors or optional values. Preserve
independent source totals, including the complete Dashboard provider count before
CloudEngine filtering. Report schemas remain 1; persisted caches are unchanged.

Keep the existing golden text expectations and update only the retired JSON
fields. Native/portable consumers and representative option, cache, filtering
and bounded-source rejection cases qualify the changed callers. Remove stale
public-documentation debt entries for retired API members.
