# CLI and Text 0.91 release notes

## 0.91.0 - 2026-11-05

### ⚠️ One proposal cache inspection command

Use `icq nns proposal cache status` instead of `icq nns proposal cache list`.
The single-snapshot status report includes snapshot validation and independent
refresh-attempt evidence. For JSON, read the optional `cache` object instead of
the former `caches` array, and use `found` and `expected_cache_path` for snapshot
presence and location. Missing snapshots retain any available `latest_attempt`.

Text consumers use `nns_governance_cache_status_report_text` instead of the
removed `nns_proposal_cache_list_report_text`. Rust consumers also adopt the
[Query 0.91 failure classification accessors](../query/0.91.md).

The command and renderer removals require a minor release. SNS collection cache
lists and Registry, node, operator, data-centre and topology reports remain
available. All current schemas remain 1. Shared inventory consumers adopt the
replacement cache and refresh shapes below.

### 🧪 Downstream tests

Remove function-pointer-only API assertions and repeated snapshot inspection
checks. Keep downstream fixture execution, custom sources, serialization,
rendered-output contracts and cache failure/recovery coverage.

### ⚠️ Shared Registry views and provider refresh

NNS node, operator and data-centre commands now use one complete Registry
snapshot. Refreshing any of those views replaces all three tables; its `--output`
file contains the shared snapshot rather than a single view. First reads collect
the new inputs; older per-view caches remain untouched and are not migrated.

Node-provider refresh returns separate `inventory` and `metadata` outcomes.
Its `--output` file contains Governance metadata without Registry node counts;
`nns node-provider list --json` returns the joined report. List/info JSON adds
`governance_source` and text identifies that independent acquisition.

Topology refresh reports three components: Subnet Catalog, shared Registry
inventory and Governance provider metadata. The metadata row's Registry version
is JSON `null` and text `-`, rather than an invented version. Registry-backed
node, operator, data-centre, provider and topology commands remain available.

### ⚠️ Retired global cache overview

Remove `icq cache status` and `ic_query_text::cache::cache_status_report_text`.
Family-specific collection cache list/status commands and typed cache admission,
confinement, refresh locks and recovery remain available. There is no replacement
cross-family file/age/lock inventory command.

### 🧪 Shared-snapshot coverage

Check that all three Registry views use one acquisition and pin, and that a
failed Governance collection cannot invalidate their snapshot. Keep partial
refresh, dry-run/export protection, raw protocol and downstream source coverage.

### 🧪 Canister CI lint scheduling

Each canister job runs the complete native Clippy target once and the dedicated
Wasm probe lint in one stage, before deterministic Testkit execution, local NNS
smoke and bundle construction. The three product checks use the already prepared
locked dependency cache and do not repeat lint or dependency preparation. Linux,
Apple Silicon macOS and Intel macOS coverage remain selected. Standalone
canister development commands retain their lint gates; lint failures stop product
execution even when Make runs with parallel jobs.

### ⚠️ Keep token and stake reads for Toko

The `sns` namespace now contains only neuron list/info/refresh and cache
list/status. Every addressed operation accepts an explicit Governance principal.
Remove project list/info/refresh, token, parameters, proposal, metrics, swap,
upgrade and canister-health commands and their Text renderers. Generic ICRC
balance, token metadata, transaction/burn reads and indexed holder pagination stay.

Neuron JSON includes raw principal permission codes in every row. Exact reports
use `neuron`, dropping the former followee/maturity-policy report. Text identifies
the Governance target and principal permissions. No output decides eligibility.

Refresh the new schema-1 Governance-addressed snapshot before cached sorting;
old Root-addressed files and project catalogs are not read, migrated or deleted.

```bash
icq sns neuron list "$GOVERNANCE_CANISTER_ID" --owner "$USER_PRINCIPAL" --json
icq sns neuron info "$GOVERNANCE_CANISTER_ID" "$NEURON_ID" --json
icq sns neuron refresh "$GOVERNANCE_CANISTER_ID"
```

### ⚠️ Consistent text clipping and refresh-attempt evidence

Long report summaries and metadata now use Host Text's terminal-column clipping.
The column budget includes the `…` marker, and Unicode display widths determine
where clipping occurs. Raw report and JSON strings remain complete.

NNS Governance, SNS neuron and ICRC account-history cache status use one shared
refresh-attempt block: `attempt_status`, `attempt_started_at`,
`attempt_updated_at`, `attempt_page_size`, `attempt_pages_fetched`,
`attempt_rows_fetched`, `attempt_last_cursor` and `attempt_last_error`.
ICRC additionally retains its index identity as `attempt_index_canister_id`.
This replaces SNS's indented lifecycle block and ICRC's `latest_attempt_*`
labels. JSON, source errors and persisted sidecars retain their typed evidence.

### 🧹 Clap owns command syntax

Clap derives complete command paths from the composed tree and owns the typed
canister filters and ICRC analytics option schemas, including repeatable labels,
cursor conflicts, enumerated sorts and numeric bounds. SNS sort parsing selects
live acquisition or the existing cache-sort type directly; principal parsing
uses Clap's typed parser and canonicalizes through Platform. Canister principal
arguments, filter principals, cursors and nonempty filter labels are admitted by
Clap before request dispatch; malformed syntax returns its usage error.

Namespace help, alphabetical subcommands, current options and defaults remain.
SNS's conditional owner/sort and live-limit rules stay together after parsing:
Clap's declared relationships check presence rather than a conditional numeric
range or another argument's required value. Report admission remains independent.
Scalar text preambles share label/field mechanics, while selected fields, token
units, availability labels and source distinctions remain report-owned.

### 🔧 Shared Tooling 0.30 and source hygiene

Adopt the committed 0.30.0 snapshot and its updated source layout, lint,
retained-state and validation ownership rules. The Governance smoke runner and Registry timing utility move
to their package's `tools/` directory and its deployable probe to `tests/fixtures/`.
Both retain their Cargo example names and existing commands. The private Testkit
package declares a tests-only LOC role; the root catalog distinguishes production,
mixed and development dependencies. Remove misleading workspace-member role
comments; Cargo target roles and explicit fixture metadata remain authoritative.

Remove the workspace-wide `needless_pass_by_value` allowance. Fix avoidable wire
cloning and scalar selector ownership; document deliberate owned conversion and
publication boundaries through scoped `expect` attributes. Keep documentation
and exported-name policies at workspace scope and enable unfulfilled-expectation
warnings explicitly.

Local shell and Rust test scratch uses workspace `target/tmp/`; shell adapters
retain explicit `TMPDIR` overrides. Persistent ICP identities remain under their
separate custody contract. The new shared release runner checks bounded Git-side
retention and keeps new reproducible validation trees under `target/`.
Committed-source manifest ordering also retains its extracts under `target/`,
keeping Git-side recovery state free of new source copies. Retire reviewed
legacy source/build copies with explicit cleanup approval, preserving historical
commits, qualification evidence and recovery metadata. This does not claim
native Linux/macOS release qualification.

The Registry timing utility uses Clap for its required native-path argument,
usage, help and rejection of unknown options, before any live acquisition:

```bash
cargo run -p ic-query-cli --example subnet_catalog_timing -- --help
```

### 🛡️ Terminal diagnostics

CLI runtime errors and cache-refresh progress escape untrusted control characters
in remote messages, selected paths and endpoint fields. The contributor smoke
runner also escapes captured stderr and cleanup diagnostics. Keep raw typed errors and
report evidence intact, and retain Clap-owned usage formatting and local refresh
advice. This prevents source text from injecting additional terminal lines or
control sequences through these application-owned sinks.

Refresh the Shared snapshot to `4d09618` for the latest committed LOC reporter.
Workspace summaries use concise names, `???` identifies unclassified lines, and
classification details remain available through JSON diagnostics. A single
workspace has one summary row; subcrate rows remain explicitly selectable.
