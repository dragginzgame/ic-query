# CLI and Text 0.93 release notes

## 0.93.2 - 2026-11-06

### 🧪 Stable deadline fixture

Launch a checked-in stalled-command fixture in the Governance smoke harness
deadline test. Avoid writing an executable immediately before parallel process
tests launch it, which exposed a Linux `Text file busy` failure. Keep the timeout,
original stdout and original Host failure evidence assertions unchanged.

### 🧹 Shared rendering and command adapters

Use the existing scalar-field renderer for account, CloudEngine, Governance and
Subnet Catalog preambles. Retain field names and order, escaping, decimal policy,
custom balance lines and table sections. Host Text continues to own the formatting
mechanics; Query Text owns the report fields and units.

Extend that field rendering to token summaries and Registry/Governance provenance.
Share Dashboard and token metadata JSON display conversion, retaining null
placeholders, string contents, terminal escaping, fee units and logo summaries.

Share topology summary and coverage label/value table construction through the
existing Host Text table adapter. Keep each report's selected rows, headers,
alignment, escaping and section spacing unchanged.

Share node-operator/data-centre inventory dispatch and explicit source-endpoint
argument setup. Keep their existing typed requests, lazy cache-root lookup,
collection modes, defaults, help, argument order and diagnostic behavior. No
command, report or public API is removed.

### 🧹 Release-group Cargo selection

Selected CLI/Text plans use Clippy for their two packages, then verify
Text and CLI archives in dependency order against the actual local Query/Text
peers. Unchanged Query/Testkit engine checks and Query packaging are omitted;
feature/runtime and public-consumer boundaries remain required. Full CI and
full-fallback releases retain both groups' checks and all archives. Standalone
workspace commands and product behavior are unchanged.

Remove the second native Cargo check stage: its package, target, feature and
profile selection is already covered by Clippy's compiler checks. Keep the
standalone developer check and distinct feature, Wasm and archive verification.

The new mapping requires native full/selected comparison evidence before host
admission. Until then, releases keep the complete gate. Fixtures inspect real
Make/Cargo dispatch, failure propagation and archive source admission without
claiming native qualification or measured savings.

## 0.93.1 - 2026-11-06

### 🧹 Typed command options

Use typed Clap argument records for the remaining report options and share
source/output, inventory and pagination declarations. Remove their duplicate
argument-building and string-keyed extraction helpers. Keep the existing command
tree, defaults, bounds, collection policies and text/JSON report contracts.
Command descriptions now remain separate from Rust option-type documentation,
including pages that previously displayed internal type names.

### 🧹 Shared report context and field rendering

Use the existing report-field helper for Dashboard provenance, reward details,
account records, canister metadata and series summaries. Keep each report's
selected fields, order, optional-value formatting, escaping and table layout.
No command, report field or renderer is removed.
Pass the existing typed collection context directly to the shared NNS analytics
preamble, preserving its identity, timestamps and provenance fields.

### ⬆️ Build tooling

Adopt Build 0.75.0 for the Governance smoke tool and the shared release metadata
CLI. The removed upstream inspection/configuration APIs are unused here; keep
the existing probe input resolver, source fingerprint, limits and metadata
publication behavior. Product commands and output are unchanged.

## 0.93.0 - 2026-11-05

### 🧹 Enforce the Candid source boundary

Adopt Shared Tooling 0.30.4 at committed revision `a08f03a`, including its
generic inherent-header fix, through the snapshot exporter. CI and both release
plans run `candid-boundary-check` once over all first-party Rust source, tests
and examples. Each necessary external IC DTO or codec helper has an exact named
declaration allowance with its protocol and reason; whole modules and owned
application models are not exempt. The lexical check rejects unreviewed trait
references and stale allowances without Cargo or network access. It complements
the released model separation in [#114](https://github.com/dragginzgame/ic-query/issues/114);
native CI acceptance remains separate. No CLI or report contract changes.

Shared Tooling now supplies `docs/supported-hosts.md`. Preserve Query's native
matrix and requirements in `docs/query-supported-hosts.md`, updating local guide
links without narrowing required hosts or changing qualification obligations.

### ⬆️ Host and simulator alignment

Adopt published Host Tools 0.83.0 and Testkit 0.87.0. Both select Platform 0.23,
removing the retained Platform 0.22 generation. Canonical Types/Runtime remain
shared. Query already uses Platform's strict certificate/hash-tree decoder;
replace stale feature guards with that capability's current name.

The compiled Governance fixture owns one Tokio runtime and awaits client startup,
network calls, installation and report assertions. It explicitly deletes its
instance before releasing server custody. Failed assertions also attempt deletion;
the original panic is retained and any secondary deletion failure is reported.
No blocking-client compatibility wrapper or private per-call runtime is added.

### ⚠️ Rust dependency identities

Host Tools 0.83 changes the Host-owned `LedgerTip` package identity returned by
`authenticate_ledger_tip` under `ledger-evidence-host`. Callers exchanging that
value with Host's chain verifier select Host Tools 0.83. Query report fields,
JSON/schema-1 contracts, authentication order and byte/nesting limits remain
unchanged. This public Rust boundary requires a Query minor release. Rust text
renderer callers adopt the corresponding Query model generation; command syntax
and text/JSON output do not change.
