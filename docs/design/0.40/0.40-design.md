# 0.40 Design: Portable NNS Public-Neuron Distribution Analytics

- Status: implemented in the 0.40.0 release slice
- Scope: deterministic distribution totals over one caller-supplied,
  API-exhausted public NNS neuron collection
- Authority: local projection of unauthenticated Governance `NeuronInfo`
  evidence
- Runtime: pure Rust under the existing no-default library surface
- Persistence: caller-owned; no new cache or stable-memory contract
- Workspace: exactly the existing `ic-query` and `ic-query-cli` crates

## Purpose

The public-neuron continuation API can already collect every row exposed by
Governance while preserving bounded one-call advances and API-exhaustion
evidence. Callers building governance dashboards still need to validate those
retained rows and repeat basic distribution accounting before presenting the
collection.

The first 0.40 slice adds that pure local projection. It reports factual
counts by raw neuron state, optional visibility, and optional neuron type;
effective-stake totals; coverage-aware totals for optional staked maturity and
current voting-power fields; known-neuron metadata coverage; Neurons' Fund
join-timestamp presence; and the range of row retrieval timestamps.

This is not an authenticated owner view or a network-wide balance sheet.
Governance returns a limited unauthenticated `NeuronInfo` view, collection is
sequential, and optional values can be absent. The report preserves those
limits instead of interpreting absence as zero or claiming atomic state.

## Release outcome

The public library surface consists of:

- `NNS_NEURON_DISTRIBUTION_REPORT_SCHEMA_VERSION`, fixed at `1` before 1.0;
- `build_nns_neuron_distribution_report`, a synchronous pure builder over a
  complete `NnsNeuronCollectionState` and its retained rows;
- `NnsNeuronDistributionReport` and typed state, visibility, and neuron-type
  distribution rows;
- `NnsNeuronDistributionError`, retaining collection, row, and checked-
  accounting failures;
- `validate_nns_neuron_distribution_report` and
  `NnsNeuronDistributionValidationError`, providing pure validation for
  retained or deserialized reports; and
- `nns_neuron_distribution_report_text`, the reusable human renderer.

All surfaces are available with `default-features = false` on native and Wasm
targets. The slice adds no CLI command or option.

## Crate and feature boundary

The workspace remains two crates:

```text
ic-query
  public-neuron continuation state and rows
  pure distribution validation, aggregation, report model, and renderer

ic-query-cli
  unchanged; no 0.40.0 parsing, dispatch, or process output
```

No Cargo feature or dependency is added. There is no Wasm-specific analytics
implementation. A canister may collect rows through `CanisterNnsSource`, but
the report builder itself performs no host call and needs no runtime feature.

## Input contract

The builder borrows a final continuation state and all rows admitted beside
it:

```rust,ignore
pub fn build_nns_neuron_distribution_report(
    collection: &NnsNeuronCollectionState,
    neurons: &[NnsNeuronRow],
) -> Result<NnsNeuronDistributionReport, NnsNeuronDistributionError>;
```

The collection must pass the existing continuation-state validator and have
status `complete`. `ready`, `collecting`, and `page_limit_reached` states are
rejected. The supplied row count must exactly equal the state's cumulative
`neurons_fetched` accounting.

Rows must remain in the strictly ascending, unique neuron-id order required by
the continuation and cache contracts. Raw state, visibility, neuron-type, and
recent-ballot vote codes must agree with their typed classifications. The
builder shares that existing row-validation path instead of introducing a
second interpretation.

The state and rows are caller-owned evidence. Their structural agreement does
not cryptographically bind their contents or authenticate storage.

## Completeness, visibility, and time

“Complete” means the retained walk observed `get_neuron_index` API exhaustion.
It does not mean:

- every NNS neuron or every private neuron field was visible;
- controllers, followees, private unstaked maturity, or disbursement state
  were exposed;
- all rows describe one Governance instant;
- response content is certified; or
- the collection is bound to a Registry or Governance state version.

The report therefore always sets `point_in_time_guaranteed: false`. It retains
the final collection network, fixed Governance canister id, concrete source
provenance, caller-supplied collection start/update times, admitted page and
row counts, plus the earliest and latest raw
`retrieved_at_timestamp_seconds` found in the included rows.

Replica-query and replicated inter-canister-call provenance remain distinct.
Local aggregation does not strengthen either transport's assurance.

## Report contract

The schema-1 report contains:

| Field group | Evidence |
| --- | --- |
| collection | network, Governance canister, source provenance, start/update times, page and row counts |
| assurance | `point_in_time_guaranteed: false` and optional retrieval-time range |
| complete values | total public effective stake in e8s |
| optional coverage | reported/unreported row counts and the sum of reported staked maturity, deciding voting power, and potential voting power |
| public metadata | known-neuron metadata count and Neurons' Fund join-timestamp-present count |
| dimensions | raw-code-ordered state, optional visibility, and optional neuron-type rows with neuron count and effective stake |

Optional numeric fields are never converted from `None` to zero. Each optional
summary records both reported and unreported row counts, and its numeric total
sums reported values only.

Distribution rows preserve raw evidence:

```rust,ignore
pub struct NnsNeuronStateDistribution {
    pub state: i32,
    pub state_text: NnsNeuronState,
    pub neuron_count: u64,
    pub effective_stake_e8s: u64,
}

pub struct NnsNeuronVisibilityDistribution {
    pub visibility: Option<i32>,
    pub visibility_text: NnsNeuronVisibility,
    pub neuron_count: u64,
    pub effective_stake_e8s: u64,
}

pub struct NnsNeuronTypeDistribution {
    pub neuron_type: Option<i32>,
    pub neuron_type_text: NnsNeuronType,
    pub neuron_count: u64,
    pub effective_stake_e8s: u64,
}
```

State rows sort by raw numeric code. Optional visibility and neuron-type rows
sort with absent `None` first, followed by raw numeric codes. Distinct unknown
codes remain distinct rows even when their semantic class is unknown. Each
dimension's neuron counts sum to `collected_neuron_count`, and each
dimension's effective stake sums to `total_effective_stake_e8s`.

All counts and totals use `u64`; every conversion, increment, and sum is
checked. Accounting overflow returns a typed error rather than wrapping or
emitting a partial report.

## Retained report validation

`validate_nns_neuron_distribution_report` accepts a borrowed report and makes
no host call or state write. Freshly built reports pass through the same path
before return.

The validator checks schema 1, mainnet and Governance identities, transport-
specific provenance, positive and row-feasible complete-collection page
evidence, false point-in-time assurance, retrieval-range presence and order,
optional-field coverage accounting, metadata-count bounds, raw
classification, canonical dimension ordering, nonzero dimension rows, and
count/stake totals.

The report does not retain its source rows, so validation proves internal
consistency and canonical shape only. It cannot recompute source aggregates,
authenticate caller storage, or prove an atomic Governance snapshot.

## Deliberately excluded calculations

The 0.40.0 report does not expose or infer:

- controllers, followees, hot keys, owner identity, or authenticated fields;
- private unstaked maturity or pending disbursements;
- neuron rewards or reward-event history;
- proposal turnout, voting participation, or delegation quality;
- stake or voting-power concentration scores, percentiles, rankings, or
  arbitrary histogram buckets;
- current Neurons' Fund membership from any evidence other than presence of
  the public join timestamp; or
- joins to Registry, Dashboard, ledger, or off-chain data.

Those calculations require separate authority, visibility, or interpretation
contracts. Recent ballots remain bounded public row evidence and are not
promoted into complete participation history.

## Determinism and resource bounds

For identical valid collection state and rows, serialized output is
deterministic. The builder performs one linear row pass plus deterministic
ordering over distinct raw classification codes. It allocates only the
aggregate maps and clones no full row collection.

The number of distribution rows cannot exceed the number of retained neuron
rows. The builder makes zero network calls and performs no retry, scheduling,
state write, cache access, or background work.

## Text and JSON output

JSON is the script-facing form and retains raw codes, raw e8s, raw voting-
power values, counts, timestamps, and source provenance. Text renders a
collection and coverage summary, one blank line, then separate state,
visibility, and neuron-type tables.

The renderer returns `String`. Process arguments, terminal inspection,
stdout/stderr selection, and output writes remain exclusively in
`ic-query-cli`.

## Module ownership

- Distribution DTOs, builder, validator, and focused tests live below the
  existing NNS neuron report family.
- The continuation module continues to own collection-state invariants.
- The neuron source module continues to own row classification and ordering
  validation.
- Existing Governance helpers own source provenance validation.
- Public re-exports remain under `ic_query::nns::neuron`.
- `ic-query-cli` receives no 0.40.0 code.

The second pure complete-collection report justifies sharing narrow Governance
source-validation mechanics, but not a generic analytics framework, dataframe
layer, or universal grouping trait.

## Cache and publication policy

The builder reads no cache and writes no report. Native callers may supply
rows from a complete filesystem snapshot, canisters may use caller-owned
stable state, and tests may supply fixtures. Storage identity, atomic
replacement, scheduling, and freshness remain outside this report contract.

A caller restoring a serialized distribution report should validate it before
publishing or using it. No compatibility reader, fallback parser, migration,
stable-memory layout, cache key, lock, or attempt sidecar is added.

## Verification

Tests cover:

- complete aggregation across raw state, visibility, and neuron-type codes;
- effective-stake totals and optional-field reported/unreported accounting;
- known-neuron and Neurons' Fund timestamp-presence counts;
- retrieval-time range and empty complete collections;
- incomplete, page-limited, state/row-count, classification, and ordering
  rejection;
- checked accounting overflow;
- deterministic JSON and exact text section separation;
- retained-report round-trip and invariant corruption;
- no-default and public downstream API construction; and
- `wasm32-unknown-unknown` checks with no features and with `canister`.

## Explicit exclusions

The 0.40.0 slice does not add a crate, Cargo feature, dependency, CLI surface,
network call, filesystem cache, stable-memory policy, or schema above `1`.
It does not accept partial collection as complete analytics or claim
certification, owner authorization, full private visibility, historical
completeness, or point-in-time consistency.
