## Goal

`0.30` establishes a cryptographically authenticated path from the mainnet IC
root key to Registry evidence. The work proceeds in independently useful
stages: first authenticate the Registry's latest version, then validate
certified delta batches, then reconstruct and publish a certified Subnet
Catalog only if bootstrap and incremental replay remain explicitly bounded.

The release must preserve the distinction between:

- a certified `current_version` leaf;
- an exact-version ordinary `get_value` join;
- matching ordinary evidence from multiple endpoints; and
- Registry key state reconstructed from a complete certified delta sequence.

Only the final case may produce `CatalogAssurance::Certified`.

## Upstream Contract

The implementation follows the pinned Registry canister implementation and
protobuf definitions reviewed for this design:

- [Registry certified query methods](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/registry/canister/canister/canister.rs)
- [Registry certification tree](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/registry/canister/src/certification.rs)
- [Registry transport protobuf](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/registry/transport/proto/ic_registry_transport/pb/v1/transport.proto)
- [Registry chunk storage](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/registry/canister/src/storage.rs)
- [Upstream chunk reconstruction contract](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/nervous_system/chunks/src/lib.rs)
- [Mixed hash-tree protobuf](https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/protobuf/def/messaging/xnet/v1/mixed_hash_tree.proto)

`get_certified_latest_version` returns a protobuf `CertifiedResponse`. Its
mixed hash tree commits to a canonical unsigned-LEB128 `current_version` leaf
and the pruned Registry delta-map root. `get_certified_changes_since` returns
the same certified current version plus a requested range from the delta map.
Neither method directly certifies an arbitrary `get_value` response.

## Trust And Failure Model

The built-in mainnet path trusts only the compiled-in mainnet root key and the
Registry canister identity. It must reject:

- invalid certificate signatures, delegation, or canister authority;
- stale certificates or certificate times outside the caller observation
  window;
- a certificate whose `certified_data` value does not match the mixed-tree
  digest;
- malformed, missing, excessively deep, or excessively large tree nodes;
- pruned digests that are not exactly SHA-256 length;
- absent, unknown, non-leaf, overflowing, truncated, trailing, or
  noncanonical version values;
- delta gaps, regressions, duplicate versions, noncanonical mutation order,
  and truncated replay presented as completion; and
- a bootstrap or incremental sequence exceeding its explicit call, byte,
  version, key, or value ceilings.

Certificate verification authenticates evidence; it does not make sequential
queries point-in-time atomic. Every reconstructed snapshot identifies its
selected certified Registry version and rejects values newer than it.

## 0.30.0 — Certified Latest Version

The existing `icq nns registry version` command and public report are hard-cut
to the Registry's `get_certified_latest_version` method. The live adapter:

1. rejects non-mainnet network identity before agent construction;
2. performs one response-bounded Registry query;
3. decodes the official protobuf `CertifiedResponse` and mixed hash tree;
4. authenticates the CBOR certificate against the mainnet root key;
5. verifies the Registry canister `certified_data` commitment;
6. reads a canonical unsigned-LEB128 `current_version` leaf;
7. checks certificate time within five minutes of the caller-supplied
   collection time; and
8. returns certificate time, root-key digest, raw certificate, raw encoded
   witness, and exact byte counts.

The report schema moves from version 1 to version 2. Text remains compact and
shows assurance, time, digest, and evidence sizes; JSON preserves raw evidence.
The operation remains live and uncached. Command names and options do not
change.

The mixed-tree decoder currently accepts at most 128 levels and 65,536 nodes,
in addition to the shared 8 MiB native-agent response-body limit. These are
defence-in-depth ceilings rather than an estimate that the latest-version tree
will approach them.

`certified-subnet-catalog-host` owns the direct CBOR dependency required for
certificate decoding and includes `subnet-catalog-host`. `nns-host` includes
that focused certified surface alongside `nns-topology-host`; the narrower
`nns-topology-host` and `subnet-catalog-host` graphs remain unchanged.

## 0.30.1 — Certified Delta Batch

This stage adds a pure validator plus a caller-runtime async transport for
one `get_certified_changes_since` batch. A validated batch must retain:

- requested start version;
- certified latest version;
- first and last visible delta versions;
- canonical ordered mutations and mutation timestamps;
- certificate time, root-key digest, endpoint, and raw evidence sizes;
- whether more certified versions remain; and
- exact call and byte accounting.

Visible delta labels are eight-byte big-endian versions. They must begin at
`requested_version + 1`, increase by exactly one, and never exceed the
certified latest version. Each leaf must decode as the official
`HighCapacityRegistryAtomicMutateRequest`. In `0.30.1`, every large-value
chunk reference was rejected as incomplete pending a bounded retrieval design.

A batch validator does not publish a catalog and does not expose
`CatalogAssurance::Certified`.

The `0.30.1` public operation performs exactly one query and never follows
`more_available` implicitly. The caller must issue the next request from the
returned last version. The validator enforces at most 1,000 visible versions,
65,536 mutations, 65,536 preconditions, 4,096 bytes per key, 2 MiB of combined
inline values, the shared 8 MiB agent response limit, and the existing
mixed-tree depth and node limits. These ceilings are returned in the report so
custom sources and consumers can audit the applied contract.

The report preserves raw mutation discriminants and typed native
insert/update/delete/upsert kinds, key and inline-value bytes as canonical
lowercase hexadecimal, atomic mutation order, preconditions, timestamps,
query and byte counts, and certificate evidence. Unknown mutation kinds,
decreasing key order, noncontiguous version labels, and initially unsupported
large-value chunk references fail closed. Repeated committed keys and retained
delete content are handled by the later `0.30.7` compatibility stage. A
pure public validator recomputes every structural derived count and
boundary for trusted custom source reports. It checks certificate evidence
shape and freshness but does not reauthenticate custom-source certificate
bytes; cryptographic authentication remains that source's responsibility.

The `0.30.1` operation is mainnet-only, live, async, and uncached. It does not
loop, bootstrap historical state, retrieve large-value chunks, replay
mutations, publish a mirror, alter CLI grammar, or strengthen Subnet Catalog
assurance.

## 0.30.2 — Bounded Large-Value Completion

The certified delta transport now completes every
`LargeValueChunkKeys` mutation before returning the batch. The certified tree
authenticates the ordered SHA-256 chunk references; each content-addressed
`get_chunk` response is accepted only when its content hashes to the expected
digest. Repeated hashes within or across mutations reuse the already verified
content rather than issuing another query.

Completion is one finite extension of the selected delta response, not hidden
delta pagination. The transport enforces all of these fixed ceilings:

- 64 chunk references across the batch;
- 1,800,000 decoded bytes per chunk;
- 10 MiB reconstructed bytes per value;
- 16 MiB combined inline and reconstructed value bytes;
- 32 MiB of encoded chunk-response bytes; and
- the shared 8 MiB limit on each individual agent response body.

The report schema moves from version 1 to version 2. Every mutation records
whether its original certified representation was absent, inline, or chunked;
chunked rows retain the ordered digest list and the complete reconstructed
value. Batch evidence separately reports certified-response bytes,
chunk-response bytes, chunk references, unique chunk query calls, inline
value bytes, reconstructed value bytes, and their totals. The pure validator
recomputes all structural counts and requires the chunk-query count to equal
the number of unique retained digests.

The same bounded reconstruction helper now protects ordinary Registry
`get_value` large-value responses used by exact-version catalog and topology
collectors. That path still provides ordinary query evidence, not certified
assurance. This slice adds no cache, replay loop, CLI surface, or
`CatalogAssurance::Certified` path.

## 0.30.3 — Pure Bounded Replay State

This stage adds an in-memory replay state and one-batch atomic apply function.
The state always starts empty immediately before Registry version one. A batch
is accepted only after the existing public certified-delta validator succeeds
and its `requested_version` exactly equals the state's current
`through_version`.

Replay follows the pinned Registry's committed-changelog reconstruction
semantics, not the validation rules for a proposed new transaction. The
Registry stably sorts committed rows by key and normalizes insert, update, and
upsert operations to replacement writes before recording the certified
changelog. Replay therefore treats every committed non-delete row as
replacement and every delete as removal. Repeated same-key rows remain in
their stable order and are applied sequentially. Recorded preconditions and
delete value content are retained in batch evidence but are not re-evaluated
or applied after the transaction has already been committed.

Every apply requires caller-selected maximum live entries and maximum combined
raw key/value bytes. There is deliberately no default memory budget. The
existing batch ceilings still bound the amount of new content decoded by one
call. Application occurs on a candidate state; version mismatch, invalid batch
evidence, accounting failure, or a caller ceiling leaves the original state
unchanged.

`NnsRegistryReplayState` retains canonical raw-byte key order, current raw
values, each value's last mutation version and timestamp, total content bytes,
and the version through which replay has completed. Progress reports whether
that state reached the current batch's certified latest version. The state is
not serializable authority evidence and does not carry certificates; callers
must retain the validated batch reports that produced it.

This slice performs no network call, follows no cursor, chooses no bootstrap
budget, writes no cache, exposes no CLI, and does not enable
`CatalogAssurance::Certified`.

## 0.30.4 — Exact-Target Replay Session

This stage adds pure cumulative coordination around the one-batch replay
primitive. The first accepted report selects its certified latest Registry
version as the immutable session target. A later report may authenticate a
newer live latest version, but the session applies only contiguous mutations
through its original target. A later report that no longer certifies at least
the target fails closed.

One session requires explicit ceilings for the selected Registry version,
admitted batch count, reported query calls, reported encoded response bytes,
live state entries, and combined raw key/value bytes. It retains cumulative
accepted batch, call, response-byte, and applied-mutation accounting. All
checks happen before session counters are published, and the underlying batch
application remains atomic, so any validation, target, root-key, cumulative,
or state-limit error leaves the session unchanged.

Every admitted report must retain the same root-key digest. Sources may differ
because endpoint identity is not the cryptographic authority, but every report
still validates against its explicit request endpoint and mainnet Registry
identity. The public custom-source boundary continues to make authentication
the source's responsibility.

The session deliberately does not fetch a batch or follow `more_available`.
Its cumulative ceilings bound evidence admitted after the caller has obtained
it; they do not reserve or constrain network work already performed by that
caller. A future live bootstrap coordinator needs its own pre-call budget and
mainnet measurements before any default ceiling is selected.

Session state remains nonserializable and is not standalone authority. This
slice adds no cache, CLI, catalog projection, assurance promotion, or implicit
source call.

## 0.30.5 — Explicit Bounded Bootstrap

This stage adds a caller-runtime async coordinator that explicitly bootstraps
from Registry version zero. It creates each next delta request from the replay
session's current version, uses the first response to pin the immutable target,
and returns only when that exact version is reconstructed. Newer versions
observed during later calls remain validated but are not applied beyond the
target.

Before invoking the built-in source, the coordinator proves that the remaining
session budget can accommodate one complete worst-case batch under the fixed
delta contract. The reservation is:

- one certified `get_certified_changes_since` query;
- up to 64 distinct `get_chunk` queries;
- up to 8 MiB for the certified response body; and
- up to 32 MiB across encoded chunk responses.

Therefore every attempted batch reserves 65 calls and 40 MiB before any call.
After a successful report, cumulative accounting advances by actual calls and
bytes, so unused reserved capacity remains available to later batches. If the
remaining budget cannot cover another full attempt, collection stops without
starting that source call. A failed in-flight source call was already covered
by its reservation and terminates the operation.

The network contract is enforced before reservation or source invocation. The
built-in live path authenticates every response and stays within the one-batch
transport ceilings. The custom-source variant is useful for fixtures and
specialized authenticated transports, but such a source remains responsible
for bounding its own internal work; the coordinator can validate and account
only what it returns.

There are deliberately no default bootstrap limits. The operation name and
request make its multi-call behavior explicit, it uses the caller's runtime
and cancellation, and it writes no cache. An error discards the coordinator's
owned partial session rather than exposing incomplete state as a successful
bootstrap.

This slice still does not retain a persistable certificate chain, publish a
mirror, project a Subnet Catalog, or enable `CatalogAssurance::Certified`.
Current mainnet history must be measured before any recommended or default
bootstrap budget is documented.

## 0.30.6 — Bounded Bootstrap Probe

The complete bootstrap intentionally discards its owned partial session on an
error. That is the correct publication contract but makes empirical sizing
needlessly opaque. This stage adds a separate diagnostic probe that shares the
same collection loop and can terminate successfully with one of two explicit
statuses:

- `Complete` means the first response's exact certified target was fully
  reconstructed; or
- `CapacityReached` means another worst-case batch would exceed a named batch,
  query-call, or response-byte ceiling. It reports the configured maximum and
  cumulative amount required for the rejected attempt.

The capacity status is decided before source invocation, so the outcome retains
the state and actual accounting from admitted batches without performing the
call that would exceed its budget. A zero-batch budget returns an empty
`CapacityReached` outcome and performs no source work. Unsupported networks,
source failures, malformed evidence, replay failures, and state payload limits
remain errors and never masquerade as normal probe completion.

Complete bootstrap delegates to this same loop, accepts only `Complete`, and
converts `CapacityReached` back into `SessionLimitExceeded`. This preserves its
complete-only contract and prevents the diagnostic API from weakening normal
bootstrap semantics.

Probe state is deliberately in-memory and nonserializable. An incomplete probe
is sizing evidence, not a resumable checkpoint, cache candidate, certified
mirror, or Subnet Catalog authority. No CLI is added, and no recommended or
default mainnet limits are selected by this slice.

Historical Registry entries also establish a wire-compatibility requirement.
The legacy `RegistryMutation.value` was a plain proto3 `bytes` field, so an
empty value was omitted from the encoded mutation. When that historical byte
sequence is decoded through `HighCapacityRegistryMutation`, its content oneof
is therefore absent. The official Registry transport interprets absent
content on a non-delete mutation as an empty value; ic-query must do the same.
Absent content on a delete remains a delete. The later complete-history probe
showed that some committed deletes retain ignored content; `0.30.7` preserves
that evidence without applying it.

A bounded mainnet observation on 2026-08-06 authenticated exact target
`62948` and reconstructed versions `1..=270` in one call: 1,082 applied
mutations, 804 current entries, and 1,386,570 encoded response bytes. The
one-batch probe then stopped before another call with `CapacityReached`. This
is evidence that the diagnostic boundary works; it is not a complete-history
budget recommendation.

## 0.30.7 — Complete-History Compatibility And Measurement

A larger bounded probe exposed two more differences between transaction-input
validation and the Registry's committed changelog. First, one atomic version
may contain the same key repeatedly. The canister uses a stable key sort and
then applies every row sequentially, so equal-key ordering is significant and
the final row determines current state. Validation now requires nondecreasing
raw key order rather than uniqueness, preserves every row, and rejects only a
decrease.

Second, historical committed deletes may retain value content. The canister
ignores that content and records a deletion marker when reconstructing current
state. ic-query retains the certified content, encoding, and byte accounting
as evidence but replay removes the key. These rules apply only to interpreting
already committed certified history; ic-query does not submit mutations.

After both corrections, a cacheless bounded probe completely reconstructed
exact mainnet Registry target `62948` from version zero. The run used 75
batches and 77 calls, admitted 63,814,080 encoded response bytes, applied
147,284 mutations, and produced 17,184 current keys occupying 22,345,176 raw
key/value bytes. Its explicit ceilings were 128 batches, 8,320 calls, 256 MiB
of responses, 100,000 keys, and 128 MiB of state.

This single observation establishes practical feasibility and validates the
complete replay path. It does not establish defaults, a service-level budget,
or a certified cache authority contract. Persistence and catalog promotion
remain separate stages.

## 0.30.8 — Replay Provenance Commitments

Projection needs compact, deterministic correlation evidence before it needs
a filesystem format. `NnsRegistryReplaySession` therefore retains provenance
without adding a parallel receipt DTO. Each successfully admitted report
advances a domain-separated SHA-256 chain over its complete deterministic JSON
encoding and the prior chain digest. Encoding streams directly into the hash,
so the session does not allocate another report-sized buffer.

The session also retains distinct source endpoint strings in canonical order
and the minimum and maximum certificate times present in admitted reports.
Custom source reports have already passed structural validation, but their
source remains responsible for endpoint validity and cryptographic
authentication; the session does not upgrade that trust boundary. One public
provenance-schema constant versions both digest contracts.

Once the pinned exact target is complete, a separate domain-separated state
digest commits to the target version, entry and content-byte accounting,
canonical raw keys and values, and each value's last mutation version and
timestamp. It remains absent for empty or partial sessions. Completion is
measured against the pinned target, not a newer latest version that a later
report may observe.

All candidate provenance is computed before or alongside candidate replay and
published only after the batch applies successfully. A cumulative-limit,
validation, root-key, encoding, or state-limit failure leaves the prior state,
counters, endpoints, times, and digests unchanged.

These digests are commitments, not certificate chains or standalone proofs.
They are in-memory and nonserializable in this stage. No cache, catalog
projection, assurance promotion, new source call, or CLI surface is added.

## 0.30.9 — Pure Subnet Catalog Projection

Before selecting a persisted mirror format, the complete replay state must
prove that it can supply the existing Subnet Catalog projection without
ordinary `get_value` follow-ups. `project_nns_registry_subnet_catalog` therefore
accepts only a session that reached its pinned target and exposes a complete
state digest. It reads the Subnet list, routing table, and every referenced
Subnet record directly from that exact reconstructed state.

Registry protobuf decoding and raw Subnet-kind conversion reuse the ordinary
live catalog implementation. Canonical Subnet/routing ordering, current
classification policy, raw-kind consistency, known routing targets, range
direction, and overlap validation now pass through one shared content helper.
This prevents the live and replay projections from developing separate policy
or validation behavior.

The returned projection borrows the complete replay session. Its catalog rows
therefore cannot outlive the exact target, root-key digest, source endpoints,
certificate-time bounds, evidence-chain digest, state digest, and cumulative
accounting that qualify them through the projection API. The type remains
in-memory and nonserializable.

An empty or partial session fails before record access. Missing required keys,
malformed protobufs, invalid principals, absent referenced Subnet records, and
catalog structural failures remain explicit typed errors. Unrelated Registry
keys are ignored because projection reads a bounded set derived from the
certified Subnet list.

This stage performs no source call and writes no cache. It does not construct a
raw or validated authority catalog, retain a reloadable certificate chain, or
enable `CatalogAssurance::Certified`. Custom source authentication remains the
source's responsibility.

## 0.30.10 — Built-In Authentication Capability

The complete live bootstrap and the custom-source bootstrap previously returned
the same replay-session type. That erased a material authority distinction:
ic-query's built-in source authenticates every certificate, canister authority,
certified-data commitment, witness, and chunk, while the public custom-source
boundary can only promise that its implementation performed equivalent work.
Structural report validation cannot recreate that authentication.

`bootstrap_nns_certified_registry_async` therefore hard-cuts its return type to
`NnsAuthenticatedRegistryReplaySession`. The wrapper has no public constructor;
only the fixed `LiveNnsSource` coordinator can create it after exact-target
completion and the presence of root-key, evidence-chain, and complete-state
provenance. Custom bootstrap, diagnostic probes, and manual report admission
continue to produce ordinary `NnsRegistryReplaySession` values.

The wrapper exposes borrowed `.replay_session()` inspection. Consuming
`.into_replay_session()` intentionally discards the capability and cannot be
reversed through a public API. There is no `Deref`, compatibility alias, or
caller-supplied authentication flag.

`project_nns_authenticated_registry_subnet_catalog` composes the sealed wrapper
with the existing pure projection. Its result retains references to both rather
than copying rows or provenance into a second report family. This creates the
in-memory input a future certified-authority builder can require without yet
implementing that builder.

The capability is not serializable and does not retain independently reloadable
certificate proof. It cannot be reconstructed from a cache file, a digest, or a
custom-source assertion. No cache, catalog authority promotion, source call,
limit, or CLI behavior changes in this stage.

## 0.30.11 — Complete Chunk Evidence

Schema-2 delta reports retained the ordered certified chunk digests and each
fully reconstructed mutation value, but discarded individual chunk boundaries
and content after live reconstruction. A loaded report could therefore confirm
that a digest was named and that a final value was present, but could not
independently re-hash each content-addressed chunk or prove how repeated and
shared chunks produced that value. Persisting such reports would have created
an evidence archive that appeared more self-verifying than it was.

Certified delta reports are hard-cut to schema 3. Each batch now retains a
single canonical table of unique chunk digest and complete content pairs. The
table is deduplicated across the batch and sorted strictly by the lowercase
SHA-256 digest, so repeated references do not copy the same content into the
report. `chunk_evidence_bytes` separately records the unique raw content bytes;
existing `chunk_value_bytes` continues to count reconstructed mutation content,
including repeated references.

The live transport publishes the same content-addressed cache it already used
for hash-verified query reuse. The pure validator then:

- requires exactly one evidence row for every unique referenced digest and no
  unreferenced row;
- enforces canonical digest ordering and lowercase hexadecimal encodings;
- decodes every content row, enforces the existing per-chunk ceiling, and
  recomputes its SHA-256 digest;
- recomputes unique evidence-byte and query-call accounting; and
- compares every chunked mutation value with the ordered concatenation of its
  referenced contents, including repeated digests.

This closes the large-value evidence-sufficiency gap before choosing a mirror
format. It does not make the public pure validator a certificate verifier:
custom sources remain responsible for authenticating their certificate and
mixed-tree evidence. Replay evidence-chain digests naturally change because
they commit to complete schema-3 reports, while the reconstructed-state digest
algorithm is unchanged. This stage adds no persistence, cache, source calls,
CLI surface, or certified Subnet Catalog authority.

## 0.30.12 — Offline Retained-Batch Reauthentication

Schema-3 reports now retain all application-level material required to verify
one batch after collection, but deserialization alone must never recreate the
built-in live source's authentication capability. This stage adds an explicit
local transition from an ordinary retained report to a sealed borrowed
`NnsAuthenticatedRegistryDeltaBatch`.

`reauthenticate_nns_certified_registry_delta_batch` first runs the public
schema-3 structural validator. It then constructs the mainnet-root-key agent
locally, decodes the retained certificate and protobuf mixed tree, verifies the
Registry canister certificate and certified-data commitment, and decodes the
authenticated `current_version` and delta leaves through the same bounded
transport logic as the live query path.

The authenticated witness is compared with the report field by field:

- certified latest version, mutation/precondition counts, inline bytes, chunk
  references, and `more_available`;
- certificate time, root-key digest, exact certificate bytes, and exact
  canonical mixed-tree bytes;
- ordered Registry versions and mutation timestamps;
- mutation discriminants, typed native kinds, keys, original value encodings,
  inline values, and ordered chunk digests; and
- precondition keys and expected versions.

Chunked values are not carried inline in the certified tree. Their ordered
digests are authenticated by this comparison, while the schema-3 validator
independently re-hashes the exact retained content set and reconstructs each
reported value. Together these checks bind the returned report from the
mainnet certificate through the witness and chunk digests to complete values.

The endpoint remains explicit provenance and must be a clean HTTP(S) URL, but
the operation never contacts it; a frozen mainnet fixture is verified using an
unreachable `.invalid` endpoint. Reauthentication preserves the authenticated
certificate time but does not claim an historical snapshot is currently
fresh. The local verifier accepts historical certificate age only after the
structural validator binds that certificate time to the report's declared
collection time. Live agents keep their current-time age check unchanged, and
current-use freshness remains a caller policy.

The sealed batch borrows the exact report and exposes only `.report()`. It is
not serializable and has no public constructor. This stage does not yet define
an archive, authenticate a sequence as one replay session, restore replay
state, write a cache, add CLI surface, or enable certified catalog assurance.

## 0.30.13 — Authenticated Retained-Sequence Replay

Per-batch reauthentication is useful only if a complete retained sequence can
regain the same type-level replay capability as live bootstrap without opening
a path for ordinary structurally validated reports to claim authentication.
`NnsAuthenticatedRegistryReplayBuilder` provides that in-memory boundary
before any persistence format is selected.

The builder always starts at Registry version zero and requires explicit
`NnsRegistryReplaySessionLimits`. Its `apply_batch` accepts only a borrowed
`NnsAuthenticatedRegistryDeltaBatch`, so the exact report remains immutably
borrowed from local certificate verification through atomic admission. It
reuses the ordinary replay session's internal post-validation path rather than
duplicating mutation, accounting, provenance, or digest logic.

Every established replay invariant remains active: the first batch pins the
exact certified target; later batches must continue at the current version and
may not regress that target or change the root-key digest; cumulative batch,
query-call, response-byte, entry, and content-byte ceilings apply; and a failed
admission publishes no candidate state or provenance. Read-only
`.replay_session()` access permits progress inspection without exposing the
ordinary session's public `apply_batch` method through the builder.

`into_authenticated_replay_session` consumes the builder and succeeds only
when the selected target, root-key digest, evidence-chain digest, and complete
state digest are all present. It returns the same sealed
`NnsAuthenticatedRegistryReplaySession` as built-in live bootstrap. Empty,
partial, out-of-order, and over-limit sequences remain typed failures and
cannot recover the consumed authentication capability.

This stage makes caller-owned deserialized report sequences replayable after
each report is explicitly reauthenticated, but it does not define how those
reports are stored or discovered. It performs no source call or filesystem IO,
does not choose an archive schema or cache path, does not add CLI surface, and
does not enable certified Subnet Catalog assurance. Current-use freshness of
historical certificate times remains a caller policy.

## 0.30.15 — Bounded Certified Archive Manifest

Retained evidence needs a stable index before it can be published to disk, but
the index must not be mistaken for cryptographic authority. Schema 1 therefore
defines `NnsCertifiedRegistryArchiveManifest` as untrusted, recomputable
metadata over one complete version-zero authenticated replay sequence.

`NnsCertifiedRegistryArchiveManifestBuilder` accepts only the sealed
`NnsAuthenticatedRegistryDeltaBatch` capability. Before applying a report, it
streams that report's canonical compact JSON through SHA-256 and byte counting,
then enforces caller-selected batch-count, per-report-byte, and total-report-byte
ceilings. It does not allocate a second encoded report buffer. Limit or replay
failure leaves replay position, descriptor rows, and cumulative archive bytes
unchanged.

Each batch descriptor records its ordinal, requested and visible version bounds,
applied-through position, certified latest version, reported call/response
accounting, applied mutation count, canonical encoded size, and content digest.
The manifest records the delta-report, replay-provenance, and archive schema
versions once; the exact target; recomputable cumulative accounting; common
root-key identity; evidence-chain and complete-state digests; certificate-time
bounds; and canonical distinct source endpoints. Archive-wide fields are not
repeated in every descriptor.

Pure manifest validation requires canonical descriptor order, a version-zero
start, gap-free continuation, first-batch target selection, no rows after target
completion, exact descriptor totals, fixed mainnet Registry identity, canonical
digests and source endpoints, rejection of undeclared schema fields, and every
explicit archive ceiling. This is only structural validation. A loaded manifest
and its derived totals are never trusted: a future loader must bound each object
before parsing, verify its exact content digest and size, reauthenticate its raw
certificate/witness/chunks, replay every batch, and compare the completely
recomputed manifest.

This stage chooses neither filesystem paths nor a cache identity. It performs no
filesystem or network IO, adds no CLI surface, does not refresh evidence, and
does not enable `CatalogAssurance::Certified`. The future storage layer will
retain each report object once and publish a small manifest separately, avoiding
whole-history clones or duplicated snapshot payloads.

## 0.30.16 — Confined Archive Publication And Restoration

The schema-1 manifest becomes operational through an explicit caller-selected
filesystem boundary. `NnsCertifiedRegistryArchivePublisher` owns a cache-root
capability, archive directory, replay limits, and storage limits. It accepts one
sealed authenticated batch at a time, advances the 0.30.15 manifest builder,
then streams the report's canonical compact JSON directly into an owner-only
same-directory temporary file while independently counting and hashing written
bytes. The temporary object is rejected unless its exact size and SHA-256 equal
the admitted descriptor.

Report objects live once under a derived content-addressed `objects/` name; the
manifest never supplies a filesystem component. Each object is synchronized,
atomically installed, and followed by a parent-directory sync. Newly created
managed directories are also followed by a parent sync. Only `finish` writes
canonical `manifest.json`, after exact-target authenticated replay completes and
all referenced objects are durable. A failed object write poisons that publisher
instance, and a failed final manifest write leaves any prior complete manifest
unchanged. Unreferenced objects from an abandoned attempt are not discoverable
as an archive and are intentionally left for a future explicit cleanup policy.

`load_nns_certified_registry_archive` opens every path through the existing
capability-rooted no-follow boundary. It rejects traversal, symlinks, nonregular
files, and unsafe Unix modes. Manifest size is bounded before allocation and its
encoding must be exact canonical compact JSON. Structural manifest validation
runs before any object lookup. Each object is then opened and bounded separately,
matched against its exact descriptor length and SHA-256, decoded, and released
before the next object is processed.

For every decoded report the loader reconstructs the original validation request
from authenticated provenance, performs the 0.30.12 local mainnet certificate,
witness, and chunk reauthentication without a network call, and applies the
sealed capability to a new bounded manifest builder. Loading succeeds only when
the complete recomputed manifest equals the serialized manifest field for field.
The result is `NnsAuthenticatedRegistryArchive`, which keeps that recomputed
manifest attached to the sealed exact-target replay session.

This slice provides no default path, discovery, live collection, refresh policy,
refresh lock, automatic cleanup, CLI surface, or catalog promotion. Those remain
separate decisions so ordinary loads cannot accidentally bootstrap the complete
Registry history or mutate local evidence.

## 0.30.17 — Archive-Bound Certified Catalog Authority

Certified assurance is promoted only from
`NnsAuthenticatedRegistryArchive`, never from a replay session, manifest, raw
catalog, digest, Boolean, or deserialized provenance claim. The promotion first
checks that the archive manifest still agrees in every corresponding field with its sealed
replay capability: supported archive, delta-report, and replay-provenance
schemas; mainnet Registry identity; selected and applied version; batch, query,
response-byte, and mutation totals; root-key digest; evidence-chain and
complete-state digests; certificate-time bounds; and canonical source endpoints.

The exact reconstructed state is then projected through the existing Subnet
list, routing table, referenced Subnet record, raw-kind conversion,
classification, canonical-ordering, routing-validation, and catalog-digest
path. `project_nns_certified_subnet_catalog` takes the sealed archive plus the
caller's `CatalogValidationContext`. It returns
`NnsCertifiedSubnetCatalogAuthority`, whose validated catalog remains borrowed
to the archive that qualifies it.

Subnet Catalog schema 3 replaces the two loose optional certificate fields with
one `CertifiedRegistryCatalogEvidence` record. It commits to the archive,
delta-report, and replay-provenance schemas; trusted root-key digest;
evidence-chain and complete-state digests; and exact minimum and maximum
certificate times in nanoseconds. Certified `fetched_at` is derived
deterministically from the latest certificate time. The source endpoints,
Registry version, and exact query-call count remain in common provenance, and
the catalog digest covers the complete schema-3 value.

This DTO is evidence description, not an authority constructor.
`ValidatedSubnetCatalog::try_from_raw` continues to reject `Certified` for every
serialized value, even when the schema, evidence fields, and catalog digest are
otherwise valid. The internal promotion path additionally compares every
certified provenance commitment with the attached archive. Re-digesting locally
edited JSON therefore cannot acquire authority.

The earlier `project_nns_authenticated_registry_subnet_catalog` and
`NnsAuthenticatedRegistrySubnetCatalogProjection` surfaces are removed. A live
authenticated replay session is useful for immediate inspection, but it does
not retain independently reloadable report evidence. Requiring the archive
prevents a transient type-level claim from becoming durable catalog authority
without the certificate, witness, and chunk sequence needed for later local
reauthentication.

This stage makes no source call and selects no archive discovery, refresh,
cleanup, certified-catalog cache path, publication lock, or CLI surface.
Historical archive freshness remains caller policy. Schema-2 ordinary catalog
files are invalid under the existing path; read policies that permit invalid
recovery may explicitly refresh them, but there is no migration, fallback
reader, alias, or dual schema.

## 0.30.18 — Explicit Current-Use Freshness

Cryptographic authentication proves what Registry state an archive represented;
it does not prove that historical state is recent enough for a decision today.
The 0.30.17 projection accepted `CatalogValidationContext`, which rejected
future timestamps but placed no upper bound on certificate age. A valid archive
could therefore produce certified authority long after its operational value
expired.

`project_nns_certified_subnet_catalog` is hard-cut to require
`NnsCertifiedSubnetCatalogProjectionRequest`. The request contains the existing
catalog identity, observation time, and future-skew validation context plus an
explicit `maximum_certificate_age_seconds` and
`NnsCertifiedSubnetCatalogVersionPolicy`. `AllowHistoricalTarget` permits an
authenticated pinned target even if a later batch observed a newer Registry;
`RequireLatestObserved` requires those version positions to match. There is no
`Default` implementation or sentinel value that silently selects either policy.

After archive manifest/replay alignment and before decoding catalog Registry
records, projection compares the latest authenticated certificate time with the
caller's observation time. Arithmetic uses nanoseconds in `u128`, so the full
`u64` input domain cannot overflow. A certificate exactly at the maximum age is
accepted. Older evidence returns `StaleArchiveCertificate` with the latest
certificate time, observation time, exact nonnegative age, and configured
maximum. A future certificate has age zero at this stage and must still pass the
existing catalog future-skew validation before authority is returned.

The same pre-projection policy pass finds the maximum
`certified_latest_version` across retained batch descriptors. Under
`RequireLatestObserved`, a value above the selected target returns
`SupersededArchiveTarget`. This prevents a certificate collected later in a
long bootstrap from making a knowingly older pinned Registry position appear
current. `AllowHistoricalTarget` remains useful for deliberate historical
inspection without weakening the evidence's exact-version identity.

Successful `NnsCertifiedSubnetCatalogAuthority` retains
`NnsCertifiedSubnetCatalogFreshness`: observation seconds, latest certificate
nanoseconds, exact age nanoseconds, and maximum accepted age seconds. This makes
the authorization decision inspectable together with the selected version,
maximum observed certified version, and chosen version policy, without changing
schema-3 serialized catalog provenance or treating the freshness DTO as
authority by itself.

The check is pure and local. It makes no source call, reads or writes no cache,
does not refresh an archive, and adds no CLI surface. Incremental archive
refresh, cleanup, and certified cache publication remain separate work.

## 0.30.19 — Explicit Live Archive Force Bootstrap

`bootstrap_nns_certified_registry_archive_async` joins the already bounded live
bootstrap and confined archive publisher without making either behavior
implicit. Its required `NnsCertifiedRegistryArchiveBootstrapRequest` carries
the mainnet source endpoint, observation time, cumulative replay ceilings,
capability root, archive root, manifest/object storage ceilings, and refresh-
lock staleness policy. No default path, history budget, source, or lock policy
is selected.

The coordinator rejects non-mainnet before creating a directory, acquiring a
lock, constructing an agent, or invoking a source. It then holds one dedicated
`refresh.lock` beside the archive manifest for the complete operation. Before
each source call it reserves one archive batch slot plus the same 65-query-call
and 40 MiB response capacity as the in-memory bootstrap. It uses the publisher's
authenticated replay session as the only accumulating state, so live
publication does not reconstruct a second complete Registry map in parallel.

Every structurally validated report is locally reauthenticated from its
retained mainnet certificate, witness, and chunk evidence before the publisher
may write its content-addressed object. This includes reports returned by
`bootstrap_nns_certified_registry_archive_with_source_async`: a custom source
can transport authentic retained evidence, but cannot obtain archive authority
from structurally plausible fixture data. Local reauthentication adds no
source call, and a typed failure retains the rejected report's requested
Registry version.

The manifest is replaced only after the pinned exact target is complete and
all admitted objects are durable. Source, authentication, replay, capacity, or
storage failure cannot replace a previous complete manifest. The shared lock
guard releases on success and makes a best-effort release when a failed future
is dropped; ordinary cache loads never acquire it or initiate bootstrap.

This operation always begins at Registry version zero. It is deliberately
named bootstrap rather than refresh: incremental archive extension, orphan
object cleanup, cache-only/read-through archive policy, certified catalog cache
publication, progress events, and CLI surface remain separate work.

## 0.30.20 — Segmented Authenticated Archive Extension

An archive that permanently pins its first bootstrap target cannot represent
incremental history honestly. It also cannot retain a fresh certificate proving
that an unchanged Registry version is still current: a zero-version delta batch
arrives only after the prior target is already complete. Archive manifest schema
2 therefore hard-cuts the flat single-target interpretation into an explicitly
segmented replay chain.

Every `NnsCertifiedRegistryArchiveBatchDescriptor` now records a
`segment_ordinal` and `segment_target_version`, and the manifest records the
exact `segment_count`. Segment zero remains the complete version-zero bootstrap.
When another sealed batch is admitted after exact completion, it begins the next
segment and selects that report's authenticated `certified_latest_version` as
the segment target. Further batches remain pinned to that target until complete.
Only then may another segment begin.

A segment target may equal the previous target. Its authenticated empty delta
adds no Registry mutations and leaves the canonical complete-state digest
unchanged, while still extending the evidence-chain digest, source/call/byte
accounting, and certificate-time bounds. This makes a fresh unchanged-version
observation durable without pretending that state changed. A higher target
applies only the contiguous authenticated mutations after the previous target.

The ordinary `NnsRegistryReplaySession` and
`NnsAuthenticatedRegistryReplayBuilder` remain single-segment APIs and still
reject post-completion batches. Only archive construction uses the internal
authenticated segment transition, and it does so atomically: target selection,
state, counts, certificate bounds, and provenance publish together only after
the candidate batch passes every replay ceiling.

`NnsCertifiedRegistryArchivePublisher::resume` supplies the local filesystem
boundary for later incremental collection. It takes explicit replay and storage
ceilings, sequentially loads and locally reauthenticates every existing object,
requires exact manifest recomputation, and then consumes that single restored
state into a resumable publisher. Historical objects are neither decoded twice
in parallel nor rewritten. New objects become durable first and `finish`
atomically replaces the manifest only after the new segment completes.

`resume` deliberately makes no source call and acquires no refresh lock. The
future live incremental coordinator must hold the existing dedicated archive
lock across resume, bounded source collection, and final publication. Schema-1
archives are invalid after this hard cut and receive no compatibility reader,
migration, alias, or fallback; callers must explicitly force-bootstrap a new
schema-2 archive before it can be resumed.

## 0.30.21 — Lock-Guarded Live Incremental Archive Refresh

Local resume is necessary but insufficient for a safe live refresh: callers
must not accidentally load outside the lock, race another writer, begin a call
without cumulative capacity, or publish a partial target. The public
`NnsCertifiedRegistryArchiveRefreshRequest` therefore owns the complete
operation policy: mainnet source and observation time, cumulative replay
ceilings, confined cache and archive roots, cumulative storage ceilings, and
lock staleness.

Refresh rejects a non-mainnet network before filesystem or source work. It
then requires the existing managed manifest without creating a missing archive
directory and acquires the same dedicated `refresh.lock` used by force
bootstrap. The lock remains held while every retained report is bounded,
hashed, locally reauthenticated, replayed, and matched exactly against the
manifest. No agent or custom source is called until that resume succeeds.

Before each source call, refresh reserves both an archive object slot and the
same worst-case batch calls and response bytes used by force bootstrap. The
first authenticated report begins exactly one successor segment and selects
its certified latest version. Later reports remain pinned to that target, so a
newer observation cannot move a collection already in progress. Refresh
finishes immediately after exact-target completion; an empty response whose
certified latest version equals the retained target becomes a complete
unchanged-version evidence segment.

Every new source report is locally reauthenticated through the same built-in
mainnet verifier used by load and force bootstrap. Only authenticated reports
become durable objects. The manifest is atomically replaced only after the new
segment completes, and the lock is then released. Source, capacity,
authentication, replay, object-write, or manifest-write failure leaves the
prior complete manifest usable. A durable content-addressed object written
before a later failure can remain unreferenced; bounded cleanup remains a
separate explicit operation.

The refresh functions are library-only and explicit. Archive loads and
ordinary Subnet Catalog cache policies never invoke them, and no default path,
automatic retry, background task, compatibility reader, or CLI surface is
introduced.

## 0.30.22 — Authenticated Bounded Archive Orphan Cleanup

Content-addressed report objects become durable before a replacement manifest.
That ordering protects the last complete archive, but a process failure or a
later refresh error can leave an object no manifest references. Removing such
objects safely requires more than comparing filenames: a malformed or edited
manifest must not be allowed to redefine retained authority and delete valid
evidence.

`cleanup_nns_certified_registry_archive` is therefore a distinct local
maintenance operation. Its request names the existing confined archive,
cumulative replay/storage ceilings, observation time, lock-staleness policy,
and explicit scanned-object, removed-object, and removed-byte ceilings. It
selects no default location or budget and performs no network call.

Cleanup first requires the managed manifest and acquires the same archive
`refresh.lock` used by force bootstrap and incremental refresh. While holding
that lock, it bounds and locally reauthenticates every manifest-referenced
report, replays the complete segmented sequence, and requires field-exact
manifest recomputation. No object-directory scan or deletion occurs before
that authentication succeeds.

Discovery is confined to regular files directly beneath the archive's exact
flat `objects/` directory. It never traverses the archive root, the broader
cache root, child directories, symbolic links, or another cache family. A scan
that reaches its caller ceiling reports the minimum required count and stops
without deleting anything. The complete discovered orphan set and its bytes
must also fit the removal ceilings before the first delete.

The retained set consists of the unique content-addressed object paths named
by the authenticated manifest. Only discovered regular files outside that set
are removed, in canonical path order. Every removal revalidates confinement
and regular-file status and synchronizes the parent directory. The result
returns the authenticated retained archive with exact scanned, referenced,
removed, and removed-byte counts.

Deletion cannot be rolled back atomically. If a filesystem failure occurs
after earlier orphans were removed, the typed error reports their exact count
and bytes. Referenced objects were never candidates, so the authenticated
archive remains complete. Cleanup is never invoked automatically by load,
refresh, cache policy, startup, or background work, and adds no CLI surface.

## 0.30.23 — Archive-Matched Certified Cache Publication

A certified cache uses a separate schema-1 envelope, typed API, caller-selected
directory, and dedicated publication lock from ordinary Subnet Catalog
evidence. It contains the projected raw catalog plus the exact Registry
identity and version, assurance, canonical source endpoints, SHA-256 of the
complete canonical archive manifest, evidence-chain and complete-state
commitments, certificate-time bounds, catalog digest, collector version, and
classification policy identity.

The envelope does not duplicate those catalog provenance fields at its top
level. Its only fields are the certified-cache schema, the exact archive-
manifest SHA-256, and the canonical raw catalog. This keeps the existing
catalog provenance as the single owner of its Registry, certificate, source,
assurance, and classification identities.

Publication requires all of:

1. a contiguous replay from the implemented complete bootstrap segment through
   one or more authenticated exact-target extension segments;
2. deterministic application of insert, update, upsert, and delete mutations;
3. complete reconstruction of every Registry key needed by the Subnet Catalog;
4. reuse of the implemented archive-bound certified catalog projection;
5. reuse of the implemented explicit current-use freshness policy; and
6. one atomic certified cache replacement under a dedicated refresh lock.

`publish_nns_certified_subnet_catalog_cache` performs archive alignment,
freshness/version policy, exact-state projection, classification, catalog
validation, envelope construction, and caller-selected byte-limit validation
before filesystem mutation. It then creates only the confined managed parent,
holds the dedicated certified-cache lock, and writes canonical compact JSON by
same-directory atomic replacement. A failed qualification or replacement
preserves an existing cache.

Publication serializes a borrowed envelope view, so the projected catalog is
not cloned merely to write the cache. Load compares canonical serialization
directly with the bounded input bytes instead of allocating a second encoded
buffer. After the exact match, the decoded envelope is dropped and the
successful wrapper retains only the single fresh archive-bound catalog
authority.

`load_nns_certified_subnet_catalog_cache` is strictly cache-only. It bounds the
managed regular file before allocation, parses a deny-unknown-fields schema-1
envelope, requires byte-exact canonical compact JSON, and then repeats the
complete projection from the caller-supplied `NnsAuthenticatedRegistryArchive`
under the caller's current freshness and version policy. It returns
`NnsCertifiedSubnetCatalogCacheAuthority` only when the serialized envelope is
field-exact with that newly derived expected value. The successful result keeps
the new `NnsCertifiedSubnetCatalogAuthority` attached to its archive.

The envelope is deliberately an untrusted serde DTO. Its assurance label,
archive digest, and nested raw catalog are commitments and diagnostics, not an
authority constructor. Ordinary raw-catalog validation still rejects
`Certified`, and the certified cache loader cannot be called without the
sealed authenticated archive capability. A changed archive, edited cache,
different projection implementation, or different classification policy
therefore fails closed as an archive-binding mismatch.

Neither operation contacts a source. Load does not lock, publish, repair,
refresh, bootstrap, delete, or fall back. Publication does not refresh its
input archive. If a newer archive is required, the caller explicitly runs the
bounded archive refresh and explicitly republishes the cache. The existing
`UncertifiedQuery` and `MultiEndpointAgreement` paths continue unchanged.

## 0.30.24 — Explicit Certified-Cache Policy And Evidence

The cache boundary finishes with four distinct operations rather than one
read-through function whose name hides mutation:

1. `load_nns_certified_subnet_catalog_cache` is cache-only;
2. `publish_nns_certified_subnet_catalog_cache` is unconditional explicit
   publication from the supplied authenticated archive;
3. `load_or_publish_missing_nns_certified_subnet_catalog_cache` authorizes
   publication only when the cache is absent; and
4. `load_or_publish_missing_or_invalid_nns_certified_subnet_catalog_cache`
   additionally authorizes replacement of recoverably invalid cache content.

Recoverably invalid means an exceeded caller cache-byte limit, invalid JSON,
noncanonical JSON, an unsupported cache schema, or a mismatch with the fresh
projection of the supplied archive. Confinement/filesystem failures,
projection failures, serialization failures, and accounting failures are not
repair triggers and are returned unchanged. In particular, a stale or
superseded archive cannot become fresh by rewriting its catalog cache. The
caller explicitly refreshes that archive through the existing bounded live
coordinator, then explicitly republishes or uses the mismatch-recovery
operation.

Every successful operation retains
`NnsCertifiedSubnetCatalogCacheDisposition`: `CacheHit`, `PublishedMissing`,
`PublishedInvalid`, or `ForcedPublication`. The successful authority also
retains the exact cache path and archive-manifest SHA-256 used by that action.
Its `authority_evidence()` method produces a strict compact serde DTO with the
Registry version, catalog digest, certified assurance, source endpoints,
archive-manifest SHA-256, root-key/evidence-chain/complete-state commitments,
certificate-time bounds, and disposition. It does not copy the full catalog.
It is a durable evidence description, not an authority constructor; using the
catalog again still requires cache admission against the matching sealed
authenticated archive.

This policy layer makes no source call and chooses no default location, byte
limit, age, version, lock, repair, or network policy. It does not change the
schema-1 envelope, acquire a lock on cache hits, alter ordinary Subnet Catalog
behavior, or add CLI surface.

### Unified certified load-policy hard cut

The follow-up public boundary matches the ordinary Subnet Catalog load shape
without retaining parallel compatibility flows. The four 0.30.24 entry points
and the publication-only request are removed. Their supported behavior is
owned by one `load_nns_certified_subnet_catalog` operation accepting
`NnsCertifiedSubnetCatalogLoadRequest` and
`NnsCertifiedSubnetCatalogReadPolicy`:

1. `CacheOnly` admits only an existing archive-matched cache;
2. `PublishMissing` additionally authorizes publication from the supplied
   archive when the cache is absent;
3. `PublishMissingOrInvalid` additionally authorizes replacement of the same
   bounded recoverably invalid content defined above; and
4. `ForcePublication` unconditionally projects and publishes the supplied
   archive.

Every success returns `NnsCertifiedSubnetCatalogLoadOutcome`, retaining the
fresh archive-bound authority, exact cache path, disposition, and compact
evidence projection. Publication policies carry their lock-staleness value;
cache-only carries no irrelevant lock setting. The single operation remains
local-only, performs no archive refresh, and makes no network call. This is a
source-breaking pre-1.0 replacement with no deprecated wrappers, aliases, or
dual dispatch path.

## Cache And Compatibility

The certified latest-version, single-delta-batch, and in-memory bootstrap
operations create no cache. Explicit archive force bootstrap requires caller-
selected cache and archive roots and is never reached by an ordinary catalog
load. Explicit archive incremental refresh requires the same caller-selected
location and policy, and is likewise never reached by a load. Resuming a
schema-2 archive remains a local-only explicit operation and does not contact a
source or acquire a refresh lock. Its manifest and object layout do not share a
file with version-3 ordinary Subnet Catalog caches. Explicit orphan cleanup is
local-only, lock-held, bounded before deletion, and never triggered by another
operation.
Schema-1 archives are rejected without migration or a fallback reader.
Schema-2 ordinary catalogs are rejected without automatic migration or a
fallback reader. Before 1.0, any replacement schema is a hard cut.

Failed certified refreshes must preserve the last complete certified mirror.
Cache-only, refresh, refresh-missing, and refresh-stale operations remain
distinct. A caller's minimum assurance policy may reject weaker evidence but
must never silently trigger a different network or source selection.

## Acceptance Criteria

- The live Registry version path makes exactly one certified method call.
- The live delta-batch path makes exactly one certified method call, completes
  only that batch's bounded chunk references, and returns `more_available`
  without an implicit delta-batch follow-up.
- Certificate signature, delegation, time, canister identity, certified-data
  commitment, tree structure, digest sizes, and canonical version encoding are
  validated before a version is returned.
- Fixture sources cannot mark malformed evidence as a valid version report.
- Pure replay accepts only the next validated batch, applies committed rows
  atomically, and preserves the prior state on a caller-limit failure.
- Pure replay sessions pin one exact first-batch target, reject root-key or
  target regression, and do not apply later-observed versions beyond it.
- Explicit bootstrap rejects non-mainnet before source work, reserves one
  maximum-size batch before every built-in call, and returns only complete
  exact-target state.
- Explicit archive force bootstrap rejects non-mainnet before filesystem or
  source work, holds one dedicated lock, locally reauthenticates every live or
  custom-source report, reserves before every call, and publishes only a
  complete exact-target manifest while preserving any prior manifest on
  failure.
- Archive schema 2 identifies every exact-target segment, permits an
  authenticated unchanged-version observation, and requires canonical segment
  ordering and final-target completion. Resuming first reauthenticates the
  complete prior archive under caller-selected cumulative limits, rewrites no
  historical object, and performs no live call or lock acquisition.
- Explicit incremental refresh rejects non-mainnet and missing archives before
  source work, holds the dedicated lock across bounded resume, source calls,
  authentication, and publication, reserves cumulative capacity before each
  call, and replaces the manifest only after one successor segment completes.
- Explicit orphan cleanup authenticates the complete retained archive before
  scanning, confines bounded discovery to the exact flat object directory,
  applies every deletion ceiling before removing a file, never selects a
  referenced object, and reports exact progress on a partial filesystem
  failure.
- Diagnostic probes return typed complete or pre-call capacity status while
  keeping incomplete sessions outside every cache and authority path.
- Committed same-key mutations retain stable order, and retained delete
  content is preserved as evidence but ignored by replay.
- Replay provenance commitments advance atomically, and the canonical state
  digest remains absent until the pinned target is complete.
- Pure Subnet Catalog projection requires exact-target completion and reuses
  the live catalog's canonical classification and routing-validation path.
- Only the built-in mainnet verifier can construct the authenticated replay
  capability. The live bootstrap and complete locally reauthenticated retained
  paths use it; structurally validated custom or manual replay alone remains an
  ordinary session type.
- Certified delta reports retain canonical unique chunk contents; pure
  validation re-hashes them and proves every reconstructed chunked value.
- Retained schema-3 batches can regain a sealed authentication capability only
  through local mainnet certificate, witness, and committed-content checks.
- A complete version-zero sequence of sealed retained batches can regain the
  authenticated replay-session capability only through bounded atomic replay.
- Archive manifests can be built only from those sealed batches, apply explicit
  encoded-object ceilings before replay publication, and derive every segment
  boundary, ordinal, exact target, and final completion state while validating
  strict version/order/digest/accounting invariants without claiming authority.
- Confined archive publication makes every referenced object durable before the
  manifest becomes visible; bounded restoration or resume reauthenticates one
  object at a time and requires a field-exact recomputed manifest before
  returning a sealed archive capability or accepting an extension.
- Certified catalog promotion accepts only that sealed archive capability,
  rechecks manifest/session alignment, reuses the shared canonical catalog
  validator, and keeps the validated result attached to its archive.
- Certified catalog promotion requires an explicit maximum certificate age,
  requires an explicit pinned-version policy, rejects prohibited stale or
  superseded evidence before record projection, and retains the exact decision
  with successful authority.
- Certified catalog cache publication qualifies the authenticated archive
  before filesystem mutation, applies a caller byte ceiling, holds a dedicated
  lock, and atomically replaces only its separate schema-1 envelope.
- Certified catalog cache loading is bounded and cache-only, requires canonical
  schema-1 bytes, reprojects the caller-supplied authenticated archive under
  current explicit policy, and returns authority only after a field-exact
  envelope match.
- Missing-only certified-cache recovery never replaces invalid content;
  missing-or-invalid recovery replaces only bounded content/schema/binding
  failures and never treats filesystem or projection errors as repair triggers.
- Every certified-cache success reports its exact path and disposition, and
  compact authority evidence preserves Registry/catalog/archive/certificate
  identity without retaining a second catalog snapshot.
- Text does not print full certificate or witness hex; JSON preserves both.
- Ordinary raw/cache validation always rejects a serialized
  `CatalogAssurance::Certified` claim; only archive-bound promotion may establish
  it.
- No certified operation hides an unbounded bootstrap, pagination loop, or
  large-value follow-up; every chunk call and byte is bounded and reported.
- Existing exact-version joins, endpoint agreement, cache paths, cache policy,
  CLI grammar, and process-output boundaries remain intact.
- Focused no-default, `certified-subnet-catalog-host`, `nns-host`, `host`,
  public-API, Clippy, documentation, and formatting checks pass.
