# ic-query 0.9 Design: Complete CLI Extraction

## Status

- Status: complete
- Release line: `0.9.x`
- Decision style: hard crate-ownership cut

## Decision

`ic-query` is the reusable read-only Internet Computer query library.
`ic-query-cli` is the executable adapter. The library owns typed requests,
reports, source traits, cache/refresh mechanics, report builders, renderers,
and small reusable helpers. The executable crate owns every process concern:
Clap definitions, parsing, help/version text, dispatch, stdout/JSON selection,
project-context discovery, and exit-oriented errors.

The library therefore has only two dependency modes:

- default/no-default: request and report DTOs, renderers, and pure helpers;
- `host`: live sources, filesystem cache/refresh behavior, and native report
  builders.

There is no `cli` feature on `ic-query`. A downstream Rust crate calls the
typed library API; a shell user installs `ic-query-cli` and runs `icq`.

## Why This Boundary

The previous split left family command adapters in the library after the
executable was separated mechanically. That made Clap part of the library's
feature topology, mixed process errors with query errors, and allowed command
ownership to drift between crates. Completing the extraction gives each crate
one reason to change: query/report behavior in `ic-query`, and command/process
behavior in `ic-query-cli`.

Library source traits remain the test seam for report construction. CLI tests
exercise current arguments, help, dispatch, and exit semantics without making
the library expose parser-specific types.

## Hard Cut

0.9.0 does not retain the removed library feature or any alternate path to its
command modules. There are no aliases, shims, deprecated wrappers, dual
parsers, or anti-resurrection tests for the old surface. Existing CLI command
names and JSON report shapes remain current behavior, not compatibility
layers.
