# ic-query 0.25 Design: Fuller Fixed-Size SNS Neuron Evidence

## Status

- Status: complete
- Last reviewed: 2026-08-01
- Scope: enrich existing SNS neuron rows without increasing collection calls

## Goal

Use more of the native `Neuron` value already returned by SNS Governance
`list_neurons` while keeping the existing bounded list and explicit complete
snapshot behavior. This slice adds no new remote method, follow-up call,
pagination path, or implicit cache.

## Native Fixed-Size Surface

In addition to the existing id, stake, maturity, staked maturity, and creation
timestamp, each `SnsNeuronRow` preserves:

- optional source NNS neuron id;
- optional auto-stake-maturity setting;
- raw aging-since timestamp;
- optional native dissolve state as either `DissolveDelaySeconds` or
  `WhenDissolvedTimestampSeconds`;
- voting-power percentage multiplier;
- optional vesting period; and
- accumulated neuron fees in e8s.

These values come from the same `list_neurons` response. `ic-query` does not
derive current age, effective voting power, or a point-in-time guarantee from
them. In particular, the raw aging timestamp is retained without converting
sentinel values into a calendar date.

## Deliberate Variable-Size Boundary

The native neuron also carries permissions, legacy and topic followees, and
pending maturity-disbursement vectors. This collection row does not retain
those graphs. They are variable-size detail evidence, can materially expand a
complete cache, and may depend on caller visibility. If added later, they
belong behind one explicit typed neuron-detail query with its own response
bounds and visibility semantics.

## Validation And Rendering

- Native dissolve alternatives are preserved as a typed public enum.
- Live and custom-source rows require canonical lowercase even-length neuron
  id hex, exact derived creation-time text, requested-limit compliance, and
  unique ids.
- Complete page collection and cache loading apply the same row validation;
  page overlap remains governed by the existing cursor/deduplication logic.
- JSON contains every raw field. Human text remains compact and adds fees,
  dissolve state/value, auto-stake maturity, and voting-power multiplier
  without hiding the full JSON evidence.

## Cache And Schema Hard Cut

`SnsNeuronsReport` and the complete SNS neuron cache advance from schema 1 to
schema 2 because every row changes shape. Before 1.0 this is a hard cut:

- schema-1 caches are rejected as unsupported;
- users explicitly run `icq sns neuron refresh <id|root-principal>`;
- no automatic migration, legacy reader, Serde default, alias, or fallback
  branch remains; and
- proposal and other SNS cache schemas are unchanged.
