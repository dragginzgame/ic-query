# 0.38 Design: Canister-Native NNS Governance Reporting

- Status: implemented in the 0.38 release slice
- Initial scope: the four bounded direct NNS Governance reports
- Current scope: those four point reports, bounded proposal and public neuron
  list/detail, plus caller-resumable complete proposal and neuron walks
- Authority: mainnet NNS Governance canister
- Runtime: replicated inter-canister calls from Rust canisters
- Persistence: caller-owned; no library cache or stable-memory policy
- Workspace: exactly the existing `ic-query` and `ic-query-cli` crates

## Purpose

`ic-query` already separates reusable report contracts from the `icq` process
boundary. Its no-default build compiles for `wasm32-unknown-unknown`, but that
surface currently stops at request/report DTOs, renderers, and pure helpers.
The live NNS Governance source trait and builders remain behind `nns-host`, use
`ic-agent`, and synchronously bridge through a Tokio runtime.

The 0.38 slice makes one complete report family directly usable by Rust
canisters without adding a third crate. A canister should be able to collect a
typed NNS Governance report, apply the same validation and projection as the
CLI, and decide for itself whether and how to retain or display the result.

This is a runtime-boundary extension, not a second reporting implementation.
Native and canister transports must converge before report construction.

## Release outcome

The first complete vertical slice covers the existing direct reports:

| Report | Governance method | Calls |
| --- | --- | --- |
| economics | `get_network_economics_parameters` | exactly one |
| metrics | `get_metrics` | exactly one |
| reward event | `get_latest_reward_event` | exactly one |
| maturity modulation | `get_maturity_modulation` | exactly one |

The CLI commands and their default native behavior remain unchanged. The new
surface is a Rust library API for canisters; it adds no CLI command or option.

Completion means a downstream Rust canister can enable the `canister` feature,
await any of these four reports, and receive the same public payload model and
validation guarantees as a native `icq nns governance` invocation.

## Crate and feature boundary

The workspace remains:

```text
ic-query
  pure request/report contracts, validation, projection, and rendering
  nns-host       native NNS source and synchronous convenience builders
  canister       IC runtime adapters, initially the NNS Governance source

ic-query-cli
  Clap, dispatch, process IO, and terminal progress
```

`canister` is one optional runtime feature on `ic-query`. It initially exposes
only the NNS Governance adapter and may add the canister runtime dependency
required to issue inter-canister calls. It must not enable `host`, `nns-host`,
`ic-agent`, Tokio, Reqwest, Futures, `cap-std`, `cap-fs-ext`, Prost, or
filesystem cache modules. `host` does not enable `canister`.

Later canister adapters join this feature until a measured dependency or Wasm
size problem justifies family-level canister features. The design does not
preemptively mirror the complete focused-host feature matrix.

`ic-query-cli` defines no feature matrix. It continues to depend on the full
native `host` surface because its executable size is not a selection boundary,
and it never enables `canister`.

The feature and target checks express different facts. `feature = "canister"`
means the consumer intentionally provides an IC canister runtime;
`target_arch = "wasm32"` prevents the concrete adapter from compiling as a
native transport. Generic browser or server Wasm can continue using the pure
no-default surface without enabling the IC runtime.

The only IC-runtime-specific implementation is the concrete source module: it
uses the canister call API, reads the executing canister principal and optional
IC time, and maps call rejects or timeouts. Async source contracts, Candid
encoding and decoding, response-byte validation, provenance, report assembly,
and rendering remain portable Rust.

The empty default feature set continues to expose pure Governance request and
report models, validation and assembly contracts, and text rendering. It does
not acquire a canister runtime dependency merely because it is Wasm-compatible.

## Public request contract

The current `NnsSourceRequest` assumes that every source has an HTTP endpoint.
That is not true for an inter-canister call. The direct Governance family will
therefore own one transport-aware request instead of placing a fictitious URL
in canister reports.

The request retains:

- network identity;
- collection time supplied as Unix seconds or canonical UTC text;
- one explicit source selection.

The source selection is either:

- a native replica query with one validated credential-free HTTP(S) endpoint
  and one collector identity; or
- a replicated inter-canister call to the fixed mainnet Governance canister.

Only network `ic` is supported. Unsupported network or malformed native source
selection fails before a source method is invoked. The canister selection has
no endpoint field and cannot override the mainnet Governance principal.

This replaces the direct Governance use of `NnsSourceRequest` as a pre-1.0
Rust API hard cut. It does not change other NNS Registry, inventory, proposal,
neuron, or topology request types in the same slice.

## Async source and assembly boundary

`NnsGovernanceSource` becomes a caller-runtime async capability available
without native host dependencies. Each method returns source data, not a
finished report. The shared builder then validates the request, source echo,
authority, response shape, and report invariants before projecting a public
report.

The source future follows the repository's existing boxed caller-runtime
pattern. The library does not create a Tokio runtime, helper thread, canister
executor, or background task in the shared async path.

Two concrete implementations use that boundary:

- `LiveNnsSource` under `nns-host` performs the current response-bounded
  `ic-agent` query; and
- `CanisterNnsSource` under `canister` performs one bounded-wait
  inter-canister call.

The existing synchronous native live builders remain useful convenience entry
points. They may bridge the built-in native future at the host boundary. The
custom-source `*_with_source` builders are hard-cut to the async source
contract; no deprecated synchronous custom-source wrapper or alias remains.

Fixture, mirror, proxy, and pre-collected sources continue to enter through the
same source capability. They do not bypass report validation.

## Canister execution contract

The built-in canister adapter is intended for an update method, timer,
heartbeat, or another replicated canister execution context that permits an
inter-canister call. An update execution may call a query method on another
canister and receives replicated execution semantics.

Composite-query collection is excluded from 0.38. Composite queries can call
only canisters on the same Subnet and cannot themselves be invoked by another
canister. A same-Subnet-only path would not satisfy the goal that an arbitrary
application canister can query the NNS Governance canister.

Each report:

- issues exactly one bounded-wait call;
- attaches no cycles to the Governance method;
- performs no automatic retry;
- receives raw response bytes and enforces the report's response-byte ceiling
  before Candid decoding;
- publishes no partial report if the future is cancelled, rejected, times out,
  exceeds its bound, fails decoding, or fails validation; and
- makes no state or stable-memory write.

A read-only call is safe for an application to retry explicitly, but the
library does not hide that additional call or claim that two attempts observed
the same Governance state.

## Provenance and schema hard cut

The current direct Governance report context requires
`source_endpoint: String`. Schema 1 is hard-cut to transport-aware provenance.
One tagged enum owns the transport-specific fields:

```rust
#[serde(tag = "source_transport", rename_all = "snake_case")]
pub enum NnsGovernanceSourceProvenance {
    ReplicaQuery {
        endpoint: String,
        fetched_by: String,
    },
    ReplicatedInterCanisterCall {
        collector_canister_id: String,
    },
}
```

The shared context retains schema version, network, the fixed Governance
canister principal, collection time, and this `source` value. The enum makes an
HTTP endpoint impossible on an inter-canister report and makes a collector
canister principal impossible on a native replica report.

Execution assurance is derived from the selected enum variant and is not
stored as another field that could disagree with it. The canister principal is
canonical text in serialized reports; the built-in adapter reads the typed
executing-canister principal from the IC runtime and converts it at the
boundary.

The host path must not claim replicated execution. The canister path must not
invent an HTTP endpoint or describe its response as a certificate. Replicated
inter-canister execution is stronger than an unreplicated external query, but
it is not a Registry certificate and does not turn native payload timestamps
into one broader point-in-time snapshot.

The report schema identifier remains `1` before 1.0. There is no version-2
contract, legacy reader, Serde alias, optional compatibility field, or
automatic migration. These reports are live-only, so no persisted cache needs
replacement.

## Wire and validation ownership

The native Governance Candid request/response types currently compile only
with `nns-host`. The wire models required by both transports move behind the
smallest shared Governance boundary. They remain private implementation
details; public consumers use the stable report DTOs rather than native wire
types.

Shared validation continues to enforce:

- mainnet network and fixed Governance principal;
- exact agreement between request and returned source identity;
- transport-specific provenance invariants;
- the typed Governance application error returned by `get_metrics`;
- finite floating-point metric buckets so JSON remains lossless; and
- the existing economics, reward-event, and maturity-modulation report shapes.

Remote rejects, response timeouts, Candid encoding/decoding failures,
oversized responses, and invalid source data are typed errors. None traps the
calling canister as ordinary error handling. Candid arguments are encoded
before issuing the call so encoding failure is returned rather than hidden in
an infallible call-builder path.

## Time, calls, and resource ownership

Collection time remains explicit input to the report request. A convenience
constructor may read the canister's current IC time, but validation and fixture
builders accept caller-supplied time so tests and pre-collected sources remain
deterministic.

The canister adapter records the executing canister principal from the runtime
rather than accepting an arbitrary claimed collector principal. The report
retains native Governance timestamps unchanged inside their payloads.

The caller owns scheduling, instruction and cycle budgeting, concurrency,
retry policy, and durable storage. `ic-query` owns the one-call bound, response
byte bound, decoding, validation, projection, and provenance.

## Persistence

0.38 introduces no stable-memory backend, cache key, refresh lock, attempt
sidecar, timer, or automatic refresh policy. The returned report is an ordinary
Serde value. A consuming canister may serve it immediately or persist it using
its chosen stable-state design.

Filesystem cache abstractions must not be generalized into a fake cross-runtime
storage layer. A canister storage trait should be added only when a later
complete paged collection demonstrates shared atomic-publication requirements.

## Module ownership

- Pure request, source-selection, provenance, report, validation, and rendering
  contracts remain under `ic_query::nns::governance`.
- The native Candid transport remains in the library's NNS host boundary.
- The canister transport lives in a Governance canister module gated by
  `canister` and the Wasm target where required.
- `ic-query-cli` continues to own command parsing, clock acquisition for CLI
  requests, JSON/text output selection, and process errors.
- No canister runtime type appears in a public no-default report DTO.

## Staged delivery

### 0.38.0 vertical slice

1. Add the feature and negative dependency boundary.
2. Introduce the transport-aware direct Governance request and provenance.
3. Extract shared async source, wire, validation, and report assembly.
4. Adapt `LiveNnsSource` and the existing CLI to the new shared path.
5. Add `CanisterNnsSource` and the four canister-call report entry points.
6. Add Wasm compilation, fixture, public API, and CLI regression coverage.

### 0.38.2 bounded proposal slice

The first follow-up reuses the established source pattern for one bounded NNS
proposal page and one exact proposal detail. `NnsProposalListRequest` and
`NnsProposalRequest` carry the shared transport-aware `NnsGovernanceRequest`;
native and canister adapters converge on the same async `NnsProposalSource`,
row conversion, validation, view filtering, sorting, report assembly, and
tagged source provenance.

The list calls `list_proposals` exactly once with a limit from 1 through 100
and an optional exclusive proposal-id cursor. Governance status and reward-
status filters are sent upstream. Topic, proposer, free-text, and sort options
remain local views of that one returned page; they do not trigger refills or
additional calls. The report is a bounded live result and never claims API
exhaustion, stable pagination, or one point-in-time collection.

Exact detail calls `get_proposal_info` exactly once and requires the returned
proposal id to equal the request. Both operations attach no cycles, perform no
retry, enforce the shared 8 MiB raw-response ceiling before Candid decoding,
validate transport provenance, and retain the current proposal row payload,
including ballots and tally evidence.

The native CLI remains cache-preferred with native live fallback and gains no
command or option. Complete filesystem refresh remains native-only. Existing
complete caches continue to describe the replica query that collected them;
cache reads never manufacture inter-canister provenance.

The proposal report schema remains `1` and is hard-cut to the shared flattened
Governance context with tagged source provenance. The former always-present
`source_endpoint` and `fetched_by` report fields are removed because they
cannot represent an inter-canister call. No compatibility fields or alternate
reader are retained.

### 0.38.3 bounded neuron slice

The second follow-up reuses the same transport-aware Governance request and
portable async source pattern for one public NNS neuron-index page and one
exact public neuron detail. `NnsNeuronListRequest` and
`NnsNeuronInfoRequest` carry `NnsGovernanceRequest`; native, canister, and
custom adapters converge on one `NnsNeuronSource`, wire conversion, validation,
report assembly, and tagged source-provenance path.

The list calls `get_neuron_index` exactly once with an optional exclusive
neuron-id cursor and a page size from 1 through 300. It accepts no more than
the requested number of rows, requires strictly ascending unique neuron ids,
requires every returned id to be above the cursor, and accepts a next cursor
only when a full page makes the final returned neuron id the exact continuation
cursor. The builder returns that cursor but never follows it automatically.

Exact detail calls `get_neuron_info` exactly once, maps Governance's typed
not-found code to a neuron-specific error, and requires the returned neuron id
to equal the request. Both operations attach no cycles, perform no retry,
enforce the shared 8 MiB raw-response ceiling before Candid decoding, validate
transport provenance, and retain the current public `NeuronInfo` projection.

The native CLI remains cache-preferred with native live fallback and gains no
command or option. Complete filesystem refresh remains native-only and may use
the portable source through the native runtime bridge. Existing complete
caches continue to describe their replica query; cache reads never manufacture
inter-canister provenance.

The neuron report schema remains `1` and is hard-cut to the shared flattened
Governance context with tagged source provenance. The former always-present
`source_endpoint` and `fetched_by` report fields are removed without aliases,
fallback readers, or compatibility fields.

### 0.38.4 resumable proposal and public-neuron collection slice

#### Proposal continuation

Complete proposal collection becomes a caller-driven sequence rather than one
automatic multi-call builder. `NnsProposalCollectionState` is a portable,
Serde-compatible schema-1 continuation. It fixes the mainnet identity, source
selection, page size, and cumulative page ceiling when created, then retains
the admitted concrete source provenance, page and row counts, exclusive next
proposal cursor, caller-supplied start/update times, and one explicit lifecycle
status.

Portable page ceilings and admitted-page counters use `u32`; cumulative
proposal-row accounting uses `u64`. No serialized counter depends on the
producer or consumer target's pointer width.

`advance_nns_proposal_collection_with_source` borrows the prior state and
per-call `NnsGovernanceRequest`, validates both before source work, and makes
exactly one existing response-bounded `list_proposals` call with no status or
reward filter. Success returns the unfiltered bounded list report and a
candidate next state together. The input state is unchanged on validation,
transport, decoding, response, provenance, or accounting failure. A caller
should retain the returned page before atomically replacing its stored
continuation with the returned state.

Every noninitial state is revalidated after deserialization. The next page
must remain below the prior exclusive cursor, and subsequent pages must retain
the source selection and the exact concrete collector provenance admitted by
the first page. A replica walk therefore cannot change endpoint or collector
label. A replicated inter-canister walk cannot silently continue under a
different collector canister.

The collection is `complete` only after a short page or a full terminal page
whose minimum proposal id is one leaves no continuation cursor. If another
cursor exists when the explicit cumulative page ceiling is consumed, the
state becomes `page_limit_reached`; it is successful diagnostic progress but
not publishable complete data. Advancing a complete or page-limited state
fails before another source call.

One advance therefore reserves at most one Governance call, one 8 MiB raw
response, and the configured page size of at most 100 rows. `max_pages` bounds
the cumulative calls and rows admitted by the whole continuation. There is no
default background loop, retry, timer, instruction measurement, or cycle
charge. Callers decide when their own instruction/cycle budget permits the
next step.

The state is coordination metadata, not authenticated data or a stable-memory
layout. Pages can span Governance changes and remain explicitly not
point-in-time. The application owns page storage, interruption recovery, and
the final atomic publication rule; it should expose a complete collection
only after retaining every admitted page and observing `complete`. Native
filesystem proposal refresh uses this same continuation engine beneath its
existing lock, attempt, and atomic snapshot boundary. The CLI and its cache
contract do not change.

#### Public-neuron continuation

Complete public-neuron collection adopts the same caller-driven one-page
coordination model. `NnsNeuronCollectionState` is a portable,
Serde-compatible schema-1 continuation. It fixes mainnet identity, source
selection, page size, and cumulative page ceiling when created, then retains
the concrete source provenance admitted from the first page, page and row
counts, exclusive next neuron-id cursor, caller-supplied start/update times,
and one explicit lifecycle status.

Portable page ceilings and admitted-page counters use `u32`; cumulative
neuron-row accounting uses `u64`. No serialized counter depends on the
producer or consumer target's pointer width.

`advance_nns_neuron_collection_with_source` borrows the prior state and a
per-call `NnsGovernanceRequest`, validates both before source work, and makes
exactly one existing response-bounded `get_neuron_index` call. Success returns
the bounded list report and a candidate next state together. The input state
is unchanged on validation, transport, decoding, response, provenance, or
accounting failure. A caller should retain the returned page before atomically
replacing its stored continuation with the returned state.

Every noninitial state is revalidated after deserialization. Rows remain
strictly ascending and unique, the first row must be above the prior exclusive
cursor, and every full page must return its final neuron id as the exact next
cursor. Subsequent pages retain the source selection and exact concrete
collector provenance admitted by the first page. A replica walk therefore
cannot change endpoint or collector label, while an inter-canister walk cannot
silently continue under another collector canister.

The collection is `complete` only after a short page, including an empty page,
observes API exhaustion. A full page always retains its exact continuation
cursor. If that page consumes the configured cumulative page ceiling, the
state becomes `page_limit_reached`; it records successful bounded progress but
does not claim completeness. Advancing a complete or page-limited state fails
before another source call.

One advance reserves at most one Governance call, one 8 MiB raw response, and
the configured page size of at most 300 rows. `max_pages` bounds cumulative
calls and admitted rows. There is no automatic loop, retry, timer, instruction
measurement, or cycle charge. Callers decide whether their instruction and
cycle budget permits each next step.

The state and returned report DTOs are portable Serde values, but they are
coordination metadata rather than authenticated data or a prescribed stable-
memory layout. Pages can span Governance changes and remain explicitly not
point-in-time. The application owns page storage, interruption recovery, and
final atomic publication. Native complete-neuron filesystem refresh consumes
the same continuation engine beneath its existing lock, attempt, and atomic
snapshot boundary. The CLI and cache contracts do not change.

### Later work after 0.38.4

The planned 0.38 NNS Governance point, bounded proposal/neuron, and resumable
complete proposal/neuron library boundaries are now represented. Further
canister-native authority families require separate designs rather than an
expansion of these Governance continuation contracts.

SNS, ICRC, Registry, certified state, CMC, CloudEngine, and Dashboard HTTP
adapters remain outside 0.38. Each authority must retain its own provenance
and call constraints rather than inheriting NNS Governance semantics.

## Explicit exclusions

This slice does not:

- add another workspace or published crate;
- add or change CLI commands;
- enable every `ic-query` host feature inside a canister;
- support composite-query or same-Subnet-only collection;
- add arbitrary Candid invocation;
- issue authenticated Governance mutations;
- cache reports or prescribe stable-memory layout;
- automatically retry, fan out, paginate, or schedule refreshes; or
- claim certification, cross-report point-in-time consistency, or historical
  completeness.

## Verification

The implementation gate includes:

```text
cargo fmt --all -- --check
cargo check -p ic-query --target wasm32-unknown-unknown --no-default-features
cargo check -p ic-query --target wasm32-unknown-unknown --no-default-features --features canister
cargo check -p ic-query --test nns_public_api --target wasm32-unknown-unknown --no-default-features --features canister
cargo check -p ic-query --no-default-features --features nns-host
cargo check -p ic-query-cli
cargo test -p ic-query --test nns_public_api --no-default-features
cargo test -p ic-query --test nns_public_api --no-default-features --features nns-host
cargo test --workspace --all-features
```

Feature-boundary checks reject native process, network, runtime, and filesystem
dependencies from the canister graph. Fixture tests prove pre-call network and
source validation, exact method/argument selection, raw response-byte bounds,
typed rejects, Candid failure handling, provenance invariants, non-finite
metric rejection, equivalent payload projection across native and canister
sources, text/JSON rendering, and no source call after invalid input.

A Wasm example within the existing `ic-query` package compile-checks downstream
canister usage without adding a workspace crate. The release design also
required a manual mainnet canister smoke recording one successful call for
each method and confirming that the resulting provenance identifies replicated
inter-canister execution. No repository-backed receipt was recorded for the
tagged 0.38 releases, so this check is not claimed as demonstrated; that
evidence gap does not establish whether the smoke was or was not run.
