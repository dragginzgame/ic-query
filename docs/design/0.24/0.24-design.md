# ic-query 0.24 Design: Bounded SNS Governance Metrics

## Status

- Status: complete
- Last reviewed: 2026-08-01
- Scope: one bounded native SNS Governance metrics report

## Goal

Expose the official SNS Governance metrics response without reconstructing a
treasury from transaction history or presenting cached values as live ledger
state. The report resolves one SNS through targeted discovery and adds no
fanout or cache.

## Authority And Native Method

`icq sns metrics <id|root-principal>` calls Governance `get_metrics` as one
composite query. Its required `time_window_seconds` controls the recent
submitted/executed proposal counts. The CLI defaults to 30 days and rejects
values above 365 days before discovery or agent construction.

The response preserves:

- recent submitted and executed proposal counts;
- the latest SNS-ledger block timestamp fetched by Governance;
- the SNS genesis timestamp;
- Governance's cached treasury metrics; and
- Governance's cached voting-power metrics.

Each treasury row retains its raw native treasury code, derived native kind,
optional name, source ledger and account, current/original e8s amounts, and
metric timestamp. Native codes are `0` unspecified, `1` ICP, and `2` SNS token;
unknown future codes remain visible as `Unknown` alongside the raw value.

## Freshness And Call Bound

A direct command makes three client requests:

1. one SNS-W deployed-inventory query;
2. one Governance metadata query for only the selected SNS; and
3. one Governance `get_metrics` composite query.

The composite query performs its own bounded SNS-ledger lookup for the latest
block timestamp. Treasury and voting-power values come from Governance's
cached metrics and carry their own timestamps. Therefore the report always
sets `point_in_time_guaranteed` to `false` and
`treasury_metrics_cached` to `true`.

`ic-query` does not call ledger transaction endpoints, follow archives,
reconstruct balances, query another SNS, fan out, or create a cache. An SNS
running an older Governance Wasm without `get_metrics` returns the normal typed
agent-call failure; there is no legacy fallback.

## Source Validation

The custom-source boundary requires:

- the returned Governance principal to equal the resolved SNS principal;
- exact `get_metrics` and `composite_query` evidence;
- the echoed time window to equal the request;
- no point-in-time claim and an explicit cached-treasury claim;
- at most 16 treasury rows, canonically ordered by native treasury code;
- unique treasury codes and matching native kind labels;
- canonical optional ledger/account principals;
- lowercase 32-byte account subaccounts when present; and
- non-empty, trimmed optional treasury names.

Absent optional native values remain absent. The adapter does not infer a
ledger, owner, amount, timestamp, or treasury name.

## Public Boundaries

- `SnsMetricsRequest` carries the SNS selector and bounded proposal window.
- `SnsMetricsSource` is the focused host capability on `LiveSnsSource`.
- `MainnetSnsMetrics` is the validated host source result.
- `SnsMetricsReport`, `SnsTreasuryMetricRow`, `SnsTreasuryKind`, and
  `SnsVotingPowerMetrics` remain usable without default features.
- `build_sns_metrics_report_with_source` applies the same validation to custom
  sources as the built-in live adapter.

No generic Candid invocation, compatibility alias, mutation behavior, or
unrequested follow-up is introduced.
