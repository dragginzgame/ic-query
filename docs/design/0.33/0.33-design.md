# 0.33 Design: Certified API Boundary-Node Reporting

## Status

- Status: implemented for the 0.33 release slice
- Authority: certified IC state tree authenticated by the mainnet root key
- Collection mode: one response-bounded live `read_state` request
- Public family: `ic_query::ic`

## Purpose

The certified IC state tree now exposes configured API boundary nodes directly.
This closes the identity gap left by the official Dashboard resources without
pretending that three different authorities are interchangeable:

- certified state supplies API boundary-node principals, domains, addresses,
  and one common state-tree time;
- the Dashboard v4 resource supplies off-chain data-center aggregates; and
- the Dashboard node snapshot supplies off-chain operational observations for
  its documented default scope.

The CLI surface is intentionally singular and nested below the IC authority
family:

```bash
icq ic api-boundary-node list
icq ic api-boundary-node list --json
```

## Collection Contract

The built-in `LiveIcStateSource` constructs a response-bounded `ic-agent` for
the explicit mainnet `--source-endpoint` and requests the complete
`api_boundary_nodes` subtree once. The fixed NNS Registry canister principal is
the effective canister id required to route `read_state`; the collector does
not query Registry canister state and does not call any boundary node
individually.

`ic-agent` authenticates the certificate signature, delegation, and state-tree
proof using its built-in mainnet root key. The collector then requires:

- a canonical unsigned LEB128 `time` leaf;
- a proven `api_boundary_nodes` subtree with at least one and at most 1,000
  rows;
- one canonical principal label per node;
- a required UTF-8 `domain` and `ipv6_address` leaf; and
- either a proven UTF-8 `ipv4_address` leaf or proven absence of that optional
  leaf.

The standard agent response ceiling is 8 MiB. There is no pagination, cache,
fallback authority, per-node lookup, or automatic endpoint discovery.

## Report Contract

`IcApiBoundaryNodeReport` uses schema `1` and preserves:

- explicit mainnet network and source endpoint;
- `authority: certified_ic_state_tree`;
- the effective routing canister id;
- caller retrieval time in Unix seconds and UTC;
- raw certificate time in Unix nanoseconds, its floor-to-seconds projection,
  and UTC rendering;
- `certified: true` and `point_in_time_guaranteed: true`; and
- canonical node principal, lowercase DNS domain, optional IPv4, and IPv6 for
  every row.

JSON keeps the raw protocol nanoseconds because the certified `time` leaf is
defined at that precision. The extra Unix-second field is a direct integer
projection for ordinary scripting, and human text shows seconds. The report
does not relabel a nanosecond protocol field as seconds.

Projection rejects certificates more than five minutes before or after the
caller observation time, noncanonical principals or DNS names, invalid IPv4 or
IPv6 families, duplicate principals or domains, inconsistent source echoes,
and empty or oversized collections. It canonicalizes row order by node
principal. Custom sources pass through the same projection contract but remain
responsible for authenticating the certificate evidence they supply.

## Authority Limits

This is point-in-time authenticated configuration, not an operational report.
It does not establish:

- health, reachability, latency, or successful TLS/HTTP service;
- physical location, data-center ownership, or node-provider identity;
- membership in the separate HTTP-gateway infrastructure; or
- equivalence with a Dashboard data-center count or its default node-status
  scope.

Those meanings remain with separately named sources and reports. A future join
must preserve each authority and timestamp rather than promoting the weaker
source to certified state.

## Public Library Boundary

Pure no-default builds expose the request, report, row, certified-state
provenance, constants, and text renderer. The focused `ic-state-host` feature
adds `LiveIcStateSource`, `IcApiBoundaryNodeSource`, source-data contracts, and
the live/custom-source builders.

`ic-state-host` enables `ic-agent`, Tokio, and URL validation. It does not
enable the confined cache filesystem, Dashboard Reqwest transport, Registry
Prost decoding, Futures collection, direct CBOR decoding, or direct SHA-256
hashing. The convenience `host` feature includes it.

## Cache Contract

The report is live-only. It does not read, write, invalidate, or migrate a
cache. One small certified state tree already supplies a complete coherent
snapshot, and adding implicit persistence would create freshness policy not
required by the current use case.
