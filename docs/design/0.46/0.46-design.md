# 0.46 Design: Cache-only NNS Analytics

- Status: released in 0.46.0; current analytics validation ownership described below
- Scope: local proposal activity and public-neuron distribution in the CLI
- Authority: retained sequential NNS Governance collection evidence
- Persistence: existing complete snapshots, schema-1 shape hard cut

The existing pure analytics builders remain the owners of validation and
aggregation. The native cache adapters load complete snapshots and invoke those
builders; CLI code owns parsing, dispatch, and process output. No additional
collection engine, analytics cache, network adapter, or retry owner is added.

Builders validate caller-supplied state and rows, then construct reports using
checked aggregates and canonically ordered maps. They do not run the restored-
report validators on their own output. Those public validators remain the
boundary for accepting externally supplied or deserialized reports; fixture
tests check that constructed reports satisfy them. The unused `InvalidReport`
variants are removed from both analytics builder error enums as a Rust API
hard cut. The validators and their error types remain public.

## Input evidence

Native collectors produce a final portable continuation. Current publication
stores only its independent caller evidence under `data.collection_evidence`:
`requested_source`, `max_pages` and `started_at`. Identity, concrete replica
provenance, `fetched_at`, page size/count and row count live once in the shared
snapshot envelope. No completed cursor or lifecycle status is stored again.
The fixed caller-supplied times are collection labels, not measured wall-clock
duration or a point-in-time guarantee.

Cache readers require complete envelope accounting, reconstruct final state,
and validate its current schema, identity, time ordering, source binding,
counters and family completion rules. They independently admit retained rows.
These are structural checks, not authenticated content commitments. Portable
caller-owned continuation JSON remains flat with unchanged fields.

Earlier proposal and neuron snapshots require explicit refresh. This schema-1
shape replaces the former contract in place, with no former reader or migration.
Coordinate raw-cache consumers and preserve any externally needed files before
replacement. Query does not delete retained files automatically. Explicit
refresh can replace an invalid snapshot; incomplete or failed refresh preserves
the previously published file. Analytics use the last admitted complete snapshot
independently of a later refresh-attempt sidecar.

## Commands

```bash
icq nns proposal activity
icq nns proposal activity --from 1700000000 --until 1700100000 --json
icq nns neuron distribution
icq nns neuron distribution --json
```

Both commands are cache-only and fail for missing or invalid snapshots. They
do not create files, refresh, auto-page, or select a live endpoint. Use the
existing explicit `refresh` operations to collect current data. Proposal
activity applies a half-open window to proposal creation timestamps only.
Neuron distribution preserves public visibility and optional-field coverage.

Text uses the existing human renderers; JSON uses the existing raw analytics
DTOs. Source provenance describes how stored rows were collected, not a new
network call. Collection timestamps remain visible, and
`point_in_time_guaranteed` remains false.

## Verification

Use fixture sources to test complete collection, empty exhaustion, activity
window boundaries, raw totals, inconsistent evidence, missing/corrupt caches,
and preservation of the last complete snapshot after refresh failure. CLI
process fixtures cover text/JSON, invalid arguments, local-only failure, and
unchanged snapshot bytes. Preserve shared help ordering and namespace behavior.
