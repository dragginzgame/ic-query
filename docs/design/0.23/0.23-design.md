# ic-query 0.23 Design: Bounded SNS Completeness

## Status

- Status: active
- Last reviewed: 2026-08-01
- Scope: bounded native SNS swap, upgrade, and treasury reporting

## Goal

Expand the existing per-SNS follow-up surface without introducing discovery
or swap-state fan-out, unbounded canister responses, or caches whose
completeness cannot be proved. Each capability remains a narrow source trait
on `LiveSnsSource` and resolves one deployed SNS through a targeted SNS-W
discovery contract.

## Targeted Discovery Hard Cut

The host source boundary is `SnsDiscoverySource`. It separates:

- one unenriched `fetch_sns_inventory` result from SNS-W; and
- `fetch_sns_metadata` for exactly the supplied `MainnetSnsCanisters` rows.

`MainnetSnsInventory` retains SNS-W order and provenance.
`MainnetSnsMetadata` is keyed by Root principal, and report builders require
canonical, unique, exact target coverage before joining it. Missing,
duplicate, invalid, or unrequested metadata rows are typed source-data
failures.

Direct id or Root lookup resolves against the unenriched SNS-W inventory and
then requests metadata for only that selected SNS. Unknown targets make no
metadata query. `sns list` is the only flow that requests metadata for every
inventory row. This replaces the unpublished `SnsListSource` and public
`MainnetSnsList` source contract as a pre-1.0 hard cut; no compatibility alias,
default fallback, or second discovery path remains.

## First Slice: Swap Lifecycle And Sale State

`icq sns swap <id|root-principal>` resolves one SNS and attempts exactly three
small public query methods against its discovered swap canister:

- `get_lifecycle`;
- `get_sale_parameters`; and
- `get_derived_state`.

The report preserves the raw optional lifecycle code, its native lifecycle
label, lifecycle timestamps, sale parameters, participation totals, and the
derived SNS-token-per-ICP value. Unknown lifecycle discriminants remain
visible as their raw number and receive the label `unknown`.

The adapter deliberately does not call `get_state`. That response includes
participant and neuron-recipe collections and can grow with the sale. The
bounded report therefore has a fixed three-call swap-component budget.
Including discovery, a direct swap report makes five canister queries: one
SNS-W inventory query, one Governance metadata query for the resolved SNS, and
the three swap queries. It never enriches another SNS, enumerates participants,
or reads or writes a cache.

## Evidence And Failure Contract

SNS-W discovery retains its own endpoint and collection timestamp. The three
swap queries use one resolved canister identity and the same endpoint, but the
swap interface exposes no shared state version across them. The report always
sets `point_in_time_guaranteed` to `false`.

Agent construction and invalid target principals are report failures. Once the
target is established, each component query is attempted independently. A
transport, encoding, or decoding failure becomes one typed
`SnsSwapQueryGap`, while successful sibling components remain in the report.
The source validator requires:

- the returned swap principal to equal the resolved SNS swap principal;
- exact native method names;
- no point-in-time claim;
- at most one gap per component, with a non-empty reason;
- lifecycle and derived-state values to have a value or matching gap;
- no component to have both a value and a gap; and
- a finite, non-negative `sns_tokens_per_icp` value when present.

An absent `params` value from a successful `get_sale_parameters` response is
preserved as `sale_parameters: null`; it is not invented as an error.

## Public Boundaries

- `SnsSwapSource` is the host capability trait.
- `SnsDiscoverySource` owns unenriched inventory and exact-target metadata.
- `MainnetSnsInventory`, `MainnetSnsCanisters`, and `MainnetSnsMetadata` are
  the host discovery DTOs.
- `MainnetSnsSwap` is the validated host source-result envelope.
- `SnsSwapReport` and its nested native DTOs remain usable without default
  features.
- `build_sns_swap_report_with_source` gives embedders the same validation and
  assembly path as the built-in live adapter.
- Text rendering is human-facing; JSON retains raw numeric fields and typed
  gaps.

No compatibility alias, generic Candid invocation, mutation behavior, or
unrequested follow-up is introduced.

## Second Slice: Running And Next Blessed Version

`icq sns upgrade <id|root-principal>` resolves one SNS and makes exactly two
report-specific native queries:

- Governance `get_running_sns_version` for the deployed version and optional
  pending-upgrade state; and
- SNS-W `get_next_sns_version` for the next blessed version after that exact
  Governance-reported deployed version.

The report preserves lowercase hexadecimal hashes for the native archive,
Root, swap, ledger, Governance, and ledger-index roles. Pending state preserves
the proposal id, failure deadline, upgrade-lock checking value, and optional
target version without interpreting undocumented semantics.

The Governance query is required evidence. A transport/decode failure or a
response without `deployed_version` fails the report. After deployed evidence
exists, an SNS-W next-version failure becomes `SnsUpgradeQueryGap`; a
successful SNS-W response with `next_version: null` instead proves only that
the method returned no blessed successor. Source validation requires the
resolved Governance and canonical mainnet SNS-W principals, exact native
method names, six non-empty lowercase even-length hexadecimal hashes per
present version, and a non-empty trimmed gap reason. A next-version value and
gap cannot coexist.

Including one SNS-W inventory query and one selected-SNS metadata query, the
complete live command makes at most four canister queries. It does not read
`get_upgrade_journal`, call `list_upgrade_steps`, download Wasms, query another
SNS, or read or write a cache. Governance and SNS-W are sequential authorities
without a shared snapshot version, so `point_in_time_guaranteed` is always
`false`.

The public boundary follows the existing focused adapter shape:

- `SnsUpgradeSource` owns the bounded host capability;
- `MainnetSnsUpgrade` is its validated source result;
- `SnsUpgradeReport`, `SnsVersion`, `SnsPendingUpgrade`, and
  `SnsUpgradeQueryGap` remain usable without default features; and
- `build_sns_upgrade_report_with_source` applies the same target and evidence
  validation to custom sources as the built-in live adapter.

## Remaining 0.23 Direction

1. Add treasury evidence only through an authoritative, explicitly bounded
   account or canister interface.
2. Expand neuron state only where the public governance interface exposes it
   without authenticated ownership assumptions.

Each later slice must state its call bound, response bound, authority,
point-in-time limit, and cache policy before implementation.
