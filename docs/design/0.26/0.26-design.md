# ic-query 0.26 Design: SNS Maturity Reward Evidence

## Status

- Status: implemented for 0.26.0
- Last reviewed: 2026-08-04
- Scope: read-only SNS neuron permission evidence, API-exhausted observed
  maturity checkpoints, and locally reconciled reward-allocation evidence

## Goal

Support SNS DAOs that use Governance maturity as a measure of reward
entitlement. The new surface must let an operator assess whether maturity
conversion is disabled across the observed permission surfaces, collect an
API-exhausted reward-event-aligned maturity checkpoint, and compare two
checkpoints without enumerating proposal ballots. A diff becomes allocation
evidence only after its raw maturity changes reconcile exactly to one native
Governance reward event.

The slice remains reporting-only. It does not sign identities, call
`manage_neuron`, submit proposals, alter permissions, reset maturity, transfer
revenue, or generate JavaScript for execution in another application's browser
context.

## Protocol Facts And Policy

SNS Governance currently defines these neuron permission codes:

| Code | Permission |
| ---: | --- |
| 0 | `Unspecified` |
| 1 | `ConfigureDissolveState` |
| 2 | `ManagePrincipals` |
| 3 | `SubmitProposal` |
| 4 | `Vote` |
| 5 | `Disburse` |
| 6 | `Split` |
| 7 | `MergeMaturity` |
| 8 | `DisburseMaturity` |
| 9 | `StakeMaturity` |
| 10 | `ManageVotingPermission` |

Codes 7, 8, and 9 do not have identical economics and are reported as separate
findings:

- `MergeMaturity` (7) performs a ledger mint into neuron stake;
- `DisburseMaturity` (8) deducts maturity and schedules a later token mint; and
- `StakeMaturity` (9) moves unstaked maturity into staked maturity without
  itself minting tokens.

The checkpoint derives these observations:

- `maturity_mint_conversion_observed_disabled` requires codes 7 and 8 to be
  absent from `neuron_claimer_permissions`,
  `neuron_grantable_permissions`, and every current principal permission entry,
  and requires every pending maturity-disbursement collection to be empty;
- `manual_maturity_staking_observed_disabled` requires code 9 to be absent from
  the same three permission surfaces; and
- every neuron's `auto_stake_maturity` state is reported separately because
  `ConfigureDissolveState` (1), not `StakeMaturity` (9), authorizes changing
  that setting.

Each observation and the overall
`maturity_conversion_policy_observed_status` use
`ObservedSatisfied | Violated | Unassessable`, never a bare global boolean. A
known prohibited permission or pending maturity disbursement produces
`Violated`. Any unknown permission code, anomalous `Unspecified` code 0,
missing permission list, or missing principal in claimer, grantable, or current
principal permissions fails closed as `Unassessable`. Unknown codes remain
visible as raw evidence.

The global parameter checks govern new claims and future grants. They do not
revoke a permission already held by a principal, so a parameter-only audit is
not sufficient for an existing SNS. The API-exhausted paged neuron observation
is required, but it is not a point-in-time proof: permissions can still change
while pages are being read or between checkpoints.

`ManagePrincipals`, `Vote`, and `SubmitProposal` are required claimer
permissions in the current Governance implementation. Whether
`ManagePrincipals` should be grantable to another principal is a separate
control-transfer policy. The report exposes that fact as a warning but does not
classify it as maturity inflation.

Reward distribution adds new maturity to staked maturity when auto-stake is
enabled and to unstaked maturity otherwise. The reconciliation value for one
neuron is therefore:

```text
combined_maturity_e8s_equivalent =
    maturity_e8s_equivalent
    + staked_maturity_e8s_equivalent.unwrap_or(0)
```

Changing auto-stake moves future accrual between those components and does not
invalidate the combined value. A pending maturity disbursement is preserved as
separate evidence and makes the mint-conversion observation `Violated`; it is
not silently added back into the combined maturity value.

There is no native operation that resets maturity to zero as pure accounting.
Merge and disburse can create additional SNS-token stake or liquid supply,
while stake only reclassifies maturity. SNS token supply can also increase
independently through a `MintSnsTokens` proposal. This design therefore makes
no global SNS non-inflation claim; it reports observed maturity-conversion
policy and uses immutable checkpoint reconciliation instead of reset behavior.

## Existing Surface And Hard Boundary

`SnsNeuronRow` continues to represent the fixed-size fields used by normal
bounded lists and complete neuron caches. Its current report and cache schema
is 1. It is not expanded with permissions, followees, or pending
disbursements.

The reward workflow uses a separate explicit row and report because it needs
variable-size permission and pending-disbursement evidence. This preserves the
0.25 rule that ordinary `sns neuron list` and `sns neuron refresh` do not grow
their response, cache, or rendering contract implicitly.

## CLI Surface

The intended command surface is:

```bash
icq sns neuron info <id|root-principal> <neuron-id>
icq sns reward checkpoint <id|root-principal>
icq sns reward diff <before-checkpoint.json> <after-checkpoint.json>
```

All live commands accept the existing explicit SNS source endpoint and global
mainnet network identity. Text is a human-facing summary. `--json` retains raw
permission codes, principals, maturity values, event fields, timestamps, and
policy findings.

`reward diff` is local-only. It must reject network and source-endpoint options
rather than accepting an option that appears capable of making a live call.

## Neuron Detail

`sns neuron info` calls native Governance `get_neuron` for one exact neuron id.
It preserves:

- every principal and raw permission code, with a derived current permission
  name when known;
- unstaked and staked maturity;
- the auto-stake setting;
- pending maturity disbursements, including raw amount, timestamps, and the
  complete destination account owner and subaccount;
- fixed-size neuron state already represented by `SnsNeuronRow`; and
- legacy and topic followees as native detail evidence.

Unknown future permission codes remain visible and receive an `unknown` label,
while the relevant policy observation becomes `Unassessable`. Code 0 is also
anomalous evidence rather than an allowed permission. Missing principals and
malformed ids remain typed source-data failures. Every neuron id supplied by a
caller or returned by a source must be exactly 32 bytes represented as 64
lowercase hexadecimal characters. The report is live-only and does not read or
write the complete neuron cache.

Including targeted discovery, one detail report makes three client queries:
one SNS-W inventory query, one selected-SNS metadata query, and one Governance
`get_neuron` query. SNS neurons are publicly readable under the current native
contract, so the built-in source remains anonymous and does not introduce
identity-file handling.

## Reward Checkpoint Collection

`sns reward checkpoint` performs this ordered collection:

1. resolve exactly one deployed SNS through targeted discovery;
2. read `get_running_sns_version`;
3. read the complete Governance nervous-system parameters response;
4. read the complete `get_latest_reward_event` response;
5. exhaust `list_neurons` with the native maximum page size of 100;
6. read the complete reward event again;
7. read the complete nervous-system parameters response again; and
8. read `get_running_sns_version` again.

For `N` neuron pages, this makes `N + 8` client queries including targeted
discovery. It does not call `get_proposal`, enumerate ballots, fan out with one
`get_neuron` call per row, query a ledger, or inspect transaction history.

The two entire typed nervous-system parameter responses must be equal, not only
their permission lists. The two entire typed `RewardEvent` responses must be
equal, including proposal ids and every optional field. The two entire typed
running-version responses must be equal, including deployed and pending
versions. A mismatch or missing required bracketing field is a typed unstable
checkpoint failure; no checkpoint is emitted. This brackets a Governance
upgrade as well as parameter or reward-event movement during collection.

This evidence collector does not reuse permissive cross-page deduplication from
another collection. Every page and the global walk must preserve strictly
increasing canonical neuron ids. It rejects any duplicate across pages,
partial page overlap, cursor regression, an advertised next cursor that is not
the final row id, a cursor on a short or empty exhausted page, and any row
offered after exhaustion. A full page advertises its final row id as the exact
exclusive cursor; a short or empty page proves API exhaustion.

The before parameters also establish a mandatory collection ceiling:

```text
collection_row_ceiling = min(
    nervous_system_parameters.max_number_of_neurons,
    200_000,
)
```

The parameter must be present and greater than zero; a reported value above the
official protocol ceiling is invalid source evidence. The collector rejects
more rows than the derived ceiling and performs at most
`ceil(collection_row_ceiling / 100) + 1` page calls, where the final additional
call is only the empty exhaustion probe needed after an exactly full final
page. An optional diagnostic page cap may be more restrictive, but reaching it
is incomplete and cannot produce a checkpoint. A faulty custom source can
therefore never drive an unbounded sequence of unique pages.

Each checkpoint row contains:

- neuron id and creation timestamp;
- unstaked, staked, and combined maturity;
- auto-stake state;
- every current principal permission entry;
- every pending maturity disbursement, including destination owner and
  subaccount; and
- row-level policy findings.

The checkpoint summary contains both full bracketing parameter responses, both
full reward-event responses, both running-version responses, page count, row
count, unique neuron-id count, the mandatory collection ceiling, collection
start and end timestamps, aggregate raw maturity totals, finding counts, the
two separate maturity-conversion findings, auto-stake counts, and the overall
`maturity_conversion_policy_observed_status` enum. It does not serialize a
global non-inflation claim.

The report always states `point_in_time_guaranteed: false`. Stable bracketing
shows that the full observed reward event, parameters, and running Governance
version did not change during the walk. Governance exposes no collection
version proving that all neuron rows came from one instant, and principals may
still change neuron state between pages. The artifact is therefore an
`API-exhausted observed collection`, not a complete point-in-time checkpoint or
proof of the global effective permission state.

## Checkpoint Publication

The first slice does not add another implicit cache or overwrite the existing
complete neuron snapshot. A checkpoint is a versioned report emitted to stdout;
an operator persists JSON explicitly, for example:

```bash
icq sns reward checkpoint 1 --json > reward-checkpoint-1785715200.json
```

This keeps history retention, filesystem naming, and backup policy visible to
the caller. A later append-only checkpoint store must define collision,
retention, and content-integrity behavior before writing beneath the shared
cache root.

## Local Reward Diff

`sns reward diff` treats both loaded files as untrusted serialized evidence. It
strictly parses the current schema, then recomputes from raw parameter,
version, event, neuron, permission, maturity, auto-stake, and pending-
disbursement fields:

- each row's combined maturity;
- canonical 64-character lowercase-hex neuron ids, uniqueness, and row counts;
- aggregate raw maturity totals;
- every policy finding and observation status;
- equality of each checkpoint's complete before/after parameter, reward-event,
  and running-version brackets;
- canonical target identity; and
- every diff numerator, denominator, and reconciliation sum.

Serialized derived totals, finding counts, collection booleans, status values,
or allocation values are never calculation inputs. If a schema retains a
derived field for readable standalone evidence, the recomputed value must equal
it or validation fails. The same recomputation path is used for in-memory
checkpoint values and filesystem-loaded JSON.

The checkpoints must match by canonical stable canister principals: network,
Root, Governance, and every additional resolved canister principal retained in
the target evidence. Mutable SNS names and SNS-W numeric list positions are
display metadata, not identity and never authorize a match.

Each checkpoint must independently be an API-exhausted observed collection
whose recomputed maturity-conversion policy status is `ObservedSatisfied`.
Every bracketing response inside each checkpoint must be stable. The canonical
reward-event position is the required `end_timestamp_seconds`; the after value
must be strictly later than the before value. The deprecated `round` is not the
primary ordering identity, but it and `rounds_since_last_distribution` provide
an additional immediate-successor continuity check:

```text
after.rounds_since_last_distribution = Some(k), where k > 0
after.round = before.round + k
```

A missing end timestamp, arithmetic overflow, skipped intermediate reward
event, or failed continuity check makes allocation invalid. The after event's
`actual_timestamp_seconds` must also be strictly later than the earlier
checkpoint's collection completion. This ensures the represented distribution
occurred after the baseline observation instead of merely carrying a later
nominal event position.

Rows are joined by the full 32-byte neuron id. A neuron first observed after
the earlier checkpoint receives a synthetic before value of zero only when its
creation timestamp is strictly after the earlier collection, no later than the
later event's actual distribution timestamp, and consistent with the later
collection. Any other unmatched row is unexplained. For each
joined row the raw signed field is:

```text
maturity_delta_e8s_equivalent =
    after.combined_maturity_e8s_equivalent
    - before.combined_maturity_e8s_equivalent
```

The diff always preserves that name and raw integer value; it does not relabel
an unreconciled net change as a reward. Allocation is valid only when every
condition below holds with checked integer arithmetic:

```text
aggregate_maturity_delta =
    sum(after combined maturity) - sum(before combined maturity)

aggregate_maturity_delta
    == after.reward_event.distributed_e8s_equivalent

sum(per-neuron maturity_delta_e8s_equivalent)
    == after.reward_event.distributed_e8s_equivalent
```

In addition:

- every per-neuron maturity delta is non-negative;
- no neuron from the earlier observation is missing later;
- no new neuron has an unsupported creation-time classification;
- every recomputed row, unique-id count, aggregate, and policy status is valid;
  and
- the after event is the immediate successor covered by the comparison.

These checks reject a conversion hidden by a larger reward. For example, a
combined maturity change of `+10` cannot reconcile to an event that reports
`50` distributed, even if maturity was reduced by `40` and then rewarded by
`50` between observations.

The report preserves:

- positive, zero, and negative deltas;
- neurons created after the earlier checkpoint;
- neurons missing from the later checkpoint;
- permission or pending-disbursement policy changes; and
- every failed reconciliation invariant.

A negative delta, unexplained neuron, target mismatch, policy failure,
bracketing failure, skipped event, reconciliation mismatch, or arithmetic
overflow makes the allocation `Invalid`. It remains visible as typed evidence
rather than being clamped to zero.

The report's `allocation_status` is `Valid | NoAllocation | Invalid`, with
typed invalid reasons. It is `Valid` only after every observation,
immediate-successor, and exact reconciliation invariant passes.

When all checks pass and the native distributed amount is positive, the report
produces per-neuron integer allocation numerators equal to the recomputed
non-negative maturity deltas and one denominator equal to
`after.reward_event.distributed_e8s_equivalent`. When the native distributed
amount is zero, exact zero reconciliation produces the typed result
`NoAllocation`, not an empty or zero-denominator allocation. A non-zero maturity
change beside a zero distributed amount is `Invalid`.

The report does not infer a beneficiary or transfer account. An SNS neuron may
contain several principals, and its permission list does not define one
canonical owner. A payout system must use a separately authenticated
beneficiary registry or a claim mechanism. Local JSON files also have no
content-authenticity guarantee merely because their internal evidence
reconciles; signing or digesting persisted checkpoints requires a separate
design.

## Permission Remediation And Operational Sequence

For a new SNS, operators configure both claimer and grantable permission lists
without codes 7 and 8 before neurons are claimed. They also remove code 9 when
the intended policy disables manual maturity staking. Auto-stake configuration
remains a separate observed state controlled through permission 1.

For an existing SNS, the safe sequence is external to `ic-query`:

1. adopt the parameter change that removes 7 and 8, and code 9 when required,
   from future claimer and grantable permissions;
2. have authorized users remove the same permissions from every current
   principal entry on every neuron;
3. wait for every already-pending maturity disbursement to finalize;
4. collect an API-exhausted observed checkpoint to assess the policy and
   establish the baseline;
5. collect another checkpoint after the immediate next settled reward event,
   ordered by `end_timestamp_seconds`; and
6. use only a fully reconciled local allocation as input to an independently
   authorized revenue payout process.

Changing global grantability prevents removed maturity permissions from being
granted again under the current parameters, but a later Governance proposal
can change those parameters. Every checkpoint therefore repeats the global and
per-neuron observation. This sequence does not constrain an independent
`MintSnsTokens` proposal and is not a global SNS supply or non-inflation proof.

Permission removal itself is intentionally not automated here. Native
Governance permits a caller with `ManagePrincipals` to remove its own
permissions and even to remove the last permission entry, permanently locking
the neuron. An identity-aware wallet or frontend should render the exact
`RemoveNeuronPermissions` request, require informed confirmation, and protect
the last `ManagePrincipals` holder. `ic-query` reports the before and after
state only.

## Public Library Boundaries

- `SnsNeuronSource` owns one exact native detail lookup.
- `SnsRewardSource` owns nervous-system parameters, latest reward event, and
  running SNS version bracketing plus paged reward-neuron collection for one
  resolved SNS.
- `SnsNeuronDetailReport`, `SnsRewardCheckpointReport`,
  `SnsRewardCheckpointRow`, permission and pending-disbursement DTOs, and
  `SnsRewardDiffReport` remain usable without default features.
- A pure in-memory checkpoint-diff builder and all of its validation and
  reconciliation remain available without default features.
- Live builders, filesystem checkpoint loading, and source traits remain behind
  `host`; only filesystem loading is host-specific in the local diff path.
- Report builders validate custom-source evidence with the same target,
  strict pagination, mandatory ceiling, full-response bracketing, permission,
  and arithmetic rules as the built-in adapter.

Reusable permission-code decoding belongs in the SNS report module. CLI
parsing and dispatch remain in `ic-query-cli`; network calls, report assembly,
filesystem checkpoint reads, and rendering remain in the SNS report owners.

## Validation And Tests

Focused fixture tests cover:

- every known permission code, an unknown future code, anomalous code 0, and
  missing permission/principal data;
- prohibited claimer, grantable, and current-principal permissions;
- pending maturity disbursements with complete destination accounts;
- auto-staked and unstaked combined maturity;
- any full reward-event, nervous-system parameter, or running-version change
  across a paged walk;
- duplicate ids across pages, partial overlap, non-increasing ids, cursor
  regression, wrong advertised cursors, rows after exhaustion, malformed rows,
  diagnostic caps, mandatory-ceiling exhaustion, and non-exhausted sources;
- valid new-neuron maturity deltas, negative deltas, missing neurons, and
  unsupported creation timestamps;
- checkpoint schema, stable-principal target, network, and canonical
  `end_timestamp_seconds` ordering or actual-distribution coverage mismatches;
- a conversion hidden by a larger reward;
- a skipped intermediate reward event;
- zero distributed reward producing `NoAllocation`;
- an unknown permission code producing `Unassessable`;
- tampered serialized totals, statuses, row counts, and allocation values that
  disagree with raw-row recomputation;
- exact aggregate maturity, native distribution, per-neuron numerator, and
  denominator reconciliation; and
- local-only diff behavior with no live source calls.

Unit tests use fixture sources and temporary files. No test depends on a live
SNS, an identity, a signed update, or exact full human-readable output unless
that text is the command contract.

## Non-Goals

- signed `manage_neuron` calls or identity storage;
- proposal submission or parameter mutation;
- browser-console jailbreak scripts;
- maturity reset, burn, merge, stake, or disbursement;
- treasury transfers or automatic payouts;
- global SNS supply or non-inflation proofs;
- beneficiary inference from neuron permissions;
- proposal-ballot collection; and
- a claim or Merkle-distribution canister.
