# 0.8 Design

## Hard Cut

Version 0.8 intentionally carries no compatibility readers, aliases,
deprecated wrappers, or automatic migrations for contracts changed in this
release. Every current report `schema_version` is 1; before 1.0, replacing a
shape resets the current schema rather than preserving a numeric lineage.

Complete NNS proposal, SNS proposal, and SNS neuron snapshots use schema version
1 and require `domain`, `entity`, `collection`, and `scope`. Files outside the
current shape are rejected and must be refreshed; there is no prior schema
lineage or migration path. Loaded snapshots must also have internally
consistent page/row counts, logical identity, and unique required row ids.

Refresh-lock JSON accepts exactly the current schema, network, process,
timestamp, and `target_path` fields, and those identity values are validated
before a lock is treated as active or stale. Refresh-attempt sidecars likewise
accept only their current fields and validate schema, network, target identity,
status, and progress. SNS attempts carry the assigned list id so local numeric
status lookup does not depend on an already-published snapshot.

Numeric SNS proposal and neuron cache lookup scans validated snapshot headers
and fully loads only the matching candidate. A numeric id claimed by more than
one cache is ambiguous and rejected; callers can use the root principal to
select an exact cache. Cache-list reports continue to load every snapshot so
invalid local files remain visible.

The atomically replaced snapshot is the publication commit point. Attempt
finalization occurs afterward; if that sidecar write fails, the refresh report
returns the finalization error alongside the successful snapshot result rather
than writing a contradictory failed attempt over the published data.

Public refresh builders validate paging controls, stalled pagination is
incomplete rather than API-exhausted, and stale locks require explicit operator
cleanup. Tests cover the current schema and generic unsupported input rather
than preserving historical removed shapes as anti-resurrection fixtures.

Generic ICRC ownership follows the same boundary rules as NNS and SNS. Command
dispatch constructs public requests, option modules own Clap parsing, report
assembly consumes the public source trait, and the live adapter is the only
synchronous bridge to async Candid fetching. Public request/report contracts,
host-source data, typed errors, and subaccount validation have separate owners;
the module split does not introduce alternate public paths or aliases.

CLI version output is flag-only (`-V` or `--version`); concrete commands whose
domain operation is named `version` remain commands. JSON preserves raw
metadata values, while text rendering escapes control characters and may use a
bounded human-readable projection. Routing catalogs with overlapping ranges
are invalid because resolution must not depend on row order; validation tests
exercise every ordering of representative valid and overlapping ranges. Shared
SNS lookup, topology read, and SNS refresh-attempt DTOs each have one canonical
public type; per-report aliases are not retained.
