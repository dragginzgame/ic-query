# ic-query 0.10 Design: Canonical Library API Paths

## Status

- Status: complete
- Release line: `0.10.x`
- Decision style: hard public-path cut

## Decision

Every NNS and SNS report family exposes its reusable public contract from the
family root. These are the canonical paths:

- `ic_query::nns::data_center`
- `ic_query::nns::node`
- `ic_query::nns::node_operator`
- `ic_query::nns::node_provider`
- `ic_query::nns::proposals`
- `ic_query::nns::registry`
- `ic_query::nns::topology`
- `ic_query::sns`

Their internal `report` modules remain implementation owners for report
construction, host calls, cache reads, models, sources, and text rendering,
but are private Rust modules. Public request, report, row, source, builder,
renderer, path, and schema-constant items are exported only at the matching
family root.

Topology follows the same shape as the other NNS families instead of requiring
the exceptional `ic_query::nns::topology::report` path. The node-provider
endpoint constant is `DEFAULT_NNS_NODE_PROVIDER_SOURCE_ENDPOINT`, matching the
family-specific naming used by the other inventory modules.

## Hard Cut

The former nested `report` paths and the former generic node-provider endpoint
constant are removed. There are no re-export shims, deprecated paths, constant
aliases, compatibility features, or anti-resurrection tests. Current-contract
public API tests import the canonical family roots directly.

This slice does not change CLI arguments, query behavior, cache identity, JSON
report shapes, or report schema versions.
