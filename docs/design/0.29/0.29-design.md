# 0.29 Design: Subnet Catalog Authority And Embedder Hardening

## Status

- Target: `0.29.0` through the `0.29.x` release line
- State: `0.29.0` foundation prepared; later hardening is staged below
- Primary consumer: Canic placement, funding, signer, and imported-canister
  routing decisions
- Network: public mainnet identity `ic`
- Compatibility: pre-1.0 hard cuts only; no old cache reader, migration, alias,
  wrapper, or fallback authority path

## Problem

The Subnet Catalog already resolves one Registry version and reads the Subnet
list, routing table, and every Subnet record at that exact version. It validates
principal syntax, routing references, range direction, and overlap, and it
publishes complete replacements atomically. Those properties prevent internal
Registry-version skew and partial-cache publication.

The catalog is nevertheless consumed as stronger evidence than its current
shape proves. Its Registry calls are ordinary single-replica query calls, its
persisted provenance and classifications are freely constructible, freshness
repair does not report whether a network call occurred, and route results can
be detached from the snapshot that established them. The host filesystem and
runtime APIs also need stronger embedder boundaries.

`0.29` makes authority, validation, freshness, route evidence, filesystem
confinement, feature cost, errors, and async ownership explicit. It must not
claim certification merely because records share one Registry version.

## Preserved Contracts

- Resolve the Registry version once and use it for every Subnet list, routing
  table, and Subnet-record lookup.
- Validate a complete joined snapshot before atomic replacement.
- Preserve the prior cache when collection or validation fails.
- Keep cache-only inspection distinct from every network-capable policy.
- Keep the fixture-backed source seam.
- Keep raw Registry `SubnetType` evidence and IC-native `SubnetKind` labels.
- Keep `subnet-catalog-host` independent of ic-query's immediate Reqwest and
  CBOR edges.
- Keep the reusable library free of process output and mutation behavior.

## Threat Model

The authority path must account for:

- one malicious or faulty replica fabricating an uncertified query result;
- an endpoint returning stale but internally consistent Registry data;
- locally edited JSON changing the Registry identity, Subnet kind, routing,
  classification policy, or collection timestamp;
- noncanonical data producing different digests for equivalent content;
- a caller unknowingly accepting stale or silently repaired evidence;
- a caller retaining a route while discarding its qualifying snapshot;
- symlink substitution, path escape, permissive cache modes, and rename races;
- a synchronous adapter hiding thread creation from an async embedder; and
- a narrow downstream feature paying for unrelated reporting families.

The catalog does not protect a hostile process with the same operating-system
identity after that process has read validated values into memory. Filesystem
hardening protects the authority boundary during path resolution, load, lock,
and publication.

## Registry Assurance

Every catalog carries one typed assurance value:

```rust
pub enum CatalogAssurance {
    Certified,
    MultiEndpointAgreement,
    UncertifiedQuery,
}
```

`SubnetCatalogProvenance` records:

- canonical network and Registry canister identity;
- exact Registry version;
- assurance;
- all source endpoints that contributed to the result;
- collection and optional certificate times;
- the trusted root-key digest when a certificate was verified;
- collector version; and
- the classification and resolver policy identities described below.

The existing live collector must emit `UncertifiedQuery`. An ordinary
`Agent::query` response can never be promoted by validation or cache loading.

### Multi-endpoint agreement

Agreement is optional and explicit. It queries caller-supplied, independently
selected endpoints, requires the same Registry version and the same canonical
raw Registry-derived snapshot from each, and records every endpoint. A mismatch
is a typed failure; it does not fall back to one endpoint. Agreement strengthens
operational confidence but is not cryptographic certification.

Endpoint count and calls remain bounded. No endpoint is discovered implicitly,
and a repeated hostname is rejected rather than counted as independent
evidence.

### Certified Registry data

The Registry canister exposes `get_certified_latest_version` and
`get_certified_changes_since`. It does not expose a bounded certified witness
for arbitrary `get_value` reads. A certified catalog therefore requires all of:

1. verify the response certificate against the compiled-in mainnet root key;
2. verify certificate delegation, canister identity, hash tree, and certified
   data commitment;
3. enforce certificate-time freshness;
4. reconstruct the relevant Registry key state from a complete, contiguous,
   certified delta sequence;
5. reject gaps, regressions, duplicate versions, truncated replay, and values
   newer than the selected snapshot; and
6. derive the catalog only from that reconstructed state.

The implementation may use a separately versioned incremental certified
Registry mirror, but it must have an explicit bootstrap ceiling and must never
download unbounded history as a side effect of an ordinary catalog load.
An unchecked raw value can deserialize the label, but it cannot become a
`ValidatedSubnetCatalog`; no collector emits `Certified` until this verifier
exists.

This follows the Registry's pinned certified method implementation at
<https://github.com/dfinity/ic/blob/eebffee61e857f28e47fc4038a8b3309f2674abf/rs/registry/canister/canister/canister.rs>
and the ICP certified-data model at
<https://docs.internetcomputer.org/concepts/certified-data/>.

## Raw And Validated Catalogs

Serde input is separated from authority-bearing data:

```rust
pub struct RawSubnetCatalog { /* public serialized representation */ }

pub struct ValidatedSubnetCatalog { /* private fields */ }
```

`RawSubnetCatalog` is data, not authority. Cache parsing and custom sources
produce it. `ValidatedSubnetCatalog::try_from_raw` requires a validation context
containing expected network, Registry identity, caller-supplied current time,
future-skew allowance, and supported policy identities. Only the validated type
can resolve an authority-bearing route or be published as a cache.

The validated type exposes typed accessors and immutable slices. Callers cannot
edit a validated Subnet, range, provenance record, assurance level, or digest.
Tests mutate raw fixtures and then validate them.

Validation requires:

- current cache schema;
- canonical mainnet network and Registry canister identity;
- a nonzero Registry version;
- syntactically valid collection, optional certificate, and endpoint data;
- no collection or certificate timestamp beyond the allowed future skew;
- credential-free HTTP(S) endpoints with hosts and no query or fragment;
- assurance-specific endpoint, certificate-time, and root-key evidence;
- canonical, unique Subnet ordering by principal;
- canonical routing ordering by principal-byte range, then target Subnet;
- valid, nonoverlapping ranges whose target Subnets exist;
- the raw Registry `subnet_type` numeric code for every Subnet;
- exact agreement between raw type, `SubnetKind`, and
  `charges_apply_by_default`;
- exact classification-source rules and current classification policy digest;
- exact curated annotations for principals known by the selected policy;
- deterministic defaults for every uncurated Subnet; and
- the current resolver implementation identity.

Loading rejects noncanonical order. Live and fixture collectors canonicalize
before validation and publication. This makes the catalog digest stable and
detects content edited without consistently resealing its evidence. The digest
is unkeyed and is not a local-tamper or authenticity boundary: an editor can
recompute it, and callers must still enforce the recorded assurance.

## Classification And Resolver Policy

The catalog records:

```text
collector_version
classification_schema_version
classification_policy_digest
resolver_schema_version
```

The classification digest commits to raw `SubnetType` conversion, charging
defaults, curated Subnet principals and annotations, source-label rules, and
canonical ordering rules. The resolver version commits to principal-byte
ordering and inclusive range matching. Both use stable lowercase SHA-256 hex.

The collector version is evidence, not an automatic invalidation key. A newer
binary may load an older catalog only when its schema and policy identities are
still supported. A changed classification or resolver policy invalidates the
cache explicitly.

## Catalog Digest And Route Evidence

The catalog digest is SHA-256 over the canonical serialized authority payload,
excluding the digest field itself. It includes Registry identity and version,
assurance evidence, raw Registry type codes, annotations, and routing ranges.

An authority-bearing canister lookup returns:

```rust
pub struct ResolvedCanisterRoute {
    canister: Principal,
    subnet: Principal,
    matched_range: RoutingRange,
    registry_version: u64,
    catalog_digest: [u8; 32],
    provenance: CatalogProvenance,
}
```

The route cannot be constructed from a raw catalog. Subnet and canister
identities use `Principal`; report DTOs convert them to canonical text only at
the JSON/text boundary. General human-facing resolution also carries the same
snapshot evidence rather than only a cloned Subnet row.

## Explicit Freshness Policy And Outcome

One policy API replaces ambiguous read-through behavior:

```rust
pub enum CatalogReadPolicy {
    CacheOnly,
    RefreshMissing { source_endpoint: String },
    RefreshMissingOrInvalid { source_endpoint: String },
    RefreshMissingInvalidOrOlderThan {
        source_endpoint: String,
        max_age_seconds: u64,
    },
    ForceRefresh { source_endpoint: String },
}

pub enum CacheDisposition {
    CacheHit,
    RefreshedMissing,
    RefreshedInvalid,
    RefreshedStale,
    ForcedRefresh,
}

pub struct CatalogLoadOutcome {
    catalog: ValidatedSubnetCatalog,
    path: PathBuf,
    disposition: CacheDisposition,
}
```

The load request includes caller-supplied `now_unix_secs`; no library clock is
hidden in policy decisions. `CacheOnly` never accepts a source or endpoint.
Every other policy names its possible network behavior. Invalid-content
recovery remains distinct from IO, permission, confinement, and active-lock
failures. A failed refresh preserves the prior file and returns the refresh
error.

The CLI may keep separate user-facing commands, but report builders consume the
same policy and expose the disposition in JSON and text provenance. Canic can
require a fresh observation before publishing a plan and later load the exact
plan evidence without re-resolving topology.

## Filesystem Confinement

Host cache operations use a capability-style root boundary rather than joining
unchecked paths and later testing `is_file`:

- canonical cache identities are resolved beneath an already opened root;
- symlinks are rejected for the root's managed descendants, including parent
  components, targets, locks, and temporary files;
- loads require a regular file opened without following a final symlink;
- path traversal and any resolved escape are typed confinement failures;
- Unix managed directories are owner-only and managed files are owner-readable
  and owner-writable only;
- publication keeps exclusive temporary creation, file sync, atomic rename,
  and parent-directory sync; and
- separately requested output paths are not silently treated as authority
  cache paths and retain their own explicit policy.

The implementation should prefer a small capability/open-at dependency over a
check-then-open sequence that remains vulnerable to races. Unsupported
platform guarantees are surfaced rather than claimed.

## Typed Errors

Library errors do not embed `icq` command prose. Every Subnet Catalog host error
provides:

- a stable `SubnetCatalogErrorCode`;
- `SubnetCatalogErrorCategory` covering input, network, authority, freshness,
  validation, confinement, cache IO, lock, and source failures;
- typed retryability;
- structured paths, endpoints, principals, and validation fields; and
- an optional structured remediation kind.

`Display` remains concise and context-rich. The CLI maps remediation kinds to
`icq` examples; Canic can render its own guidance without parsing strings.

## Async And Synchronous APIs

The live Registry collector exposes a caller-owned async entry point in the
foundation slice. The async refresh pipeline follows in `0.29.2`. Those entry
points do not create a runtime or helper thread, so async callers own
cancellation, deadlines, tracing, and scheduling.

Synchronous functions remain explicit adapters over the same async core for
CLI and non-async consumers. Documentation states that a sync call made from an
existing runtime may create a scoped helper thread. No async operation writes
process output.

Custom source traits retain a fixture-friendly boundary. The async seam uses a
boxed future or associated future shape already supported by the repository's
MSRV; it does not introduce a macro framework solely for async traits.

## Feature Boundaries

`0.29` adds genuine family host gates:

- `registry-core`: Registry protobuf, transport, assurance, and validation;
- `subnet-catalog-host`: focused catalog fetch, cache, resolution, and reports;
- `nns-topology-host`: exact-version joined topology plus its focused cache;
- `dashboard-host`: official Dashboard HTTP adapters;
- `sns-host`: SNS live/cache adapters;
- `icrc-host`: ledger, index, archive, and certificate host adapters; and
- `host`: convenience union of every family.

Pure DTO modules are gated with their family when they are not genuinely shared.
`nns-topology-host` must not enable Dashboard, SNS, or ICRC host adapters. The
published archive remains one crate during `0.29`; a dedicated catalog crate is
reconsidered only after feature measurements show that Cargo gating cannot
provide an adequate embedder boundary.

Dependency checks distinguish direct feature edges from transitive packages.
In particular, `subnet-catalog-host` does not claim to remove Reqwest or CBOR
from the complete dependency graph when `ic-agent` itself brings them.

## Implementation Slices

### 0.29.0 — authority and freshness foundation

- add raw/validated catalog separation;
- add explicit `UncertifiedQuery` provenance and policy identities;
- retain raw Registry subnet-type codes and strengthen validation;
- add canonical catalog digest and provenance-bound route results;
- add explicit read policies and cache dispositions;
- remove CLI prose from library errors and expose structured classification;
- expose live catalog fetch on a caller-owned async runtime while retaining the
  synchronous adapter;
- hard-cut the cache schema with no fallback reader; and
- update reports, fixtures, public tests, README, and impact ledger.

### 0.29.1 — confined host storage

- add capability-root cache load, lock, and publication;
- reject symlinks, nonregular files, escapes, and unsafe managed modes;
- preserve atomic rename and directory fsync; and
- apply the shared boundary to every managed `.icq` cache family after the
  Subnet Catalog proves it with focused tests.

### 0.29.2 — async refresh ownership and bounded agreement

- extend the async catalog fetch foundation to cache refresh;
- keep sync adapters;
- add explicit bounded multi-endpoint agreement; and
- report exact endpoints, agreement digest, and call counts.

### 0.29.3 — focused Registry topology features

- add `registry-core` and `nns-topology-host`;
- gate unrelated pure and host families;
- add downstream compile fixtures and dependency-tree assertions; and
- record direct and transitive dependency measurements accurately.

### Later 0.29.x — certified delta mirror, only if bounded

- prototype and measure certified delta bootstrap and incremental storage;
- implement complete certificate and hash-tree verification;
- publish `Certified` only after adversarial fixtures and bounded-resource
  acceptance tests pass; and
- otherwise leave the type reserved and document the Registry interface gap.

## Acceptance Criteria

- Validation rejects inconsistent Registry identity, raw Subnet kind, charging
  policy, annotations, ordering, assurance, policy identity, and digest.
- An unkeyed catalog digest is never described as proof against a local editor
  who can rewrite and reseal raw JSON.
- Every live single-endpoint catalog says `UncertifiedQuery`.
- No API reports `Certified` without application-level witness verification.
- A caller can require fresh evidence and can observe whether refresh occurred.
- A resolved route retains exact Registry version, catalog digest, provenance,
  and matched range.
- Cache-only paths cannot make a network call.
- Failed refreshes preserve the prior complete cache.
- Managed authority paths reject symlinks and root escapes after the confinement
  slice lands.
- Async callers do not incur hidden runtime or thread creation.
- `nns-topology-host` compiles without unrelated host families.
- Each patch includes the downstream impact table and focused feature tests.
