# 0.29 Changelog

Detailed release notes for the `0.29.x` release line.

## 0.29.3 - 2026-08-05

### Authority-bearing route and load policy

- Adds the matched validated `SubnetInfo` to `ResolvedCanisterRoute`. An
  embedder can now consume the routed Subnet principal, `SubnetKind`, complete
  classification, matched range, Registry version, catalog digest, and
  provenance from one result without a second catalog lookup or an
  impossible-error branch.
- Adds `minimum_assurance` to `SubnetCatalogLoadRequest` with
  `with_minimum_assurance`. Existing constructors default to
  `UncertifiedQuery`, preserving prior behavior unless the caller explicitly
  requires stronger evidence.
- Returns typed `InsufficientAssurance` when valid cached evidence is weaker
  than the caller's minimum. A refresh selection that cannot establish the
  minimum fails before source collection or cache replacement. Insufficient
  authority is not silently treated as missing, invalid, or stale.
- Adds `CatalogAuthorityEvidence`, a compact serializable load result carrying
  Registry version, catalog digest, assurance, canonical source endpoints, and
  cache disposition for embedding in durable downstream plans. It identifies
  the validated load outcome but is not itself a route-capable catalog.
- Adds
  `SubnetCatalogLoadRequest::refresh_missing_invalid_or_older_than`, retaining
  the explicit source, caller time, and maximum accepted age in one request.
  Downstream consumers remain responsible for selecting and documenting their
  own authority-age ceiling.

### Release flow

- Keeps the complete CI gate in `bump-version.sh` before any version-file
  mutation. A failed test, changelog check, or cleanliness check therefore
  prevents the bump.
- Removes the duplicate full-CI invocation from `release-push`. The final push
  still requires a clean tree and a current-version tag resolving to `HEAD`,
  but a second flaky test run can no longer strand a local release commit and
  tag after the pre-bump gate already passed.
- Extends release-guard fixtures to prove failed pushes propagate, stale tags
  cannot push, and the post-bump push target cannot regain a duplicate CI gate.

### Compatibility and operations

- This is a pre-1.0 Rust API hard cut for exhaustive
  `ResolvedCanisterRoute` and `SubnetCatalogLoadRequest` construction or
  pattern matching. No compatibility field, constructor, wrapper, or alias is
  retained.
- Cache and report schemas, cache paths, CLI grammar and output, and ordinary
  single-endpoint network behavior are unchanged.
- `MultiEndpointAgreement` is implemented and may satisfy a caller minimum;
  `Certified` remains reserved and unsupported until certified Registry-state
  reconstruction is implemented.

### Downstream impact

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `subnet-catalog-host` | Hard cut: routes gain matched `SubnetInfo`; load requests gain minimum assurance; compact authority evidence and stale-policy constructor added | Unchanged | Defaults unchanged; known-insufficient selected sources fail before calls | Update exhaustive construction/matches, consume route classification directly, and select minimum assurance and maximum age explicitly |
| `host` | Inherits the focused Subnet Catalog API hard cut | Other family schemas and APIs unchanged | Other adapters unchanged | Review only Subnet Catalog integrations |
| CLI | Unchanged | Unchanged | Unchanged | None |
| Release tooling | — | — | Full CI runs once before version mutation; push retains clean-tree and tag-at-`HEAD` guards | Use the normal release target; do not restart it after a post-tag recovery |

## 0.29.2 - 2026-08-05

### Async ownership and source selection

- Moves Subnet Catalog cache refresh and network-capable load policies onto
  caller-runtime async implementations. `refresh_subnet_catalog_async`,
  `refresh_subnet_catalog_with_source_async`, `load_subnet_catalog_async`, and
  `load_subnet_catalog_with_source_async` create no runtime or helper thread;
  callers own cancellation, deadlines, tracing, and scheduling.
- Keeps the existing synchronous refresh/load names as adapters over that one
  async core. A synchronous call made inside an existing Tokio runtime may use
  the repository's scoped runtime thread adapter.
- Hard-cuts `SubnetCatalogSource::fetch_catalog` to return
  `SubnetCatalogSourceFuture`, requires source implementations to be
  `Send + Sync`, and requires custom sources to echo the exact requested
  endpoint in their single-endpoint evidence.
- Replaces endpoint strings in `CatalogReadPolicy` and
  `SubnetCatalogRefreshRequest` with `CatalogSourceSelection`. Callers select
  either one `UncertifiedQuery` endpoint or an explicit
  `MultiEndpointAgreement` list; no endpoint discovery or fallback is hidden
  behind a load.
- Groups raw single-endpoint constructor provenance in
  `UncertifiedCatalogCollection`, including the required positive Registry
  query-call count, instead of extending a positional constructor indefinitely.
- Makes async refresh-lock ownership cancellation-safe. Dropping an in-flight
  refresh removes the lock it acquired and publishes no partial catalog.

### Bounded agreement and durable evidence

- Accepts exactly two or three agreement endpoints and requires distinct
  hostnames. Endpoint strings are validated as clean credential-free HTTP(S)
  URLs and stored in canonical order. Distinct hostnames are a bounded source
  rule, not proof of independent operators.
- Collects one complete exact-version catalog from every selected endpoint.
  Agreement succeeds only when every endpoint returns the same nonzero
  Registry version and the same canonical Registry-derived payload digest.
  Version, payload, endpoint, or source failures are typed; no successful
  endpoint is accepted as a fallback.
- Records `agreement_digest` and the exact summed
  `registry_query_call_count` in catalog provenance and list/info/refresh
  reports. Counts include latest-version, value, per-Subnet, and large-value
  chunk query attempts made by the live Registry adapter.
- Validates loaded agreement endpoint bounds, canonical order, unique
  hostnames, absence of certificate claims, agreement digest, positive call
  count, and the enclosing catalog digest. `Certified` remains reserved and
  unsupported.
- Replaces the Subnet Catalog and list/info/refresh report schemas with version
  2. There is no version-1 reader, Serde default, alias, or migration path.
  Authorized invalid-content read-through can collect a replacement;
  cache-only callers receive the schema failure and must refresh explicitly.

### Compatibility and operations

- CLI grammar is unchanged. Current `icq nns subnet` and topology refresh
  flows construct a single-endpoint selection and therefore keep their prior
  live fan-out.
- Multi-endpoint agreement is an explicit library operation. It increases
  calls only when the caller supplies that selection and remains
  non-certified evidence even after all selected endpoints agree.
- No process output, background refresh, compatibility wrapper, automatic
  cache deletion, or endpoint discovery is introduced.

### Downstream impact

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `subnet-catalog-host` | Hard cut to async source futures and typed source selections; new caller-runtime async load/refresh functions; sync names retained as adapters | Catalog and list/info/refresh report schema 2; path unchanged; no migration | One endpoint remains unchanged when selected; agreement explicitly fans out to 2–3 distinct hosts and requires exact version/payload equality | Update source implementations and request policy fields, enforce acceptable assurance, refresh version-1 cache evidence, and test async cancellation |
| NNS topology through `host` | Embedded Subnet refresh request constructs an explicit single-endpoint selection; nested report gains digest/count evidence | Topology paths unchanged; nested Subnet refresh report schema 2 | Existing one-endpoint topology refresh call pattern is unchanged | Rebuild exhaustive nested report literals/deserializers |
| `host` | Inherits the focused hard cut and async APIs | Other family schemas and paths unchanged | Other adapters unchanged | Review only Subnet Catalog integrations |
| CLI | Grammar unchanged; Subnet list/info verbose and refresh output expose call count and optional agreement digest | Same catalog path; version-1 catalog is invalid current evidence | Continues to use one endpoint | Allow authorized read-through to replace old evidence or run an explicit refresh before cache-only use |

## 0.29.1 - 2026-08-05

### Confined managed storage

- Moves managed cache loads, collection discovery, refresh locks, attempt
  sidecars, and atomic publication behind one capability-rooted filesystem
  boundary. Each operation resolves from the selected cache root rather than
  trusting an already-resolved ambient path.
- Rejects cache-root escapes, symbolic-link roots/parents/final files, and
  nonregular managed files. On Unix, every managed directory must deny group
  and other access, and every managed cache or lock file must use mode `0600`.
  New directories use `0700`; new files use `0600`.
- Preserves same-directory temporary publication, file synchronization, atomic
  rename, and parent-directory synchronization. Refresh failures continue to
  preserve the previous complete snapshot.
- Applies the same boundary to Subnet Catalog, NNS, SNS, ICRC, observed node
  status, generic snapshot, cache-status, and refresh-lock flows. Explicit
  caller-selected output files remain ordinary output paths rather than managed
  cache authority.
- Treats confinement and unsafe-mode failures as typed storage-authority
  failures. They cannot masquerade as recoverably invalid JSON and therefore do
  not authorize a live repair call.
- Replaces the generic cache inventory's ambient `ReadDirectory` error with a
  `CacheOperation(CacheFileError)` hard cut. `CacheFileError` gains explicit
  unsupported-platform, confinement, managed-open, and unsafe-permission
  variants; Subnet Catalog classification exposes `Confinement` separately
  from ordinary cache IO.

### Compatibility and operations

- Cache schemas, cache identities, paths, stale policies, live call counts, and
  CLI grammar are unchanged.
- This is a pre-1.0 operational hard cut. Cache trees created with permissive
  modes by older releases are not migrated, chmodded, deleted, or automatically
  replaced. Remove the old cache root or restrict all managed directories and
  files before use; the next explicitly authorized refresh recreates missing
  storage with owner-only modes.
- Capability confinement is supported on Unix. Other platforms return the typed
  `UnsupportedConfinementPlatform` error instead of falling back to ambient
  path operations.
- `subnet-catalog-host` now directly enables `cap-std` and `cap-fs-ext`; the
  broader `host` feature inherits them through its existing strict-superset
  relationship.

### Downstream impact

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `subnet-catalog-host` | Operation signatures unchanged; exhaustive matches must handle the new confinement error category/variants; direct capability-FS dependencies added | Unchanged | Unchanged; storage-authority failures never trigger repair | Remove or secure older permissive cache trees and retest cache-only/read-through behavior |
| NNS topology through `host` | Compatible operation signatures; shared cache errors can report confinement | Unchanged | Exact-version calls and policies unchanged | Retest managed-cache permissions if embedding the host feature |
| `host` | Operation signatures unchanged; shared cache errors gain confinement variants and `CacheStatusError` replaces `ReadDirectory` with `CacheOperation` | All managed family paths and schemas unchanged | No new calls; unsafe storage fails before refresh | Recreate or secure the selected cache root, then retest refresh and cache status |
| CLI | Grammar and report schemas unchanged | Same user-level root and paths | No new calls | Remove or secure a cache tree created with permissive modes before running cache-backed commands |

## 0.29.0 - 2026-08-05

### Subnet Catalog authority

- Replaces the freely constructible `SubnetCatalog` authority shape with
  serde-facing `RawSubnetCatalog` and private-field
  `ValidatedSubnetCatalog`. Host cache loads and refresh publication validate
  fixed mainnet and Registry identity, canonical timestamps and endpoints,
  canonical Subnet/routing order, exact raw-kind and charging relations,
  current classification/resolver policy identity, curated annotations, and
  the canonical payload digest.
- Records the raw Registry `SubnetType` numeric discriminant on every Subnet
  row. One conversion owns Application, Verified Application, System, Cloud
  Engine, Unspecified, and unknown mappings for the catalog and joined
  topology paths.
- Adds `CatalogAssurance` and labels the existing one-endpoint ordinary
  Registry query path `UncertifiedQuery`. The exact Registry version still
  prevents an internally skewed join, but neither validation nor the unkeyed
  catalog digest promotes that response to certified evidence.
- Records the collector version, classification schema and SHA-256 policy
  digest, resolver schema/backend, all contributing endpoints, and optional
  certificate evidence fields. Unsupported `Certified` or
  `MultiEndpointAgreement` claims fail closed until their collection and
  verification paths exist.

### Routes, freshness, and errors

- `ValidatedSubnetCatalog::resolve_canister_route` returns typed canister and
  Subnet principals with the matched inclusive range, exact Registry version,
  binary catalog digest, and complete provenance. General raw-catalog
  resolution also retains its supplying digest and provenance for diagnostic
  use.
- Replaces ambiguous read-through helpers with `CatalogReadPolicy`:
  cache-only, refresh-missing, refresh-missing-or-invalid,
  refresh-missing-invalid-or-older-than, and force-refresh. Successful loads
  return `CacheDisposition` so embedders can distinguish hits from missing,
  invalid, stale, and forced refreshes.
- Keeps caller-supplied current time and future-skew policy explicit. Cache-only
  requests carry no endpoint and never invoke a source; filesystem and lock
  failures remain non-recoverable by content-repair policies; failed refreshes
  preserve the original cache.
- Removes embedded `icq` command prose from library errors and exposes stable
  error codes, operational categories, retryability, and structured
  remediation. CLI grammar is unchanged.
- Adds a caller-runtime `fetch_subnet_catalog_async` entry point. Existing
  synchronous collection and report builders remain adapters over the same
  async Registry core.

### Reports and cache compatibility

- List, info, and refresh reports now expose assurance, source endpoints,
  canonical catalog digest, collector/classifier/resolver identity, and—where
  a load policy applies—the observed cache disposition. Text output renders
  the same provenance.
- This is a pre-1.0 Rust-API hard cut. `SubnetCatalog`,
  `CachedSubnetCatalog`, and the `load_or_refresh_subnet_catalog*` functions
  are removed rather than retained as aliases or wrappers. Callers construct
  `SubnetCatalogLoadRequest`, select `CatalogReadPolicy`, and consume
  `CatalogLoadOutcome`.
- The version-1 persisted catalog and report shapes are replaced in place; no
  old reader or migration is provided. Ordinary list/info read-through
  replaces missing or invalid catalog content atomically. Cache-only consumers
  receive the parse/validation failure and must select an explicit refresh
  policy.
- Live collection still resolves one Registry version and performs the same
  Subnet-list, routing-table, and per-Subnet record calls. No new CLI command,
  option, network fan-out, or background refresh is introduced.
