# 0.29 Changelog

Detailed release notes for the `0.29.x` release line.

## 0.29.0 - 2026-08-05

### Subnet Catalog authority

- Replaces the freely constructible `SubnetCatalog` authority shape with
  serde-facing `RawSubnetCatalog` and private-field
  `ValidatedSubnetCatalog`. Host cache loads and refresh publication validate
  fixed mainnet and Registry identity, canonical timestamps and endpoints,
  canonical Subnet/routing order, exact raw-kind and charging relations,
  current classification/resolver policy identity, curated annotations, and
  the canonical payload digest.
- Records the raw Registry `SubnetType` numeric discriminant on every Subnet
  row. One conversion owns Application, Verified Application, System, Cloud
  Engine, Unspecified, and unknown mappings for the catalog and joined
  topology paths.
- Adds `CatalogAssurance` and labels the existing one-endpoint ordinary
  Registry query path `UncertifiedQuery`. The exact Registry version still
  prevents an internally skewed join, but neither validation nor the unkeyed
  catalog digest promotes that response to certified evidence.
- Records the collector version, classification schema and SHA-256 policy
  digest, resolver schema/backend, all contributing endpoints, and optional
  certificate evidence fields. Unsupported `Certified` or
  `MultiEndpointAgreement` claims fail closed until their collection and
  verification paths exist.

### Routes, freshness, and errors

- `ValidatedSubnetCatalog::resolve_canister_route` returns typed canister and
  Subnet principals with the matched inclusive range, exact Registry version,
  binary catalog digest, and complete provenance. General raw-catalog
  resolution also retains its supplying digest and provenance for diagnostic
  use.
- Replaces ambiguous read-through helpers with `CatalogReadPolicy`:
  cache-only, refresh-missing, refresh-missing-or-invalid,
  refresh-missing-invalid-or-older-than, and force-refresh. Successful loads
  return `CacheDisposition` so embedders can distinguish hits from missing,
  invalid, stale, and forced refreshes.
- Keeps caller-supplied current time and future-skew policy explicit. Cache-only
  requests carry no endpoint and never invoke a source; filesystem and lock
  failures remain non-recoverable by content-repair policies; failed refreshes
  preserve the original cache.
- Removes embedded `icq` command prose from library errors and exposes stable
  error codes, operational categories, retryability, and structured
  remediation. CLI grammar is unchanged.
- Adds a caller-runtime `fetch_subnet_catalog_async` entry point. Existing
  synchronous collection and report builders remain adapters over the same
  async Registry core.

### Reports and cache compatibility

- List, info, and refresh reports now expose assurance, source endpoints,
  canonical catalog digest, collector/classifier/resolver identity, and—where
  a load policy applies—the observed cache disposition. Text output renders
  the same provenance.
- This is a pre-1.0 Rust-API hard cut. `SubnetCatalog`,
  `CachedSubnetCatalog`, and the `load_or_refresh_subnet_catalog*` functions
  are removed rather than retained as aliases or wrappers. Callers construct
  `SubnetCatalogLoadRequest`, select `CatalogReadPolicy`, and consume
  `CatalogLoadOutcome`.
- The version-1 persisted catalog and report shapes are replaced in place; no
  old reader or migration is provided. Ordinary list/info read-through
  replaces missing or invalid catalog content atomically. Cache-only consumers
  receive the parse/validation failure and must select an explicit refresh
  policy.
- Live collection still resolves one Registry version and performs the same
  Subnet-list, routing-table, and per-Subnet record calls. No new CLI command,
  option, network fan-out, or background refresh is introduced.
