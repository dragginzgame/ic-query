# 0.36 Changelog

## 0.36.0 - 2026-08-09

### Node-provider reward records and history

- Adds `icq nns node-provider reward info <reward-id>` for one exact official
  Dashboard reward record.
- Adds `icq nns node-provider reward list` for one explicit offset page. The
  request defaults to 50 rows, accepts at most 100, and can reuse a returned
  reward-index ceiling through `--max-reward-index`.
- Adds `icq nns node-provider reward history` for one bounded aggregate
  history request. The default covers the preceding 365 days at a one-day
  step; explicit windows accept steps from 60 through 259,200 seconds and at
  most 1,000 requested observations.

```bash
icq nns node-provider reward info 7562 --json
icq nns node-provider reward list --limit 25
icq nns node-provider reward list --offset 25 --max-reward-index 6470 --json
icq nns node-provider reward history --start 1752537600 --end 1784073600 --step 86400
```

### Raw contract and upstream behavior

- Preserves reward and aggregate amounts as raw ICP e8s and uses Unix seconds
  for reward and history timestamps. The Dashboard database's separate raw
  `updated_at` string remains available as `dashboard_updated_at`.
- Preserves the node-provider principal, raw reward-mode name, optional
  proposal and Registry ids, optional cap/floor inputs, optional XDR
  conversion-rate evidence, and mode-specific details as a JSON object.
  Historical records with empty details and XDR evidence remain representable.
- Accepts the Dashboard's historical integer-valued JSON numbers such as
  `10270.0` only when their decimal fraction is exactly zero. Fractional,
  negative, and decimal-encoded values above JSON's exact integer range are
  rejected.
- Makes exactly one request per operation and never scans or combines pages.
  Live adjacent offset pages were observed to overlap even with the returned
  reward-index ceiling pinned. The list therefore preserves upstream row order,
  exposes `pages_may_overlap: true`, and labels its arithmetic continuation as
  `next_offset_hint` rather than a completeness guarantee.

### Authority, validation, and library

- Records schema `1`, `official_ic_dashboard_api`, the exact endpoint and
  collection time, `certified: false`, and
  `point_in_time_guaranteed: false`. No report cache is created.
- Validates page and history bounds before source calls; echoed query and
  provenance identity; exact reward-id identity; canonical provider
  principals; unique ids within one page; account identifiers when present;
  paired positive XDR evidence; and strictly increasing in-window history
  timestamps.
- Exposes pure requests, reports, reward rows, history observations, constants,
  and text renderers from `ic_query::ic`. The `dashboard-host` feature adds the
  focused `IcNodeProviderRewardSource`, live/custom-source builders, and source
  data contracts.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| CLI | New `nns node-provider reward history|info|list` namespace | Use exact info for a record, list for one non-complete upstream page, and history for bounded aggregate e8s observations |
| Pure library | New reward request/report/row/observation contracts and text renderers | Import them from `ic_query::ic` |
| Dashboard host | New focused source trait and live/custom builders | Enable `dashboard-host` for official REST collection |
| Cache/schema | Live-only schema-1 reports; no persisted cache | Do not treat list offsets as a complete-snapshot protocol |
