# 0.44 Changelog

## 0.44.1 - Unreleased

### Rust toolchain and lint coverage

- Updates the development toolchain, CI pin, and canister smoke prerequisites
  to Rust 1.99.0. The declared minimum remains Rust 1.91.0.
- Fixes 36 Clippy findings by comparing empty values directly so failed
  assertions report the unexpected contents.
- Adds no-default library linting to `make clippy` and the CI gate. Tightens
  feature guards around transport helpers and scopes host-only fixtures to
  their consumers so the portable test build passes with warnings denied.
- Refreshes locked dependencies, including Candid and transport, build, and
  Wasm support packages, without changing direct dependency requirements.

### Canic Subnet Catalog feedback

- Records the review of Canic's current 0.44.0 integration and earlier
  acquisition feedback. Concurrent collection, typed progress, bounded
  retries, and cancellation cleanup address the earlier concerns.
- Identifies cold or expired-cache refresh in a new process as the remaining
  history-replay cost. Documents measurement and integrity requirements for a
  future persisted checkpoint contract; checkpoints remain memory-only.

See [performance and feedback notes](../design/subnet-catalog-acquisition-performance.md)
for the evidence and follow-up requirements. This patch changes no production
CLI surface, report or cache schema, or acquisition policy.

## 0.44.0 - Unreleased

### Governance canister smoke tooling

- Updates the smoke harness, CI archive checksum, and project schema reference
  to ICP CLI 1.6.0. The local NNS runtime remains pinned to 16.0.0. The
  harness commands and production `icq` behavior are unchanged.
- Refreshes the lockfile's transitive dependencies without changing direct
  library requirements or the Rust 1.91.0 minimum.

### Subnet Catalog cold-start measurement

- A fresh two-endpoint acquisition at Registry version 64346 took 88.199 s
  and 312 explicit queries in one development-build run. Immediate cache reuse
  took 18.382 ms; a forced refresh with the same in-memory source took
  15.278 s and 158 queries. These are upstream example measurements, not
  Canic generation timings or latency guarantees. Separate CLI processes do
  not share the in-memory history checkpoint.
