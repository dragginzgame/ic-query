# 0.44 Changelog

## 0.44.2 - Unreleased

### Release build artifacts

- Retains Cargo build artifacts throughout release/version-bump workflows by
  removing the automatic post-gate `cargo clean` and its retry logic. Subsequent
  builds can reuse `target/`; `make clean` remains an explicit maintainer action.

### Refresh export protection

- Fixes Canic's reported dry-run defect: selecting the managed Subnet Catalog
  as an export path could overwrite a valid catalog while returning
  `wrote_catalog=false`.
- Rejects export paths that alias the operation's managed cache or refresh
  lock in Subnet Catalog and shared NNS cache refreshes, for both dry runs and
  normal publication. Rejections return the typed
  `CacheFileError::OutputAliasesManagedPath` error.
- Checks resolved paths, relative names, parent traversal, symlinks, missing
  targets, and Unix hard links. Catalog requests reject known aliases before
  collection; the shared writer rechecks before truncation to catch aliases
  introduced during collection. Distinct dry-run exports preserve existing
  cache bytes; failures after lock acquisition release the operation's owned
  refresh lock.

### Canic feedback recheck

- Confirms Canic's selected registry 0.44.1 still contains the defect. Its
  current loader supplies no export path and does not expose the triggering
  combination. Its caller-owned live source can adopt the disk configuration
  below; no Canic dependency or source files are changed here.

### Cross-process Registry history reuse

- Standard live Subnet Catalog load/refresh APIs retain validated history under
  the request's private cache root. Caller-owned `LiveSubnetCatalogSource`
  instances opt in with `with_history_cache(root)`; their clones keep the same
  configuration. Cache hits and cache-only reads make no history IO or network
  calls. Dry-run convenience refreshes use memory-only history.
- Adds a confined schema-1 transcript with eight endpoint/prefix identities,
  4,096 pages per transcript, and a 64 MiB file ceiling. Replays normalized
  mutation pages to restore tombstones and cumulative resource accounting;
  older pins replay from zero. The checksum protects accidental corruption
  under an explicit trusted-local-owner contract and provides no certification.
- Preserves fresh pinned record reads, endpoint agreement, assurance floors,
  and atomic catalog publication. Publishes the first complete page, every
  eight collected pages, and completion, reducing cold disk IO while bounding
  ordinary interrupted-run rework to seven pages. Durable prefixes survive
  cancellation; concurrent writers merge identities and preserve newer prefixes.
  Typed progress exposes restoration, rejection, publication, and skipped retention.
- Adds public `SubnetCatalogProgressPhase::HistoryCache` and
  `RegistryFetchError::HistoryCache` variants. Exhaustive downstream matches
  must handle them; Canic's progress projection needs an adoption change along
  with its explicit source configuration.
- Lists history files and writer locks in local cache inventory. Invalid
  content is repaired only during an already-authorized live acquisition;
  filesystem authority and IO failures remain errors. Export alias protection
  also covers the operation's history file and lock, including a caller-owned
  source configured with a different root.
- Updates the timing example to force live agreement using new source instances
  and to support measuring consecutive processes against one cache directory.
- In one development-build mainnet trial, cold agreement took 92.236 s and
  318 queries; another process reused history in 20.979 s and 164 queries,
  avoiding all 154 history queries while returning the same Registry version
  and agreed content. These timings are observations, not latency guarantees.

Validation passed: 1,151 workspace tests, 212 library tests with Canic's minimal
feature selection, warning-denied pure/workspace/minimal-feature Clippy, the
Rust 1.91.0 MSRV check, and documentation, process-boundary, schema, formatting,
feature-boundary, and CI-script guards. Fixtures cover separate processes,
tombstones, identity isolation, cumulative limits, corruption, cancellation,
and writer-lock policy.
The public documentation backlog falls by one warning. Canic was inspected
read-only; its tests, live transport-fault injection, and the full release gate
were not run. See [performance and feedback notes](../design/subnet-catalog-acquisition-performance.md)
for evidence. Existing report and catalog schemas remain unchanged; the new
history contract starts at schema 1. This patch adds no production CLI surface.

## 0.44.1 - Unreleased

### Rust toolchain and lint coverage

- Updates the development toolchain, CI pin, and canister smoke prerequisites
  to Rust 1.99.0. The declared minimum remains Rust 1.91.0.
- Fixes 36 Clippy findings by comparing empty values directly so failed
  assertions report the unexpected contents.
- Adds no-default library linting to `make clippy` and the CI gate. Tightens
  feature guards around transport helpers and scopes host-only fixtures to
  their consumers so the portable test build passes with warnings denied.
- Refreshes locked dependencies, including Candid and transport, build, and
  Wasm support packages, without changing direct dependency requirements.

### Canic Subnet Catalog feedback

- Records the review of Canic's current 0.44.0 integration and earlier
  acquisition feedback. Concurrent collection, typed progress, bounded
  retries, and cancellation cleanup address the earlier concerns.
- Identifies cold or expired-cache refresh in a new process as the remaining
  history-replay cost. Documents measurement and integrity requirements for a
  future persisted checkpoint contract; checkpoints remain memory-only.

See [performance and feedback notes](../design/subnet-catalog-acquisition-performance.md)
for the evidence and follow-up requirements. This patch changes no production
CLI surface, report or cache schema, or acquisition policy.

## 0.44.0 - Unreleased

### Governance canister smoke tooling

- Updates the smoke harness, CI archive checksum, and project schema reference
  to ICP CLI 1.6.0. The local NNS runtime remains pinned to 16.0.0. The
  harness commands and production `icq` behavior are unchanged.
- Refreshes the lockfile's transitive dependencies without changing direct
  library requirements or the Rust 1.91.0 minimum.

### Subnet Catalog cold-start measurement

- A fresh two-endpoint acquisition at Registry version 64346 took 88.199 s
  and 312 explicit queries in one development-build run. Immediate cache reuse
  took 18.382 ms; a forced refresh with the same in-memory source took
  15.278 s and 158 queries. These are upstream example measurements, not
  Canic generation timings or latency guarantees. Separate CLI processes do
  not share the in-memory history checkpoint.
