# 0.35 Changelog

## 0.35.0 - 2026-08-08

### CloudEngine Type4 node inventory and detail

- Adds `icq cloud-engine node list` for the complete official Dashboard node
  resource selected with `include_node_reward_type=Type4` and explicit
  `DOWN`, `UP`, `DISABLED`, and `DEGRADED` status filters. An optional
  `--node-provider-id` applies one exact provider filter to that request.
- Adds `icq cloud-engine node info <node-id>` for one exact Dashboard node
  resource and rejects a valid non-Type4 node instead of presenting it as a
  CloudEngine node.
- Preserves raw node status, node/reward type, provider and operator
  principals, ordinary and CloudEngine Subnet assignments, alert, GuestOS,
  TEE, address, IPv4 connectivity, hardware generation, data-center, owner,
  and region fields. Null `cloud_engine_subnet_id` values remain explicit
  unassigned observations.
- Reports raw operational-status counts, distinct provider and assigned
  CloudEngine Subnet counts, and the unassigned Type4 node count without
  rewriting the separate provider aggregate resource.

```bash
icq cloud-engine node list
icq cloud-engine node list --node-provider-id bvcsg-3od6r-jnydw-eysln-aql7w-td5zn-ay5m6-sibd2-jzojt-anwag-mqe
icq cloud-engine node info 53amq-7hjxu-6lxaj-o2sp6-kmngy-qa22h-b7bo6-oeyyn-fkqnv-7tauf-7qe --json
```

### Authority and bounds

- Uses the official Dashboard v3 node resources as off-chain authority and
  records `official_ic_dashboard_api`, the exact endpoint and collection
  time, `certified: false`, and `point_in_time_guaranteed: false`.
- Makes exactly one REST request per operation, rejects response bodies above
  the shared 8 MiB ceiling, accepts at most 10,000 list rows, and creates no
  cache. List explicitly requests every currently documented status because
  the upstream resource otherwise applies its own default scope.
- Validates canonical node, operator, provider, and optional Subnet
  principals; unique node ids; consistent provider names; bounded strings;
  the echoed filter scope; requested-provider membership; and exact node-id
  identity before report construction.
- Does not claim Registry state, native CloudEngine control-plane state,
  reachability, certified liveness, or consistency with the separately
  collected provider aggregates.

### Library and maintenance

- Exposes pure schema-1 node request/report DTOs, the shared raw Dashboard
  node row, Type4/status/bound constants, and text renderers without host
  dependencies.
- Extends `dashboard-host` with `CloudEngineNodeSource`, list/info source-data
  contracts, live/custom-source builders, and the existing `LiveIcSource`.
  The default node-status cache continues to exclude CloudEngine nodes and is
  not reused by this explicit live Type4 resource.
- Generalizes internal raw-node canonicalization and status aggregation so
  both Dashboard scopes share validation without sharing cache identity.

### Breaking change

The public constant
`DEFAULT_CLOUD_ENGINE_PROVIDER_SOURCE_ENDPOINT` is removed and replaced by
`DEFAULT_CLOUD_ENGINE_DASHBOARD_SOURCE_ENDPOINT`. Downstream code should import
the replacement from `ic_query::cloud_engine`; no compatibility alias is
provided before 1.0.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| CLI | New `cloud-engine node info|list` namespace | Use it for explicit Type4 node health and provider membership; keep NNS `status` views for the cached default scope |
| Pure library | New node requests, reports, shared row alias, constants, and renderers | Import them from `ic_query::cloud_engine` |
| Focused host | Node source trait and builders under `dashboard-host` | Enable `dashboard-host` when official Dashboard collection is needed |
| Public constant | Provider-named Dashboard endpoint constant removed | Rename imports to `DEFAULT_CLOUD_ENGINE_DASHBOARD_SOURCE_ENDPOINT` |
| Cache/schema | Live-only schema-1 reports; no persisted cache | None |
