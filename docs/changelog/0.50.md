## 0.50.0 - 2026-10-08

- Moves smoke protocol IO to the existing development-only Rust helper using
  `ic-agent`: certified module hashes, public Candid/build metadata, and typed
  Candid `report` update calls with completion polling. ICP retains project
  builds, bundling, deployment and managed-network lifecycle.
- Removes ICP report/status/metadata response envelopes and the JSON-to-hex-to-
  Candid decoding path, together with the unused workspace and development
  `ic-host-tools` dependency. No replacement response wrapper or fallback reader
  is kept. The probe's JSON report text is returned intact, preserving raw numbers.
- Hard-cuts schema-1 receipts: `reports.<kind>.reply_file` identifies an adjacent
  binary Candid file, retained before Candid/report admission; `report` contains
  the validated JSON payload. One `canister_id` identifies the selected principal;
  `module_hash_before` and `module_hash_after` hold unprefixed SHA-256 text.
  Deletes duplicated status objects and their tautological identity comparison;
  certified reads bind both observations to the requested principal. Update
  external receipt readers and select a fresh directory for each run; existing
  evidence must remain available under its original contract. No migration or
  automatic deletion is performed, and schemas remain 1.
  CI artifact uploads retain the adjacent binary replies as well as receipts.
- Keeps bounded agent response bodies, bounded Candid reply admission, per-call
  deadlines, explicit endpoints and failure/cleanup checkpoints. Local root-key
  fetching is allowed only for loopback HTTP endpoints; mainnet HTTPS calls use
  the built-in IC root key. Report calls remain updates, preserving replicated
  inter-canister provenance. HTTP redirects are disabled to retain the selected
  endpoint's trust policy.
- Adds the development helper's `metadata`, `module-hash` and `report` operations:

```bash
cargo run -p ic-query-cli --example governance_artifact --locked --offline -- \
  report mainnet-smoke https://icp-api.io/ "$PROBE_CANISTER" economics "$REPLY_FILE"
```

- Adds the standing AGENTS.md preference for `ic-agent` wherever it owns the
  needed IC protocol capability. Package versions and release effects remain
  maintainer-owned.
- Selects published `ic-host-artifacts` and `ic-host-fs` 0.7.1 at reviewed source
  `410fee7c309e781edf6a361f0e480d71b7c11e5a`. Those crates' implementation files
  are unchanged from 0.6.0, with the existing disabled-default profiles retained.
  No process dependency or second execution bridge is introduced. Host's new
  communication engine is tracked in [Host #5](https://github.com/dragginzgame/ic-host-tooling/issues/5);
  Query requires its current five-second TERM grace and five-second reap bound,
  which Host's synchronous KILL/reap owner cannot supply. Receipt integration
  and native acceptance remain necessary after that owning-library gap is fixed.
  The selected 0.7.1 graph passes 55 cache-file tests, six Rust helper tests,
  15 Python receipt tests and strict helper Clippy on Linux. All 38 Python
  receipt/process tests passed earlier at 0.7.0, whose Rust implementations are
  unchanged. A disposable consumer compiles with one registry identity each
  for artifacts and fs;
  consumers selecting Host 0.6 need a coordinated 0.7 update, tracked in
  [Query #24](https://github.com/dragginzgame/ic-query/issues/24).
  Host 0.7.1 passes Linux and MSRV owner CI; both macOS jobs are queued.
  Current Query native/live smoke qualification remains separate.
- Retains Shared Tooling 0.1.23 after reviewing 0.1.26 and 0.1.27: the new runner fixture
  creates real commits, tags and pushes in scratch repositories, conflicting
  with Query's simulation-only release-fixture boundary. An admissible shared
  fixture selection is requested in [Shared #70](https://github.com/dragginzgame/shared-tooling/issues/70).
  No vendored file is patched and the engineering baseline pin is unchanged.
