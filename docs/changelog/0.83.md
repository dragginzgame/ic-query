# 0.83 release notes

## 0.83.0 - 2026-11-01

### ⚠️ Breaking

Registry inventory source records, NNS node/provider/operator/data-center list
and detail reports, and `NnsInventoryRefreshReport` carry their six acquisition
fields through `provenance: NnsRegistryInventoryProvenance`. Read, for example,
`report.provenance.registry_version`, and supply the record in custom source and
report literals. Registry JSON stays flat, including strict list-cache admission.
Existing schema-1 inventory caches remain readable without a reset or migration.

`SnsCanisterReport.inventory: MainnetSnsCanisterInventory` owns the Root methods,
call policy, point-in-time flag, rows and gaps. This payload is available in
portable builds, while canonicalization remains at the host source boundary.
Access Rust rows through `report.inventory.canisters`. Summary counts remain in
the report envelope; JSON fields and human text stay unchanged.

`IcrcIndexReport.index` and `SnsTokenReport.ledger_index` retain `IcrcIndexData`
through report construction. JSON consumers read one externally tagged outcome:
`{"index":{"found":"<principal>"}}` or
`{"index":{"unavailable":"<reason>"}}`; SNS uses the `ledger_index` field.
Rust sources continue returning `Found` or `Unavailable`; Rust report consumers
match that outcome directly. Discovery absence is distinct from outer transport
failure. Text retains its existing principal and diagnostic labels.

`IcrcTipCertificateReport.certificate` is either `null` or one
`IcrcTipCertificateEvidence` record containing `certificate_hex`,
`certificate_bytes`, `hash_tree_hex` and `hash_tree_bytes`. Presence follows the
optional record rather than a separate flag. JSON consumers read these fields
under `certificate`; Rust consumers match the option. Raw certificate/witness
bytes, byte counts, authentication policy and text output are preserved.

These are pre-1.0 hard cuts requiring 0.83.0. Report schemas remain 1. Update Rust
callers and JSON scripts together; there are no aliases, fallback readers or
migrations. The changed index and tip reports are live-only, so no managed-cache
reset is required. Retain previously exported reports as historical evidence;
consumers processing new output must select the current shape.

### ⬆️ Dependencies

- Select Build and Host Foundation 0.73.5 and Host Tools/Testkit 0.76.1 across
  the root dependency catalog and lockfile. The update preserves existing APIs,
  Rust 1.91, endpoint policy, raw report fields, schema-1 caches and Wire bytes.
  Platform 0.16.0, Types 0.15.1 and Wire/Derive 0.13.3 remain aligned.

### 🧹 Cleanup

- Keep canonical SNS catalog order for the ID view; lifecycle filtering preserves
  that order. Name sorting and independent live/cache admission stay intact.
- Construct proposal action labels only after the title fails to match. Generic
  action labels retain their existing values and escaping.
- Share public SNS context fixtures and compact-identity/optional-boolean display
  policy. Preserve caller-selected widths, terminal escaping, public formatting
  entrypoints, text sections and raw JSON fields.
- Resolve Dashboard provider-reward history bounds through the existing CLI
  helper, preserving explicit timestamps and saturating default-window arithmetic.
- Routine release qualification keeps Query's cache preparation, actual Make
  routing, adapter metadata, source/receipt custody, rejection and recovery
  checks. The generic runner matrix remains upstream for opt-in qualification
  when its contract changes. Retire its unused vendored entrypoint through the
  canonical exporter at the existing reviewed revision; production runner helpers
  and the complete product/native release gates remain selected.
  ([#110](https://github.com/dragginzgame/ic-query/issues/110))

CLI options, human text, external IC protocol bytes and the supported Rust floor
are unchanged. All current report and cache schema identifiers remain 1.
