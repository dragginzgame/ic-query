# 0.52 release notes

## 0.52.3 - 2026-10-09

- Adopts reviewed Shared Tooling 0.2.6 at
  `ce13a5314916891fd239d9b199b4a91b04775054` through the canonical exporter,
  selecting 75 files and retaining the separately pinned engineering baseline.
  The selected Rust tool fixture now declares its installer and checksum helper
  as required companions, preventing incomplete exports before consumer writes.
  Snapshot guidance distinguishes upstream integration suites from consumer
  adoption tests and local metadata adapters.
  [Shared #73](https://github.com/dragginzgame/shared-tooling/issues/73).
- Carries the shared literal hook-path guidance from 0.2.5. Query does not
  select the shared hook installer or pre-commit hook; this refresh neither
  adds them nor changes the checkout's hook configuration. Newer uncommitted
  upstream changes remain outside the reviewed snapshot.
  [Shared #89](https://github.com/dragginzgame/shared-tooling/issues/89).
- Replaces duplicated release and formatter recipes with immutable
  `make/release.mk` and `make/rust-format.mk`. Query retains its execution-mode
  guard and local cache preparation, adapters, publication and validation.
  Target-specific bindings preserve local helper routing under inherited and
  command-line snapshot selections, including nested consumer fixtures.
  Formatter prerequisite admission and execution select one `FORMAT_CARGO`
  executable, preserving offline and no-rustup-install policy. Check-only
  formatting retains manifests, lockfiles and unrelated edits; no hooks are
  installed or activated. Shared's generic fixture isolation and outer Make
  admission issues remain upstream-owned.
  [#35](https://github.com/dragginzgame/ic-query/issues/35).

```bash
make fmt-check FORMAT_CARGO=cargo
```

- Selects the maintainer's published Host artifacts/filesystem/process 0.9.4
  lockfile within the existing compatible requirements. Library sources are
  unchanged from 0.9.3; the release adopts Shared's Make includes, with Query's
  runtime policies retained.
- Selects the unique deployed smoke probe directly from the discovery iterator,
  removing the temporary match list and stopping at the first duplicate.
  Missing/duplicate probes and absent, non-text or invalid principals remain
  refusals; unrelated deployed canisters remain valid.
- Resolves node, Subnet and provider status targets in one identifier pass,
  retaining only borrowed prefix matches until a report or error needs owned
  strings. Removes the complete identifier buffer and unique-match clone;
  exact-match priority, whitespace handling and ordered ambiguity evidence
  remain unchanged.
- Delegates the package/publication clean-worktree guard to the already selected
  shared source checker. Failures identify staged, unstaged and untracked paths,
  including safely quoted filenames, instead of a generic dirty-checkout error.
  Unavailable Git observations still refuse before Cargo or registry work;
  source, index and caller-owned evidence remain intact.

## 0.52.2 - 2026-10-09

- Makes `main` push and PR events own automatic source qualification. An atomic
  branch/tag release now schedules nine native jobs once, removing the second
  three-host complete-CI matrix from tag events. Check names, host matrices,
  MSRV, live canister smoke, failure artifacts and per-source concurrency remain
  intact. Annotated tag/version/commit admission remains with the existing
  release and publication guards.
  [#34](https://github.com/dragginzgame/ic-query/issues/34).
- Adds explicit workflow dispatch for selected branches and tags, running all
  nine jobs at that ref without a checkout override. Tag-only and non-main
  releases require that exact-source qualification; queued or absent runs do
  not qualify them. The workflow must already exist on the default branch, and
  the selected ref must carry the dispatch-enabled workflow.

```bash
gh workflow run ci.yml --repo dragginzgame/ic-query --ref v0.52.2
```

- Adopts committed Shared Tooling 0.2.3 at
  `ac4549c5ebde497f7db0da5d05d32835112e51de` through the canonical exporter,
  retaining 73 selected files and the separately pinned engineering baseline.
  The optional installer suite now declares all five wrappers as required
  companions; Query does not select that suite or add installers. Updated
  task guidance distinguishes persistent queues and duplicate validation from
  source failures without activating scheduled execution.
- Streams source contents into the probe fingerprint and uses Host's stream
  hasher for the Cargo lock digest. Removes whole-file allocations from both
  hashing paths while preserving the sorted relative-path/NUL/content/NUL
  encoding, source roster and schema-1 build metadata.

## 0.52.1 - 2026-10-09

- Adopts reviewed Shared Tooling 0.2.2 at
  `ee48bb37c98c771e77b92fd891f0757d8c1c8b99` through the canonical exporter,
  retaining the same 73 selected files and separately pinned engineering
  baseline. Both IC installer loops consume the final validated record without
  requiring a trailing newline, so setup cannot omit a tool and offline checks
  cannot skip its version/hash admission. Original pin bytes and retained
  bundles remain unchanged. [Shared #87](https://github.com/dragginzgame/shared-tooling/issues/87).
- Selects published Host artifacts/filesystem/process 0.9.2 within the existing
  compatible requirements. Host now uses one durable publication options
  representation and closes captured pipes at EOF. Query retains its named
  publication, private create-new replies, process-group ownership, deadlines
  and five-second TERM/reaping policy; no consumer compatibility layer is added.
  The 0.9.2 library sources are unchanged from 0.9.1; its release adopts the
  same Shared Tooling fixes and preserves qualification of each pushed commit.
- Carries Shared's updated CI installer guidance. The separate CI binary
  installer changed in Shared 0.2.2 is outside Query's selected executable
  helpers; this refresh does not introduce another installation entry point.
- Moves admitted report values into smoke receipts instead of cloning them,
  and streams pretty JSON through a bounded buffer into Host's durable writer
  rather than allocating a complete encoded receipt at every checkpoint.
  Flush completes before atomic publication; owner-only permissions, raw
  arbitrary-precision numbers, the final newline and failure preservation
  remain intact.

## 0.52.0 - 2026-10-09

- Hard-cuts the common IC tool bundle to Quill, ICP CLI, didc, ic-wasm and
  wasm-opt through reviewed Shared Tooling 0.2.0 at
  `8140e3dd1b44409d682c721889ab702f438c6a17`. PocketIC provisioning, pins and
  installer branches are removed together. The 73-file snapshot selection and
  separately pinned engineering baseline remain intact; retired PocketIC
  checkers were never selected in Query.
  [#33](https://github.com/dragginzgame/ic-query/issues/33),
  [Shared #76](https://github.com/dragginzgame/shared-tooling/issues/76).
- Existing six-tool bundles fail the new offline check. Run explicit
  `make install-ic-tools` to activate the five-tool bundle, then
  `make ic-tools-check`. Prior bundles, pins, receipts and failed candidates
  remain caller-owned evidence without migration or automatic deletion.
  Query has no PocketIC runtime callers and does not add a Testkit dependency.
  The ICP-managed Governance smoke runner retains its current operations,
  endpoints, process ownership and cleanup timing.
- Carries the dependency-pinning validation fix from Shared 0.1.38: exception
  catalogs must contain exactly one fully validated array. Schema admission,
  evidence checks and suppression consume the same document. Malformed,
  duplicate or multiple documents fail without changing consumer inputs;
  valid catalogs retain their behavior.
  [Shared #86](https://github.com/dragginzgame/shared-tooling/issues/86).
- Refreshes the shared setup and verification guidance for prepared tools used
  by isolated formatting hooks. Query's existing hook selection is unchanged.
- Completes the maintainer's Host artifacts/filesystem/process 0.9 selection
  with published 0.9.0 and a coherent locked graph. Its library sources are
  unchanged from 0.8.10; the minor release adopts the same Shared 0.2.0 setup
  hard cut. Optional features and cache contracts remain intact.
- Loads the built probe Wasm once through the shared bounded reader and
  structural inspection before appending metadata and publishing those same
  bytes. Removes the second file read, duplicate hashing and between-read
  comparison. Module verification and `inspect-wasm` still hash the admitted
  bytes; the 64 MiB ceiling and structural bounds remain unchanged.
