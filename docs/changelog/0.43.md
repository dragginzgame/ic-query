# 0.43 Changelog

## 0.43.1 - Unreleased

### Canister smoke tooling

- Updates the smoke harness, CI archive checksum, and project schema reference
  to ICP CLI 1.6.0. The local NNS runtime stays pinned to 16.0.0. ICP CLI
  1.6.0 changes macOS binary signing and internal project code organization;
  it introduces no command or manifest changes for this harness.

### Subnet Catalog acquisition

- Collects at most two endpoints concurrently while retaining independent pins,
  canonical validation order, and exact version/content agreement.
- Adds `LiveSubnetCatalogSource` for endpoint-local, memory-only history prefix
  reuse across retries and refreshes. Validated pages survive cancellation;
  incomplete catalog data never replaces the published cache. New processes
  still discover routing keys from version zero.
- Exposes typed endpoint, pin, history-page, record-read, and retry progress via
  `with_progress`, without library output or background tasks.
- Retries connection/timeouts and HTTP 502/504 at most twice, retaining exact
  request inputs and final typed failure provenance. Avoids layering retries
  over ic-agent's existing HTTP 429/503 retry policy.
- Adds recovery/concurrency tests and a live acquisition/cache/refresh timing
  example. No production CLI surface or persisted schema changes.

```bash
cargo run -p ic-query-cli \
  --example subnet_catalog_timing -- /tmp/icq-catalog-timing
```

See [performance and adoption notes](../design/subnet-catalog-acquisition-performance.md)
for measurements, limitations, and Canic integration.

### Measured performance and adoption

- At Registry version 64108, a single development-build cold acquisition from
  `https://ic0.app` and `https://icp-api.io` improved from 158.961 s to
  91.008 s, approximately 43%, with 316 explicit queries in both runs.
- Immediate cache reuse measured 19.294 ms before and 18.701 ms after, with
  zero queries and identical authority to each preceding acquisition.
- A forced refresh using the retained source took 18.181 s and 162 queries,
  avoiding 154 history-page queries while reading every catalog record again.
  All live measurements retained the same canonical agreement digest.
- Downstream callers gain history reuse by retaining one
  `LiveSubnetCatalogSource` across attempts and passing it to
  `load_subnet_catalog_detailed_with_source_async`. Use `with_progress` for
  structured events and retain caller-owned deadlines and heartbeats.
- History retention is memory-only: a new process still scans from zero.
  Measurements are individual observations, not latency guarantees.
- Validation passed 117 focused correctness/recovery and public API tests,
  formatting, the portable-library check, and Clippy with warnings denied.
  The full workspace suite and live fault injection were not run.

## 0.43.0 - Unreleased

### Governance canister execution evidence

- Adds the deployable `governance_probe` Wasm example to the existing
  `ic-query` package under its `canister` feature. It exercises economics,
  metrics, latest reward event, and maturity modulation through the existing
  `CanisterNnsSource`, with one bounded replicated Governance call per report.
- Adds `make canister-build`, `make canister-smoke`, and
  `make canister-bundle`, using ICP CLI 1.5.0 and an isolated project under
  `tests/canister/`. Local execution uses network launcher 16.0.0, a loopback
  gateway, and installed NNS canisters. Tool settings, identities, downloads,
  and runtime state remain inside the checkout.
- Embeds public Candid and build metadata in the probe. Verification checks
  the deployed module hash and Candid interface before collecting reports,
  validates report identity and replicated collector provenance, and checks
  the module hash again after collection.
- Retains schema-1 JSON receipts for successful runs and handled failures,
  including timestamps, tool versions, build evidence, raw Candid replies,
  and decoded reports. Local receipts explicitly identify local NNS evidence;
  sequential collection retains a false point-in-time guarantee.
- Publishes receipts incrementally using atomic file replacement, recording
  the active phase and update time before operations and after replies.
  Previously validated reports and raw replies that fail validation remain
  available. A hard process termination leaves the last complete snapshot
  marked `running`, which is incomplete evidence rather than a success.
- Handles SIGINT and SIGTERM, terminates the interrupted command's process
  group, and attempts network cleanup even when local startup has not yet
  returned. Command timeouts also stop their child processes. Repeated
  termination signals do not interrupt the first signal's cleanup. Receipts
  retain the failed phase, interruption signal, and any cleanup error; only
  completed verification and successful cleanup produce `status: passed`.
  Pre-existing running harness networks are rejected without stopping them.
- Adds environment-specific bundles containing the probe Wasm and a manifest
  with a prebuilt SHA-256 reference. The ordinary `ic` environment has no
  canisters; mainnet bundle use selects `mainnet-smoke` explicitly.
- Adds `verify-mainnet --canister` to the harness for checking an existing
  mainnet probe at the explicit mainnet endpoint. It performs no mainnet
  funding, creation, installation, upgrade, or deletion. Current local
  receipts do not replace the missing historical 0.38 mainnet smoke receipt.

```bash
make canister-build
make canister-smoke
make canister-bundle

# After deploying the reviewed probe separately, supply its mainnet principal.
python3 scripts/canister/smoke.py verify-mainnet --canister "$PROBE_CANISTER_ID"
```

Usage, prerequisites, evidence limits, and artifact locations are documented
in the [Governance canister smoke guide](../canister-smoke.md).

### Toolchain and CI

- Fetches the fresh RustSec database through a shallow, single-branch Git
  clone with progress output. Transfers below 1 KiB/s for 30 seconds fail;
  interactive Git prompts are disabled. Auditing uses that isolated snapshot
  without a second fetch, retaining existing warning and advisory policy.
  Failed downloads stop the check, and temporary databases are removed on exit.

- Aligns development and CI on Rust 1.98.1, preserves the Rust 1.91.0 minimum,
  and refreshes the locked dependency graph. Adapts decimal parsing to the
  newer Clippy check and documents the canister adapter's single-threaded
  future behavior through a scoped lint expectation.
- Adds a separate local-canister CI job with a checksum-pinned ICP CLI 1.5.0
  binary, Wasm Clippy, receipt validation tests, local NNS execution, and
  bundle creation. CI retains receipts, the probe Wasm, and the bundle for
  30 days, including receipts available from failed runs. Identity and runtime
  state are excluded from uploaded artifacts.
- Extends the feature-boundary gate to compile-check the deployable example
  and the CI script checks to test malformed replies, provenance mismatches,
  module mismatches, module changes during collection, atomic receipt
  publication, real process signals, child-process timeout cleanup, and
  retention of partial evidence after a hard kill.
- Keeps the two-crate workspace, existing Cargo features, production `icq`
  surface, and report/cache contracts. Every new versioned receipt remains
  schema 1.

### Detailed failure allocation

- Changes detailed load results to `Box<SubnetCatalogLoadFailure>` and detailed
  source results to `Box<SubnetCatalogSourceFailure>`. The internal Registry
  failure path is boxed too. Complete typed provenance and original causes
  remain intact, while results carry a pointer instead of a large inline error.
- Source failure constructors now allocate and return a box; they are no longer
  `const`. Evidence builders retain that allocation and `into_source` consumes
  it. Downstream explicit return types and direct failure literals must adopt
  the boxed contract; ordinary field access and simple host-error APIs retain
  their behavior. There are no schema, cache-format, or CLI changes.
- Removes the replaced large-error lint suppressions and makes synchronous
  Registry fixtures return ready futures.
