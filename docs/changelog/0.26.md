# 0.26 Changelog

Detailed release notes for the `0.26.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.26.6 - 2026-08-03

### Changed

- Replaces the free-form lifecycle field in NNS Governance, SNS neuron/proposal,
  and ICRC account-transaction refresh-attempt reports with the shared
  `CacheRefreshAttemptStatus::{Running, Complete, Failed}` Rust enum.
- Makes NNS, SNS, and ICRC attempt writers accept the enum directly, removing
  repeated lifecycle string construction and preventing unsupported internal
  states from being published.
- Centralizes raw sidecar lifecycle parsing in the shared validator. The
  persisted string remains an explicitly untrusted read boundary so an unknown
  value continues to produce the existing invalid-attempt diagnostic instead
  of being mistaken for a sidecar migration or generic JSON-shape failure.

### Compatibility

- Public refresh-attempt `status` fields are a pre-1.0 Rust source-level hard
  cut with no string wrapper or alias. The enum preserves the exact `running`,
  `complete`, and `failed` report JSON, sidecar JSON, and CLI text labels.
  Sidecar schema 1, cache paths, refresh behavior, and network behavior are
  unchanged; no migration or cache clearing is required.

## 0.26.5 - 2026-08-03

### Changed

- Replaces the separate free-form `cache_status` strings in NNS neuron, NNS
  proposal, SNS neuron/proposal, and ICRC account-transaction cache summaries
  with the shared `CacheValidationStatus::{Valid, Invalid}` Rust enum.
- Removes the redundant internal `ok` and `invalid` snapshot-status constants.
  Builders, text renderers, and tests now consume the shared typed contract.
- Makes the pure cache report models and validation enum available without the
  `host` feature; filesystem discovery, status building, and text rendering
  remain host-only.

### Compatibility

- The `cache_status` Rust field type changes are a pre-1.0 source-level hard
  cut with no string wrapper or alias. The enum serializes `Valid` as `ok` and
  `Invalid` as `invalid`, so existing JSON report schemas and CLI text remain
  unchanged. Cache files, cache paths, refresh policies, and network behavior
  are unchanged.

## 0.26.4 - 2026-08-03

### Changed

- Replaces the free-form `CacheStatusRow.status` string with
  `CacheFileStatus::{Fresh, Stale, Unmanaged, Invalid}` and the free-form
  `CacheRefreshLockStatusRow.status` string with
  `CacheRefreshLockStatus::{Active, Stale, Invalid}`. Both enums expose stable
  `as_str` labels and serialize to the exact existing snake-case JSON values.
- Separates bounded candidate discovery, generic cache-header projection, and
  refresh-lock projection behind the existing public cache-status builder.
  This removes the large mixed-responsibility status owner without changing
  scan bounds, ordering, freshness policy, error visibility, local-only
  behavior, or text output.

### Compatibility

- The status-field Rust type changes are a pre-1.0 source-level hard cut with
  no string compatibility wrapper or alias. JSON report schema 2 and CLI text
  remain unchanged because their serialized labels are identical.

## 0.26.3 - 2026-08-03

### Changed

- Extends the bounded, local-only `cache status` report with refresh-lock rows,
  counts, filesystem sizes, recorded targets, networks, process ids,
  acquisition times, ages, stale thresholds, and typed
  `active`/`stale`/`invalid` status. Malformed and future-dated locks remain
  visible and are not removed.
- Shows each managed cache's stale threshold in text output as well as JSON.
  The 10,000-entry scan bound now applies to complete-cache and refresh-lock
  candidates together.
- Keeps path-derived component labels stable by omitting per-SNS Root
  principals and hashed ICRC account identities from generic status labels;
  the complete relative path remains available separately.
- Advances the shared refresh-lock file to schema 2 and records the stale
  threshold selected by the refresh that created it. A competing refresh uses
  that recorded threshold instead of reclassifying the existing lock through
  its own request policy.
- Centralizes strict refresh-lock parsing so acquisition and global status use
  the same schema and shape validation.
- Normalizes NNS Registry leaf, Subnet catalog, and Subnet topology cache paths
  below `nns/<network>/...`, matching the domain-then-network ordering already
  used by NNS Governance, SNS, and ICRC caches.

### Cache and compatibility

- `cache status` remains read-only and local-only: it does not probe process
  liveness, make network calls, delete locks, or repair cache state. Operators
  must still verify that no refresh is running before manually removing a stale
  or invalid lock.
- Cache-status report schema 2 and refresh-lock schema 2 are pre-1.0 hard cuts.
  A lingering schema-1 lock is invalid evidence and requires the same explicit
  operator verification and cleanup as any other malformed lock; normally
  released locks leave no persistent file to migrate.
- The replaced top-level NNS Registry and Subnet cache paths are another
  pre-1.0 hard cut. They are not discovered by typed loaders or migrated;
  refresh the affected cache explicitly to publish it at its new path.

## 0.26.2 - 2026-08-03

### Added

- Adds top-level local-only `cache status` in text and JSON. It walks at most
  10,000 known complete-cache paths without following symlinks and reports the
  cache root, path, component, schema, network, collection timestamp, age,
  filesystem size, applicable stale threshold, and generic header errors.
  Large unmanaged histories stop at the header/completeness boundary rather
  than reading their complete row arrays; the small age-managed families are
  fully JSON-checked before receiving `fresh` or `stale`.
- Adds a complete joined SNS discovery catalog at
  `sns/<network>/catalog/discovery/full.json`, one refresh lock, atomic
  replacement, strict identity/completeness validation, and public host APIs
  for cache-only, refresh-if-stale, and forced-refresh use.
- Adds explicit `sns refresh` for operators who want to replace the joined
  deployed-SNS catalog before its automatic age threshold.

```bash
icq cache status
icq cache status --json
icq sns refresh
icq sns refresh --json
icq sns list
```

### Changed

- Makes `sns list` a cache-backed read with a one-hour age policy. A missing or
  older catalog produces visible refresh progress; a fresh catalog produces
  no live request. Parse, schema, identity, network, and IO failures remain
  errors rather than implicit replacement triggers.
- Keeps per-SNS commands on their existing bounded targeted discovery path.
  They do not refresh or depend on the all-SNS catalog, so a targeted query
  cannot silently trigger metadata requests for every deployed SNS.
- Advances the SNS list report to schema 2 with explicit `data_source`,
  `cache_path`, and `cache_complete` provenance.
- Advances NNS topology health to schema 2 and adds
  `unknown_freshness_source_count`. Sources without an age policy now fail the
  cache-freshness check instead of being treated as fresh.
- Reuses the SNS catalog stale-policy constant in the global cache inventory
  and recognizes the Subnet catalog's native `catalog_schema_version` header.

### Cache and compatibility

- `cache status` is read-only. It excludes refresh-attempt sidecars, follows
  no symlinks, performs no network calls, and neither refreshes nor deletes
  files. `unmanaged` means the cache has a readable age but no registered age
  policy; it does not mean semantically current.
- SNS catalog refresh failures preserve the prior complete cache. The catalog
  cache and changed SNS-list/topology-health JSON shapes are pre-1.0 hard cuts
  with no legacy reader, report alias, or automatic migration.

## 0.26.1 - 2026-08-03

### Changed

- Replaces the abbreviated `sns params <SNS>` spelling with
  `sns parameters <SNS>` so the public CLI uses the native full term.
- Retains the family-operation-identifiers grammar for nested SNS commands:
  `canister`, `neuron`, `proposal`, and `reward` operations precede the SNS
  selector.
- Makes every command namespace without a selected operation render the same
  complete local help as its explicit `help` subcommand and exit successfully.
  Incomplete leaf commands remain errors.
- Alphabetizes every CLI `Commands` section by command name, including Clap's
  generated `help` entry, through one shared command-tree policy.
- Centralizes namespace-help and subcommand-order policy in the shared Clap
  command-tree boundary.

```bash
icq sns
icq sns info 1
icq sns parameters 1
icq sns canister list 1
icq sns neuron list 1
icq sns neuron info 1 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f
icq sns proposal info 1 387
icq sns reward
icq sns reward checkpoint 1 --json
```

### Compatibility

- This is a pre-1.0 hard cut. `sns params` has no Clap alias, fallback parser,
  or compatibility dispatch.

## 0.26.0 - 2026-08-03

### Added

- Adds exact live SNS neuron detail through native Governance `get_neuron`,
  preserving fixed-size state, native 32-byte identifiers, raw permissions,
  followees, pending maturity-disbursement accounts, auto-stake state, and
  tri-state maturity-policy findings without expanding the ordinary neuron
  list or cache schema.
- Adds live `sns reward checkpoint` collection with strict native pagination,
  parameter/reward-event/running-version brackets, parameter-derived bounds,
  complete raw neuron evidence, and bounded text output. A walk of `N` pages
  performs `N + 8` client queries and creates no implicit cache or file.
- Adds no-host pure checkpoint validation and reward-diff construction plus a
  host-only strict file loader. Reward diff is local-only, joins all neuron
  ids, retains signed maturity deltas, and returns typed `valid`,
  `no_allocation`, or `invalid` evidence.

```bash
icq sns neuron info 1 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f --json
icq sns reward checkpoint 1 --max-pages 10 --json
icq sns reward diff before-checkpoint.json after-checkpoint.json --json
```

### Validation and compatibility

- Exact-detail custom sources must return the requested native neuron identity,
  canonical principals/subaccounts, unique permission evidence, valid followee
  ids, and recomputed policy findings. Unknown permission codes fail closed as
  `unassessable`; known conversion permissions or pending disbursements are
  typed violations.
- Checkpoints reject duplicate, overlapping, or non-increasing ids, malformed
  cursors, unstable brackets, overflow, and collection beyond the validated
  Governance ceiling. `--max-pages` is diagnostic and cannot publish an
  incomplete observation.
- Loaded checkpoints are untrusted: raw rows, identities, ordering, totals,
  policies, brackets, timestamps, and query counts are recomputed. A valid
  allocation requires stable target/event evidence, immediate native event
  continuity, observed-satisfied policies, non-negative explained deltas, and
  exact reconciliation to `distributed_e8s_equivalent`.
- The native identifier and public parameter/report DTO changes are pre-1.0
  hard cuts. No legacy parser, cache branch, Serde alias, or Candid wire-shape
  compatibility is retained; existing fixed-size neuron cache schema 2 remains
  unchanged.
