# 0.49 Changelog

## 0.49.0 - 2026-10-08

- Changes public `SnapshotRefreshAttempt<Metadata>.status` from `String` to
  `CacheRefreshAttemptStatus`. The shared validator now returns `Result<(), String>`;
  callers read the validated status from the field. Writers and NNS/SNS/ICRC
  projections carry one typed representation, removing string reparsing and
  redundant status tuples/parameters. This is a minor-release Rust API hard cut:
  update struct literals and validator callers; no compatibility wrapper remains.
  Schema 1 and `running`, `complete`, `failed` JSON labels remain unchanged, so
  valid sidecars need no reset. Unknown labels now fail strict deserialization
  and project as parsing errors rather than invalid-attempt validation errors.
  Status/error consistency, metadata identity, progress, budgets and unknown-field
  admission checks remain enforced.
  [#22](https://github.com/dragginzgame/ic-query/issues/22).
- Simplifies the private CLI leaf runner to the current Inventory request types,
  removing four single-implementation request traits, four associated request
  types and repeated macro selections. The shared runner and distinct family
  reports, errors and renderers remain; command behavior is unchanged.
  [#21](https://github.com/dragginzgame/ic-query/issues/21).
- Adopts the 59-file Shared Tooling 0.1.23 snapshot at reviewed revision
  `0ba0ad00ed94848e54ecc82629b6b7873b7284c0`, including the PR delivery
  helper. The exporter records exact committed bytes and executable modes;
  the engineering baseline stays pinned separately. Updated governance describes
  explicit PR delivery selection and
  the additional merged-source validation contract.
- Updates snapshot-consumption guidance for physical temporary-root handling in
  owner LOC fixtures. Upstream 0.1.22 repairs those fixtures and the native test
  timeout that interrupted Intel qualification. Those installer/LOC corrections
  remain in the selected snapshot; the release runner additionally receives 0.1.23.
  [Shared #57](https://github.com/dragginzgame/shared-tooling/issues/57),
  [Shared #42](https://github.com/dragginzgame/shared-tooling/issues/42).
- Query retains direct release delivery and its atomic branch/tag push.
  The local adapter refuses other delivery selections before creating validation
  state; PR delivery requires a separately adopted merged-source adapter and
  matching gate/evidence qualification. Maintainers retain release execution.
- The canonical shared runner fixture and Query's adapter fixtures explicitly
  select direct delivery, so an enclosing PR selection cannot change their
  effect stubs. Shared PR fixtures remain upstream and are not selected by Query.
  Query package versions, CLI and persisted contracts are unchanged by the
  Shared Tooling refresh.
- Rechecks the exact committed payload, index/worktree and annotated tag object
  after the final release check. Completed direct resume verifies local/remote
  tag identity and observed branch ancestry, accepting known descendants and
  refusing conflicts or unavailable observations without repeating release effects.
  [#20](https://github.com/dragginzgame/ic-query/issues/20),
  [Shared #58](https://github.com/dragginzgame/shared-tooling/issues/58).
- Selects published `ic-host-artifacts`, `ic-host-fs` and `ic-host-tools` 0.5.1
  at reviewed revision `81f9809861159def2fd0987fcb7961cda4afd969`. All four
  Host crates are published and non-yanked. The selected lockfile checksums match
  the official registry, and release-source crate files match the reviewed 0.5.0
  implementation.
  The maintainer's manifest/lock changes are limited to those three Host rows.
  Query uses retained bounded streams, path resolution, descriptor publication,
  hashing, structural inspection and response decoding; it does not expose the
  changed compression arguments, Wasm fact literals or exhaustive inspection
  error matches through its public API. Host 0.5.1 changes release tooling only;
  its committed crate files match 0.5.0. This dependency update is compatible.
- Retains disabled Host defaults, cache-only artifact features and the
  development helper's response-only tools profile. Owned process execution,
  gzip and IC limit-report features are not added; the Python smoke harness's
  piped IO, deadlines and interruption integration remain with
  [Host #5](https://github.com/dragginzgame/ic-host-tooling/issues/5).
  Cache/receipt schemas, budgets, identities and publication outcomes are unchanged.
  Host's exact-source Linux, Intel/ARM macOS and MSRV CI passes; the new dirty
  consumer graph still requires matching native Query CI.
- Preserves the original Governance smoke operation error when network cleanup
  or receipt storage also fails. Receipts retain available command stdout/stderr,
  converting incomplete subprocess byte diagnostics to displayable UTF-8;
  failed publication diagnostics stay on the original exception and in a later
  receipt when storage recovers. Standalone cleanup/storage failures still fail
  a verified attempt. Adds process fixtures for concurrent piped IO, blocked or
  escaped pipes, signal cleanup with descendants and successful background startup.
- An attempted development-only `OwnedChild` bridge failed the successful
  background lifetime fixture: Host's current ordinary-exit group cleanup stops
  a launcher that the network cleanup phase must own. The candidate was withdrawn;
  no process dependency or dormant bridge remains. The missing explicit handoff
  contract and its acceptance criteria are reported in
  [Host #5](https://github.com/dragginzgame/ic-host-tooling/issues/5#issuecomment-6055899595).
  Existing artifact admission, receipt schema 1 and the current startup flow remain.
