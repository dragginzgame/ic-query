# 0.37 Changelog

## 0.37.1 - Unreleased

### Cache correctness

- Enforces the SNS mainnet-only contract at both cached proposal entry points
  before any local snapshot lookup. A cache placed under another network
  namespace can no longer make proposal list or detail reporting succeed.
- Moves SNS id-or-root cache resolution into the shared family storage boundary
  while preserving the distinct missing-neuron-id and missing-proposal-cache
  errors.
- Loads NNS neuron snapshots through the shared complete-snapshot key validator
  used by other cache families. Domain, entity, collection, and `full` scope
  mismatches now return `NnsNeuronHostError::CacheIdentityMismatch`; malformed
  neuron refresh-attempt sidecars return `InvalidRefreshAttempt` rather than
  being conflated with snapshot validation.

### Human-readable cache output

- Uses one human-facing list format for SNS neuron and proposal caches. Both
  include `COMPLETE`, compact the root principal consistently, preserve raw
  fields in JSON, and separate the summary preamble from the table.
- Uses one SNS cache-status formatter. It emits a missing-cache refresh hint
  even when a numeric SNS id has no known snapshot or attempt path, prints a
  refresh-attempt path once, and separates the hierarchical latest-attempt
  block with a blank line.
- Separates report preambles from following tables across compact and verbose
  NNS data-center, node, node-operator, and node-provider lists and Subnet
  Catalog lists.

### Internal ownership and code hygiene

- Centralizes official Dashboard source requests, network and principal
  validation, provenance construction, invalid-source mapping, and provenance
  text for IC and CloudEngine reports without changing their public evidence
  or request bounds.
- Centralizes NNS proposal and neuron refresh-attempt starting, running,
  complete, failed, and strict-read behavior under the Governance collection
  owner. Sidecar paths and schema remain unchanged.
- Removes redundant NNS CLI command-construction wrappers, one-function SNS
  cache report and lookup leaves, duplicate SNS cache renderers, tiny topology
  capacity and proposal-conversion leaves, and tests whose only purpose was to
  keep deleted historical forms absent.
- Simplifies complete-snapshot identity to its current full-snapshot contract
  and keeps unsupported-schema tests on schema `1` with generic invalid input.
  The public-documentation debt guard is lowered to the newly achieved count.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| SNS text | Cache list/status formatting is consistent across neurons and proposals | Use JSON rather than parsing human-facing text; expect `COMPLETE` and a titled attempt block |
| SNS cache policy | Cached proposal reports reject every non-mainnet namespace before lookup | Use the supported `ic` network namespace |
| NNS Rust errors | Neuron snapshot identity and attempt-sidecar failures have distinct variants | Update exhaustive `NnsNeuronHostError` matches |
| CLI and schemas | No commands, options, JSON fields, cache paths, or schema identifiers changed | No migration or cache rewrite is required |

## 0.37.0 - Unreleased

### ICRC account and holder index reports

- Adds `icq icrc analytics account list` for one official v2 account-index
  page of at most 100 rows, with optional owner filtering, explicit upstream
  sorting, and reusable opaque forward/backward cursors.
- Adds `icq icrc analytics account info <ledger-canister-id> <account-id>` for
  one exact official v1 account lookup using the stable id returned by list.
- Adds `icq icrc analytics holder list` for one official v2 principal-level
  holder page of at most 100 rows with explicit sorting and cursors.

```bash
icq icrc analytics account list mxzaz-hqaaa-aaaar-qaada-cai --limit 25
icq icrc analytics account list mxzaz-hqaaa-aaaar-qaada-cai --sort-by=-balance --json
icq icrc analytics account info mxzaz-hqaaa-aaaar-qaada-cai 222nw-nqiei-h4uy6-fqm54-d3slu-jveav-vqrn6-yojxi-4eug3-2ejie-vae
icq icrc analytics holder list mxzaz-hqaaa-aaaar-qaada-cai --sort-by=-balance
```

### Raw contract and timestamps

- Account rows preserve opaque account id, canonical owner, raw subaccount and
  base-unit balance, transaction counts and latest index, fee-collector state
  and raw ranges, ledger identity, and the raw Dashboard update string.
- Holder rows preserve canonical principal, raw aggregate base-unit balance,
  transaction evidence, raw numeric supply percentage, nullable raw USD value,
  ledger identity, and the raw Dashboard update string.
- Normalizes the upstream nanosecond creation value to
  `created_at_unix_secs` while retaining `created_at_subsec_nanos`, preserving
  exact subsecond precision without exposing a 19-digit primary timestamp.

### Cursor and authority behavior

- Makes exactly one request per operation and never follows, merges, or scans
  pages. Returned opaque cursors can be supplied unchanged to `--after` or
  `--before`; composite cursor translation remains inside the live HTTP
  adapter.
- Records schema `1`, `official_ic_dashboard_api`, the exact endpoint and
  collection time, `certified: false`, and
  `point_in_time_guaranteed: false`. No report cache is created, and list
  reports do not claim completeness or API exhaustion.
- Uses the API's v2 account/holder page resources and its v1 exact account
  resource explicitly rather than hiding a version change behind follow-up.

### Validation and library

- Validates page limits and cursor exclusivity before source calls; ledger and
  optional owner principals; query/provenance echoes; per-row ledger identity;
  canonical principals and unsigned decimal balances; numeric holder
  percentages; non-empty update evidence; exact info identity; and within-page
  uniqueness.
- Exposes pure requests, sorts, reports, rows, constants, and text renderers
  from `ic_query::ic`. The `dashboard-host` feature adds the focused
  `IcIcrcIndexSource`, live/custom-source builders, and source-data contracts.

### Release flow

- Release bumps update every `ic-query` dependency example in `README.md` and
  `docs/library-usage.md` to the target release line after the clean-tree CI
  gate. Changelog readiness remains enforced, but documented dependency
  versions no longer need to be edited before running a bump.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| CLI | New `icrc analytics account info|list` and `holder list` operations | Use returned account ids for exact follow-up and reuse cursors explicitly |
| Pure library | New account/holder request, sort, row, report, and renderer contracts | Import them from `ic_query::ic` |
| Dashboard host | New `IcIcrcIndexSource` and live/custom builders | Enable `dashboard-host` for official REST collection |
| Cache/schema | Live-only schema-1 reports; no persisted cache | Do not treat cursor pages as complete snapshots |
