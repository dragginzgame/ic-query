## 0.24.0 - 2026-08-01

### Added

- Adds `icq sns metrics <id|root-principal>` using the official SNS Governance
  `get_metrics` composite query.
- Preserves raw proposal-window counts, latest SNS-ledger block timestamp,
  genesis timestamp, cached treasury metrics, voting-power metrics, and each
  treasury row's native code/name, source ledger/account, current/original e8s
  amounts, and timestamp.
- Adds `SnsMetricsSource`, `MainnetSnsMetrics`, `SnsMetricsRequest`,
  `SnsMetricsReport`, nested metrics DTOs, live/custom-source builders, and text
  rendering. Report/request DTOs and rendering remain available without
  default features; live and custom source builders remain host-only.

```bash
icq sns metrics 1
icq sns metrics 23ten-uaaaa-aaaaq-aabia-cai --window 90d --json
```

### Evidence And Bounds

- The proposal-count window defaults to 30 days, accepts the shared duration
  syntax, and is capped at 365 days before discovery or agent construction.
- A direct command makes one SNS-W inventory request, one selected-SNS metadata
  request, and one Governance composite query. Governance performs its own
  bounded SNS-ledger latest-block query inside that composite query.
- Treasury amounts remain explicitly cached Governance metrics with their own
  timestamps. They do not inherit the report collection time or latest ledger
  block timestamp, and the report cannot claim one point-in-time snapshot.
- Validates the resolved Governance principal, exact native method and call
  type, requested window, canonical treasury ordering, unique native treasury
  codes, native kind labels, canonical optional principals, 32-byte account
  subaccounts, non-empty trimmed names, and a finite treasury-row bound.
- Does not enumerate ledger transactions, derive historical balances, query
  another SNS, fan out, read or write a cache, or fall back to a different
  Governance method when an older SNS Wasm does not expose `get_metrics`.
