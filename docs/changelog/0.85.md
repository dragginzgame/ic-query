# 0.85 release notes

## 0.85.0

### ⚠️ Breaking

All packages now require Rust 1.99.1, matching the pinned development, lint and
release compiler. Upgrade older consumer toolchains. `make compiler-check`
admits and records actual Cargo/rustc identities against inherited package
policy; compiler failures and mismatches stop before product validation.
The separate MSRV lane and override targets are removed. The retained checks
and canister lanes run on Linux, macOS ARM64 and macOS Intel. Complete checks
still compile all workspace packages, targets and features, and retain isolated
library/native/Wasm consumer graphs and archive qualification. Canister jobs
retain Testkit and installed local-runtime acceptance. There is no new cleanup,
dependency refresh or package-version change.
([#111 — Adopt Rust 1.99.1 and consolidate compiler qualification](https://github.com/dragginzgame/ic-query/issues/111))

NNS data-center, node, node-operator and node-provider list/detail builders,
and the SNS proposal-list builder, expose a default convenience entry point
and an explicit `*_with_source_and_progress` entry point. The source-only and
progress-only forwarding variants are removed. Pass a caller-owned source and
progress sink to the explicit builder; a closure can ignore progress:

```rust
let report = build_nns_data_center_list_report_with_source_and_progress(
    &request,
    &source,
    &mut |_| {},
).await?;
```

For native live calls with progress, pass `LiveNnsSource::default()` or
`LiveSnsSource::default()` as appropriate. Fixture sources retain the same
source-trait contracts. Default convenience builders remain silent.

Complete NNS proposal and public-neuron caches replace the previous schema-1
payload in place. The snapshot envelope is the single owner of network,
Governance identity, concrete replica provenance, collection end timestamp,
page size/count and row count. `data.collection_evidence` retains the requested
source selection, original page ceiling and collection start timestamp beside
rows. Cache admission reconstructs final state from that evidence, validates
identity, timestamps, source binding, page/row bounds and family-specific
completion rules, then retains it for existing analytics.

After upgrading, explicitly replace the affected complete snapshots with
`icq nns proposal refresh` and `icq nns neuron refresh` using the intended cache
root, network and endpoint. Preserve existing files if needed for external
consumers before replacing them, and coordinate consumers of the former raw
cache payload. Query does not delete caches, migrate files, or read the former
shape. An incomplete or failed refresh preserves the previously published
snapshot. Refresh-attempt sidecars and locks keep their current contracts.

Portable continuation JSON fields and public getters are unchanged.
Proposal activity and neuron distribution report JSON remain unchanged, with
collection timing and the false point-in-time guarantee intact. Sequential
collection evidence does not authenticate rows or establish an atomic snapshot.

NNS/SNS library diagnostics retain typed errors and source chains but omit CLI help.
Unsupported-network diagnostics include the requested network. The CLI owns
mainnet examples and missing-cache refresh advice; topology network errors
point to complete local help rather than repeating its command list.

These public API, diagnostic and persistence changes require a pre-1.0 minor
release. Package versions and release execution remain maintainer-owned.

### 🧹 Cleanup

Governance continuations share metadata initialization, restored identity
validation and admitted-page lifecycle updates while retaining descending
proposal cursors, ascending neuron cursors and family errors. The CLI passes
inventory builders and renderers directly to shared leaf operations, removing
the forwarding trait, empty adapters and implementation macro.

Proposal status, reward status and topic filters derive from their native
classification definitions. Sort choices own their labels once. Clap adapts
these domain-owned choice lists without parallel CLI enums; accepted labels,
help ordering and defaults remain unchanged, including `any` and API order.

Dashboard time-series requests share observation-budget admission while each
family retains its allowed step policy and caps. Registry version and refresh
text reuse provenance formatting without changing field order or escaping.
SNS Root health results pass directly to one inventory projector, preserving
inventory authority and partial-failure gaps.

ICRC query tests share bounded HTTP/Agent setup, reply envelopes and request
extraction. Per-test payloads, limits and assertions remain local.

### 🔧 Changed

Adopt Shared Tooling 0.27.26 at committed revision
`e84252f5740bacd708359580455ea2b6fd67df38`. Cargo-tool reuse fingerprints native
build tools, headers and libraries rather than unrelated Linux application
packages. Setup records the selected tool requirements for each physical
checkout and discards its own successful compiler scratch after executable and
receipt admission. Existing tool versions and Query dependency selections are
unchanged; use the existing setup targets before offline admission under the new
input policy.

The adopted dependency checker supports explicit normal-edge observations for
runtime ownership. Query retains its local dependency exclusions and release
adapters. Shared validation-proof reuse and tool-generation reclamation remain
explicit operations under their owner contracts.


### 📚 Documentation

The README keeps installation and first-use guidance. Detailed command/evidence
and Rust API material now lives in linked references, also listed in the docs index.

### ⬆️ Dependencies

Adopt published Metrics 0.26.0 with default features disabled, preserving the
arithmetic-only dependency on native and Wasm. This release raises Metrics'
compiler floor to Rust 1.99.1, which Query already selects. Its arithmetic source
is unchanged from 0.25.1, preserving checked neuron distribution totals,
percentage rounding, typed overflow projection, text and raw JSON.

The production Query/CLI graph selects Metrics 0.26.0. Testkit 0.78 retains its
independent Metrics 0.25.1 dependency in the development-only harness graph;
this adoption does not require a Testkit update or another dependency refresh.
