# 0.84 release notes

## 0.84.0 - 2026-11-01

### ⚠️ Breaking

Platform 0.17.0, Host Tools 0.77.0 and Testkit 0.78.0 share canonical Types
0.16.0. Align direct dependencies and rebuild callers that exchange Principal,
certificate/hash-tree or ledger DTO types. Native simulator callers use the
maintained `ic_platform::pocket_ic` 0.17 client, including its builder, time and
reply identities. Canister adapters delegate to canonical Runtime 0.17.1; align
other runtime consumers on that owner. External protocol bytes, schema-1 caches
and the PocketIC 16.1.0 server remain unchanged.

`SnsInstanceContext` owns network, SNS-W principal, acquisition timestamp,
endpoint, collector, SNS id/name and Root principal. Root canister inventory,
metrics, token and swap reports carry it through `context`. Existing Governance
report envelopes carry it through `SnsReportContext.instance`, retaining their
Governance principal separately. Read, for example, `metrics.context.name` or
`params.context.instance.name`; construct the shared context in Rust fixtures.
All of these fields remain flat in JSON.

`NnsGovernanceAnalyticsContext` owns schema version, collection identity/source,
collection timestamps, page count and the point-in-time flag. Proposal activity
and neuron distribution reports carry it through `context`. Their family row
counts remain in the report envelope. Validators inspect this owned record
instead of reconstructing a borrowed header. Independent source, admitted-cache
and restored-report checks remain in place.

`NnsRegistryVersionData` and `NnsRegistryVersionReport` carry acquisition fields
through `provenance: NnsRegistryInventoryProvenance`, matching Registry inventory
reports. Update custom sources and Rust field access, including
`report.provenance.registry_version`. Flat JSON and certification fields remain
unchanged.

These Rust API changes require a pre-1.0 minor release. Consumers update field
access and struct literals together; no aliases or compatibility wrappers remain.
JSON consumers need no field changes. Existing schema-1 caches and retained
reports remain current: no reset, migration or evidence deletion is required.

### 🧹 Cleanup

- Carry the existing `NnsRegistryCertification` record from authentication through
  version results, delta witnesses and batches into report projection. Derive UTC
  certificate time at authentication; retain raw certificate/witness evidence,
  bounded decoding, freshness checks, private authenticated constructors and
  restored-data reauthentication.
- Share proposal page/detail and neuron-detail reply projection between native
  and replicated adapters. Keep their transport, provenance and error admission
  separate.
- Derive cache-status row metadata from the classified path and pass the existing
  snapshot-replacement flag directly to lock callbacks. Lock order, publication
  custody, failed-attempt evidence and finalization behavior are unchanged.
- Share start/end/step URL writing while retaining each Dashboard resource's
  request limits and exact parameter order.
- Share local NNS provenance fixtures with explicit version/time overrides; fold
  the private compact-principal leaf into its existing text owner. Preserve
  compact widths, escaping and human output sections.

### ⬆️ Dependencies

Select Platform 0.17.0, Build and Host Foundation 0.73.6, Host Tools 0.77.0 and
Testkit 0.78.0 through the root dependency catalog. The lockfile selects canonical
Types 0.16.0, Runtime/macros/guard 0.17.1 and the maintained Platform PocketIC client
0.17.0. Select Metrics 0.25.1 with default features disabled and Wire/Derive
0.14.2 for development protocols.
Query uses the core codec without optional Principal/Account schemas or Endpoint
integration. This adoption preserves probe frames, metadata, limits, malformed
input admission and retained reply evidence; no Query API or protocol cut is
required for the optional upstream Types identity change.

Metrics 0.25 aligns optional native metadata with Wire 0.14. Query uses only its
unchanged arithmetic API, keeping Wire outside production graphs. Testkit 0.78
shares this arithmetic-only Metrics identity for its private benchmark helpers,
removing the older Metrics copy from the test graph. No Metrics types cross
Query's public API, and calculation, report and cache contracts are unchanged.
Testkit's optional Wire calls now select Wire 0.14 too; Query's fixture retains
its explicit core-codec calls and enables only Testkit's reply fixtures. The
locked Testkit CLI advances to 0.78.0 with the same PocketIC 16.1.0 server.

Build's qualified target-cfg recipes are additive; Query retains its existing
probe build settings and exact-input/artifact custody. Host Tools and Testkit
release independently upstream. The Platform adoption changes Rust type and
runtime ownership; CLI behavior, external protocol bytes and Rust 1.91 remain
unchanged. Contributor tool setup selects the new locked Build metadata editor
and Testkit CLI.
