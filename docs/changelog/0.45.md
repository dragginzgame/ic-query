# 0.45 Changelog

## 0.45.1 - Unreleased

### Canonical timestamp validation

- Enforces the existing canonical UTC contract in the shared timestamp parser.
  Text must match the Unix-seconds constructors' second-precision formatting,
  such as `2026-06-04T00:00:00Z`. Unpadded components, excess padding, and extra
  signs are rejected; invalid calendar dates, fractional seconds, offsets,
  and surrounding whitespace remain unsupported. Canonical leap dates and
  expanded years emitted by the formatter remain valid within the existing
  parser range.
- Governance requests reject noncanonical collection times with the existing
  `NnsGovernanceError::InvalidTimestamp` before source calls. Restored proposal
  and neuron continuations apply the same rule to their start/update times;
  inclusive interval ordering and existing error fields are preserved.
- Other shared-parser consumers apply their existing invalid-content or
  freshness policy to noncanonical report/cache timestamps. Correctly formatted
  existing data remains valid. Stored text is neither normalized nor migrated.
  Catalog validation uses the same parser instead of a separate format check.

### Cache implementation simplification

- Uses one load/refresh/reload runner for missing, owner-classified invalid,
  and stale caches. Each family still selects its recovery and freshness rules;
  SNS proposal reads still refresh only missing snapshots. Refresh occurs at
  most once, and its persisted result is loaded again before report projection.
- Loads complete snapshots through their concrete envelopes and constructs
  generic JSON cache failures through `HostCacheError`. Removes the private
  snapshot trait and error-mapper adapters while preserving family-specific
  missing-cache guidance, error classifications, and validation order.
- Publishes snapshots and refresh-attempt sidecars directly through the shared
  atomic JSON writer. Serialization preflight, confinement, permission checks,
  lock ownership, failed-refresh preservation, and attempt finalization ordering
  remain intact. Removes the forwarding writers and test-only unbounded readers.
- Proposal list/detail cache reads use the loader's missing-cache result rather
  than a separate existence probe. A missing snapshot permits the existing
  fallback, including when a file disappears before the read; malformed content
  and filesystem failures remain errors. Local cache inventory/status reports
  retain their presence checks and invalid-content summaries.
- Reuses parsed Governance interval endpoints and removes historical path
  assertions already covered by the exact current cache-path test.

### Compatibility and validation

- Ships as a patch because the changes fix documented behavior and simplify
  private machinery. Public Rust signatures and error variants, CLI grammar,
  report/cache shapes, cache identities, and raw JSON fields are unchanged.
  Every schema identifier remains `1`; the Rust minimum remains 1.91.0.
- Callers supplying timestamp text should use canonical UTC or the existing
  Unix-seconds request constructors. Previously admitted noncanonical text now
  receives the owner's existing validation or stale-data outcome.
- Validation passed: 1,184 workspace tests, focused parser and restored-state
  tests, portable Governance rejection-before-source-call coverage, warning-denied
  workspace and no-default library Clippy, the Rust 1.91.0 workspace check,
  the canister WebAssembly build, public documentation checks, and formatting,
  whitespace, type-documentation, process-boundary, and schema guards. The feature
  and public-API matrix also passed during the earlier cache-consolidation pass.
  Live IC queries, canister deployment/integration smoke, packaging, and the
  complete release gate were not run. No CLI command or option is added.

## 0.45.0 - 2026-10-03

### Compatibility and release scope

- Starts a new pre-1.0 minor line because public error enums gain variants
  that require downstream exhaustive-match updates. Cache and decoder
  ceilings also reject previously admitted oversized content or excessive
  decoding work. Governance endpoint and restored-evidence validation are
  stricter.
- Report, cache, transcript, sidecar, and lock schema identifiers remain `1`.
  No compatibility aliases, fallback readers, or automatic migrations are
  introduced. The Rust minimum remains 1.91.0.

### Cache admission, repair, and locks

- Caps shared JSON cache reads at 64 MiB for inventories, observed node status,
  joined SNS discovery, and exact Subnet topology, or 512 MiB for complete
  NNS/SNS proposal and neuron histories and ICRC account transactions. Metadata
  is checked before allocation; streamed growth stops at the ceiling plus one
  byte. Oversize shared caches return `HostCacheError::CacheTooLarge`.
- Caps Subnet Catalog cache reads at 64 MiB and retains typed
  `SubnetCatalogHostError::CachedCatalogTooLarge` failures with the
  `SubnetCatalogErrorCode::CachedCatalogTooLarge` classification.
- Treats successfully read invalid UTF-8 as invalid JSON content. Invalid-byte
  and oversized caches follow each owner's existing recovery policy;
  cache-only reads make no live calls, genuine IO and confinement failures
  remain errors, and failed repair preserves the previous file.
- Ends refresh-lock ownership immediately after successful removal. A later
  directory sync error is returned without deleting a replacement owner's lock.
- Queues paths rather than live sibling-directory handles during cache-status
  discovery. Bounds visited entries at 16 times the selected-file scan limit
  and directory depth at 32; reaching any bound reports `truncated: true`.
  Reopened paths retain capability-rooted permission and link checks.

### Candid replies and archive callbacks

- Applies finite Candid decoding budgets to native ledger/index, SNS,
  CloudEngine, CMC, Registry, and Governance replies and canister Governance
  replies. Both maintained account-index codecs use the same limits.
- Allows 1,000,000 decoding work units plus 32 times the reply byte length,
  capped at 256,000,000; limits skipped work to 100,000 units, type-table
  entries to 4,096, and type headers to 64 KiB. These supplement transport
  byte ceilings; they are not measured canister instruction counts.
- Follows ICRC-3 archives using the supplied callback method name with its
  typed argument/result contract. Non-default method names are supported;
  execution remains query-only, and per-archive failures remain visible.

### Governance request and restored-report validation

- Uses the native URL parser for portable Governance requests and restored
  provenance. Rejects malformed authorities and ports, credentials, whitespace,
  controls, queries, and fragments. URL parsing is now a direct portable
  dependency without enabling native transport or runtime dependencies.
- Validates canonical UTC collection timestamps and complete-collection
  counters. Neuron and proposal continuations reject a time earlier than the
  previous update before invoking the source; restored states, distribution
  reports, and activity reports require start <= update. Equal timestamps
  remain supported.
- Adds `NnsGovernanceError::InvalidTimestamp` and
  `NnsGovernanceError::InvalidTimestampOrder`. Downstream exhaustive matches
  must handle these and the new cache-size error variants above. Current
  emitted and persisted schema identifiers remain `1`; invalid evidence is
  rejected without a migration or fallback reader.

### CLI output

- Preserves writer IO error kinds when JSON serialization encounters a closed
  stdout pipe. Help, namespace help, and version output use fallible writes;
  early pipe closure exits successfully without a panic or spurious diagnostic,
  matching text-report output.
- CLI library callers using exhaustive error matches must handle the new
  `IcqCliError::Io` variant.

### Cache performance and public documentation

- Streams managed pretty-JSON publication through the atomic temporary file
  after serialization preflight, avoiding another complete encoded cache copy.
- Combines top-level field, schema, and network validation into one JSON header
  pass before typed deserialization. Strict loads use two full traversals
  instead of three while preserving duplicate/unknown-field checks and typed
  schema errors.
- In an isolated harness over the actual old/new loaders with shared
  regular-file IO stubs, five warmed samples per case reduced median load time
  from 0.299 s to 0.221 s at 13.7 MB and from 1.827 s to 1.445 s at 68.5 MB.
  These 26% and 21% improvements measure JSON loading work, not end-to-end
  native cache or network performance.
- Shares retained Registry checkpoints and encoded history pages, tracks
  retained bytes incrementally, and reuses the shared streaming digest helper
  without changing transcript identity or authority.
- Documents 87 additional public API items in the latest audit cleanup,
  reducing its missing-documentation count from 1,418 to 1,331 and prioritizing
  source contracts, requests, and errors. Replaces the aggregate baseline with
  1,331 known item identities, so unrelated documentation improvements cannot hide
  a newly undocumented item. Updates current README, library, CLI, and design
  guidance to match the supported behavior.

Validation passed: 1,182 workspace tests; 354 public API test executions across
feature selections; native, pure, and canister Wasm feature/dependency checks;
warning-denied workspace and pure-library Clippy; the Rust 1.91.0 MSRV check;
eight documentation-gate identity tests; and documentation, formatting,
whitespace, type-documentation, process-boundary, schema, and CI-helper guards.
Fixtures cover amplified Candid decode/skip work, excessive type tables,
wide recursive values, near-8-MiB byte vectors, non-default archive callbacks,
invalid-byte repair, reversed intervals, replacement locks, and closed stdout.
Cache inventory also passed with 120 sibling directories under a 64-descriptor
limit. Live IC queries, canister deployment/integration smoke, packaging, and
the full release gate were not run for this audit slice. No CLI command or
option is added.
