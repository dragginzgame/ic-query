## 0.45.12

### Release ownership

- Patch, minor, and major releases share one sequential bump, stage,
  commit/tag, and push recipe. Every step stops the sequence on failure,
  including when Make is invoked with parallel jobs.
- Removes the bump script's duplicate target-version changelog check. The CI
  gate checks the committed target notes first, after the clean-tree preflight;
  failed cleanliness, changelog, and CI checks still prevent metadata edits.

  commit allowlist: their package and internal dependency versions already
  inherit the workspace. Release edits remain confined to root `Cargo.toml`,
  `Cargo.lock`, README dependency examples, and library-usage examples.
- Replaces exact Makefile recipe-text assertions with ordering and failure
  fixtures for all three release kinds. Publish-entry fixtures verify dirty or
  untracked worktrees and missing or stale tags fail before Cargo is invoked.

  package against the local library; publishing verifies registry resolution,
  waits for the library to become visible, and skips already-published crates
  on reruns. The release sequence runs the full CI gate once.

### ICRC cursor and history validation

- Normalizes request cursors by validating unsigned ASCII-decimal text and
  stripping leading zeroes, replacing the parse-to-Candid-and-format round trip.
  Zero and transaction ids beyond `u64` retain their existing normalized forms.
- Refresh-attempt reads use the same text validator directly rather than
  allocating a normalized string that is discarded. Existing leading-zero
  attempt evidence remains accepted and preserved. Native query arguments
  retain checked Candid `Nat` conversion at the wire boundary.
- Resident block uniqueness and resident/archive separation have one owner in
  disjoint page-range validation. Removes resident ids from the additional
  duplicate set; followed archive blocks still require matching callback ranges
  and unique numeric ids, including equivalent decimal spellings. Row order,
  callback identity, log-length checks, and archive failure evidence are retained.

### SNS page validation

- Neuron pages validate row fields and use their required strict ascending order
  to establish uniqueness, removing the redundant per-page id set. Bounded
  neuron results and disk snapshots retain independent set-based uniqueness
  checks because their supported contract permits unordered rows.
- Neuron and proposal results share the capability-aware row-limit check. Removes
  the neuron forwarding validator that combined unordered and ordered flows.
  Limit errors retain their capability labels and reasons; duplicate or descending
  pages remain invalid source data before row ingestion or attempt advancement.
  Inclusive boundary overlap, exhaustion, and failed-refresh preservation remain
  unchanged.

### Compatibility

- Public Rust APIs, CLI grammar, cache identities, serialized shapes, and schema
  identifiers are unchanged; all schemas remain `1`. No new CLI surface,
  compatibility reader, or migration is added. Notes target 0.45.12; package

- Establishes guard ownership immediately after exclusive lock creation,

  repeated decimal/Nat round-trips, and the report builder's cursor-normalizing

## 0.45.9

### ICRC archive following

- Validates ledger blocks and archive ranges against the requested page before
  making callback calls. Rejects empty or overlapping ranges and limits one
  page to 100 callbacks. Callbacks retain the supplied query method and arguments;
  following remains one hop.
- Admits at most 64 MiB of cumulative archive Candid replies for decoding,
  including replies that fail decoding. An over-budget reply is discarded
  before decoding; each response retains the existing 8 MiB transport cap. Once
  the aggregate budget is exhausted, remaining callbacks produce explicit
  error rows without further queries.
- Rejects duplicate archive block ids and ids outside their callback ranges
  without retaining a partial invalid callback result. Independent callback
  failures remain visible alongside successful blocks.
- Custom-source report builders enforce the same page bounds, unique followed
  block ids, callback provenance, and explicit archive-follow selection.

### Cache publication and refresh locks

- Uses the same read/write ceilings for complete histories (512 MiB), bounded
  report snapshots and inventories (64 MiB), and refresh attempts (1 MiB).
  Pretty-JSON publication checks size before replacing a cache and bounds the
  temporary-file serialization too, preserving the previous snapshot even if
  serialization changes between passes.
- Subnet Catalog now uses the bounded streaming writer for ordinary refreshes,
  removing the complete encoded JSON string from that path. Catalog reads and
  publication share the 64 MiB inventory ceiling. Explicit exports check that
  ceiling before publication; dry-run exports remain independent of cache
  admission. Provenance, query order, exact pretty-JSON bytes, output alias
  protection, and lock cleanup remain unchanged.
- Refuses refresh-lock writes above their reader's 64 KiB ceiling and removes
  the incomplete lock. Lock acquisition establishes cleanup ownership before
  syncing its parent directory, so a sync failure attempts to remove the newly
  created lock. Existing active, stale, or malformed locks are not removed
  automatically.

### SNS pagination

- Requires ascending neuron page ids and binds any supplied cursor to the
  final row. Full pages must supply an advancing cursor. Inclusive boundary
  overlap and cursor omission on short terminal pages remain supported.
- Validates proposal rows against the requested exclusive boundary and uses
  the lowest returned id for continuation, preserving unordered source pages.
  Invalid later pages leave complete snapshots intact and record failed
  refresh attempts with the last accepted progress.

### Compatibility

- Adds `IcrcError::InvalidTransactionPage` and
  `CacheFileError::WriteLimitExceeded`; downstream exhaustive Rust matches
  must handle these variants. Custom source adapters must provide the
  validated pagination and archive evidence described above.
- CLI grammar, cache identities, report/cache/sidecar shapes, and raw JSON
  fields are unchanged. All schema identifiers remain `1`; no new CLI surface
  is added. Notes target 0.45.9; package version metadata is unchanged.

### Validation

- Full workspace tests passed across all targets and features: 1,239 tests.
  The suite used localhost transport fixtures; no live IC query was made.
- Passed 20 focused Subnet Catalog refresh tests, including exact published
  JSON bytes, dry-run exports, output alias protection, source failures, and
  lock cleanup. Shared cache regressions cover exact byte ceilings, rejected
  oversized replacements, changing serialization, and acquisition sync failure.
- Warning-denied workspace Clippy and isolated Subnet Catalog, certified

## 0.45.0 - 2026-10-03

### Compatibility and release scope

- Starts a new pre-1.0 minor line because public error enums gain variants
  that require downstream exhaustive-match updates. Cache and decoder
  ceilings also reject previously admitted oversized content or excessive
  decoding work. Governance endpoint and restored-evidence validation are
  stricter.
- Report, cache, transcript, sidecar, and lock schema identifiers remain `1`.
  No compatibility aliases, fallback readers, or automatic migrations are
  introduced. The Rust minimum remains 1.91.0.

### Cache admission, repair, and locks

- Caps shared JSON cache reads at 64 MiB for inventories, observed node status,
  joined SNS discovery, and exact Subnet topology, or 512 MiB for complete
  NNS/SNS proposal and neuron histories and ICRC account transactions. Metadata
  is checked before allocation; streamed growth stops at the ceiling plus one
  byte. Oversize shared caches return `HostCacheError::CacheTooLarge`.
- Caps Subnet Catalog cache reads at 64 MiB and retains typed
  `SubnetCatalogHostError::CachedCatalogTooLarge` failures with the
  `SubnetCatalogErrorCode::CachedCatalogTooLarge` classification.
- Treats successfully read invalid UTF-8 as invalid JSON content. Invalid-byte
  and oversized caches follow each owner's existing recovery policy;
  cache-only reads make no live calls, genuine IO and confinement failures
  remain errors, and failed repair preserves the previous file.
- Ends refresh-lock ownership immediately after successful removal. A later
  directory sync error is returned without deleting a replacement owner's lock.
- Queues paths rather than live sibling-directory handles during cache-status
  discovery. Bounds visited entries at 16 times the selected-file scan limit
  and directory depth at 32; reaching any bound reports `truncated: true`.
  Reopened paths retain capability-rooted permission and link checks.

### Candid replies and archive callbacks

- Applies finite Candid decoding budgets to native ledger/index, SNS,
  CloudEngine, CMC, Registry, and Governance replies and canister Governance
  replies. Both maintained account-index codecs use the same limits.
- Allows 1,000,000 decoding work units plus 32 times the reply byte length,
  capped at 256,000,000; limits skipped work to 100,000 units, type-table
  entries to 4,096, and type headers to 64 KiB. These supplement transport
  byte ceilings; they are not measured canister instruction counts.
- Follows ICRC-3 archives using the supplied callback method name with its
  typed argument/result contract. Non-default method names are supported;
  execution remains query-only, and per-archive failures remain visible.

### Governance request and restored-report validation

- Uses the native URL parser for portable Governance requests and restored
  provenance. Rejects malformed authorities and ports, credentials, whitespace,
  controls, queries, and fragments. URL parsing is now a direct portable
  dependency without enabling native transport or runtime dependencies.
- Validates canonical UTC collection timestamps and complete-collection
  counters. Neuron and proposal continuations reject a time earlier than the
  previous update before invoking the source; restored states, distribution
  reports, and activity reports require start <= update. Equal timestamps
  remain supported.
- Adds `NnsGovernanceError::InvalidTimestamp` and
  `NnsGovernanceError::InvalidTimestampOrder`. Downstream exhaustive matches
  must handle these and the new cache-size error variants above. Current
  emitted and persisted schema identifiers remain `1`; invalid evidence is
  rejected without a migration or fallback reader.

### CLI output

  stdout pipe. Help, namespace help, and version output use fallible writes;
  early pipe closure exits successfully without a panic or spurious diagnostic,
  matching text-report output.
- CLI library callers using exhaustive error matches must handle the new
  `IcqCliError::Io` variant.
