# 0.45 Changelog

## 0.45.5

### SNS complete-collection ownership

- Removes the proposal and neuron collection-state wrappers and their
  forwarding modules. Each refresh adapter now owns the existing shared paged
  state directly and validates source pages before ingesting rows.
- Keeps family-specific cursors, cross-page deduplication, page ceilings, stall
  detection, progress events, attempt-sidecar updates, atomic publication, and
  failed-refresh preservation. No replacement state layer or compatibility
  wrapper is introduced.

### NNS topology diagnostics

- Consolidates nine per-provider maps and the separate identity set into one
  map of provider aggregates. Report construction consumes those entries,
  moving owned identities and metadata into the report rather than reconstructing
  them through separate lookups and clones.
- Preserves registration evidence even when both name and Governance count are
  absent, registered providers without activity, and unregistered references.
  Governance counts and Registry observations remain distinct. Spare slots and
  over-assignment remain sums of per-operator values, without netting one
  operator's spare capacity against another's deficit. Distinct data-center and
  region counts, status ordering, and component Registry versions are preserved.
- Moves five summary-only counting methods out of the shared relation index.
  Summary construction now collects join coverage in one pass over node rows
  and one over operator rows; summary and gap reports still use the same
  authoritative relation-membership checks.

### Compatibility and validation

- Public Rust APIs, CLI grammar, report/cache/sidecar shapes, cache identities,
  and raw JSON fields are unchanged. All schema identifiers remain `1`; no
  command or option is added, and the declared Rust minimum remains 1.91.0.
- Full workspace validation passed across all targets and features: 1,213 tests.
  Focused validation for the slice passed: 197 SNS tests, 18 shared-cache tests,
  29 SNS public API tests, 31 topology tests, and 43 NNS public API tests;
  warning-denied workspace, isolated SNS, and minimal topology Clippy;
  type/public documentation, process-boundary, and schema guards; formatting
  and whitespace checks. The provider regression covers empty registration
  metadata, unregistered references, unknown operator counts, distinct
  locations, and simultaneous spare capacity and over-assignment.
- MSRV execution, benchmarks, live IC queries, external downstream builds,
  canister deployment/integration smoke, packaging, and the full release gate
  were not run. Notes target 0.45.5; package version metadata is unchanged.

## 0.45.4

### Explicit Catalog collection metadata

- Removes `UncertifiedCatalogCollection::new` and
  `UncertifiedCatalogCollection::with_registry_evidence`. Custom sources now
  construct the public struct with explicit fields, including `routing_source`
  and complete `registry_records`. Construction no longer supplies historical
  routing and empty evidence for a later builder call to replace.
- This is a Rust source-compatibility hard cut. Downstream constructor callers
  must update; no wrapper, alias, fallback reader, or migration is introduced.
  Historical Registry routing remains supported by explicit historical replay
  policy, and authoritative validation continues to reject insufficient
  uncertified record evidence. The adoption guide documents current construction.

### SNS identity and provenance ownership

- Makes the resolved `MainnetSns` the single owner of the selected inventory id.
  Direct lookup retains one owned SNS and its shared source request, consuming
  the temporary joined inventory instead of retaining it alongside a cloned row.
  Inventory validation still requires exact request provenance and the mainnet
  SNS-W identity before report or refresh construction.
- Uses that request and identity throughout direct report assembly and complete
  proposal/neuron cache refreshes. Numeric and root-principal lookups preserve
  original SNS-W order ids, targeted metadata calls, report/cache/sidecar identity,
  and rejection of unknown targets before metadata fetching.
- Borrows operation-owned refresh paths and removes the collection `Clone`
  requirement. Cached catalog validation borrows rows and principal text directly;
  cached views consume their loaded rows while preserving complete snapshot
  identity, lifecycle filtering, sorting, and provenance.

### Complete SNS catalog validation

- Removes the final full-catalog validation scan from live collection: inventory
  admission, exact-target metadata admission, and lifecycle admission establish
  the invariants before joining fields and assigning ids. Stored catalogs retain
  full validation at the disk boundary, now in one row pass using the same
  required lifecycle-field validator as source admission. The optional/required
  flag, forwarding helper, and second lifecycle pass are removed.
- Preserves unknown lifecycle codes and their `unknown` label through live
  reports and cache round trips. Missing or contradictory lifecycle evidence
  remains invalid, and failed refreshes preserve the existing snapshot. When
  multiple cached rows are invalid, error selection follows the single row pass.

### Snapshot publication and attempt observations

- Removes repeated validation of trusted admitted collections during ICRC
  account-history and NNS public-neuron publication. ICRC still validates its
  final collection timestamps before writing. Disk reads and caller-owned
  analytics inputs retain full validation; invalid source pages cannot replace
  an existing complete snapshot.
- Validates canonical account-history transaction ids through decimal text and
  length-aware ordering without constructing an arbitrary-precision number for
  every row. Unique newest-first order and ids larger than `u64` remain supported;
  wire cursor parsing and normalization retain their numeric representation.
- Moves validated Dashboard node rows and observation metadata into the cache
  envelope without cloning the complete snapshot. Public mutable snapshot
  projections and disk loads keep their validation boundaries.
- Reads an NNS proposal refresh-attempt sidecar once for exact status and reuses
  that observation in the nested cache summary. Malformed sidecars remain errors
  for status; cache listing retains best-effort evidence. Snapshot and sidecar
  reads remain separate observations, not an atomic pair.

### Compatibility and validation

- Fixes the pre-1.0 schema guard's numeric matcher, which previously accepted
  nonconforming values beginning with `1`, including `10`, `11`, and `100`.
  Its fixtures cover the current identifier and invalid single- and multi-digit
  values.
- CLI grammar, report/cache/sidecar shapes, cache identities, raw JSON fields,
  and schema identifiers are unchanged; schemas remain `1`. No command or option
  is added, and the declared Rust minimum remains 1.91.0.
- Initial implementation validation passed: workspace tests across all targets
  and features; 240 minimal `subnet-catalog-host` library tests; isolated SNS
  library and public API tests; 24 neuron tests, including invalid later-page
  classification, cursor, and boundary rejection with snapshot preservation;
  warning-denied workspace, pure-library, and minimal Catalog Clippy; native and
  WebAssembly feature checks; type/public documentation, process-boundary, schema,
  and CI-script guards; formatting and whitespace checks.
- The catalog-validation follow-up passed 197 isolated SNS tests, 29 SNS public
  API tests, and warning-denied isolated `sns-host` Clippy. The full workspace
  suite and feature matrix were not rerun for that local follow-up.
- External downstream builds, MSRV execution, benchmarks, live IC queries,
  canister deployment/integration smoke, packaging, and the full release gate
  were not run. These notes target 0.45.4; package version metadata remains
  unchanged until the maintainer performs the version bump.

## 0.45.3 - Unreleased

### Bounded SNS cache discovery and reads

- Limits each SNS collection snapshot or attempt scan to 1,024 candidate files
  and 16,384 network-directory entries. Entries without a matching collection
  consume the directory allowance too. Results remain canonically ordered;
  confinement, regular-file, and permission checks remain enforced. Exceeding
  either bound fails discovery instead of returning a truncated candidate set.
- Gives cache lists and numeric-id lookup operations one shared 1 GiB read
  allowance across candidate headers, selected snapshot loads, and attempt
  sidecars. Numeric status retains that allowance through attempt-only fallback.
  Reads from malformed content consume the allowance; metadata admission occurs
  before allocation, streamed growth stops at the remaining ceiling plus one
  detection byte, and partial IO failures are charged conservatively.
- Reports exhausted discovery or read bounds as
  `CacheFileError::ScanLimitExceeded` through the SNS cache-operation error.
  Exhaustion cannot become an invalid-summary row, absent sidecar, missing
  cache, falsely unique lookup, or automatic refresh trigger. Within the bounds,
  ordinary content failures retain their existing family policy. Direct
  root-principal operations retain the 512 MiB snapshot and 1 MiB sidecar limits
  without scanning unrelated entities. All inspection remains local.

### Lookup correctness and attempt simplification

- Binds the final loaded snapshot's id to the requested numeric SNS id. An
  atomic replacement that changes the id after header discovery returns the
  existing `SnsHostError::CacheIdentityMismatch`; a replacement with the same id
  remains readable. Ambiguous headers and unrelated strict header failures still
  terminate lookup before selected row loading. Discovery does not provide an
  atomic view of every collection file.
- Uses one validated SNS attempt reader for status and failed-refresh progress
  recovery. Best-effort failure recording retains valid page/row/cursor progress
  and preserves the original refresh error when prior evidence is unreadable.
  Exact status remains strict; listing keeps its best-effort sidecar policy
  except for operation-wide limit exhaustion.
- Removes the redundant running-attempt forwarding helper and one-use attempt
  construction model. Sidecar fields, atomic publication, lock ownership,
  completion warnings, and failed-refresh preservation remain unchanged.

### Compatibility and validation

- Adds the public `CacheFileError::ScanLimitExceeded` variant; downstream
  exhaustive matches must handle it. Public function signatures, CLI grammar,
  cache identities, serialized report/cache/sidecar shapes, and raw JSON fields
  remain unchanged. All schema identifiers remain `1`, and the declared Rust
  minimum remains 1.91.0. No command or option is added.
- Validation passed: 1,206 workspace tests, including bounded discovery/read
  fixtures, deterministic snapshot replacement, and SNS failed-refresh progress
  preservation; warning-denied workspace and isolated `sns-host` Clippy;
  formatting and whitespace checks; type-documentation, process-boundary, and
  schema guards; and the working-tree changelog entry/heading/link check.
  MSRV and canister WebAssembly checks, benchmarks, live IC queries,
  deployment/integration smoke, packaging, and the full release gate were not
  run for this slice.

## 0.45.2 - Unreleased

### Local cache inspection and refresh ownership

- Bounds top-level cache-status inspection to 64 MiB per file. Registered
  age-policy caches retain full JSON syntax checks and reject oversized files
  or streamed growth beyond the ceiling. Other cache headers retain early
  completion before collection payloads; exhausting the header budget reports
  invalid local evidence. Inspection remains local and does not refresh caches.
  Complete-history loaders retain their separate 512 MiB admission limit.
- Checks whether a snapshot already exists after acquiring its refresh lock,
  so replacement reporting reflects the locked state. Lock contention and
  snapshot inspection failures prevent collection; acquired locks are released
  on failure. Atomic publication and failed-refresh preservation remain intact.

### SNS report and cache simplification

- Builds live and cached proposal reports from the identity and acquisition
  metadata they actually require. Removes synthetic discovery inventories and
  SNS records previously constructed solely to project cached proposals.
  List/detail fields, provenance, filtering, and sorting retain their contracts.
- Uses one concrete SNS lookup header instead of a generic flattened header
  plus metadata wrapper. Full JSON syntax, allowed fields, schema, network,
  selected-snapshot identity, and numeric-id ambiguity checks remain enforced.
- Reads the selected refresh-attempt sidecar once for exact cache status and
  reuses that observation in the top-level report and nested cache summary.
  Malformed sidecars remain errors for exact status; cache listing retains its
  best-effort attempt evidence. Snapshot and sidecar reads are separate
  observations, not an atomic pair.

### ICRC account-history correctness and simplification

- Computes collection completion from the caller-supplied Unix start clock
  plus monotonic elapsed time rather than mixing the caller's clock with the
  process wall clock. Attempt update times remain independent wall-clock
  observations. Unrepresentable collection intervals fail before replacing
  the previous complete snapshot.
- Requires canonical collection timestamps with completion at or after start.
  Equal timestamps remain valid. Reversed cached intervals return the existing
  invalid-cache error; repair occurs only through an explicitly selected
  read-through policy. Cache-only reads remain strict, with no migration.
- Uses the retained first-page balance to represent collection initialization,
  removing a redundant flag while preserving empty-page handling and stable
  oldest-transaction checks. Parses each cached transaction id once for both
  canonical decimal validation and unique descending order, preserving ids
  larger than `u64`.

### Compatibility and validation

- Public Rust signatures and error variants, CLI grammar, serialized report
  and cache shapes, cache identities, and raw JSON fields are unchanged.
  Schema identifiers remain `1`, and the declared Rust minimum remains 1.91.0.
  Oversized inspection inputs and reversed ICRC intervals now receive the
  existing invalid-evidence outcomes. No command or option is added.
- Validation passed: 1,196 workspace tests, including focused ICRC and SNS
  fixtures; warning-denied workspace Clippy; formatting and whitespace checks;
  and type-documentation, process-boundary, and schema guards. MSRV and canister
  WebAssembly checks, benchmarks, live IC queries, deployment/integration smoke,
  packaging, and the full release gate were not run for this slice.

## 0.45.1 - Unreleased

### Canonical timestamp validation

- Enforces the existing canonical UTC contract in the shared timestamp parser.
  Text must match the Unix-seconds constructors' second-precision formatting,
  such as `2026-06-04T00:00:00Z`. Unpadded components, excess padding, and extra
  signs are rejected; invalid calendar dates, fractional seconds, offsets,
  and surrounding whitespace remain unsupported. Canonical leap dates and
  expanded years emitted by the formatter remain valid within the existing
  parser range.
- Governance requests reject noncanonical collection times with the existing
  `NnsGovernanceError::InvalidTimestamp` before source calls. Restored proposal
  and neuron continuations apply the same rule to their start/update times;
  inclusive interval ordering and existing error fields are preserved.
- Other shared-parser consumers apply their existing invalid-content or
  freshness policy to noncanonical report/cache timestamps. Correctly formatted
  existing data remains valid. Stored text is neither normalized nor migrated.
  Catalog validation uses the same parser instead of a separate format check.

### Cache implementation simplification

- Uses one load/refresh/reload runner for missing, owner-classified invalid,
  and stale caches. Each family still selects its recovery and freshness rules;
  SNS proposal reads still refresh only missing snapshots. Refresh occurs at
  most once, and its persisted result is loaded again before report projection.
- Loads complete snapshots through their concrete envelopes and constructs
  generic JSON cache failures through `HostCacheError`. Removes the private
  snapshot trait and error-mapper adapters while preserving family-specific
  missing-cache guidance, error classifications, and validation order.
- Publishes snapshots and refresh-attempt sidecars directly through the shared
  atomic JSON writer. Serialization preflight, confinement, permission checks,
  lock ownership, failed-refresh preservation, and attempt finalization ordering
  remain intact. Removes the forwarding writers and test-only unbounded readers.
- Proposal list/detail cache reads use the loader's missing-cache result rather
  than a separate existence probe. A missing snapshot permits the existing
  fallback, including when a file disappears before the read; malformed content
  and filesystem failures remain errors. Local cache inventory/status reports
  retain their presence checks and invalid-content summaries.
- Reuses parsed Governance interval endpoints and removes historical path
  assertions already covered by the exact current cache-path test.

### Compatibility and validation

- Ships as a patch because the changes fix documented behavior and simplify
  private machinery. Public Rust signatures and error variants, CLI grammar,
  report/cache shapes, cache identities, and raw JSON fields are unchanged.
  Every schema identifier remains `1`; the Rust minimum remains 1.91.0.
- Callers supplying timestamp text should use canonical UTC or the existing
  Unix-seconds request constructors. Previously admitted noncanonical text now
  receives the owner's existing validation or stale-data outcome.
- Validation passed: 1,184 workspace tests, focused parser and restored-state
  tests, portable Governance rejection-before-source-call coverage, warning-denied
  workspace and no-default library Clippy, the Rust 1.91.0 workspace check,
  the canister WebAssembly build, public documentation checks, and formatting,
  whitespace, type-documentation, process-boundary, and schema guards. The feature
  and public-API matrix also passed during the earlier cache-consolidation pass.
  Live IC queries, canister deployment/integration smoke, packaging, and the
  complete release gate were not run. No CLI command or option is added.

## 0.45.0 - 2026-10-03

### Compatibility and release scope

- Starts a new pre-1.0 minor line because public error enums gain variants
  that require downstream exhaustive-match updates. Cache and decoder
  ceilings also reject previously admitted oversized content or excessive
  decoding work. Governance endpoint and restored-evidence validation are
  stricter.
- Report, cache, transcript, sidecar, and lock schema identifiers remain `1`.
  No compatibility aliases, fallback readers, or automatic migrations are
  introduced. The Rust minimum remains 1.91.0.

### Cache admission, repair, and locks

- Caps shared JSON cache reads at 64 MiB for inventories, observed node status,
  joined SNS discovery, and exact Subnet topology, or 512 MiB for complete
  NNS/SNS proposal and neuron histories and ICRC account transactions. Metadata
  is checked before allocation; streamed growth stops at the ceiling plus one
  byte. Oversize shared caches return `HostCacheError::CacheTooLarge`.
- Caps Subnet Catalog cache reads at 64 MiB and retains typed
  `SubnetCatalogHostError::CachedCatalogTooLarge` failures with the
  `SubnetCatalogErrorCode::CachedCatalogTooLarge` classification.
- Treats successfully read invalid UTF-8 as invalid JSON content. Invalid-byte
  and oversized caches follow each owner's existing recovery policy;
  cache-only reads make no live calls, genuine IO and confinement failures
  remain errors, and failed repair preserves the previous file.
- Ends refresh-lock ownership immediately after successful removal. A later
  directory sync error is returned without deleting a replacement owner's lock.
- Queues paths rather than live sibling-directory handles during cache-status
  discovery. Bounds visited entries at 16 times the selected-file scan limit
  and directory depth at 32; reaching any bound reports `truncated: true`.
  Reopened paths retain capability-rooted permission and link checks.

### Candid replies and archive callbacks

- Applies finite Candid decoding budgets to native ledger/index, SNS,
  CloudEngine, CMC, Registry, and Governance replies and canister Governance
  replies. Both maintained account-index codecs use the same limits.
- Allows 1,000,000 decoding work units plus 32 times the reply byte length,
  capped at 256,000,000; limits skipped work to 100,000 units, type-table
  entries to 4,096, and type headers to 64 KiB. These supplement transport
  byte ceilings; they are not measured canister instruction counts.
- Follows ICRC-3 archives using the supplied callback method name with its
  typed argument/result contract. Non-default method names are supported;
  execution remains query-only, and per-archive failures remain visible.

### Governance request and restored-report validation

- Uses the native URL parser for portable Governance requests and restored
  provenance. Rejects malformed authorities and ports, credentials, whitespace,
  controls, queries, and fragments. URL parsing is now a direct portable
  dependency without enabling native transport or runtime dependencies.
- Validates canonical UTC collection timestamps and complete-collection
  counters. Neuron and proposal continuations reject a time earlier than the
  previous update before invoking the source; restored states, distribution
  reports, and activity reports require start <= update. Equal timestamps
  remain supported.
- Adds `NnsGovernanceError::InvalidTimestamp` and
  `NnsGovernanceError::InvalidTimestampOrder`. Downstream exhaustive matches
  must handle these and the new cache-size error variants above. Current
  emitted and persisted schema identifiers remain `1`; invalid evidence is
  rejected without a migration or fallback reader.

### CLI output

- Preserves writer IO error kinds when JSON serialization encounters a closed
  stdout pipe. Help, namespace help, and version output use fallible writes;
  early pipe closure exits successfully without a panic or spurious diagnostic,
  matching text-report output.
- CLI library callers using exhaustive error matches must handle the new
  `IcqCliError::Io` variant.

### Cache performance and public documentation

- Streams managed pretty-JSON publication through the atomic temporary file
  after serialization preflight, avoiding another complete encoded cache copy.
- Combines top-level field, schema, and network validation into one JSON header
  pass before typed deserialization. Strict loads use two full traversals
  instead of three while preserving duplicate/unknown-field checks and typed
  schema errors.
- In an isolated harness over the actual old/new loaders with shared
  regular-file IO stubs, five warmed samples per case reduced median load time
  from 0.299 s to 0.221 s at 13.7 MB and from 1.827 s to 1.445 s at 68.5 MB.
  These 26% and 21% improvements measure JSON loading work, not end-to-end
  native cache or network performance.
- Shares retained Registry checkpoints and encoded history pages, tracks
  retained bytes incrementally, and reuses the shared streaming digest helper
  without changing transcript identity or authority.
- Documents 87 additional public API items in the latest audit cleanup,
  reducing its missing-documentation count from 1,418 to 1,331 and prioritizing
  source contracts, requests, and errors. Replaces the aggregate baseline with
  1,331 known item identities, so unrelated documentation improvements cannot hide
  a newly undocumented item. Updates current README, library, CLI, and design
  guidance to match the supported behavior.

Validation passed: 1,182 workspace tests; 354 public API test executions across
feature selections; native, pure, and canister Wasm feature/dependency checks;
warning-denied workspace and pure-library Clippy; the Rust 1.91.0 MSRV check;
eight documentation-gate identity tests; and documentation, formatting,
whitespace, type-documentation, process-boundary, schema, and CI-helper guards.
Fixtures cover amplified Candid decode/skip work, excessive type tables,
wide recursive values, near-8-MiB byte vectors, non-default archive callbacks,
invalid-byte repair, reversed intervals, replacement locks, and closed stdout.
Cache inventory also passed with 120 sibling directories under a 64-descriptor
limit. Live IC queries, canister deployment/integration smoke, packaging, and
the full release gate were not run for this audit slice. No CLI command or
option is added.
