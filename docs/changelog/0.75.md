# 0.75 release notes

## 0.75.5 - 2026-10-28

### Dependencies and contributor tooling

- Align Host, Build and Testkit requirements and executable selections with IC
  Tooling 0.69.4. Its Platform, Wire and Unicode-width minimums match Query's
  existing resolved selections; public APIs and the Rust 1.91 minimum remain
  unchanged.
- Adopt Shared Tooling 0.27.3 at reviewed commit
  `cc81a58a5b2dd287c577cbffd2c576c178b6785c`. Snapshot verification can compare
  declared payload bytes and executable modes with an independently selected
  source commit:

```bash
bash scripts/ci/verify-shared-tooling-snapshot.sh --consumer . \
  --source ../shared-tooling \
  --revision cc81a58a5b2dd287c577cbffd2c576c178b6785c
```

- Unattended maintenance uses explicit source-read/evidence-write filesystem
  scopes, a cleared launch environment and disabled network, app and escalation
  access. Requalify existing host launcher configuration before resuming
  schedules; snapshot adoption does not activate a schedule.
- Add optional sccache catalog and freshness-inspection support. Compiler-cache
  installation remains opt-in and the common executable roster is unchanged.

### Governance canister qualification

- Extend the installed probe with missing-result, excessive-type-table,
  amplified-skipping and oversized-reply cases, while retaining acceptance of
  small unused Candid values.
- Distinguish IC rejection of an oversized reply from Query's 8 MiB admission
  check on received bytes. Document Platform's existing one-shot call ownership
  and Query's external Candid, validation and raw rejection-code responsibilities.
  [#108](https://github.com/dragginzgame/ic-query/issues/108)

## 0.75.4 - 2026-10-28

### Cache inspection

- Preserve native path-component positions during cache inventory classification.
  A non-UTF-8 component leaves the path shape unrecognised, with no known
  recovery or freshness policy. Inspection retains the file and its evidence.

### Dependencies and contributor tooling

- Align direct dependency requirements with IC Tooling 0.69.3, Platform 0.7.1,
  Wire 0.7.18 and Metrics 0.16.3. Build and Testkit executable setup follows the
  selected lockfile versions with their existing explicit CLI features.
- Adopt Shared Tooling 0.27.2 at committed revision
  `7efce1e36275ff9e4bbbdd9ccab9a8d94520fd98` through the canonical exporter.
  Its guidance places native/compiler bootstrap before Cargo-tool preparation
  and keeps shared dependency remediation at the supplying owner. Query retains
  its maintainer-only release boundary and selected consumer fixture scope.

### Internal simplification

- Flatten NNS inventory refresh adapters and construct source provenance once,
  preserving validation before atomic publication and reload after refresh.
- Share SNS collection bookkeeping while keeping family page admission,
  neuron boundary-row handling, progress and failure evidence intact.
- Carry immutable NNS cache admission into distribution and activity projection.
  Public caller-owned inputs retain full validation; activity still checks
  timestamps before filtering and rejected snapshots remain untouched.
- Share ICRC account-history bounds and identity admission, preserving cursor
  semantics, typed errors and deferred refresh checks on cache hits.
- Centralize Dashboard CLI request conversion, project topology coverage directly
  into its reports, and keep provider aggregation together. Subnet status views
  use status-only counting and neuron sort options reuse existing conversion.
  Public APIs, report fields, cache formats and command options are unchanged.

## 0.75.3 - 2026-10-27

### Cache-aware NNS reports

- Add `build_nns_neuron_list_report_with_cache_and_source`,
  `build_nns_neuron_info_report_with_cache_and_source`,
  `build_nns_proposal_list_report_with_cache_and_source` and
  `build_nns_proposal_report_with_cache_and_source`. These builders prefer an
  admitted complete snapshot and use the supplied source when the cache or
  requested detail is absent. Invalid caches remain strict errors and these
  reads do not publish snapshots. Existing live-only and cache-only builders
  retain their behavior.
- Move the CLI's existing cache-selection decisions into these report builders
  and share Governance request conversion through common NNS options.

### Internal simplification

- Carry cache admission into node-status projections without repeating row
  validation and counting. Public raw-snapshot projectors still validate every
  input, and publication still reloads and admits the persisted snapshot.
- Reuse Registry Protobuf decoding with unchanged message labels and share
  optional-value sorting rules, keeping missing values last in either direction.
- Retain parsed identities through shared strict principal admission for
  CloudEngine. Permissive request normalization remains separate.
- Store observed analytics timestamp bounds together and derive unreported-neuron
  counts from the validated collection population. Serialized fields, checked
  amount totals and empty-collection behavior remain unchanged.
- Compare Type4 status scope directly with the canonical ordered constant and
  share Dashboard unsigned-integer admission predicates and failure construction.

## 0.75.0 - 2026-10-27

### Breaking changes and migration

- Adopt published Host, Build and Testkit 0.69.0 with Platform 0.7.0. Query's
  `CertificateVerificationError::Decode` contains Host Tools'
  `certificate::ParseError`, and `authenticate_ledger_tip` returns its
  `ledger_evidence::LedgerTip`. These are package-owned Rust types with new
  identities in Host Tools 0.69. Downstream callers naming these types must
  update their direct `ic-host-tools` requirement to 0.69 alongside Query.
- Host Tools' Registry APIs now share Platform 0.7's owned Principal with Query.
  The selected graph no longer retains Platform 0.6. Required external Agent,
  Candid, Principal, certificate and standard ledger DTO identities remain
  unchanged. The canister runtime retains executor 2.0.0 and ic0 1.2.0.
- No report fields, CLI behavior, wire encodings, persisted schema identifiers
  or cache formats change. Existing cache files require no reset. No compatibility
  wrapper, old reader or dependency override is introduced.

### Shared development policy

- Adopt Shared Tooling 0.26.22 at reviewed revision
  `5fc904a935d82ad31f0fba14434b71ccb8c10345` through its canonical exporter.
  The policy makes external Candid boundaries explicit and strengthens native
  error-derive, source-inspection, machine-output, subprocess and terminal
  diagnostic guidance. Executable scripts and tool catalogs are unchanged.

### Internal cleanup

- Parse ICRC callback ranges once and index them by callback identity, retaining
  disjoint-range checks, callback binding, duplicate refusal and raw evidence.
- Select a Subnet Catalog cache decision before executing one refresh path,
  preserving cache-only behavior, explicit recovery policy and detailed failures.
- Reuse the computed SNS reward summary during internal assembly while keeping
  complete recomputation for untrusted reports and imported checkpoints.
- Separate Registry page-budget accounting and mutation application, preserving
  validation order, pinned versions and partial-history recovery evidence.
- Share Dashboard query-identity and offset-page admission checks, cursor query
  encoding and page text metadata without changing labels, bounds or output order.
- Centralize optional cached-snapshot loading within each NNS family and common
  cache-status row fields, preserving missing-cache, invalid-content and unknown-age
  distinctions.
