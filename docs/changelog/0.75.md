# 0.75 release notes

## 0.75.2

### Native cache fixtures

- Keep SNS refresh-attempt coverage under non-UTF-8 cache roots where the native
  filesystem accepts the name. On macOS, assert the typed directory-creation
  failure and original `EILSEQ` cause when it rejects the name; other setup
  failures remain errors. Production cache-path policy is unchanged.
  [#107](https://github.com/dragginzgame/ic-query/issues/107)

### Shared development tooling

- Adopt published IC Tooling 0.69.2 across Host, Build and Testkit while retaining
  Platform 0.7.0 and the existing feature selections. Prepare the lock-selected
  Cargo metadata editor and Testkit server with their existing explicit CLI
  features, removing the mismatch with older prepared executables. Public Query
  APIs, report fields and cache formats are unchanged.
- Adopt the qualified Shared Tooling 0.27.0 revision
  `a273b49113d25a039ddb1d53a6ac3977453061e2` through the canonical exporter.
  Module-path screening now uses the shared Rust lexer, so unrelated later
  text no longer disables formatting-result reuse. The lexer participates in
  fingerprinting; real external-module attributes still require full formatting.

### Internal cleanup

- Normalize ICRC account-cache targets once across read-through retries. Keep
  refresh-only validation deferred on cache hits and share target comparisons
  between snapshots and attempt sidecars without changing their typed errors.
- Share SNS reward bracket comparisons and mandatory neuron-ceiling admission
  between live collection and persisted-report validation. Preserve independent
  validation, diagnostics and failure ordering at both boundaries.
- Convert shared SNS CLI lookup options in one place and join selected SNS
  metadata directly through the existing exact-target validator.
- Pass grouped topology inventories through converters and provenance helpers,
  and calculate region totals together, preserving read and report ordering.
- Flatten cache-component classification helpers and borrow expected Subnet
  identifiers during Registry evidence coverage checks. Cache recovery, freshness
  and inspection policies remain unchanged.

  retaining command-order, failure-stop and diagnostic-retention checks.
- Adopt Shared Tooling 0.26.24 at reviewed revision
  `16efc62257a40c75f05a5fb8ee53b2f2d135ad00` through the canonical exporter.
  The producer commit and changelog are labeled 0.26.25, but its committed
  `VERSION` still reports 0.26.24. Record that canonical identity; Query's selected
  payloads are unchanged from the preceding adoption because the new scanner
  fixture is outside its snapshot selection.
- Refresh staged-file hooks to preserve opaque submodules and staged gitlink
  identities while formatting selected regular files. Retain Query's existing
  formatter selection and dependency graph.
- Use the shared Rust formatting driver for per-pass progress and elapsed times.
  Preserve grouped manifest sorting, prepared-tool admission, staged-hook
  isolation and retained failure logs; explicit no-cache formatting remains
  available. Conditional-attribute screening currently disables result reuse for
  Query, so formatting still runs in full.
  [Shared Tooling #315](https://github.com/dragginzgame/shared-tooling/issues/315)
  tracks the conservative guard's false positive.
- Adopt the shared gzip ownership guidance. Query has no direct application gzip
  encoders requiring migration; infrastructure evidence archives retain their
  existing owner.

### Internal cleanup

- Reuse the authenticated catalog projection when repairing an archive-binding
  mismatch. Preserve fresh qualification on every load, explicit publication
  policies and rejection of malformed cache content before archive qualification.
- Avoid repeating structural validation during catalog sealing. Keep complete
  validation for untrusted catalogs and preserve metadata/content error ordering.
- Recompute SNS reward checkpoint summaries once during reconciliation, retaining
  usable aggregates and policy observations when checkpoint validation fails.
- Carry explicit routing-shard bounds through Registry collection and centralize
  certified archive evidence projection. Preserve pinned and returned versions,
  shard validation and completed-record failure evidence.
- Share checked Registry chunk-budget arithmetic while preserving ceilings,
  overflow diagnostics and unchanged counters after rejected updates.
- Centralize SNS permission assessability and reuse canonical-principal validation
  for Governance provenance, retaining unspecified and unknown codes and existing
  diagnostics.
- Remove intermediate private ICRC export lists and borrow catalog membership and
  routing sort keys, preserving public entry points and canonical ordering.
- Carry pinned Registry identity and completed response evidence through one
  acquisition context, retaining value-version checks and detailed failure stages.
- Project SNS neuron detail directly into report rows, share neuron-ID admission
  and import internal validators from their owners without changing public exports.
- Accumulate topology provider totals in one pass, share operator-capacity
  arithmetic and reuse summary join counts in checks and text. Preserve unknown
  counts, saturation, relation ordering and flat serialized fields.
- Consume SNS archive/dapp inventory IDs directly during summary matching,
  retaining missing, duplicate and unmatched-summary evidence.
- Share canonical JSON byte-count/hash calculation between cache helpers and
  certified archive admission, retaining independent publication verification.
- Reuse canonical decimal admission for ICRC page evidence while keeping request
  normalization permissive. Construct reward-diff rows from known neuron identities
  without changing new/missing-neuron evidence or allocation behavior.

Public APIs, CLI behavior, report fields and cache formats remain unchanged.
Existing cache files require no reset.

## 0.75.0 - 2026-10-27

### Breaking changes and migration

- Adopt published Host, Build and Testkit 0.69.0 with Platform 0.7.0. Query's
  `CertificateVerificationError::Decode` contains Host Tools'
  `certificate::ParseError`, and `authenticate_ledger_tip` returns its
  `ledger_evidence::LedgerTip`. These are package-owned Rust types with new
  identities in Host Tools 0.69. Downstream callers naming these types must
  update their direct `ic-host-tools` requirement to 0.69 alongside Query.
- Host Tools' Registry APIs now share Platform 0.7's owned Principal with Query.
  The selected graph no longer retains Platform 0.6. Required external Agent,
  Candid, Principal, certificate and standard ledger DTO identities remain
  unchanged. The canister runtime retains executor 2.0.0 and ic0 1.2.0.
- No report fields, CLI behavior, wire encodings, persisted schema identifiers
  or cache formats change. Existing cache files require no reset. No compatibility
  wrapper, old reader or dependency override is introduced.

### Shared development policy

- Adopt Shared Tooling 0.26.22 at reviewed revision
  `5fc904a935d82ad31f0fba14434b71ccb8c10345` through its canonical exporter.
  The policy makes external Candid boundaries explicit and strengthens native
  error-derive, source-inspection, machine-output, subprocess and terminal
  diagnostic guidance. Executable scripts and tool catalogs are unchanged.

### Internal cleanup

- Parse ICRC callback ranges once and index them by callback identity, retaining
  disjoint-range checks, callback binding, duplicate refusal and raw evidence.
- Select a Subnet Catalog cache decision before executing one refresh path,
  preserving cache-only behavior, explicit recovery policy and detailed failures.
- Reuse the computed SNS reward summary during internal assembly while keeping
  complete recomputation for untrusted reports and imported checkpoints.
- Separate Registry page-budget accounting and mutation application, preserving
  validation order, pinned versions and partial-history recovery evidence.
- Share Dashboard query-identity and offset-page admission checks, cursor query
  encoding and page text metadata without changing labels, bounds or output order.
- Centralize optional cached-snapshot loading within each NNS family and common
  cache-status row fields, preserving missing-cache, invalid-content and unknown-age
  distinctions.
