# 0.46 Changelog

## 0.46.5

### CI and release fixture simplification

- CI, release, and publication fixtures compare trace files directly rather
  than loading command logs into arrays and separately checking lengths,
  indices, or joined strings. Removes `mapfile`, negative array indexing,
  and redundant count state. Expected multi-step plans retain their small
  ordered arrays; actual execution evidence remains in its trace file.
- Failed CI cases check the complete expected prefix, including every command
  preceding the failure. Publication delegation and release sequence checks
  preserve command boundaries instead of flattening lines into space-joined
  strings. Extra, omitted, reordered, or combined command lines are rejected.
- Mock Make commands use the existing last-positional-argument idiom instead
  of negative-offset expansion. The changed fixtures no longer depend on the
  Bash features identified as unavailable in bundled macOS Bash 3.2. This
  removes known shell blockers; it does not qualify native macOS workflows.
- Keeps sequential patch/minor/major orchestration, failure status propagation,
  cleanliness/tag checks, library-before-CLI publication, index visibility,
  retry-safe publication, and artifact retention checks. Fixtures use isolated
  temporary workspaces and mock tools; production release scripts and Make
  recipes are unchanged.
- No CLI surface, public Rust API, report/cache shape, dependency, package
  version, or schema identifier is changed; schemas remain `1`.

### Verification

- Reproduced the existing CI fixture failure with `mapfile` disabled, then
  passed CI-script, release-guard, and publication-guard fixtures under the
  same restriction. The CI-script fixtures include eight maintained
  documentation-parser unit tests.
- An injected wrong intermediate command, retaining the expected failed-trace
  length and final target, was rejected by the complete-prefix comparison.
- Shell syntax, ShellCheck, and whitespace checks passed for the changed
  scripts. Mock fixtures performed no real publication, commit, tag, push,
  dependency fetch, or repository version change.
- Rust code is unchanged; Cargo tests/Clippy, full workspace/CI/release gates,
  MSRV, packaging, and publishing were not run. Standalone Bash 3.2 and native
  macOS execution are unavailable here; the host matrix and native
  qualification remain required.

## 0.46.4

### Formatting, Dashboard validation, and tooling cleanup

- Cycle counts and arbitrary-precision decimal cycle rates use one authoritative
  unit table. Integer count conversion and decimal rate rounding retain their
  distinct input contracts; byte counts retain binary IEC units.
- Decimal rate rounding reads the three required digits from borrowed input
  instead of assembling a temporary scaled fractional string. Full input
  validation, half-up rounding, unit promotion, leading-zero handling, values
  above `u128`, and sanitized invalid-input fallback remain unchanged. Removes
  a redundant decimal-point check already enforced by ASCII digit validation.
- Token base-unit rounding uses the existing suffix width and first digit
  directly, deleting its padding helper and temporary discarded-digit string.
  Leading zeros are normalized in the existing input buffer instead of copying
  the normalized substring. Keeps canonical digits before scaling/rounding,
  fixed two-decimal output, half-up carries, the full `u8` precision range,
  underscore/whitespace handling, and unchanged invalid-input fallback. ICRC,
  SNS, and Governance callers retain their shared formatter and raw amounts.

  enforce uniqueness, removing a separate set and principal copies. Independent

  validation, build/evidence preservation, tooling ownership, feedback, and

## 0.46.3

### Shared hex decoding and subaccount validation

- Malformed Unicode ICRC subaccounts now return `IcrcError::InvalidSubaccountHex`
  instead of panicking when a two-byte substring crosses a UTF-8 character
  boundary. CLI subaccount options report an ordinary argument error before
  dispatch or live source calls.
- Rejects signed byte pairs such as `+a` that the old integer parser could
  accidentally interpret as hexadecimal bytes. Non-hexadecimal input has an
  explicit ASCII-hexadecimal diagnostic. Odd-length input retains its separate
  hex error; valid hex of the wrong byte length retains
  `IcrcError::InvalidSubaccountLength`.
- ICRC subaccount normalization and SNS neuron-id parsing use the existing
  shared lowercase-hex decoder, removing their separate decoding loops. The
  decoder is available to portable subaccount APIs without a host feature.
- ICRC still accepts mixed-case hex and surrounding whitespace, normalizes to
  lowercase, and requires exactly 32 bytes. SNS IDs remain exactly 64 lowercase
  ASCII hex characters with no whitespace normalization. Invalid SNS IDs fail
  with `SnsHostError::InvalidNeuronIdText` before discovery or source calls.
- Registry/archive callers retain strict lowercase decoding, including valid
  empty byte strings. No compatibility parser, dependency, CLI surface, public
  Rust API, report/cache shape, or schema identifier is added or changed;
  schemas remain `1`. Package metadata is unchanged in this prepared slice.

## 0.46.2

### SNS checkpoint and sorting cleanup

- SNS reward collection derives exhaustion from its admitted page count and
  next cursor instead of storing a redundant completion flag. A new collection
  remains distinguishable from an API-exhausted empty collection. Rejected
  pages preserve accepted progress; pages after exhaustion remain errors.
- Ending parameters, reward-event, and running-version responses must still
  equal the validated starting responses in full. Removes repeated evidence
  validation after those equality checks. Collection call order, mandatory
  row/page ceilings, diagnostic caps, strict pagination, final completion-time
  checks, and independent restored-checkpoint validation remain enforced.
- NNS and SNS proposal text comparison folds ASCII bytes during comparison
  instead of constructing lowercase string copies. Ascending/descending
  ordering, prefixes, empty values, and non-ASCII bytes retain their existing
  semantics. Optional text still places missing values last.
- SNS neuron stake, maturity, and creation sorts share one local comparator
  for descending numeric values and ascending neuron-id ties. It compares
  borrowed IDs instead of cloning string keys; API and ID ordering are
  unchanged. Cache-backed sorting and limits remain view operations.
- Live neuron details, reward pages, and restored checkpoints share the neuron
  model's permission and pending-disbursement validation. Removes the separate
  checkpoint implementation of canonical principal, duplicate principal/code,
  permission-label, and destination-subaccount checks. Each trust boundary
  still validates independently. Detail requires permission principals;
  checkpoints preserve missing principals and unknown/unspecified codes as
  unassessable evidence. Malformed restored checkpoints now distinguish
  incorrect permission labels from duplicate codes in their diagnostics.
- Public Rust APIs, CLI commands/options, text and JSON report shapes, cache
  identity and shape, and schema identifiers are unchanged; schemas remain
  `1`. Package metadata is unchanged in this prepared release slice. No new
  dependency, compatibility path, or sorting framework is added.

## 0.46.0

### Cache-only NNS analytics

- Adds `icq nns proposal activity`, reporting retained proposal counts by topic,
  decision status, reward status, and UTC creation day. `--from` is inclusive
  and `--until` exclusive, both in Unix seconds; invalid windows fail visibly.
- Adds `icq nns neuron distribution`, reporting public-neuron state, visibility,
  and type counts, effective stake, and coverage-aware optional-field totals.
- Both commands read only the complete local snapshot, support text and raw
  JSON, and reuse the existing pure calculations and renderers. They do not
  fetch, refresh, retry, or create another cache. Missing and invalid snapshots
  fail rather than falling back to a live call. Completeness means observed API
  exhaustion; neither report claims certified or point-in-time data.

```bash
icq nns proposal refresh
icq nns proposal activity
icq nns proposal activity --from 1700000000 --until 1700100000 --json
icq nns neuron refresh
icq nns neuron distribution
icq nns neuron distribution --json
```

### Collection evidence and library APIs

- Complete NNS snapshots retain the actual final portable `collection_state`
  beside their rows. Native publication carries that state directly, replacing
  separate completion-result page-count and cursor fields. Readers validate
  state lifecycle and its agreement with snapshot identity, concrete replica
  provenance, timestamp, page accounting, and row count before projecting data.
- Adds `build_nns_proposal_activity_report_from_cache` and
  `build_nns_neuron_distribution_report_from_cache` under `nns-host`. They use
  `NnsGovernanceCacheRequest` and return the existing analytics reports, with
  recorded collection times rather than reconstructed continuation state.
- Adds `NnsProposalHostError::Activity`, `NnsNeuronHostError::Distribution`,
  and `NnsNeuronHostError::MissingNeuronCache`. Missing neuron snapshots now
  carry an explicit refresh command; downstream exhaustive matches must update.
- NNS proposal and neuron cache shapes change in place at schema `1`.
  Existing snapshots require an explicit successful refresh before cache-backed
  reads. There is no fallback reader, automatic migration, or schema increment.
  Snapshot paths, cache identities, pure analytics APIs, and analytics JSON
  shapes remain unchanged. No dependency or feature is added. Package version
  metadata remains unchanged in this prepared release slice.
