# 0.38 Changelog

## 0.38.4 - Unreleased

### Resumable complete NNS proposal and public-neuron walks

- Adds `NnsProposalCollectionState` and `NnsNeuronCollectionState`, portable
  serializable schema-1 continuations that bind network and source selection
  and retain concrete collector provenance, page/row accounting, the family-
  specific exclusive cursor, caller-supplied time range, and lifecycle.
- Adds `advance_nns_proposal_collection_with_source` and
  `advance_nns_neuron_collection_with_source`. Each validates the request and
  retained state before making exactly one bounded family-specific call and
  returns the page with candidate next state; callers persist the state only
  after retaining that page.
- Requires an explicit valid page size and nonzero cumulative page ceiling.
  A full final budgeted page with another cursor becomes
  `page_limit_reached`, not `complete`. Proposal exhaustion requires a short
  page or terminal proposal id; neuron exhaustion requires a short page.
- Makes neuron report DTO deserialization portable so serialized collection
  steps can be restored without the native host feature. Native complete
  proposal and neuron cache refreshes use the corresponding continuation
  engines.
- Adds no CLI surface, automatic loop, retry, stable-memory layout, scheduler,
  or canister publication policy.

## 0.38.3 - Unreleased

### Canister-native bounded NNS neurons

- Adds one-call bounded public neuron-index pages and exact public neuron
  detail to the existing `canister` feature and `CanisterNnsSource`. Both use
  replicated inter-canister execution, attach no cycles, perform no retries,
  enforce the shared 8 MiB raw-response ceiling, and return typed failures.
- Makes native, canister, and custom neuron sources converge on one portable
  async source, wire conversion, request/provenance validation, ordered-page
  validation, and report assembly path. Pages accept 1 through 300 upstream
  rows and never follow a returned cursor automatically.
- Hard-cuts schema-1 neuron reports to the shared flattened Governance context
  and tagged source provenance. Complete cache refresh stays native-only;
  cache reads retain the replica-query evidence that collected them.
- Adds no CLI command, option, automatic pagination, retry, scheduling,
  filesystem cache behavior, or stable-memory policy.

## 0.38.1 - Unreleased

### Release integrity

- Stages every file generated by a version bump, including README and library-
  usage dependency examples. `release-commit` rejects unstaged, untracked, or
  unexpected staged paths and creates the release tag only if the commit leaves
  a clean tree. Post-gate Cargo cleanup retries once so a concurrent missing-
  artifact race does not produce a spurious warning.

## 0.38.0 - Unreleased

### Canister-native NNS Governance boundary

- Keeps the existing two-crate workspace: `ic-query` owns reusable reporting
  and runtime adapters, while `ic-query-cli` remains the only CLI crate.
- Adds one `canister` runtime feature, exposing the four bounded
  direct NNS Governance reports without enabling the native host, Tokio,
  `ic-agent`, Reqwest, or filesystem cache graph. `ic-query-cli` retains no
  feature matrix and always uses the full native host surface.
- Hard-cuts the direct Governance request, source, and schema-1 provenance
  contracts to one tagged enum that distinguishes native replica queries from
  replicated inter-canister calls. Transport assurance is derived from the
  variant, transport-incompatible field combinations are unrepresentable, and
  malformed native endpoints fail validation before source invocation.
- Makes native and canister transports share one caller-runtime async
  source, validation, and report-assembly path.
- Leaves persistence, scheduling, retries, cycle budgeting, and stable-memory
  policy with the consuming canister.

Each built-in canister source operation makes exactly one `Call::bounded_wait`
call to the fixed mainnet Governance canister, attaches no cycles, enforces an
8 MiB raw response ceiling before Candid decoding, and maps call rejects,
timeouts, encoding, decoding, source-evidence, and payload validation failures
to typed errors. The caller supplies collection time and owns execution
context, scheduling, retry, cycle-budget, and durable-state policy.

Detailed design: [0.38 canister-native NNS Governance reporting](../design/0.38/0.38-design.md)

### Release tooling

- Runs `cargo audit` against a fresh disposable RustSec checkout on every
  dependency gate instead of its long-lived shared advisory cache. This avoids
  duplicate-ID and related parse failures from files retained after upstream
  advisory moves, without weakening advisory freshness or deny rules. The
  helper removes its exact temporary checkout on success and failure.
