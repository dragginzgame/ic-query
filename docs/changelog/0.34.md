# 0.34 Changelog

## 0.34.0 - Unreleased

### CloudEngine provider inventory and detail

- Adds `icq cloud-engine provider list` for one complete official Dashboard
  node-provider resource. The report validates every returned row, up to
  1,000, before retaining providers with a nonzero CloudEngine count or at
  least one CloudEngine location.
- Adds `icq cloud-engine provider info <node-provider-id>` for one exact NNS
  node-provider principal. It preserves the provider's complete raw general
  and CloudEngine counts, locations, website, and nullable logo, and reports
  `cloud_engine_evidence_present: false` instead of hiding a valid provider
  whose current record contains no CloudEngine evidence.
- Keeps node-provider identity distinct from CloudEngine Subnet principals,
  operator-canister principals, and engine instances.

```bash
icq cloud-engine provider list
icq cloud-engine provider list --json
icq cloud-engine provider info rbn2y-6vfsb-gv35j-4cyvy-pzbdu-e5aum-jzjg6-5b4n5-vuguf-ycubq-zae
```

### Authority and bounds

- Uses the official Dashboard v3 node-provider resources as their own
  off-chain authority. Reports identify `official_ic_dashboard_api`, preserve
  the explicit source endpoint and retrieval time, and state
  `certified: false` and `point_in_time_guaranteed: false`.
- Makes exactly one REST request for either operation, rejects response bodies
  above the shared 8 MiB ceiling, and creates no report cache.
- Rejects empty or oversized complete resources, duplicate or noncanonical
  provider principals, inconsistent location counts, duplicate data-center
  keys, invalid coordinates, and impossible unassigned-node totals. General
  and CloudEngine location arrays are validated independently because the live
  API exposes them as different scopes.
- Does not join the separate boundary-node location aggregate: that resource
  contains city buckets and counts but no node or provider identifiers.

### Library and maintenance

- Exposes pure schema-1 provider request/report/location DTOs and text
  renderers without host dependencies.
- Extends `dashboard-host` with `CloudEngineProviderSource`, source-data
  contracts, live/custom-source builders, and the existing `LiveIcSource`.
  Native control-plane support remains independently owned by
  `cloud-engine-host`.
- Extends focused feature and public-API checks for the Dashboard-backed
  CloudEngine capability.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| CLI | New `cloud-engine provider info|list` namespace | Use it for Dashboard provider footprint; keep `cloud-engine info|list|prices` for Registry and native control-plane evidence |
| Pure library | New provider request, report, row, location, constants, and renderers | Import them from `ic_query::cloud_engine` |
| Focused host | Provider source trait and builders under `dashboard-host` | Enable `dashboard-host` when only official Dashboard provider collection is needed |
| Cache/schema | Live-only schema-1 reports; no persisted cache | None |
