# 0.80 release notes

## 0.80.0

### ⚠️ Breaking

- SNS neuron list requests select `SnsNeuronCollection::Live` or `Cached`.
  Construct them with `SnsNeuronsRequest::live` or `cached`; cached requests
  require a root and `SnsNeuronsCacheSort`. Owner filtering belongs only to live
  requests. Cached requests no longer carry an ignored live owner or optional
  cache root; remove matching of the obsolete `SnsHostError::MissingCacheRoot`
  variant. CLI options, bounds and acquisition behavior are unchanged.
- Custom SNS metadata and lifecycle sources return `outcome: Result<_, String>`.
  Successful metadata carries `MainnetSnsMetadataFields`, whose individual fields
  remain optional; lifecycle success preserves the raw numeric code. Keep query
  failures in the error outcome. Catalog/report JSON and retained failure evidence
  are unchanged, including unnamed-project fallback and unknown lifecycle codes.
- Inventory detail reports compose their canonical `node`, `node_operator`,
  `node_provider` or `data_center` row. Catalog list, info and refresh reports
  compose `metadata: SubnetCatalogReportMetadata`. Read Rust fields through
  those records; flattened JSON retains its existing field names and raw values.
- ICRC transaction reports compose `transactions: IcrcTransactionsData` and
  followed archive rows compose `block: IcrcTransactionBlockRow`. Custom sources
  and renderers use those shared payloads; block summaries and raw evidence are
  preserved in the existing JSON shape.
- NNS refresh reports use `cache::SnapshotRefreshAttemptStatus` directly. SNS and
  ICRC attempt reports compose it as `lifecycle`, alongside their family identity
  fields. Replace the former NNS-specific status type and use the nested Rust
  fields for SNS/ICRC. Stored sidecars and emitted status JSON remain unchanged.

### 🧹 Cleanup

- Parse SNS proposal, neuron, metrics and reward-checkpoint commands directly
  into public requests. Keep clocks, cache-root resolution and process output at
  the CLI boundary, with existing argument errors and help behavior.
- Carry one Registry version/evidence contract from native collection through NNS
  validation. Preserve certificate authentication, request binding and original
  evidence rather than copying it into parallel DTOs.
- Project catalog metadata from one admitted catalog and replace the report
  construction macro with ordinary typed records. Keep cache disposition,
  freshness and refresh-only results in their respective envelopes.
- Share validated refresh-attempt projection across NNS, SNS and ICRC while
  retaining family admission checks and failure/finalization evidence.
- Render shared SNS context fields through common helpers, preserving report
  ordering, escaping and blank lines before tables.

### 🧭 Migration Notes

- This is a pre-1.0 Rust API hard cut. Update callers and custom sources together;
  no compatibility aliases or wrappers retain the replaced contracts.
- Existing schema-1 snapshots and sidecars remain readable without regeneration
  or reset. External canister protocols, cache identities, JSON fields and CLI
  commands/options are unchanged.

### 🔧 Changed

- Raise the Build and Foundation Host minimums to published 0.73.2 and Wire to
  0.13.1; require Host Tools/Testkit 0.75.1. These dependency updates preserve raw
  report fields, protocol frames, schema-1 caches and the Rust 1.91 requirement.
- Prepare the newly selected locked Build metadata editor with
  `make install-release-tools` before offline admission. Wire remains limited to
  development probes and fixtures; production graphs still exclude it.
- Testkit now selects arithmetic-only Metrics 0.24, sharing Query's resolved
  Metrics identity and eliminating the development-only 0.23.2 package. Prepare
  the updated locked Testkit CLI through the existing shared installer; the
  selected simulator server and protocol budgets are unchanged.

### 🩹 Fixed

- Repair catalog entries left behind by the 0.79.0 release. Future release
  preparation delegates all three version projections to Build's TOML
  renderer instead of rewriting only the library entry. Fixtures assert that
  every catalog version matches the prepared workspace and lockfile versions.
