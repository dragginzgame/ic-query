# 0.39 Changelog

## 0.39.1 - Unreleased

### Retained activity report validation

- Adds `validate_nns_proposal_activity_report`, a synchronous pure validator
  for schema-1 `NnsProposalActivityReport` values restored from caller-owned
  storage or received across another application boundary.
- Adds typed `NnsProposalActivityValidationError` failures with deterministic
  reasons for invalid schema, mainnet identity, source provenance, collection
  page evidence, false point-in-time assurance, half-open window accounting,
  included timestamp ranges, dimension classifications, canonical ordering,
  nonzero row counts, count totals, and UTC-day alignment and coverage.
- Routes freshly built reports through the same validator before returning
  them, keeping publication and restored-report checks on one invariant path.
- Keeps the schema version at `1` and adds no compatibility reader, crate,
  Cargo feature, dependency, network call, cache or stable-memory policy, or
  CLI surface.

## 0.39.0 - Unreleased

### Portable NNS proposal activity analytics

- Adds `build_nns_proposal_activity_report`, a synchronous pure projection
  over a valid, API-exhausted `NnsProposalCollectionState` and the complete
  caller-retained proposal rows accounted for by that state.
- Adds schema-1 `NnsProposalActivityReport` output with collection network,
  Governance canister, source and collector provenance, start/update times,
  admitted page/row counts, and an explicit false point-in-time guarantee.
- Supports an optional inclusive `from` and exclusive `until` proposal-
  creation timestamp window. Reports retain included and both excluded counts,
  the observed included timestamp range, and canonically ordered topic,
  decision-status, reward-status, and UTC-day counts.
- Preserves distinct unknown raw native codes even when they share the
  `Unspecified` classification. Missing, zero, duplicate, count-inconsistent,
  or raw/typed-inconsistent rows and incomplete collection states return typed
  `NnsProposalActivityError` failures instead of partial output.
- Adds a reusable text renderer with separate provenance, selection, topic,
  status, reward-status, and daily-activity sections. JSON retains raw codes,
  Unix seconds, provenance, and counts.
- Keeps the builder and renderer available under `default-features = false`
  for native and Wasm callers. Adds no crate, Cargo feature, dependency,
  network call, cache, persistence policy, or CLI surface.
