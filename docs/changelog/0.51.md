# 0.51 release notes

## 0.51.0

- Hard-cuts the Governance development harness to one Rust runner,
  `governance_smoke`. Make targets and the ICP build callback select it directly.
  Deletes the Python orchestration and fixtures, both separate Rust helpers,
  and the serialized request/result and Unix-socket cancellation transport.
  Direct script/helper callers must update together; no aliases or fallback
  entry points remain. Production `icq` and the canister runtime gain no process
  or mutation surface. [#29](https://github.com/dragginzgame/ic-query/issues/29).
- Keeps schema-1 receipt fields, adjacent original Candid reply files, durable
  checkpoints, fresh private attempt directories and exact deployed-module and
  metadata verification. Previous receipts stay caller-owned evidence. Cleanup
  retains five seconds for TERM grace and five seconds for bounded reaping;
  successful background startup hands off only after output admission.
  Operation errors remain primary when runtime cleanup or receipt storage fails.
- Retains explicit endpoints, loopback-only local root-key fetching, built-in
  mainnet trust, disabled redirects, body limits and agent-call deadlines.
- Requires exactly one Candid text reply within 2 MiB, bounded decoding and
  skipping work, 4,096 type entries and a 64 KiB header. Stores original bytes
  before admission and preserves arbitrary-precision JSON numeric evidence.
  [#30](https://github.com/dragginzgame/ic-query/issues/30).
- Reports inventory refresh progress from the shared library read-through
  decision, and catalog refresh progress after source selection and refresh-lock
  admission. NNS list/info and CloudEngine list render those events on stderr.
  Invalid-cache and selected stale-cache refreshes are visible; valid hits,
  cache-only reads and authority refusals do not announce a source call.
  [#28](https://github.com/dragginzgame/ic-query/issues/28).
- Selects published Host 0.8.8, retaining explicit command deadlines, owned
  process groups and the five-second TERM/reaping policy. The new direct-child
  API does not replace group ownership required for smoke runtime cleanup.
- Standard maintainer release entry points prepare the selected lockfile with
  `cargo fetch --locked` after source/candidate admission and before offline
  validation. Explicit Cargo offline settings remain authoritative; missing-cache
  and network failures preserve their diagnostics/status and stop without retry
  or lock repair. Standalone adapters remain offline, and saved-evidence recovery
  does not fetch against partially prepared metadata. Internal preparation
  permission is removed before child dispatch. The adopted shared contract now
  documents this preparation convention and authorized dependency network access.
  [Shared #84](https://github.com/dragginzgame/shared-tooling/issues/84).
- Removes `scripts/dev/cloc-tooling.pl`, its snapshot record and the local help
  and host-guide references. Fleet inventories stay with Shared Tooling. Query
  keeps `scripts/dev/cloc.sh`, shared tool setup/checks and checksum verification.
  The unchanged shared Make include explains the optional selection when someone
  invokes `cloc-tooling` directly. [#31](https://github.com/dragginzgame/ic-query/issues/31).

- Adopts reviewed Shared Tooling 0.1.35 at
  `be550afa57fe9e16872e5110b5cd69c24b4fa9e8` through the canonical exporter,
  selecting 73 files and retaining the separate engineering baseline. The shared
  pin parser admits the complete six-tool, three-host matrix before emitting
  records for comparison; comments and row order no longer force downloads.
  The installed pins remain the exact installation input, and reuse preserves
  caller files, installed receipts and the active bundle. Changed records still
  refuse offline reuse before executable admission. File-hash and exact-version
  verification remain required. Owner installer fixtures and fleet dashboards
  remain with Shared Tooling.
  [Shared #79](https://github.com/dragginzgame/shared-tooling/issues/79).
- The optional shared Rust installer accepts an exact registry package with one
  binary or example and an explicit debug/release profile. It checks Cargo
  provenance, binary and receipt digests without executing the installed target,
  reuses matching selections offline, preserves earlier installations and failed
  build evidence, and refuses concurrent ownership or redirected paths.
  Query's existing tool setup recipes retain their selections.
  [Shared #65](https://github.com/dragginzgame/shared-tooling/issues/65).
