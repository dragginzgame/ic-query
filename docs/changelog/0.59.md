# 0.59 release notes

## 0.59.0

- **Breaking:** Replace the Governance probe's filtered raw-byte source digest
  with IC Build's root-relative captured-inventory digest. All selected regular
  files, including non-Rust files, directory membership and missing observations
  contribute. Remove the second file-reopen/hash pass and the CLI's direct SHA-2
  dependency. Required-input checks and post-projection validation remain.
- Generate new probe artifacts and matching receipts together. The schema-1
  `source_sha256` field now describes this complete inventory; external comparison
  consumers must adopt the replacement contract. Preserve old artifacts and their
  evidence without a fallback reader or migration. This is not build attestation.
  [#65](https://github.com/dragginzgame/ic-query/issues/65).
- Use the published IC Metrics nearest/half-up ratio projection for topology
  coverage and capacity, preserving one-decimal text, zero-denominator `-` and raw
  report fields. Admit denominator widths explicitly; overflowing coverage totals
  render `-` rather than presenting saturation as an exact total.
  [#56](https://github.com/dragginzgame/ic-query/issues/56).
- Adopt IC Build 0.8's published Host Process 0.21 boundary for the development
  harness. Preserve cancellation, original process evidence, five-second TERM
  grace and five-second bounded reaping.
- Replace remaining CLI, Governance smoke and topology API fixture-directory
  allocators with Host FS's existing collision-safe, private allocation. Tests
  needing missing cache roots select unused children and retain their own cleanup.
- Use the captured header as cache-inspection completion evidence, removing
  formatted Serde-error matching. Preserve full-document validation for managed
  caches, bounded prefix-only history inspection and genuine header failures.
- **Breaking:** Remove `ic_query::nns::NnsGovernanceQueryError` and its conversion
  into `NnsGovernanceError`. Native Governance, proposal and neuron sources now
  propagate `NnsGovernanceError` directly; consumers must update imports and
  conversions. No replacement alias remains.
- Share native NNS Candid transport and bounded reply decoding with ICRC and SNS.
  Preserve endpoint-bound agents, response ceilings, empty versus single-argument
  requests, encoding-before-agent admission and family-specific diagnostic labels.
- Decode subaccounts and retained hex evidence through one ASCII byte-pair loop.
  Subaccounts still trim whitespace, admit mixed case and require 32 bytes;
  evidence still requires lowercase without trimming.
- Fold neuron distribution and proposal activity dimensions through report-local
  validators. Preserve unknown raw codes, optional-code ordering, classification
  checks, nonzero counts, checked count/stake totals and day-specific validation.
- Route missing-only and stale node-status reads through one recovery flow.
  Missing-only reads retain expired complete snapshots; stale reads retain the
  existing 60-second threshold, recovery classification and progress reporting.
- Share portable proposal/neuron continuation request binding, identity/time
  admission and page ceilings under Governance validation. Preserve family error
  variants, validation precedence, schema-1 fields and distinct cursor/exhaustion
  rules. Retained provenance remains independently checked before source calls.
- Validate SNS reward checkpoints and retain their derived summaries for diff
  projection. Valid checkpoints avoid a second summary computation; invalid
  checkpoints retain independently derivable raw aggregates and policy evidence,
  remain invalid and receive no allocation. Public validation and JSON stay unchanged.
- Derive reward-diff new/missing neuron flags from before/after row presence,
  removing redundant internal boolean arguments while retaining report fields.
- Match restored archive manifests against their exact compact JSON encoding
  through the shared streaming matcher, removing the second serialized byte buffer.
  Preserve original manifest bytes, typed failures and retained-object authentication.
- Route CloudEngine argument encoding and bounded native queries through the
  shared Candid mechanics. Preserve mainnet admission, agent response limits,
  exact query counts and request/response diagnostic labels. CloudEngine unit
  tests require Registry fixtures only when catalog support is selected.
- Share live/cached NNS proposal view projection and request-derived report
  assembly, removing the duplicate list-parts DTO. Cached snapshots retain their
  extra cursor/status filtering and post-sort limit; live pages retain API scope.
- Share strict principal-text evidence checking across Dashboard, CloudEngine,
  SNS and topology validation. Preserve family error variants and messages;
  request normalization remains separate from evidence rejection.
- Handle Host 0.22's additional artifact length-error variant as invalid read
  data; dependency selections remain unchanged by this cleanup.
- **Breaking:** Replace the two SNS neuron/proposal refresh requests with
  `SnsSnapshotRefreshRequest` and both results with `SnsSnapshotRefreshReport`.
  Refresh JSON identifies `collection` as `neurons` or `proposals` and reports
  `row_count`. Replace both family refresh text functions with
  `sns_snapshot_refresh_report_text`; update imports, field access and scripts.
  The report remains schema 1. Persisted snapshots and attempt sidecars keep
  their current contracts; no stored evidence needs replacement for this change.
- Remove the request-view trait, forwarding macro, request-generic refresh
  plumbing and duplicate publication/report mappings. Collection-specific source
  traits, cursor validation, page limits, locking and post-publication sidecar
  finalization retain their boundaries and failure evidence.
- **Breaking:** Remove `NnsGovernanceHostError`. All four native Governance
  point-report builders return `NnsGovernanceError` directly, matching their
  caller-source counterparts. Update error annotations and pattern matches;
  network admission, transport diagnostics and error details remain unchanged.
- Assemble live and cached SNS neuron lists through one shared owner and reuse
  the existing SNS identity context for neuron and proposal reports. Preserve
  owner-filtered bounded live scope, cached pre-limit totals, view settings,
  acquisition provenance and raw JSON fields.
- **Breaking:** Replace `NnsNeuronRefreshReport` and `NnsProposalRefreshReport`
  with `NnsGovernanceRefreshReport`, owned by `nns::governance` and exported at
  `nns`. Replace both family refresh renderers with
  `nns_governance_refresh_report_text`. Update imports and JSON consumers from
  `neuron_count`/`proposal_count` to `row_count`; use `collection` to identify the
  result. Both families expose `wrote_cache` and `point_in_time_guaranteed`,
  derived with row counts and provenance from the successfully published snapshot.
  Report schema remains 1; persisted snapshots and sidecars are unchanged.
- **Breaking:** Replace flat inventory settings on `NnsNodeListRequest` with
  `inventory: NnsInventoryListRequest`, retaining separate `filters` and the
  constructor/filter helpers. Remove the internal inventory-input forwarding
  trait and implementations; cache loading now takes the concrete shared request.
  Filtering still follows complete inventory acquisition and does not affect
  cache identity, recovery or refresh progress.
- **Breaking:** Replace the node, node-provider, node-operator and data-center
  refresh report types/renderers with `nns::NnsInventoryRefreshReport` and
  `nns::nns_inventory_refresh_report_text`. Refresh JSON identifies `collection`
  as `nodes`, `node_providers`, `node_operators` or `data_centers` and uses
  `row_count` instead of family count fields. `governance_canister_id` is optional
  and present for provider metadata. Update Rust imports, struct literals,
  scripts and custom topology source implementations. Family refresh builders
  remain distinct. Removed family refresh-schema constants have no replacement;
  the common report schema remains 1. Persisted inventory snapshots keep their
  existing shapes and require no reset for this change.
- Project publication outcomes once from admitted inventory and actual write
  evidence. Topology uses those collection labels/counts directly; dry runs,
  explicit exports and cache replacement flags keep their current policies.
  Custom topology refresh sources must return the collection selected by each
  capability; mismatches refuse before invoking the next source.
- Remove the remaining leaf cache/refresh request traits, implementation macro,
  fixture-only request types and CLI refresh-result/formatter indirection. The
  cache helpers and fixtures use the concrete shared inventory requests.
- Apply SNS eligibility, proposer, text search and sorting through one view
  helper after source-specific scope selection. Live mixed-case queries now
  match case-insensitively like cached queries, while reports retain the exact
  query text. Cached before/status/topic filtering and final limit, live page
  limits, sort tie breakers and cache identities remain unchanged.
- **Breaking:** Compose targeted SNS neuron, proposal, metrics, reward and
  complete-snapshot refresh requests from `lookup: SnsLookupRequest`. Constructors
  accept that scope followed by their operation settings; snapshot refresh takes
  `(cache_root, lookup, page_size)`. Update direct field access and struct literals.
  Builders borrow the existing lookup instead of reconstructing it. Cache-only
  and whole-SNS list requests retain their separate scope. Collection clocks,
  endpoints, admission order, page ceilings and report/cache JSON remain unchanged.
- **Breaking:** Remove `NnsTopologySourceRequest` and
  `NnsTopologyRefreshSourceRequest`. Topology source capabilities take
  `NnsTopologyReadRequest` or `NnsTopologyRefreshRequest` directly. Refresh requests
  compose `read: NnsTopologyReadRequest` and their constructor takes `(read,
  lock_stale_after_seconds)`. Update custom adapters and callers. Live adapters
  needing caller-clock provenance can use `read.source_request()`; cached reports
  retain their original provenance. Remove the request-parts traits, forwarding
  implementations and source-request reconstruction helpers without aliases.
- **Breaking:** Replace `NnsNeuronVote` and `NnsProposalVote` with
  `nns::governance::NnsGovernanceVote`. Codes 0/1/2 retain their current labels;
  all other i32 codes retain their exact value as `unknown(code)` in text/JSON.
  Update imports and use Display for labels. Neuron and proposal transport/source
  boundaries share the canonical type; their report families remain distinct.
- Proposal source and stored-snapshot admission reject raw/classified ballot
  disagreement with typed errors. The schema remains 1. Proposal snapshots with
  unknown raw codes paired with a collapsed classification require explicit
  refresh under the replacement contract. Preserve retained source evidence;
  cache reads never rewrite or migrate those bytes. Known-code snapshots and
  neuron snapshot labels retain their current shapes. No compatibility aliases,
  fallback classification, alternate reader or automatic migration is introduced.

- **Breaking:** Introduce `ic::IcDashboardRequest` as the endpoint/caller-clock
  scope for Dashboard operations. It replaces `IcBoundaryNodeDataCentersRequest`
  and `IcNodeStatusSnapshotRequest` directly. Canister, metric, daily-statistics,
  replica-version, provider-reward, CloudEngine Dashboard and ICRC analytics targets compose it through
  `dashboard`; their constructors accept that scope before operation settings.
  ICRC analytics leaf constructors also receive the Dashboard scope before ledger
  identity and query. Update imports, literals and field access. The scope derives
  live `IcSourceRequest` provenance once; custom-source provenance admission,
  explicit API-specific endpoints, window bounds and raw report JSON are unchanged.
- Share NNS Governance snapshot locking, running/failed/complete attempt writes,
  envelope construction, atomic publication and refresh report projection under
  `nns/governance/collection/`. Neuron and proposal collectors retain their own
  cursor/page admission, row envelopes and errors. All schemas remain 1; snapshot
  and sidecar shapes are unchanged and require no reset. A sidecar finalization
  failure after successful publication remains reported alongside `wrote_cache`.
