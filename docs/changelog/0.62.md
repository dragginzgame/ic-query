# 0.62 release notes

## 0.62.3

- Add `ledger_evidence::icp::decode_transfer` for bounded current ICP protobuf
  blocks. Reject noncanonical bytes, unknown/duplicate fields, missing send fields,
  invalid account lengths and inconsistent parent presence. Decoded transfer fields
  carry no certificate or spending authority; callers authenticate the selected
  block and retain expected-transfer comparisons. The existing optional
  `ledger-evidence-host` feature selects the decoder; default builds stay unchanged.

## 0.62.2 - 2026-10-18

- Explicitly unlock refresh guards after failed actions, cancellation and unwind,
  preserving original action failures and successful-action unlock errors.
  Duplicated or inherited descriptors no longer extend a finished refresh's lock.
  Make the cache-status fixture explicitly unlock before observing availability,
  and cover duplicate-descriptor ownership with deterministic regression tests.

- Finish the Host text/export extractions using published APIs: canonical UTC
  parsing/formatting, exact fixed/compact decimal rounding and guarded in-place
  export writes. Remove local calendar arithmetic, decimal rounding and export
  path/inode/write mechanics. Query retains timestamp freshness, token input
  normalization, cycle/byte unit selection, protected cache/lock paths, the
  64-link ceiling and its existing typed error projection. Managed atomic cache
  publication is unchanged. Require Host Text 0.27.4 and Host FS 0.27.3 or newer;
  the existing lockfile already selects 0.27.4 for both.

- Share package graph observation and dependency-feature-edge admission through
  Shared PR #285; keep Query’s graph matrix independently runnable.

- Complete the already selected IC Build 0.17 probe specification with an
  explicit caller environment, preserving harness compilation and tool custody.

- Select the published `ic-platform` 0.1.11 archive for Candid contract imports,
  qualified derives, argument encoding and bounded replies. Public upstream
  Candid identities, wire labels, limits and error projection stay unchanged.
  Remove the CLI's direct Candid/old-decoder declarations and the library's
  normal direct declarations.
- Complete the Testkit 0.54 adoption with Platform's canonical `DecodeLimits`
  and decoder errors. Remove the separate decoder dependency, its ownership
  exception and obsolete graph fixtures. Preserve all five reply ceilings,
  typed simulator calls, tuple arity and Governance report/failure assertions.
- Enable Platform certification for `certificate-host` and `ic-state-host`,
  removing Query direct `ic-certification` declarations and redirecting types and
  fixture constructors. Use the published subtree results and labeled-hash exports;
  Platform #4's consumer migration is complete. Host parse errors, witness budgets
  and Agent authentication remain unchanged.
- Route native Agent imports, typed errors, host feature selections and the smoke
  harness through Platform. Remove direct Agent catalog/member declarations and
  forbid them through the shared ownership policy, completing Platform #9 adoption.
  Preserve the selected Agent identity, explicit endpoints, root-key admission,
  bounded HTTP clients, query verification, raw replies and logical retry policy.
  Keep management-type features disabled. Host Tools owns its native Platform
  parser selection; the canister graph excludes it. The probe
  reads the same upstream clock through Platform's raw system-call surface,
  selected by the `canister` feature's CDK integration.
- Route ICRC ledger DTOs through Platform's `icrc-ledger-types` feature in the
  existing ICRC, SNS and ledger-evidence host selections. Remove Query's direct
  catalog/member dependency and reject direct declarations through the shared
  gate. Keep upstream 0.2.0 identities, wire bytes, hashes, account semantics and
  typed archive callbacks; retain caller budgets, admission and evidence policy.
  Keep ledger DTOs out of portable/canister selections and reject the upstream
  stable-memory storage dependency throughout the supported feature graphs.
- Adopt 0.1.11 with Query's finite decoders and identity selection unchanged.
  Keep the optional management snapshot/status DTO surface disabled; Query has
  no consumer for those APIs. Preserve upstream wire/Agent identities. The
  typed CDK boundary preserves automatic argument/reply handling and trap
  semantics. The added cycle and instruction-counter exports are unused;
  Query does not add funding or counter-attribution policy.
- Route Governance's canister identity, `Call` and `CallFailed` through Platform's
  CDK facade and the probe through its maintained `update` generator. Remove all
  direct Candid/CDK catalog/member declarations and their ownership exceptions.
  The `canister` feature selects Platform's `cdk`; native host features remain
  independent. Keep upstream CDK 0.20.3, executor 2.0.0 and ic0 1.2.0 identities,
  bounded waits, raw reply evidence and existing decoder limits. No local runtime,
  compatibility alias or storage/memory change is added. Installed-IC callback
  qualification remains separate from the compiled simulator fixture.
  The fixture also checks typed entrypoint decoding, bounded unused-argument
  skipping and successful calls after argument/quota traps.
- Add Shared's declarative direct-dependency gate to CI, including aliases and
  dependency tables; retain separate transitive feature/target graph checks.

- Adopt the reviewed Shared Tooling 0.24.0 snapshot. Common Rust setup now
  selects cargo-sort and cargo-sort-derives; the hook fixture follows that
  selection without requiring a Candid extractor. Query does not use one.
- Label production and tests/tooling catalog roles, including the portable
  Candid decoder as production. Grouped Cargo sorting is shared by write/check
  formatting, hooks and prepared/selected-source release admission. Selected
  release archives remain with their validation evidence.
- Extend locked normal/build graph checks to exclude tooling packages from
  native CLI and canister selections, including transitive edges. Document that
  deployment does not yet require a graph receipt bound to final Wasm bytes.

## 0.62.0 - 2026-10-17

- Complete the incoming Testkit 0.53 caller adoption in the compiled Governance
  fixture: use `update_candid_args` with a one-text reply tuple and the same
  explicit caller and decode budgets. Preserve the selected lock graph.

- **Breaking:** Refresh exclusion uses Host's nonblocking descriptor lock on a
  persistent, empty, owner-only coordination sidecar. Normal completion,
  cancellation and process death release ownership without unlinking the file.
  Remove refresh-lock age fields, constructor arguments, constants and
  `--lock-stale-after`; certified catalog publication policies are unit variants
  rather than stale-age payloads. Cache status reports `active`, `available` or `invalid`,
  with `available_refresh_lock_count`; remove recorded owner/time/staleness
  fields from lock rows. Cache freshness clocks and refresh-attempt evidence
  remain independent of exclusion. Schemas remain 1.
- Before upgrading, quiesce all old Query and library consumers sharing each
  cache root. Retain required cache and attempt evidence, then explicitly retire
  incompatible nonempty lock files. The new implementation refuses their content
  and never parses, rewrites or automatically removes it. Keep empty coordination
  files in place whenever any consumer may use the root; their stable inode is
  the exclusion authority. Mixed old/new writers are not supported.

- **Breaking:** `IcrcBalanceReport.value: IcrcBalanceData` and
  `IcrcAllowanceReport.value: IcrcAllowanceData` share the existing source
  payloads, now available without `icrc-host`. Update Rust construction and
  field access; source traits, human text and flat report JSON keep their values.
- **Breaking:** Decode marketplace node classes directly into
  `CloudEngineNodeType`. Its JSON spelling now matches the native Candid labels
  `type4_1` through `type4_5`; update JSON consumers. Marketplace keys and human
  text retain their dotted spelling; all five wire variants remain unchanged.
- **Breaking:** `CloudEngineListRow.operator` is
  `Result<Option<candid::Principal>, String>`, replacing independently stored
  lookup status, optional ID and optional error. JSON uses `{"Ok":"principal"}`,
  `{"Ok":null}` or `{"Err":"reason"}`. Counts and text labels derive from that
  single outcome. Ordinary lookup errors retain bounded UTF-8 evidence; invalid
  successful source evidence still aborts the report. Update Rust/JSON consumers;
  schema stays 1 with no compatibility reader or automatic rewrite.

- Adopt the committed Shared Tooling 0.23.0 snapshot. Use its ICP 1.7.0 catalog
  directly across setup, checks, the Governance harness, release admission and
  retained evidence; remove the identical Query exception catalog. Explicit
  `IC_TOOL_PINS` selections remain supported. Query continues to include IC
  setup/checks in its tool aggregates through the shared extension interface.
- Own the temporary public-documentation debt checker, guide and dedicated
  fixtures in Query, preserving the existing baseline and gate when Shared
  retires that surface. Keep the common type-doc checker shared.
  [#75](https://github.com/dragginzgame/ic-query/issues/75),
  [#76](https://github.com/dragginzgame/ic-query/pull/76).
- Prepare release and Make fixtures through Shared's declared dependency
  closure, then apply local stubs. Companion additions follow their source
  owners without another manually maintained copy list.

- **Breaking:** Remove `created_at` from SNS neuron/proposal rows and
  `decided_at`, `executed_at`, `failed_at` and ballot `cast_at` display strings.
  Use the corresponding native timestamp fields in Rust and JSON. Human-facing
  text derives UTC when rendered, preserving absent/zero ballot display rules.
  Preserve required existing evidence and coordinate consumers before explicitly
  refreshing neuron/proposal caches; schema identifiers stay 1, with no older
  reader, migration or automatic rewrite.
- Decode Dashboard token-value rows directly into `IcIcrcTokenValueSourceRow`.
  Nullable prices, volumes, providers and timestamps retain their raw values;
  report assembly still requires and validates each timestamp.

- **Breaking:** `IcrcTokenReport` and `SnsTokenReport` contain
  `token: IcrcTokenData`. Construct the existing shared payload and access token
  fields through it, such as `report.token.decimals`. Source capabilities keep
  their existing token payload. Text and serialized report JSON retain the same
  flat fields and raw metadata values.
- **Breaking:** Complete NNS neuron/proposal, SNS catalog/neuron/proposal and
  observed IC node-status snapshots nest family metadata under `metadata` and
  rows/collection state under `data`. NNS, SNS and ICRC account-history refresh
  attempts nest their family identity under `metadata`. Preserve any required
  old evidence before explicitly refreshing those caches. Schema identifiers
  stay 1; there is no fallback reader, migration or automatic rewrite.
- Use strict typed deserialization for snapshots and attempts instead of a
  preliminary header parse and manually maintained field allowlists. Unknown
  and duplicate object fields are rejected at typed boundaries. Malformed payload
  errors can now precede schema/network mismatch errors; valid payloads retain
  typed schema/network refusals. Cache-backed NNS inventory report models also
  reject unknown fields directly. File-size and scan budgets, confinement,
  complete-collection validation and failure-evidence preservation remain intact.

- **Breaking:** SNS proposal rows store raw native `action_id: u64` and ballot
  `vote: i32` only. Remove the derived `action` and `vote_text` fields and the
  public `SnsProposalAction`/`SnsProposalVote` enums. Text labels, action sorting
  and searches derive from the raw values, including generic and unknown IDs.
  Update custom sources and JSON consumers; preserve required evidence before
  explicitly refreshing complete SNS proposal caches. Strict rows reject unknown
  fields; schema identifiers remain 1 with no fallback reader or migration.
- **Breaking:** `IcrcAccountTransactionPageReport` contains the existing
  `IcrcAccountTransactionPageData` in `page`. The payload is available without
  host features. Use `report.page.transactions`, `report.page.balance`, and the
  corresponding page fields; text and flat JSON retain their existing values.
  Native index identity, row limits, order and cursor admission remain unchanged.
- Preserve the existing flat `SnsRewardCheckpointReport` fields and strict
  serialized shape. Historical checkpoint files remain usable by local reward
  reconciliation; collecting current data does not reconstruct an earlier
  observation. Pure summary recomputation and full field comparison still reject
  inconsistent raw evidence, overflows, unknown fields and duplicate fields.

- **Breaking:** Remove stored `lifecycle_name` from SNS discovery, joined catalogs,
  list rows and swap lifecycle results. Remove `treasury_kind` and the public
  `SnsTreasuryKind` enum. Sources and JSON consumers use native `lifecycle` and
  `treasury` numeric values, including unknown codes. Text labels are derived
  at rendering time. The native lifecycle value/query-error alternative is still
  validated. Preserve required catalog evidence, coordinate consumers, then
  explicitly refresh catalogs; strict joined rows reject unknown fields.
- **Breaking:** `SnsMetricsReport.metrics` contains `MainnetSnsMetrics`, and
  `SnsSwapReport.swap` contains `MainnetSnsSwap`. The existing payload types are
  available without `sns-host`; source traits keep those same types. Update Rust
  access and construction. Serialized fields stay flat except removed derived
  labels; target/method/window checks, cached/point-in-time authority checks,
  typed component gaps, raw values and canonical row validation remain intact.
