# 0.20 Changelog

Detailed release notes for the `0.20.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.20.2 - 2026-08-01

### Added

- Adds one bounded official Dashboard v3 daily network-activity query:

  ```bash
  icq ic network daily-stats
  icq ic network daily-stats \
    --start 1784937600 --end 1785542400 --format json
  ```

- Adds `IcDailyStatsQuery`, typed request/report/row/source DTOs, custom-source
  construction, and text rendering under `ic_query::ic`. The existing
  `LiveIcSource` and `IcNetworkSource` own the new operation through the shared
  Dashboard transport and provenance path.
- Adds a focused daily-statistics design contract and updates the command,
  library, cache, adapter, and 1.0 roadmap documentation.

### Guarantees

- Makes exactly one `daily-stats` request with explicit inclusive `start` and
  `end` Unix-second bounds. The CLI defaults to the preceding seven days;
  builders cap the window at 366 days and projection accepts at most 366 rows.
- Preserves the raw daily average and maximum query, update, and total
  transaction rates plus average block rate. The report deliberately excludes
  unrelated governance, supply, topology, and Internet Identity fields from
  the broad source payload rather than duplicating weaker authority surfaces.
- Canonically orders rows by increasing timestamp and permits missing days.
  Projection rejects out-of-window rows, duplicate days or timestamps,
  day/timestamp mismatches, invalid or negative rate text, mismatched query or
  provenance, and oversized results.
- Records `authority: official_ic_dashboard_api`, `network: ic`,
  `certified: false`, and `point_in_time_guaranteed: false`. The operation does
  not paginate, follow up, fan out, infer missing days, or read or write a
  cache.

### Compatibility

- This is a pre-1.0 Rust-API hard cut for custom `IcNetworkSource`
  implementations: the trait now also requires `fetch_daily_stats`. No
  compatibility default, secondary trait, or fallback adapter is retained.
- Existing command behavior, existing report JSON, and cache schemas are
  unchanged. This release adds no mutation behavior or hidden network calls.

## 0.20.1 - 2026-08-01

### Added

- Adds the finite official Dashboard v4 boundary-node data-center report:

  ```bash
  icq ic network boundary-node-data-centers
  icq ic network boundary-node-data-centers --format json
  ```

- Adds `IcBoundaryNodeDataCentersRequest`, typed report and row DTOs,
  `IcNetworkSource`, custom-source construction, and text rendering under
  `ic_query::ic`. The existing `LiveIcSource` implements the capability
  through the shared Dashboard HTTP transport and provenance model.
- Adds a focused design contract and updates the command, library, cache,
  adapter, and 1.0 roadmap documentation.

### Guarantees

- Makes exactly one request for the non-paginated
  `boundary-node-data-centers` resource. It does not issue per-location
  follow-up calls, enumerate individual nodes, or read or write a cache.
- Preserves raw data-center ids, names, owners, region labels, coordinates,
  and node-count strings, including rows that report zero nodes. It does not
  correct surprising Dashboard geography or join the result to Registry
  records.
- Canonically orders rows by data-center id and derives only the row count and
  checked sum of node counts. Projection rejects more than 1,000 rows,
  duplicate ids, empty required labels, invalid coordinates, non-canonical
  unsigned node counts, count overflow, and mismatched custom-source
  provenance.
- Records `authority: official_ic_dashboard_api`, `network: ic`,
  `certified: false`, and `point_in_time_guaranteed: false`. Data-center
  aggregates are not presented as individual boundary-node identities or
  certified Registry inventory.

### Compatibility

- Existing Dashboard canister and metric commands, report JSON, request
  behavior, and cache contracts are unchanged.
- This release adds no compatibility aliases, fallback readers, mutation
  behavior, cache schema, or hidden network calls.

## 0.20.0 - 2026-07-31

### Added

- Adds one bounded official Dashboard Metrics API query:

  ```bash
  icq ic metrics instruction-rate
  icq ic metrics cycle-burn-rate \
    --start 1700000000 --end 1700003600 --step 300
  icq ic metrics ic-node-count --format json
  ```

- Supports the official `instruction-rate`, `message-execution-rate`,
  `cycle-burn-rate`, `block-rate`, `ic-node-count`, `ic-subnet-total`,
  `registered-canisters-count`, `total-ic-energy-consumption-rate-kwh`, and
  `boundary-nodes-count` resources.
- Adds `IcMetricKind`, the shared `IcMetricQuery`, typed request/report/series
  and observation DTOs, `IcMetricSource`, custom-source construction, and text
  rendering under `ic_query::ic`. The existing `LiveIcSource` implements the
  new capability.

### Guarantees

- Makes exactly one REST request for one selected aggregate metric. It does not
  enumerate other metrics, fan out over Subnets, paginate, follow up, or write
  a cache.
- Defaults CLI queries to the preceding hour at a 300-second step. Explicit
  `--start`, `--end`, and `--step` values preserve the exact requested window.
  Builders enforce the official timestamp and step bounds, reject future ends,
  and cap requests at 1,000 observations per returned series before a source
  call.
- Preserves documented raw series names, observation Unix timestamps, and
  value strings. Multi-series node and canister counts are retained
  without lossy aggregation.
- Validates custom-source query/provenance echo, exact documented series,
  canonical series order, timestamp bounds and ordering, requested result
  size, and non-empty raw values before projection.
- Reuses `IcSourceRequest`, `IcDashboardReportProvenance`, `IcHostError`, the
  live HTTP transport, and `LiveIcSource`; no parallel Dashboard adapter,
  provenance DTO, or output path is introduced. The shared invalid-source
  display prefix is generalized from "canister source data" to "source data"
  so metric failures are not mislabeled.
- Records `authority: official_ic_dashboard_api`, `network: ic`,
  `certified: false`, and `point_in_time_guaranteed: false`. Metric evidence
  does not inherit Registry or certified canister authority.

### Compatibility

- Existing Dashboard canister CLI grammar, report JSON, public types, and
  live-request behavior are unchanged. Only the shared invalid-source error's
  display prefix is generalized as described above.
- This release adds no compatibility aliases, fallback readers, mutation
  behavior, cache schema, or hidden network calls.
