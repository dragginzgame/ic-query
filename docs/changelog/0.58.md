# 0.58 release notes

## 0.58.0 - 2026-10-16

- Use Shared Tooling's canonical release preflight for locked Cargo preparation
  and selected formatter setup. Recheck both tool catalogs during preparation;
  preserve original failures, caller-selected offline mode, Query source checks
  and recovery evidence. Extend simulated fixtures to cover catalog mutation.

- Replace four timestamp/counter-based test allocators with Host FS's published
  fixture allocation. Preserve test-owned cleanup and diagnostics; missing-root
  and symlink cases explicitly select unused children of the allocated directory.
  Enable the helper only for native development builds.

- Move shared Candid query encoding, transport and bounded reply decoding out of
  the ledger module. SNS and ICRC call the same mechanics while keeping endpoint,
  trust, capability classification, error labels and ingress behavior local.
  Principal validation stays with ICRC rather than the transport error adapter.
- Use Host's SHA-256 digest parser and formatter for catalog and archive input
  admission and report-object identities. Preserve lowercase digest strings,
  field-specific errors, hash algorithms and schema-1 JSON representations.

- Adapt owned report-text helpers and table cells to Host 0.20's borrowed escape
  results, preserving output while retaining borrowing in direct formatting paths.

- Replace local ICRC-3 block, archive and certificate wire declarations with
  `icrc-ledger-types`' canonical types. Keep Query's bounded reply decoding,
  callback/range admission and explicit JSON projection, including plain decimal
  integers and lowercase blob hex. Enable the existing dependency for `icrc-host`.
- Box native SNS/ICRC fetch futures directly where source adapters only forward
  an await, retaining their Send/lifetime and caller-runtime boundaries.

- Restore the formatter's required ordering of the native dev-dependency table.
  Retain nested formatter logs inside the formatting-hook fixture and print them
  on failure, exposing the actual refusal in combined CI/release diagnostics.
- Select Host Process 0.20 for IC Build 0.7's exposed `CleanupPolicy` boundary.
  Keep the other Host dependencies on 0.21 and preserve the harness's five-second
  TERM grace and five-second reap timeout. This fixes smoke-example compilation
  without an older-type alias or a cleanup-policy conversion.
  [Build Host alignment](https://github.com/dragginzgame/ic-build/issues/9).

### Breaking

- The selected Host 0.20 dependency changes the concrete parse-error type exposed
  by `CertificateVerificationError::Decode`. Consumers naming that Host type must
  align their dependency. Query's certificate error variants remain unchanged.

- Load local SNS reward checkpoints through Host FS's bounded regular-file reader
  with a 64 MiB allowance, then parse JSON directly from bytes. Oversized and
  non-regular files return the existing path-aware read error; malformed JSON,
  including invalid UTF-8, returns the path-aware parse error. Symlink following
  and caller-selected paths retain the existing policy. No source file is changed.
- This replaces previously unbounded checkpoint input admission. Oversized
  existing checkpoints remain untouched and are refused. Schema identifiers
  remain 1 and there is no alternate reader or migration.
- CMC and ICRC certificate pairs now share the bounded certificate verifier:
  an 8 MiB combined evidence budget, 64-level CBOR nesting limit and exact-value
  decoding reject oversized, deeply nested or trailing-byte evidence. Certificate
  authentication precedes witness admission. Application leaves, trust-root policy
  and original certificate/witness report bytes remain with their existing owners.
