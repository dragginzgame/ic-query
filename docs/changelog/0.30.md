# 0.30 Changelog

Detailed release notes for the `0.30.x` release line.

## 0.30.7 - 2026-08-06

### Committed-history replay compatibility

- Aligns atomic-version validation with the pinned Registry canister's
  committed-changelog reconstruction. Mutation keys must be in canonical
  nondecreasing byte order, but the same key may appear repeatedly.
- Preserves every same-key mutation in its stable certified order and applies
  them sequentially. The final same-key row determines current state, and a
  later replay failure still rolls the complete atomic version back.
- Preserves inline or reconstructed value content carried by a committed
  delete, including its raw byte accounting. Replay follows the canister and
  removes the key without applying that retained content.
- Keeps unknown mutation types, decreasing key order, malformed values,
  duplicate version labels, and every existing resource overflow as typed
  failures. Report schema 2 is unchanged.

### Complete bounded mainnet observation

- A cacheless probe on 2026-08-06 completely reconstructed exact Registry
  target `62948` from version zero in 75 certified batches and 77 total
  Registry calls, including two bounded chunk calls.
- The authenticated run admitted 63,814,080 encoded response bytes, applied
  147,284 committed mutations, and produced 17,184 current keys using
  22,345,176 combined raw key/value bytes.
- The run remained below its explicit 128-batch, 8,320-call, 256 MiB response,
  100,000-key, and 128 MiB state ceilings. These are diagnostic ceilings and
  one empirical observation, not library defaults or a production budget.

### Boundary and downstream impact

- This changes validation of authenticated historical contents, not Registry
  mutation submission: ic-query remains read-only.
- No cache, persistence, certified catalog assurance, source selection,
  command, or CLI output changes are introduced.

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `nns-host` | Existing schema-2 reports now accept official repeated-key and retained-delete-content history | No cache | Existing bounded bootstrap can now complete measured mainnet history | Retest custom validators that rejected these committed forms |
| `nns-topology-host` | Compatible | Unchanged | Unchanged | None |
| `subnet-catalog-host` | Compatible | Unchanged | Unchanged | None |
| CLI | Compatible | Unchanged | No new command | None |

## 0.30.6 - 2026-08-06

### Bounded bootstrap sizing probes

- Adds `NnsCertifiedRegistryBootstrapProbeOutcome`, typed
  `NnsCertifiedRegistryBootstrapProbeStatus`, and live/custom-source probe
  operations under `nns-host`.
- Shares one collection loop with complete bootstrap, including mainnet
  enforcement, exact-target pinning, worst-case pre-call reservation, source
  validation, and atomic replay.
- Returns `Complete` when the selected target is reconstructed. When another
  batch would exceed batch, call, or response-byte capacity, returns
  `CapacityReached` with the resource, maximum, required cumulative amount,
  and bounded session without making that call.
- Supports a zero-call diagnostic outcome without source invocation. Source,
  validation, replay, and state-limit failures remain errors rather than being
  mislabeled as capacity stops.
- Preserves the complete bootstrap contract: capacity exhaustion is still a
  typed error there and incomplete state is never returned as successful
  bootstrap state.
- Matches the official Registry transport's historical protobuf compatibility
  rule: a non-delete high-capacity mutation with no content arm represents an
  empty inline value. Delete mutations with content remain invalid, and
  content-less deletes remain deletes.

### Bounded mainnet observation

- A one-batch probe on 2026-08-06 authenticated exact Registry target `62948`,
  reconstructed versions `1..=270`, applied 1,082 mutations into 804 current
  entries, and reported 1,386,570 encoded response bytes. It then returned
  `CapacityReached` before a second call because the configured batch ceiling
  was one.
- This observation verifies bounded partial progress but does not establish a
  complete-history default or recommended production budget.

### Boundary and downstream impact

- Probe sessions are diagnostic sizing evidence only. An incomplete outcome is
  not serializable, cacheable, resumable, or Subnet Catalog authority.
- The operation has no default limits and performs no filesystem or process
  output. The live variant may make only the explicitly reserved mainnet calls;
  custom sources remain responsible for their internal work.
- CLI grammar and every cache schema and path are unchanged.

## 0.30.5 - 2026-08-06

### Explicit bounded Registry bootstrap

- Adds `NnsCertifiedRegistryBootstrapRequest`,
  `bootstrap_nns_certified_registry_async`, and a custom-source async variant
  under `nns-host`.
- Starts from Registry version zero, pins the first response's certified latest
  version, requests each next contiguous batch from the session's current
  version, and returns only after that exact target is complete.
- Before every built-in source call, requires remaining cumulative capacity for
  one whole worst-case batch: one certified query, up to 64 unique chunk
  queries, one response-bounded certified result, and up to 32 MiB of chunk
  responses. This reserves at most 65 calls and 40 MiB per attempted batch.
- Rejects non-mainnet identity before budget evaluation or source invocation.
  If a later call fails or a returned batch violates replay limits, the owned
  partial session is discarded rather than returned as complete state.
- Keeps all bootstrap limits caller-selected. No empirical mainnet defaults are
  introduced.

### Boundary and downstream impact

- The live operation is explicitly named and may issue multiple sequential
  mainnet queries. It runs on the caller's async runtime and performs no
  filesystem or process-output work.
- Pre-call reservation strictly bounds the built-in source. Custom sources are
  still responsible for authentication and for keeping any internal work
  within the public one-batch contract.
- Bootstrap results remain in-memory, nonserializable, and non-authoritative
  without their certified reports. No mirror cache or certified Subnet Catalog
  assurance is published.
- CLI grammar and all cache schemas and paths are unchanged.

| `subnet-catalog-host` | Compatible | Unchanged | Unchanged | None |

## 0.30.4 - 2026-08-05

### Exact-target replay sessions

- Adds `NnsRegistryReplaySession` and explicit
  `NnsRegistryReplaySessionLimits` under `nns-host`.
- Pins the first accepted batch's certified latest Registry version. Later
  batches must continue to certify that version, while mutations newer than
  the selected target are validated but not applied.
- Requires a stable root-key digest across admitted batches and rejects reuse
  after the exact target is complete.
- Enforces caller-selected ceilings for selected Registry versions, admitted
  batches, reported query calls, encoded response bytes, live entries, and
  combined raw key/value bytes.
- Accumulates accepted batch, call, response-byte, and applied-mutation counts.
  Every validation, trust-root, version, cumulative-limit, or state-limit
  failure leaves session state and accounting unchanged.

### Boundary and downstream impact

- The session is pure. It coordinates caller-supplied reports but does not
  call a source, reserve a network budget, follow `more_available`, or write a
  cache. Its cumulative limits govern evidence admitted after collection, not
  work a caller may already have asked a source to perform.
- Session state remains nonserializable and is not standalone authority;
  callers retain the certified reports. Certified Subnet Catalog assurance is
  still unsupported.
- CLI grammar and all cache schemas and paths are unchanged.

## 0.30.3 - 2026-08-05

### Pure bounded Registry replay

- Adds `NnsRegistryReplayState`, explicit `NnsRegistryReplayLimits`, typed
  replay errors and progress, and
  `apply_nns_certified_registry_delta_batch` under `nns-host`.
- Starts only from empty version-zero state and accepts a batch only when its
  request version equals the state's current version. Each call first runs the
  existing public certified-batch validator.
- Matches the official committed-changelog reconstruction path: insert,
  update, and upsert rows replace the current value; delete removes it.
  Preconditions remain certified transaction evidence and are not re-run
  after the transaction has already committed.
- Requires callers to provide maximum live-entry and combined raw key/value
  byte ceilings. Batch application uses a candidate state, so validation,
  version, accounting, or limit failure leaves the original state unchanged.
- Retains canonical raw-byte key order, current values, last mutation versions
  and timestamps, state size, and whether replay reached the batch's certified
  latest version.

### Boundary and downstream impact

- Replay is pure and performs no query, pagination, filesystem IO, or process
  output. There is no implicit memory default or history traversal.
- The in-memory state is not a persistable authority DTO and does not promote
  Subnet Catalog assurance. Callers must retain the certified reports that
  produced it.
- CLI grammar and all cache schemas and paths are unchanged.

## 0.30.2 - 2026-08-05

### Bounded certified large-value completion

- Hard-cuts `NnsCertifiedRegistryDeltaBatchReport` and its mutation and limits
  models to schema 2. Chunk-referenced mutations now retain their original
  encoding, ordered SHA-256 digests, and complete reconstructed value instead
  of being rejected as incomplete.
- Retrieves only the chunks named by the already selected certified batch.
  Every response is hash-verified, and repeated digests within or across
  mutations reuse one verified response.
- Enforces at most 64 references, 1,800,000 decoded bytes per chunk, 10 MiB per
  reconstructed value, 16 MiB across inline and reconstructed values, 32 MiB
  across encoded chunk responses, and 8 MiB for each agent response body.
- Separately reports certified and chunk response bytes, unique chunk calls,
  reference count, inline bytes, reconstructed bytes, and totals. The pure
  custom-source validator recomputes encoding relationships, canonical digest
  shape, value sizes, all totals, and the exact unique-digest query count.
- Applies the same bounded, hash-verified reconstruction helper to ordinary
  exact-version Registry `get_value` reads used by catalog and topology
  collectors.

### Boundary and downstream impact

- The certified API still returns at most one contiguous delta batch and does
  not follow `more_available`, replay history, or publish a cache. Chunk
  completion is finite work named by that batch and is fully reported.
- Ordinary exact-version reads remain uncertified. Completing or bounding a
  large value does not promote Subnet Catalog assurance.
- CLI grammar and cache schemas and paths are unchanged.

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `nns-host` | Certified delta report schema hard cut to 2 | No cache | One certified delta query plus zero to 64 unique chunk queries | Update custom source fixtures and report consumers |
| `nns-topology-host` | Compatible | Unchanged | Oversized or malformed ordinary chunked values now fail at fixed ceilings | Retest only if custom Registry fixtures use large values |
| `subnet-catalog-host` | Compatible | Unchanged | Same bounded ordinary large-value behavior | Retest only if custom Registry fixtures use large values |
| CLI | Compatible | Unchanged | No new command flow | None |

## 0.30.1 - 2026-08-05

### Bounded certified Registry delta batch

- Adds `NnsCertifiedRegistryDeltaBatchRequest`, report/row models, an async
  custom-source trait, `fetch_nns_certified_registry_delta_batch_async`, and a
  pure source-report validator under `nns-host`.
- Performs exactly one authenticated `get_certified_changes_since` query on
  the caller's runtime. The same certified response proves its latest Registry
  version and every visible delta leaf.
- Requires eight-byte big-endian version labels beginning immediately after
  the requested version and increasing by one. Empty batches are accepted only
  when the request already names the certified latest version; later versions
  are exposed through `more_available`, not fetched implicitly.
- Decodes native high-capacity atomic mutation protobufs, preserves mutation
  order, timestamps, preconditions, raw mutation codes, typed
  insert/update/delete/upsert kinds, and key/value bytes as lowercase hex.
- Fails closed on unknown mutation codes, duplicate mutation or precondition
  keys, invalid value/delete combinations, malformed trees or labels, count or
  byte overflows, and large-value chunk references that would require a
  separate bounded retrieval design.
- Reports one query call, response and evidence byte counts, certificate time,
  root-key digest, raw certificate and witness, and every fixed validator
  ceiling. The pure validator recomputes provenance, sequence boundaries,
  counts, content bytes, and `more_available` for trusted custom sources;
  unlike the built-in live transport, it cannot authenticate a source's raw
  certificate cryptographically.

### Boundary and downstream impact

- The operation is mainnet-only, live, async, one-call, and uncached. It does
  not paginate, replay history, write a mirror, add CLI grammar, or change any
  existing cache path or schema.
- A certified batch authenticates only the returned mutations. It does not
  reconstruct a complete Registry snapshot or enable
  `CatalogAssurance::Certified`; existing Subnet Catalog and topology behavior
  is unchanged.

## 0.30.0 - 2026-08-05

### Certified Registry latest version

- Hard-cuts `NnsRegistryVersionReport`, `NnsRegistryVersionData`, and custom
  `NnsRegistrySource` implementations to version-2 certified evidence.
- Changes the built-in live adapter from ordinary `get_latest_version` to one
  `get_certified_latest_version` query. It authenticates the certificate
  against the compiled-in mainnet root key and verifies Registry canister
  authority plus the certified-data commitment before accepting the version.
- Decodes the Registry's official protobuf mixed hash tree with explicit depth,
  node-count, child-presence, and SHA-256 pruned-digest validation. The
  `current_version` leaf must be present, proven, leaf-valued, non-overflowing,
  and canonical unsigned LEB128.
- Requires certificate time to remain within five minutes of the
  caller-supplied collection time. The IC agent independently applies its
  certificate authentication and age checks.
- Preserves certificate time in raw nanoseconds and UTC text, the trusted
  root-key digest, raw certificate and encoded witness hex, and exact byte
  counts in JSON. Human text reports certification, time, digest, and compact
  evidence sizes without printing the raw blobs.

### Assurance boundary

- Certification applies only to the Registry's committed latest-version leaf.
  Existing Subnet Catalog and exact-version topology collectors continue to use
  ordinary `get_value` calls and retain `UncertifiedQuery` or explicit
  `MultiEndpointAgreement` assurance.
- `CatalogAssurance::Certified` remains unsupported until a complete,
  contiguous, resource-bounded certified delta sequence reconstructs every
  required Registry key at the selected version.
- Adds the staged [0.30 certified Registry design](../design/0.30/0.30-design.md)
  for batch validation, measured bootstrap, incremental replay, and eventual
  atomic catalog publication.

### Dependency and operational impact

- `nns-host` now directly enables `serde_cbor` to decode the Registry system
  certificate. The focused `nns-topology-host` and `subnet-catalog-host`
  dependency graphs are unchanged in this slice.
- The Registry version operation remains live, uncached, mainnet-only, and one
  call. Command names, options, cache paths, Subnet Catalog schemas, topology
  schemas, and other report families are unchanged.
