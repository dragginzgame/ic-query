# 0.30 Changelog

Detailed release notes for the `0.30.x` release line.

## 0.30.26 - 2026-08-07

### Shared canonical serialization mechanics

- Centralizes canonical compact-JSON byte counting and exact byte comparison
  in the shared cache writer. Certified Registry archive manifests and the
  certified Subnet Catalog cache no longer maintain parallel counting and
  matching writers.
- Generalizes the archive digest writer over its output sink so report
  accounting and durable object publication use one SHA-256 and byte-counting
  implementation. Replay evidence hashing writes directly into `Sha256`
  instead of retaining a one-method adapter.
- Uses one serialization-to-IO conversion helper for managed JSON writers,
  preserving writer-originated IO error kinds where available.
- Simplifies certified catalog cache policy dispatch to one cache-load result
  and one relation between read policy, typed failure, and authorized
  publication disposition. Missing-only, missing-or-invalid, cache-only, and
  forced-publication behavior remains distinct.

### Confined cache ownership and validation

- Splits confined managed-file reads and bounded reads from directory
  discovery/removal. The capability-rooted path validator and atomic writer
  remain the single owner of traversal, symlink, regular-file, permission, and
  same-directory replacement guarantees.
- Removes redundant `nns-host` configuration branches where its focused
  `subnet-catalog-host` or `certified-subnet-catalog-host` dependency already
  enables the same implementation. Focused feature dependency graphs are
  unchanged.
- Replaces the cache-status schema-field alias with explicit handling for the
  current `schema_version` and `catalog_schema_version` fields. A cache header
  containing both is now rejected as ambiguous instead of accepting whichever
  value the deserializer encountered.

### Test organization

- Splits the Registry replay test suite into archive, certified-cache,
  projection, replay-session, and shared-fixture modules. The same 52 replay
  tests and protocol assertions remain in place.

### Downstream impact

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `certified-subnet-catalog-host` | Compatible | Unchanged; ambiguous dual schema fields fail closed | Unchanged | None |
| Other focused host features | Compatible | Unchanged | Unchanged | None |
| CLI | Compatible | Unchanged | Unchanged | None |

## 0.30.25 - 2026-08-07

### Focused certified catalog host surface

- Adds `certified-subnet-catalog-host`, a genuine focused feature containing
  `subnet-catalog-host` plus certified Registry delta collection,
  authenticated archive/replay, archive-bound catalog projection, and the
  certified catalog cache.
- The feature does not enable NNS Governance, proposal, neuron, component
  inventory, or derived-topology host adapters. It enables the existing direct
  CBOR dependency but not ic-query's direct Dashboard Reqwest edge; Reqwest can
  remain transitive through `ic-agent`.
- Makes `nns-host` a strict superset of both `nns-topology-host` and
  `certified-subnet-catalog-host`. No dependency package or lockfile version is
  added or changed.

### Unified certified catalog load policy

- Hard-cuts the four certified cache entry points from 0.30.24 to one
  `load_nns_certified_subnet_catalog` operation. Its explicit
  `NnsCertifiedSubnetCatalogReadPolicy` selects `CacheOnly`, `PublishMissing`,
  `PublishMissingOrInvalid`, or `ForcePublication`.
- Adds `NnsCertifiedSubnetCatalogLoadRequest` constructors for each supported
  policy and returns `NnsCertifiedSubnetCatalogLoadOutcome`, which retains the
  freshly projected archive-bound authority, cache path, disposition, and
  compact authority evidence.
- Removes `NnsCertifiedSubnetCatalogCachePublicationRequest`,
  `NnsCertifiedSubnetCatalogCacheAuthority`, and the prior load, publish, and
  two load-or-publish functions. This is a source-breaking pre-1.0 hard cut;
  there are no aliases, deprecated wrappers, or parallel dispatch paths.
- Every policy remains local-only. Publication policies can write only from
  the supplied authenticated archive; they cannot refresh it or make a network
  call. Missing-or-invalid recovery retains the existing narrow repair
  classification and never reclassifies filesystem, projection,
  serialization, or accounting failures.

### Bounded cache IO

- Centralizes confined bounded reads for certified Registry archive objects,
  certified catalog caches, and snapshot metadata while preserving each
  owner's typed error surface and caller-selected byte ceiling.
- Preflights managed pretty-JSON serialization and then streams it directly to
  the atomic temporary file instead of retaining a second complete encoded
  cache copy. Explicit exports retain one encoded value only when the same
  bytes must also be returned to the caller.
- Caps refresh-lock reads at 64 KiB and refresh-attempt sidecars at 1 MiB.
  Oversized metadata is reported as invalid local evidence; it is not deleted
  and does not authorize hidden network work.
- Clarifies the earlier schema-2-to-3 ordinary catalog hard cut: cache-only
  reads fail locally, while a caller-selected refresh-capable policy authorizes
  the live Registry query and atomic schema-3 replacement.

## 0.30.24 - 2026-08-07

### Explicit certified-cache recovery policy

- Adds `load_or_publish_missing_nns_certified_subnet_catalog_cache`. It reuses
  a valid cache, publishes only when the file is absent, and returns every
  invalid or operational failure unchanged.
- Adds
  `load_or_publish_missing_or_invalid_nns_certified_subnet_catalog_cache`.
  Publication is authorized only for a missing file or bounded content,
  JSON, schema, canonical-encoding, or authenticated-archive binding failure.
  Filesystem, projection, serialization, and accounting failures are never
  reclassified as repairable.
- Both operations are local-only and require the already authenticated archive
  plus the existing explicit projection and publication requests. They cannot
  refresh an old archive certificate; stale or superseded evidence fails before
  cache mutation and must be addressed by the separate archive refresh API.
- Adds `NnsCertifiedSubnetCatalogCacheDisposition` with stable `cache_hit`,
  `published_missing`, `published_invalid`, and `forced_publication` labels.

  exact completed action.
- Extends `NnsCertifiedSubnetCatalogCacheAuthority` with the exact cache path,
  disposition, and `authority_evidence()`. The new strict serde DTO records the
  Registry version, catalog digest, certified assurance, source endpoints,
  archive-manifest SHA-256, root-key/evidence-chain/state commitments,
  certificate bounds, and cache disposition without retaining another catalog
  snapshot. The DTO describes a successful authority but cannot recreate one.
- The schema-1 envelope, cache and lock paths, ordinary Subnet Catalog cache,
  archive bootstrap/refresh behavior, and CLI are unchanged. No compatibility
  aliases, automatic fallback, default policy, or background work is added.

## 0.30.23 - 2026-08-06

### Archive-matched certified Subnet Catalog cache

- Adds `NnsCertifiedSubnetCatalogCacheEnvelope` schema 1 under `nns-host`.
  It stores only the canonical archive-manifest SHA-256 beside the complete raw
  catalog; the catalog's existing provenance remains the single owner of exact
  Registry identity/version, replay commitments, certificate bounds, source
  endpoints, assurance, catalog digest, collector version, and classification
  policy identity.
- Adds caller-selected `NnsCertifiedSubnetCatalogCacheLocation` and
  `NnsCertifiedSubnetCatalogCachePublicationRequest`. There is no default
  cache directory, maximum byte size, or stale-lock policy.
- `publish_nns_certified_subnet_catalog_cache` first runs the existing
  archive-bound projection and freshness/version policy. Only after that pure
  qualification succeeds does it create a confined parent, acquire the
  certified catalog's dedicated lock, and atomically replace canonical compact
  JSON. Projection, size, lock-acquisition, serialization, and replacement
  failures cannot damage an existing complete cache.
- `load_nns_certified_subnet_catalog_cache` is a strict cache-only operation.
  It bounds bytes before allocation, rejects symlinks/nonregular files/unsafe
  modes through the shared confinement layer, requires schema-1 canonical
  compact JSON, freshly projects the caller-supplied
  `NnsAuthenticatedRegistryArchive`, and accepts only a field-exact envelope
  match.
- Publication serializes a borrowed catalog view rather than cloning the
  snapshot. Loading compares canonical serialization directly with the bounded
  input bytes without allocating a second encoded copy, and the successful
  authority wrapper does not retain the decoded envelope or a duplicate
  catalog.
- The successful `NnsCertifiedSubnetCatalogCacheAuthority` keeps that fresh
  projection attached to the authenticated archive. A serialized envelope or
  its nested `CatalogAssurance::Certified` catalog remains an untrusted DTO and
  cannot enter ordinary `ValidatedSubnetCatalog::try_from_raw` admission.
- Loading and publication make no network calls. Loading does not acquire a
  lock, repair invalid content, refresh an archive, or fall back to ordinary
  Subnet Catalog evidence. Publishing does not bootstrap or refresh its input
  archive.

## 0.30.22 - 2026-08-06

### Authenticated bounded archive orphan cleanup

- Adds `NnsCertifiedRegistryArchiveCleanupRequest`, explicit scan/removal
  limits, a typed result report, and
  `cleanup_nns_certified_registry_archive` for local archive maintenance.
- Requires an existing complete archive and holds the same `refresh.lock` used
  by bootstrap and refresh. Every manifest-referenced object is bounded,
  locally reauthenticated, replayed, and exactly matched before cleanup scans
  or deletes anything.
- Scans only regular files directly inside the archive's exact `objects/`
  directory. It does not traverse the archive root, cache root, child
  directories, symbolic links, or unrelated cache families.
- Applies caller-selected scanned-object, removed-object, and removed-byte
  ceilings before the first deletion. A truncated scan or exceeded deletion
  ceiling fails without removing an object.
- Removes only paths absent from the authenticated manifest's unique content-
  addressed object set. Each successful deletion synchronizes the object
  directory. A later filesystem failure reports the exact number and bytes
  already removed rather than implying atomic rollback.
- Returns the authenticated retained archive alongside exact scan/reference/
  removal counts. Cleanup makes no network call and is never invoked by load,
  refresh, cache policy, or background work.

### Release-gate failure diagnostics

- Changes `make patch`, `make minor`, and `make major` so `cargo clean` runs
  only after the changelog and clean-worktree checks pass, the complete CI gate
  succeeds, version metadata is updated, and the lockfile is regenerated.

## 0.30.21 - 2026-08-06

### Explicit incremental certified archive refresh

- Adds `NnsCertifiedRegistryArchiveRefreshRequest` and the built-in/custom-
  source `refresh_nns_certified_registry_archive_*_async` operations. The
  request reuses the existing mainnet source, observation time, cumulative
  replay limits, caller-selected confined roots, storage ceilings, and lock-
  staleness policy without choosing defaults.
- Requires an existing complete schema-2 manifest. Refresh rejects non-mainnet
  before filesystem or source work and rejects a missing manifest without
  creating directories or contacting the source.
- Holds the archive's existing `refresh.lock` across sequential retained-object
  loading, local mainnet reauthentication, every source call, extension-object
  publication, and final atomic manifest replacement.

  successor segment's exact target; subsequent calls stop when that target is

  unchanged. This advances retained evidence and provenance without changing
  the reconstructed state digest.
- Source, capacity, authentication, replay, or publication failure preserves
  the prior complete manifest. A newly durable content-addressed object may be
  left unreferenced after a later failure; cleanup remains explicit future
  work.

## 0.30.20 - 2026-08-06

### Segmented authenticated archive extension

- Hard-cuts the certified Registry archive manifest to schema 2. Every batch
  descriptor now records its exact `segment_ordinal` and
  `segment_target_version`, while the manifest records `segment_count` and the
  final completed target. Validation derives segment boundaries from replay
  continuity and rejects inconsistent ordering, targets, counts, or incomplete
  final segments.
- Allows the archive manifest builder to open another authenticated segment
  only after the preceding exact target completes. The first batch selects the
  next target; subsequent batches remain pinned to it. The ordinary replay
  session and authenticated replay builder remain single-segment and continue
  to reject post-completion batches.
- Preserves a fresh authenticated unchanged-version observation as a complete
  empty segment. Its certificate bounds, evidence chain, endpoints, and exact
  call/byte counts advance while the Registry state and complete-state digest
  remain unchanged.

### Resumable confined publication

- Adds `NnsCertifiedRegistryArchivePublisher::resume`. It sequentially loads,
  bounds, hashes, locally reauthenticates, and exactly recomputes the existing
  archive under caller-selected cumulative replay/storage limits before
  returning a resumable publisher.
- Extension writes only new content-addressed objects. Historical objects are
  not rewritten, and `finish` atomically replaces the manifest only after the
  new segment completes. A limit or publication failure preserves the previous
  complete manifest.
- Resume is local-only: it makes no source call and acquires no refresh lock.
  The future live incremental coordinator must hold the existing archive lock
  across resume, bounded collection, and final publication.

### Hard cut and downstream impact

- Schema-1 archives are invalid with no compatibility reader, automatic
  migration, alias, or fallback. Explicitly force-bootstrap a schema-2 archive
  before attempting resume.
- Subnet Catalog schema/path, archive-bound certified projection, live force
  bootstrap, source call behavior, and CLI grammar are otherwise unchanged.

### Archive-bound certified Subnet Catalog authority

- Adds `project_nns_certified_subnet_catalog`. It accepts only an
  `NnsAuthenticatedRegistryArchive` plus caller-owned catalog identity/time
  validation policy, and returns `NnsCertifiedSubnetCatalogAuthority` with the

  archive capability before certified promotion.

  `Certified` claim, including a correctly digested schema-3 value. Altering and
  resealing any archive commitment also fails the private archive-binding
  validation. JSON describes evidence; it does not recreate authority.
- This slice performs no source call, archive refresh, catalog cache
  publication, cache lookup, cleanup, or CLI operation. Current-use freshness
  remains caller policy through `CatalogValidationContext`.

## 0.30.16 - 2026-08-06

### Confined atomic archive publication

- Adds `NnsCertifiedRegistryArchivePublisher` under `nns-host`. It accepts one
  sealed authenticated batch at a time, streams canonical compact JSON directly
  to an owner-only temporary object, independently verifies the written size and
  SHA-256 against the manifest descriptor, synchronizes the file, and installs
  it atomically under a derived content-addressed name.
- Publishes canonical `manifest.json` only from `finish`, after every referenced
  object is durable and the exact-target authenticated replay is complete. The
  manifest never controls an object path component.
- Reuses the existing capability-rooted managed-file boundary. Archive roots
  outside the selected cache root, traversal, symlinks, nonregular files, and
  unsafe Unix modes fail closed. Newly created managed directories now receive
  the same parent-directory synchronization discipline as atomic renames.
- An object-publication failure poisons that publisher instance. A failed final
  manifest publication leaves an earlier complete manifest byte-for-byte intact;
  incomplete attempts never expose a new discoverable archive.

### Bounded sequential restoration

- Adds `load_nns_certified_registry_archive` and the private-field
  `NnsAuthenticatedRegistryArchive` result. The caller supplies archive,
  manifest, replay-state, call, response, and report-object ceilings; no hidden
  history or storage defaults are selected.
- Bounds the manifest before allocation, requires exact canonical compact JSON,
  and structurally validates it before opening any report object. Every object is
  then bounded independently and matched against the descriptor's exact byte
  length and SHA-256 before JSON decoding.
- Reconstructs each report's original validation request from retained
  provenance, reauthenticates its mainnet certificate, Registry witness, and
  chunk contents locally without a network call, and admits only the sealed
  result to a new manifest builder. One report is processed at a time rather
  than cloning or retaining the complete decoded history.
- Returns authority only when exact-target replay completes and the fully
  recomputed manifest equals every serialized field. Missing objects, altered
  bytes, noncanonical manifests, invalid evidence, ordering gaps, and accounting
  changes remain typed failures.

### Boundary and downstream impact

- Publication and restoration are explicit library calls with caller-selected
  paths. There is no default cache identity, discovery, live collection,
  refresh policy, lock, orphan cleanup, CLI surface, or automatic fallback.
- `CatalogAssurance::Certified` remains disabled. The restored capability is the
  persistence prerequisite for a later validated catalog promotion, not that
  promotion itself.

  keys, invalid value/delete combinations, malformed trees or labels, count or
  byte overflows, and large-value chunk references that would require a
  separate bounded retrieval design.
- Reports one query call, response and evidence byte counts, certificate time,
  root-key digest, raw certificate and witness, and every fixed validator
  ceiling. The pure validator recomputes provenance, sequence boundaries,
  counts, content bytes, and `more_available` for trusted custom sources;
  unlike the built-in live transport, it cannot authenticate a source's raw
  certificate cryptographically.

### Boundary and downstream impact

- The operation is mainnet-only, live, async, one-call, and uncached. It does
  not paginate, replay history, write a mirror, add CLI grammar, or change any
  existing cache path or schema.
- A certified batch authenticates only the returned mutations. It does not
  reconstruct a complete Registry snapshot or enable
  `CatalogAssurance::Certified`; existing Subnet Catalog and topology behavior
  is unchanged.

## 0.30.0 - 2026-08-05

### Certified Registry latest version

- Hard-cuts `NnsRegistryVersionReport`, `NnsRegistryVersionData`, and custom
  `NnsRegistrySource` implementations to version-2 certified evidence.
- Changes the built-in live adapter from ordinary `get_latest_version` to one
  `get_certified_latest_version` query. It authenticates the certificate
  against the compiled-in mainnet root key and verifies Registry canister
  authority plus the certified-data commitment before accepting the version.
- Decodes the Registry's official protobuf mixed hash tree with explicit depth,
  node-count, child-presence, and SHA-256 pruned-digest validation. The
  `current_version` leaf must be present, proven, leaf-valued, non-overflowing,
  and canonical unsigned LEB128.
- Requires certificate time to remain within five minutes of the
  caller-supplied collection time. The IC agent independently applies its
  certificate authentication and age checks.
- Preserves certificate time in raw nanoseconds and UTC text, the trusted
  root-key digest, raw certificate and encoded witness hex, and exact byte
  counts in JSON. Human text reports certification, time, digest, and compact
  evidence sizes without printing the raw blobs.

### Assurance boundary

- Certification applies only to the Registry's committed latest-version leaf.
  Existing Subnet Catalog and exact-version topology collectors continue to use
  ordinary `get_value` calls and retain `UncertifiedQuery` or explicit
  `MultiEndpointAgreement` assurance.
- `CatalogAssurance::Certified` remains unsupported until a complete,
  contiguous, resource-bounded certified delta sequence reconstructs every
  required Registry key at the selected version.
- Adds the staged [0.30 certified Registry design](../design/0.30/0.30-design.md)
  for batch validation, measured bootstrap, incremental replay, and eventual
  atomic catalog publication.

### Dependency and operational impact

- `nns-host` now directly enables `serde_cbor` to decode the Registry system
  certificate. The focused `nns-topology-host` and `subnet-catalog-host`
  dependency graphs are unchanged in this slice.
- The Registry version operation remains live, uncached, mainnet-only, and one
  call. Command names, options, cache paths, Subnet Catalog schemas, topology
  schemas, and other report families are unchanged.
