# 0.30 Changelog

Detailed release notes for the `0.30.x` release line.

## 0.30.2 - 2026-08-05

### Bounded certified large-value completion

- Hard-cuts `NnsCertifiedRegistryDeltaBatchReport` and its mutation and limits
  models to schema 2. Chunk-referenced mutations now retain their original
  encoding, ordered SHA-256 digests, and complete reconstructed value instead
  of being rejected as incomplete.
- Retrieves only the chunks named by the already selected certified batch.
  Every response is hash-verified, and repeated digests within or across
  mutations reuse one verified response.
- Enforces at most 64 references, 1,800,000 decoded bytes per chunk, 10 MiB per
  reconstructed value, 16 MiB across inline and reconstructed values, 32 MiB
  across encoded chunk responses, and 8 MiB for each agent response body.
- Separately reports certified and chunk response bytes, unique chunk calls,
  reference count, inline bytes, reconstructed bytes, and totals. The pure
  custom-source validator recomputes encoding relationships, canonical digest
  shape, value sizes, all totals, and the exact unique-digest query count.
- Applies the same bounded, hash-verified reconstruction helper to ordinary
  exact-version Registry `get_value` reads used by catalog and topology
  collectors.

### Boundary and downstream impact

- The certified API still returns at most one contiguous delta batch and does
  not follow `more_available`, replay history, or publish a cache. Chunk
  completion is finite work named by that batch and is fully reported.
- Ordinary exact-version reads remain uncertified. Completing or bounding a
  large value does not promote Subnet Catalog assurance.
- CLI grammar and cache schemas and paths are unchanged.

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `nns-host` | Certified delta report schema hard cut to 2 | No cache | One certified delta query plus zero to 64 unique chunk queries | Update custom source fixtures and report consumers |
| `nns-topology-host` | Compatible | Unchanged | Oversized or malformed ordinary chunked values now fail at fixed ceilings | Retest only if custom Registry fixtures use large values |
| `subnet-catalog-host` | Compatible | Unchanged | Same bounded ordinary large-value behavior | Retest only if custom Registry fixtures use large values |
| CLI | Compatible | Unchanged | No new command flow | None |

## 0.30.1 - 2026-08-05

### Bounded certified Registry delta batch

- Adds `NnsCertifiedRegistryDeltaBatchRequest`, report/row models, an async
  custom-source trait, `fetch_nns_certified_registry_delta_batch_async`, and a
  pure source-report validator under `nns-host`.
- Performs exactly one authenticated `get_certified_changes_since` query on
  the caller's runtime. The same certified response proves its latest Registry
  version and every visible delta leaf.
- Requires eight-byte big-endian version labels beginning immediately after
  the requested version and increasing by one. Empty batches are accepted only
  when the request already names the certified latest version; later versions
  are exposed through `more_available`, not fetched implicitly.
- Decodes native high-capacity atomic mutation protobufs, preserves mutation
  order, timestamps, preconditions, raw mutation codes, typed
  insert/update/delete/upsert kinds, and key/value bytes as lowercase hex.
- Fails closed on unknown mutation codes, duplicate mutation or precondition
  keys, invalid value/delete combinations, malformed trees or labels, count or
  byte overflows, and large-value chunk references that would require a
  separate bounded retrieval design.
- Reports one query call, response and evidence byte counts, certificate time,
  root-key digest, raw certificate and witness, and every fixed validator
  ceiling. The pure validator recomputes provenance, sequence boundaries,
  counts, content bytes, and `more_available` for trusted custom sources;
  unlike the built-in live transport, it cannot authenticate a source's raw
  certificate cryptographically.

### Boundary and downstream impact

- The operation is mainnet-only, live, async, one-call, and uncached. It does
  not paginate, replay history, write a mirror, add CLI grammar, or change any
  existing cache path or schema.
- A certified batch authenticates only the returned mutations. It does not
  reconstruct a complete Registry snapshot or enable
  `CatalogAssurance::Certified`; existing Subnet Catalog and topology behavior
  is unchanged.

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `nns-host` | New async batch/source/validator and report models | No cache | One explicit certified delta query | Adopt only when bounded delta evidence is needed |
| `nns-topology-host` | Compatible | Unchanged | Unchanged | None |
| `subnet-catalog-host` | Compatible | Unchanged | Unchanged | None |
| CLI | Compatible | Unchanged | Unchanged | None |

## 0.30.0 - 2026-08-05

### Certified Registry latest version

- Hard-cuts `NnsRegistryVersionReport`, `NnsRegistryVersionData`, and custom
  `NnsRegistrySource` implementations to version-2 certified evidence.
- Changes the built-in live adapter from ordinary `get_latest_version` to one
  `get_certified_latest_version` query. It authenticates the certificate
  against the compiled-in mainnet root key and verifies Registry canister
  authority plus the certified-data commitment before accepting the version.
- Decodes the Registry's official protobuf mixed hash tree with explicit depth,
  node-count, child-presence, and SHA-256 pruned-digest validation. The
  `current_version` leaf must be present, proven, leaf-valued, non-overflowing,
  and canonical unsigned LEB128.
- Requires certificate time to remain within five minutes of the
  caller-supplied collection time. The IC agent independently applies its
  certificate authentication and age checks.
- Preserves certificate time in raw nanoseconds and UTC text, the trusted
  root-key digest, raw certificate and encoded witness hex, and exact byte
  counts in JSON. Human text reports certification, time, digest, and compact
  evidence sizes without printing the raw blobs.

### Assurance boundary

- Certification applies only to the Registry's committed latest-version leaf.
  Existing Subnet Catalog and exact-version topology collectors continue to use
  ordinary `get_value` calls and retain `UncertifiedQuery` or explicit
  `MultiEndpointAgreement` assurance.
- `CatalogAssurance::Certified` remains unsupported until a complete,
  contiguous, resource-bounded certified delta sequence reconstructs every
  required Registry key at the selected version.
- Adds the staged [0.30 certified Registry design](../design/0.30/0.30-design.md)
  for batch validation, measured bootstrap, incremental replay, and eventual
  atomic catalog publication.

### Dependency and operational impact

- `nns-host` now directly enables `serde_cbor` to decode the Registry system
  certificate. The focused `nns-topology-host` and `subnet-catalog-host`
  dependency graphs are unchanged in this slice.
- The Registry version operation remains live, uncached, mainnet-only, and one
  call. Command names, options, cache paths, Subnet Catalog schemas, topology
  schemas, and other report families are unchanged.

### Downstream impact

| Feature | Rust API | Cache schema/path | Network behavior | Downstream action |
| --- | --- | --- | --- | --- |
| `nns-host` Registry version | Hard cut to required certification evidence and report schema 2 | No cache | One certified query replaces one ordinary version query | Update custom source fixtures and report consumers |
| `nns-topology-host` | Compatible | Unchanged | Unchanged | None |
| `subnet-catalog-host` | Compatible | Unchanged | Unchanged | None |
| `host` | Same Registry hard cut through `nns-host` | Unchanged | Registry version command uses certified method | Update Registry version consumers |
| CLI | JSON/text evidence expanded; grammar unchanged | No Registry version cache | One authenticated call | Review schema-2 output if scripted |
