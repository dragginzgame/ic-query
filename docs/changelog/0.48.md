# 0.48 Changelog

## 0.48.1

- Selects published `ic-host-artifacts`, `ic-host-fs` and `ic-host-tools` 0.4.6
  at reviewed revision `0fb05f9e18f032425188d68e1d69317a0f0127d5`. Their package
  provenance, Rust sources and original manifests match the owner commit; all
  four Host crates are published and non-yanked, while Query retains its three
  existing dependency selections and response-only tools profile.
- Requires `ic-host-fs` 0.4.5 or newer rather than merely the first descriptor-API
  release. The checked Darwin permission conversion fixes macOS compilation,
  including downstream library builds whose dependency resolution does not use
  Query's lockfile. The selected 0.4.6 also corrects the owner's non-UTF-8 filename
  fixture against native filesystem admission without changing publication
  behavior. Existing unrelated lockfile edges are preserved.
  [#19](https://github.com/dragginzgame/ic-query/issues/19),
  [Host #18](https://github.com/dragginzgame/ic-host-tooling/issues/18),
  [Host #19](https://github.com/dragginzgame/ic-host-tooling/issues/19).
- Host's exact-source Linux, Intel/ARM macOS and MSRV CI passes. Released Query
  0.48.0's macOS check, MSRV and smoke failures use the older 0.4.3 source;
  this repaired consumer selection requires its own matching native CI.
  Cache confinement, schemas, byte budgets, publication errors and CLI behavior
  retain the 0.48.0 contract. No compatibility surface or persisted reset is added.

## 0.48.0 - 2026-10-07

- Adopts the typed descriptor writer from published IC Host Tooling 0.4.3 at
  reviewed revision `644d49c096ae05c2e17e1b6aacf14770988c5cf6`. The selected
  artifacts, filesystem and tools package sources and original manifests match
  the owner commit. Managed publication uses the admitted parent descriptor for
  exclusive staging, file synchronization, rename, owned cleanup and parent sync,
  including when its original path is moved or replaced. Removes Query's staging
  counter, name allocator, local write/sync/rename/cleanup pipeline and JSON error
  bridge. Producers retain their original error type through the shared engine.
  [#19](https://github.com/dragginzgame/ic-query/issues/19).
- Replaces the public `CacheFileError::SyncTemp` and `Replace` variants with
  `PublishManagedFile { path, published, source, cleanup_error }`. Managed producer
  and pre-publication filesystem failures set `published: false`; final failures
  after replacement set it to true and require destination reconciliation before
  retrying. Native I/O identity, serializer causes and separate staging cleanup
  failures remain inspectable. Consumers must update exhaustive error matches
  together with this minor release; no aliases or compatibility error variants
  are retained. The still-used explicit export-path `WriteTemp` and directory/lock
  `SyncDirectory` errors retain their current purposes.
- Retains capability-root traversal, no-follow/type/mode admission, owner-only
  creation, serialization preflight and both-pass byte ceilings. Source or
  serialization failure leaves the last complete destination intact. Schema-1
  cache, lock and sidecar bytes and identities remain unchanged, so no persisted
  reset is required. Callers must exclude concurrent directory namespace writers;
  publication does not establish compare-and-swap against a hostile writer.
- Adopts the 58-file Shared Tooling 0.1.20 snapshot at reviewed revision
  `3ecc48e579f6cf6e6ab01a6645d8a250fc8c6934`, including its new contribution guide
  and linked review/release guidance. Explicitly requested PRs include scoped
  commits and topic-branch pushes; ordinary repairs stay local. The separately
  pinned engineering baseline and stricter maintainer-run release boundary remain.
  [#18](https://github.com/dragginzgame/ic-query/issues/18).
- Host 0.4.3's native macOS jobs expose a `u32`/`u16` raw-permission compile error.
  This prepared adoption requires a corrected published dependency and matching
  native consumer qualification before release. Linux validation does not qualify
  the Apple branch. The owner has the diagnosed failure and a proposed patch with
  Linux test/lint evidence in
  [Host #18](https://github.com/dragginzgame/ic-host-tooling/issues/18).
