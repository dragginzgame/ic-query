# 0.19 Changelog

Detailed release notes for the `0.19.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.19.1 - 2026-07-31

### Changed

- Consolidates the eight identical authority and retrieval fields shared by
  Dashboard detail, count, and page reports into
  `IcDashboardReportProvenance`. Serde flattening preserves the existing
  top-level report JSON keys and values.
- Reuses `IcSourceRequest` as the provenance echoed by all three Dashboard
  source-data DTOs instead of copying endpoint, timestamp, and collector
  fields into each DTO.
- Shares collection option parsing, synchronous live transport execution, and
  text provenance rendering instead of retaining parallel count/page/detail
  flows.
- Adds public-API regression coverage proving report provenance remains flat
  in JSON rather than introducing a nested `provenance` object.

### Compatibility

- CLI grammar and text output, report JSON, validation behavior, official API
  request count, and live-only/no-cache behavior are unchanged.
- This is a breaking pre-1.0 Rust-API hard cut. Dashboard reports expose the
  common fields through `.provenance`, and `IcCanisterSourceData`,
  `IcCanisterCountSourceData`, and `IcCanisterPageSourceData` expose echoed
  source provenance through `.source`. The replaced direct fields are removed
  without aliases or deprecated wrappers.
- This cleanup adds no CLI surface and therefore no command example.

## 0.19.0 - 2026-07-31

### Added

- Adds one filtered count and one explicitly bounded canister page through the
  official Dashboard v4 API:

  ```bash
  icq ic canister count --has-name true
  icq ic canister page --query ledger --limit 25 --format json
  icq ic canister page --after ryjl3-tyaaa-aaaaa-aaaba-cai --limit 25
  ```

- Adds `IcCanisterFilters`, count/page requests and reports, raw page rows and
  controller tuple metadata, text renderers, custom-source builders, and the
  focused `IcCanisterCollectionSource` capability on the existing
  `LiveIcSource` authority adapter.

### Guarantees

- Uses the official `/api/v4/canisters/count` and `/api/v4/canisters`
  resources. Each live builder and command makes exactly one REST request.
- Count fetches only the matching total. Page uses explicit canister-id order,
  defaults to 50 rows, rejects limits outside one through 100, and never
  follows a returned cursor automatically.
- Supports the official name-presence, Subnet, controller, language,
  canister-type, and text-search filters. Principal filters and cursors are
  canonicalized before a source call; raw language and canister-type terms are
  retained.
- Validates custom-source provenance, requested filters/limit/cursors, strict
  page order, unique canister and Dashboard ids, canonical row principals,
  unique controllers, optional module hashes, timestamps, and boundary
  cursors before projection.
- Keeps collection rows as discovery summaries. A returned canister principal
  drives the existing typed `info` follow-up for nullable proposal-linked
  upgrade history.
- Every report retains the endpoint and collection timestamp and explicitly
  states `certified: false` and `point_in_time_guaranteed: false`.
- Keeps all operations live-only. There is no automatic whole-catalog
  traversal, complete collection API, cache file, refresh flow, or process
  output from the library.

### Compatibility

- Existing `icq ic canister info` behavior and JSON are unchanged.
- This release adds no aliases, fallback readers, mutation behavior, or hidden
  network calls.
