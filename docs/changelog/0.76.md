# 0.76 release notes

## 0.76.2

### Internal simplification

- Use Metrics' checked aggregates for neuron-distribution counts and totals,
  retaining Query's native `u64` limits and field-specific overflow errors.
- Reuse parsed routing bounds during canonicalization and validation; keep
  independent validation of raw catalogs and existing error precedence.
- Retain duplicate SNS canister-summary counts without storing redundant
  summaries, preserving every inventory gap and deterministic ordering.
- Type Governance smoke-test receipt fields, lifecycle phases and outcomes,
  retaining raw replies, prior reports, command evidence and cleanup failures.
- Aggregate node-status group counts and non-up members in one pass, keeping
  snapshot totals independent of view filters.
- Construct reward checkpoints directly after bracketed collection, removing
  the private pass-through assembly structure.
- Share exact-or-prefix selection across inventory, node-status and Subnet
  lookup, preserving caller normalization, ordering and ambiguity diagnostics.
- Share Governance cache completeness and state-binding admission while keeping
  family-specific row checks and diagnostic order.
- Share SNS text identity preambles and inline the trivial canister-list CLI
  dispatch, preserving output fields and accepted commands.

## 0.76.1 - 2026-10-29

### Internal simplification

- Construct SNS reports alongside their builders and keep topology check
  calculation and assembly together, preserving report fields and check details.
- Simplify inventory identifier access and missing-only SNS proposal refreshes;
  preserve lookup normalization, ambiguity diagnostics, refresh progress and
  validated cache reloads.
- Move owned ICRC values into lossless JSON, borrow Subnet prefix matches, and
  remove redundant controller sorting and repeated CloudEngine inventory scans.
- Share NNS refresh-report fixture fields while keeping each family's paths,
  source endpoint and Governance identity explicit.

## 0.76.0 - 2026-10-29

### Platform boundary and migration

- Require IC Platform and its macros at 0.8.1. Platform now owns the selected
  ICRC DTOs and callback Rust types while retaining their external Candid/Serde
  forms and value-hashing contracts.
- Update custom `IcrcTipCertificateSource` implementations to return
  `ic_platform::icrc_ledger_types::ICRC3DataCertificate` from Platform 0.8.1.
  Values from the registry ledger package are a different Rust type. Other
  Query request/report DTOs and persisted schema-1 formats remain unchanged.
- Require IC Tooling's Host, Build and Testkit packages at 0.70.0. Consumers
  naming Query's Host certificate errors or ledger tips must also select
  `ic-host-tools` 0.70. Host's ledger blocks now use Platform 0.8.1 values;
  Registry principals and ledger DTOs share that Platform identity. The graph
  no longer retains Platform 0.7 or the registry ledger/CBOR dependency family.
- Keep Query's reply budgets, arity checks, fixed nesting guard, root-key policy,
  Agent identity and Rust 1.91 minimum. The existing Agent advisory acceptance
  retains its 7 November 2026 review deadline.

### Contributor tooling and Wire

- Require Wire 0.7.22, preserving runtime APIs, protocol bytes and admission
  rules. Keep the existing owned Wire RPC and external Candid boundaries.
- Adopt Shared Tooling 0.27.7 through its reviewed snapshot. Failed-target
  excerpts are retained once and printed in the outer validation summary;
  single-tool freshness checks ignore unrelated Cargo installations. Existing
  setup, scheduling and release boundaries remain explicit.

### Internal simplification

- Consolidate CLI progress writer state and derive refresh-event text and state
  together. Retain terminal detection, line cleanup and family-specific messages.
- Construct SNS info and topology provider reports beside their existing
  builders, preserving lookup validation, provider ordering, aggregate totals
  and serialized report fields.
