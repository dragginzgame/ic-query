# 0.76 release notes

## 0.76.0

### Platform boundary and migration

- Require IC Platform and its macros at 0.8.1. Platform now owns the selected
  ICRC DTOs and callback Rust types while retaining their external Candid/Serde
  forms and value-hashing contracts.
- Update custom `IcrcTipCertificateSource` implementations to return
  `ic_platform::icrc_ledger_types::ICRC3DataCertificate` from Platform 0.8.1.
  Values from the registry ledger package are a different Rust type. Other
  Query request/report DTOs and persisted schema-1 formats remain unchanged.
- Require IC Tooling's Host, Build and Testkit packages at 0.70.0. Consumers
  naming Query's Host certificate errors or ledger tips must also select
  `ic-host-tools` 0.70. Host's ledger blocks now use Platform 0.8.1 values;
  Registry principals and ledger DTOs share that Platform identity. The graph
  no longer retains Platform 0.7 or the registry ledger/CBOR dependency family.
- Keep Query's reply budgets, arity checks, fixed nesting guard, root-key policy,
  Agent identity and Rust 1.91 minimum. The existing Agent advisory acceptance
  retains its 7 November 2026 review deadline.

### Contributor tooling and Wire

- Require Wire 0.7.22, preserving runtime APIs, protocol bytes and admission
  rules. Keep the existing owned Wire RPC and external Candid boundaries.
- Adopt Shared Tooling 0.27.7 through its reviewed snapshot. Failed-target
  excerpts are retained once and printed in the outer validation summary;
  single-tool freshness checks ignore unrelated Cargo installations. Existing
  setup, scheduling and release boundaries remain explicit.

### Internal simplification

- Consolidate CLI progress writer state and derive refresh-event text and state
  together. Retain terminal detection, line cleanup and family-specific messages.
- Construct SNS info and topology provider reports beside their existing
  builders, preserving lookup validation, provider ordering, aggregate totals
  and serialized report fields.
