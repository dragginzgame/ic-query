# 0.33 Changelog

## 0.33.0 - 2026-08-08

### Certified API boundary-node configuration

- Adds `icq ic api-boundary-node list` for the complete certified mainnet
  `api_boundary_nodes` state-tree subtree. It returns canonical node
  principals, DNS domains, optional IPv4 addresses, and required IPv6
  addresses in node-principal order.
- Makes exactly one response-bounded `read_state` request, authenticates the
  certificate against the built-in mainnet root key, and performs no per-node
  calls or cache reads/writes.
- Preserves the raw certificate time as Unix nanoseconds in JSON, adds its
  lossless floor-to-seconds projection and UTC rendering, and shows the
  ordinary Unix-second time in text.

```bash
icq ic api-boundary-node list
icq ic api-boundary-node list --json
```

### Authority and bounds

- Reports `authority: certified_ic_state_tree`, `certified: true`, and
  `point_in_time_guaranteed: true`. All returned rows belong to the same
  authenticated certificate time.
- Uses the fixed NNS Registry canister principal only as the effective routing
  id for `read_state`; the report does not query or attribute its rows to
  Registry canister data.
- Rejects a certificate outside the five-minute observation window, more than
  1,000 rows, noncanonical principals or domains, invalid address families,
  duplicate node ids/domains, missing required leaves, and unproven optional
  IPv4 absence.
- Distinguishes certified configuration from Dashboard data-center aggregates,
  Dashboard operational observations, and HTTP-gateway infrastructure. The
  report makes no health, reachability, latency, ownership, or location claim.

### Library and maintenance

- Adds the focused `ic-state-host` feature with `LiveIcStateSource`,
  `IcApiBoundaryNodeSource`, pure report DTOs/rendering, and live/custom-source
  builders. Pure no-default consumers keep the DTO and renderer without host
  dependencies.
- Consolidates canonical unsigned LEB128 handling for certified state time and
  Registry transport decoding.
- Extends focused feature-boundary checks so `ic-state-host` remains separate
  from caches, Dashboard Reqwest transport, Registry Prost decoding, Futures,
  direct CBOR decoding, and direct SHA-256 hashing.

### Downstream impact

| Surface | Change | Downstream action |
| --- | --- | --- |
| CLI | New `ic api-boundary-node list` command | Use it for certified API boundary-node configuration; keep Dashboard reports for location aggregates and operational observations |
