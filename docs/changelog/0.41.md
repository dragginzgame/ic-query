# 0.41 Changelog

## 0.41.1 - Unreleased

### Current mainnet routing authority

- Replaces the live Subnet Catalog's unconditional monolithic `routing_table`
  read with a complete pinned-version reconstruction of the authoritative
  `canister_ranges_*` key family, matching the current DFINITY Registry helper.
  Live collection requires a nonempty modern family and never reads the legacy
  value; an empty family fails closed. Size-bounded Registry delta pages
  advance through the pin by their highest returned mutation version,
  independently of the response's latest-version field.
- Keeps large values on the existing bounded, hash-verified chunk path and
  preserves each record's requested pin, returned individual value version,
  Registry timestamp, exact key/schema/subject, endpoint, assurance, and
  inline/chunked representation in typed catalog and report provenance.
  Validation and agreement failures retain all completed per-endpoint record
  evidence rather than collapsing or discarding successful reads.
- Fails closed on incomplete family enumeration, missing, empty, malformed, or
  shard-boundary violations, duplicate or contradictory family mutations,
  overlapping ranges, invalid principals, and routing to a Subnet absent from
  the current Subnet list. No deleted or missing Subnet is fabricated.
- Keeps pre-shard legacy routing available only at explicit replay boundaries.
  Diagnostic replay can inspect a legacy historical state. Certified promotion
  permits legacy routing only with `AllowHistoricalTarget`;
  `RequireLatestObserved` requires nonempty modern shards. Certified projection
  retains its archive authority and does not claim ordinary per-value query
  evidence.
- Exercises the collector tests under the standalone `subnet-catalog-host`
  feature as well as the all-feature matrix, so modern routing coverage no
  longer depends on the certified feature's test-only protobuf exports.
- Hard-cuts the current catalog and report shape in schema 1, as required for
  pre-1.0 contracts, by adding typed routing-source and Registry-record
  evidence. There is no migration or older-shape reader; an explicit
  invalid-content repair policy may refresh an older ordinary cache.
- Documents the exact [downstream adoption contract](../design/subnet-catalog-downstream-adoption.md)
  for direct Rust struct literals, Canic-style typed projections, custom
  sources, and persisted schema-1 caches. The transport-representation enum
  now exposes stable `inline` and `chunked` labels without downstream
  exhaustive matching.

## 0.41.0 - 2026-08-20

### Typed Subnet Catalog load failures

- Adds detailed synchronous, asynchronous, cache-only, and caller-supplied-
  source load entry points under `subnet-catalog-host`. The returned
  `SubnetCatalogLoadFailure` retains requested network/source/minimum assurance,
  exact typed load stage and failure-side cache disposition, optional exact
  Registry version, typed offending subject, stable code/category, typed
  retryability, and the original `SubnetCatalogHostError`.
- Carries the exact pinned Registry version through every subsequent
  Subnet-list, routing-table, Subnet-record, decode, validation, and agreement-
  aggregation failure. Failures before latest-version acquisition retain
  `None`; known keys, record kinds, Subnet principals, routing ranges,
  endpoints, and fields remain typed rather than reconstructed from display
  text.
- Keeps latest-version acquisition separate from Registry record subjects,
  requires an exact key on every record subject, and distinguishes an indexed
  malformed Registry routing-table entry from a complete offending routing
  range.
- Extends `SubnetCatalogRetryability` with `Unknown` and a typed reason so
  embedders do not guess across ambiguous Registry-response, Registry-
  transport, cache-IO, or runtime failures. This is an exhaustive-match source
  change for callers of the pre-1.0 enum.
- Keeps existing simple load and source implementations operational through
  thin source-error mappings and a default detailed source method. No cache or
  report schema, CLI surface, live-call count, dependency, or persistence
  policy changes.

### Concurrent managed-cache creation

- Treats `AlreadyExists` from a managed directory creator as a possible
  observation race, then reopens and validates the component through the
  existing capability-confined boundary. Concurrent SNS refresh workers no
  longer fail when another worker creates their shared cache directory first;
  symbolic links, nondirectories, and unsafe permissions remain rejected.
