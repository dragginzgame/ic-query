# 0.27 Changelog

Detailed release notes for the `0.27.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.27.4 - 2026-08-04

### Changed

- Applies one 8 MiB JSON response-body ceiling to every live official
  Dashboard request made through `LiveIcSource`, including canister detail and
  collection, metrics, daily statistics, boundary-node aggregates, and ICRC
  analytics.
- Rejects an oversized declared `Content-Length` before allocating the body
  collection buffer or reading the body and enforces the same ceiling while
  consuming chunked or unknown-length responses. A response exactly at the
  ceiling remains valid.
- Replaces Reqwest's unbounded convenience JSON reader with bounded body
  collection followed by direct Serde JSON decoding, allowing `ic-query`'s
  immediate request for Reqwest's `json` feature to be removed. The feature
  remains transitive in the full host graph through `ic-agent`; this does not
  claim a packaged dependency reduction.

### Errors and compatibility

- Adds public `MAX_IC_DASHBOARD_RESPONSE_BYTES` and the typed
  `IcHostError::HttpResponseTooLarge { url, max_bytes, observed_bytes }`
  failure. Response-body transport failures are now reported separately as
  `IcHostError::HttpResponseBody` rather than being conflated with invalid
  JSON.
- Adding variants to the public pre-1.0 `IcHostError` enum is a Rust source
  hard cut for exhaustive downstream matches. There is no compatibility
  wrapper or fallback unbounded reader.
- Request bounds, call counts, report JSON, source provenance, live-only
  behavior, and every cache policy remain unchanged.

## 0.27.3 - 2026-08-04

### Added

- Adds `icq icrc analytics token-values <ledger-canister-id>` for one bounded
  range of price and 24-hour trading-volume observations aggregated by the
  official IC Dashboard ICRC API. It defaults to the preceding 24 hours and
  1,000 rows and accepts explicit `--start`, `--end`, and `--limit` values.
- Adds public token-value query, request, row, report, and host source-data
  contracts; live and custom-source builders; and text rendering. Report rows
  retain both legacy and explicit USD string fields plus nullable external
  provider names and URLs.

```bash
icq icrc analytics token-values mxzaz-hqaaa-aaaar-qaada-cai \
  --start 1785542400 --end 1785628800 --limit 100 --json
```

### Safety and authority

- Makes exactly one live request, follows no cursor, performs no per-row or
  ledger follow-up, and reads or writes no cache. The library caps ranges at
  the official 90-day maximum and uses a stricter 1,000-row ceiling than the
  endpoint's 5,000-row maximum.
- Validates request bounds before source invocation and validates exact source
  provenance, ledger/query echo, returned-row bounds, required in-window
  timestamps, and nondecreasing order before projection. Reaching the requested
  limit records `limit_reached: true` as possible truncation, never complete
  range evidence.
- Keeps the Dashboard aggregation authority separate from each row's external
  provider name and URL. Values remain nullable raw strings and are not
  certified, normalized, reconciled, endorsed, or verified against the native
  ledger.

### Compatibility

- Custom `IcIcrcAnalyticsSource` implementations must add the required
  `fetch_token_value_series` method. This is a pre-1.0 hard cut with no default
  implementation, compatibility trait, or fallback source call.
- Existing indexed-count and total-supply CLI paths, public report schemas,
  call counts, and cache behavior are unchanged.

## 0.27.2 - 2026-08-04

### Added

- Adds `icq icrc analytics account count <ledger-canister-id>` and
  `icq icrc analytics transaction count <ledger-canister-id>` for the current
  unfiltered totals represented by the official IC Dashboard ICRC index.
  Each operation makes one v2 request and requests no indexed rows.
- Adds public `IcIcrcIndexedCountKind::{Account, Holder, Transaction}` and one
  request/report/source-data family covering all three scalar resources.

```bash
icq icrc analytics account count mxzaz-hqaaa-aaaar-qaada-cai
icq icrc analytics transaction count mxzaz-hqaaa-aaaar-qaada-cai --json
```

### Changed

- Consolidates count URL construction, wire decoding, source calls, exact-kind
  validation, report projection, text rendering, common CLI arguments, and
  dispatch. Account, holder, and transaction totals remain distinct typed
  native API classifications rather than interchangeable integers.
- Keeps every count live-only and off-chain with exactly one request, no
  filters, row enumeration, pagination, per-row follow-up, or cache operation.

### Compatibility

- This is a pre-1.0 Rust hard cut: `IcIcrcHolderCountReport`,
  `IcIcrcHolderCountSourceData`, the holder-specific builders and renderer,
  and `IcIcrcAnalyticsSource::fetch_holder_count` are replaced by the indexed
  count family and `fetch_indexed_count`. No compatibility aliases, default
  trait method, wrapper, or parallel holder flow remains.
- The existing `icq icrc analytics holder count` command keeps its path,
  options, one-call behavior, and raw `total`; its JSON now also records
  `kind: "holder"` through the shared report contract.

## 0.27.1 - 2026-08-04

### Added

- Adds `icq icrc analytics holder count <ledger-canister-id>` for the current
  number of holder rows represented by the official IC Dashboard ICRC index.
  It makes one v2 request and has no holder-row, pagination, filter, cursor,
  follow-up, or cache operation.
- Adds `IcIcrcHolderCountReport`, host source data, live and custom-source
  builders, text rendering, and the `fetch_holder_count` operation on the
  existing `IcIcrcAnalyticsSource` capability. The count retains the same
  endpoint, retrieval timestamp, non-certified authority, and no-point-in-time
  guarantees as total-supply analytics.

```bash
icq icrc analytics holder count mxzaz-hqaaa-aaaar-qaada-cai --json
```

### Changed

- Introduces `IcIcrcAnalyticsRequest` as the canonical endpoint, collection
  time, and ledger target shared by both analytics reports. Total-supply
  requests contain that target plus their time-series query, and the CLI now
  reuses its common ICRC ledger options for both analytics reports.
- Centralizes live ledger-resource URL construction, canonical principal
  validation, source provenance/identity validation, and common CLI arguments
  across holder count and total supply.

### Compatibility

- This is a pre-1.0 Rust hard cut: `IcIcrcTotalSupplyRequest` replaces its
  direct endpoint/time/ledger fields with `analytics: IcIcrcAnalyticsRequest`,
  while its `new` constructor keeps the same arguments. Custom
  `IcIcrcAnalyticsSource` implementations must add `fetch_holder_count`; no
  compatibility wrapper, default implementation, or parallel analytics trait
  remains.
- CLI total-supply behavior, report JSON, source endpoint, call count, bounds,
  and cache policy are unchanged. Holder count is off-chain index evidence and
  does not claim certified ledger state or complete indexing coverage.

## 0.27.0 - 2026-08-04

### Added

- Adds `icq icrc analytics total-supply <ledger-canister-id>` for one bounded
  historical total-supply series from the official IC Dashboard ICRC analytics
  API. The command defaults to the preceding 30 days at a daily step and
  accepts explicit inclusive `--start`, `--end`, and hourly or daily `--step`
  values.
- Adds public `IcIcrcTotalSupply*` request, query, observation, report, and
  source-data contracts; `IcIcrcAnalyticsSource`; live and custom-source
  builders; and a text renderer. No-default consumers retain DTO,
  serialization, and rendering access while host consumers can inject a
  fixture, mirror, or proxy through the same validation path.

```bash
icq icrc analytics total-supply mxzaz-hqaaa-aaaar-qaada-cai \
  --start 1785542400 --end 1785801600 --step 86400 --json
```

### Safety and authority

- Validates the canonical ledger principal, official API timestamp minimum,
  non-future ordered window, supported `3600`/`86400` step, and a maximum of
  1,000 requested observations before a live call.
- Validates custom and live source provenance, exact ledger/query echo,
  returned-row bounds, strictly increasing in-window timestamps, and canonical
  unsigned-decimal base-unit values before report projection.
- Makes exactly one HTTP request and performs no ledger enumeration,
  pagination, per-row lookup, follow-up call, or cache read/write. The report
  identifies `official_ic_dashboard_api`, `certified: false`, and
  `point_in_time_guaranteed: false`; accepting a principal does not claim that
  the Dashboard indexes every ICRC ledger.

### Compatibility

- This release adds a separate analytics capability and CLI namespace. Native
  current supply remains available from `icq icrc ledger token`; no existing
  command, report, cache, schema identifier, or feature contract is replaced.
