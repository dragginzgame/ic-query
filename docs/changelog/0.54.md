# 0.54 release notes

## 0.54.4 - 2026-10-10

- Release adapters require successful selected-increment and source-identity
  observations before comparing their values. A helper or Git command that
  prints the expected value but fails now stops with its original status and
  diagnostics. Initial failures refuse preparation; a source-read failure after
  formatter setup refuses subsequent offline admission. Existing mismatch
  diagnostics, evidence retention and recovery ordering are unchanged.
  [#41](https://github.com/dragginzgame/ic-query/issues/41).
- Consumer fixtures inject matching-output failures before file selection,
  initial preflight and post-setup admission, verifying original status, source
  and prior-artifact preservation, and refusal before later effects. Release
  commands and Git mutations remain simulated.
- Adopts committed Shared Tooling 0.3.7 at
  `34e5ad7aac3599306c9572bb547f2239d09df1a3` through the canonical exporter,
  retaining the same 78-file selection and separate engineering baseline.
  Cargo-tool setup/check accepts `--lockfile` instead of `--version`, with strict
  single-package crates.io selection and status admission before using parser
  output. Setup rechecks selection before activation and return; changed selections
  retain existing installations and failed builds. Query has no duplicate lock
  projection to remove. The shared hook and formatting-hook checker remain outside
  the selected snapshot. [Shared #96](https://github.com/dragginzgame/shared-tooling/issues/96).
- Shared release and Cargo-tool fixtures explicitly fail mandatory comparisons
  on Bash 3.2, retaining existing completion and evidence safeguards. Selected
  Cargo setup refuses an absent host identity before preparing destinations or
  running Cargo, and refuses non-executable candidates before activation.
  [Shared #107](https://github.com/dragginzgame/shared-tooling/issues/107).
- Preserves the incoming Host artifacts/filesystem/process 0.12.5 lock selection.
  The filesystem owner rejects NUL anywhere in a pathname before creating parents,
  retaining `BeforePublication` / `InvalidInput` and valid-path publication behavior.
  No local path shim, public API, schema change or reset is needed.
  [Host #54](https://github.com/dragginzgame/ic-host-tooling/issues/54).

```bash
bash scripts/dev/install-rust-tools.sh --consumer /path/to/consumer \
  --package ic-testkit --lockfile Cargo.lock --bin ic-testkit-server --profile release
```

- Keep only the newest CI run per workflow and branch or PR, cancelling older
  queued and running checks while retaining the existing host matrix and gates
  ([Shared #108](https://github.com/dragginzgame/shared-tooling/issues/108)).

## 0.54.0 - 2026-10-10

- Selects published Host artifacts/filesystem/process 0.12.0 from
  `1ba4591868a83b367d56bae9e3c213418c66a192`. The incoming manifest and matching
  lock selections are retained; all three published checksums match and none of
  the releases is yanked. Host's minor release adopts the complete shared tooling
  contract without changing library source or APIs. Query's existing cache,
  durable publication, process limits, typed cleanup evidence and receipt shapes
  remain unchanged. No compatibility layer, schema change or evidence reset is
  needed. [Host #47](https://github.com/dragginzgame/ic-host-tooling/issues/47).
- Adopts committed Shared Tooling 0.3.0 at
  `88a73139a0f083344c41a6f6f4b5c3a8aca7dc1d` through the canonical exporter,
  retaining the same 77-file selection and separate engineering baseline.
  Host setup/check always admits jq, yq, ripgrep with PCRE2 and cloc; the
  `--with-ripgrep` and `--with-cloc` switches are removed. Standard aggregates
  run host, five IC executables and the three common Cargo tools sequentially,
  even under parallel Make. Bootstrap Rust/Cargo and native prerequisites first.
  No old parser, aggregate wrapper or compatibility alias is retained.
- Query's ordered extensions prepare and check the exact formatter receipt
  followed by pinned Cargo Audit and Cargo Machete, preserving their versions,
  profiles, explicit overrides and global audit-tool destinations. The former
  `install-dev` aggregate is removed. Existing callers must use `install-tools`
  and a separate offline `tools-check`. Narrow audit ownership is exposed by
  `install-dependency-tools` and `dependency-tools-check`; the latter checks the
  exact executable versions without setup. Common and selected formatter
  installations remain distinct; one cannot satisfy the other's admission.
  Earlier installations, receipts, failed attempts and build evidence survive.
  [#39](https://github.com/dragginzgame/ic-query/issues/39).
  [Shared #98](https://github.com/dragginzgame/shared-tooling/issues/98).
- Native CI prepares the standard complete toolset and its sequential gate checks
  that same roster before expensive work. Product extensions never recurse into
  their enclosing aggregate. Ordinary checks never install tools. Release
  preflight keeps its source/candidate admission, locked fetching, narrow selected
  formatter preparation and offline recheck; retained recovery bypasses setup.
- Query's Cargo setup recipes preserve the parent's Make jobserver. Shared
  formatter recipes still warn about closed jobserver descriptors on parallel
  GNU Make 4.3 checks; the checks succeed and the upstream repair is tracked in
  [Shared #99](https://github.com/dragginzgame/shared-tooling/issues/99).
- Shared CI inspection now refuses missing failure-log evidence instead of
  silently succeeding, while retaining partial logs and retrieval errors.
  Completed successful, neutral and skipped runs may have no failed-step logs.
  [Shared #97](https://github.com/dragginzgame/shared-tooling/issues/97).

```bash
make install-tools
make tools-check
make dependency-tools-check
```
