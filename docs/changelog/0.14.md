# 0.14 Changelog

Detailed release notes for the breaking `0.14.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.14.1 - 2026-07-30

### Added

- Adds `ICQ_CACHE_ROOT` as the explicit absolute CLI cache-root override. When
  it is unset, the CLI uses `$XDG_CACHE_HOME/ic-query` or
  `$HOME/.cache/ic-query`.
- Adds shared cache primitives for missing-or-stale refresh policy,
  component-labelled host JSON cache errors, and page/row/cursor refresh
  progress.
- Adds resolved index-canister evidence to ICRC account-history collection
  failures once index discovery and verification have completed.

### Changed

- Moves CLI cache identity from the current repository to one user-level root
  shared across working directories. Cache, refresh-lock, and
  refresh-attempt paths are now rooted directly below that directory instead
  of appending `.icq`.
- Renames public cache-root fields, parameters, accessors, and SNS builders
  from `icp_root` to `cache_root`, including `with_cache_root`.
- Consolidates identical simple ledger request contracts into
  `IcrcLedgerRequest`; Registry-derived node, node-provider, node-operator,
  and data-center request contracts into `NnsInventoryCacheRequest`,
  `NnsInventoryListRequest`, `NnsInventoryInfoRequest`, and
  `NnsInventoryRefreshRequest`; and proposal/neuron cache inspection
  contracts into `SnsCacheListRequest`, `SnsCacheStatusRequest`,
  `SnsCacheListReport`, `SnsCacheStatusReport`, and `SnsCacheSummary`.
- Makes a custom complete ICRC account-history source return the explicitly
  requested index canister instead of accepting any valid principal.
- Reduces complete account-history memory overhead by removing full-history
  transaction-id and cursor sets, detecting duplicate ids after canonical
  ordering, and consuming cached rows directly when applying list order and
  limits instead of cloning the complete snapshot.
- Reuses shared missing-cache and stale-cache flows, refresh-attempt progress,
  SNS cache projections, and host cache-error mapping without changing the
  corresponding refresh policy, report schema, or CLI command grammar.

### Removed

- Removes current-directory project discovery through `icp.yaml` and
  `dfx.json`, the `ICQ_ICP_ROOT` environment variable, and automatic
  repository-local cache selection.
- Removes the replaced family-specific ICRC ledger, NNS inventory, and SNS
  proposal/neuron cache request and report types. No aliases, deprecated
  wrappers, fallback cache readers, or automatic migration from former
  project-local `.icq` directories are retained.

## 0.14.0 - 2026-07-30

### Added

- Adds a complete ICRC account-history collector that resolves or accepts one
  index canister, verifies its reported ledger once, and uses that same agent,
  index, account, and token context for every backward page.
- Adds one atomic cache identity for source endpoint, ledger canister, account
  owner, and subaccount. Page size, page cursor, list limit, and list sort are
  operation or view options and do not create alternate snapshot identities.
- Adds distinct public cache-only load, forced refresh, refresh-if-missing, and
  refresh-if-stale APIs, plus source-adapter variants for fixture, mirror, and
  proxy consumers.
- Adds local cache status and refresh-attempt evidence. Failed transport,
  validation, or diagnostic `max_pages` outcomes record pages, rows, cursor,
  and error where available without publishing partial rows.
- Adds arbitrary-size unsigned decimal Candid `Nat` cursors instead of
  restricting account transaction ids to `u64`.

  ```bash
  icq icrc account transaction page mxzaz-hqaaa-aaaar-qaada-cai aaaaa-aa --start 12345 --limit 25 --format json
  icq icrc account transaction refresh mxzaz-hqaaa-aaaar-qaada-cai aaaaa-aa --page-size 100
  icq icrc account transaction list mxzaz-hqaaa-aaaar-qaada-cai aaaaa-aa --sort oldest --limit 100
  icq icrc account transaction cache status mxzaz-hqaaa-aaaar-qaada-cai aaaaa-aa --format json
  ```

### Changed

- Replaces `icq icrc account transactions` with the singular
  `icq icrc account transaction` operation family:
  `page`, `refresh`, `list`, and `cache status`.
- Replaces the plural public page request, report, source, data, error,
  builder, and renderer names with singular `IcrcAccountTransaction*` names.
  Complete snapshot, list, refresh, cache status, and collection-source types
  are exposed from `ic_query::icrc`.
- Requires the progress sink passed to an ICRC complete account-history
  refresh to implement both `QueryProgress` and `Send` so it can cross the
  library's synchronous host-runtime boundary. Existing `QueryProgress`
  implementations used by other families do not gain a new supertrait. The
  library still selects no process output sink.
- Complete caches validate canonical unique newest-first transaction ids,
  row and page counts, ledger/index/account/endpoint identity, timestamps, and
  source-exhaustion evidence before and after atomic publication.
- Complete snapshots record collection start and finish timestamps and
  `point_in_time_guaranteed: false`. The index API exposes no snapshot version,
  so API exhaustion is not presented as a single-ledger-tip guarantee.

### Removed

- Removes the plural `icq icrc account transactions` command and plural public
  account-page names. No CLI alias, Serde alias, deprecated wrapper, fallback
  cache reader, or migration path is retained.
