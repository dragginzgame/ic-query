# 0.8 Changelog

Detailed release notes for the breaking `0.8.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## Unreleased

## 0.8.2 - 2026-07-11

### Changed

- Makes numeric SNS proposal and neuron cache lookup scan validated snapshot
  headers first and deserialize only the matching complete snapshot. Cache list
  still validates and reports every discovered snapshot.
- Rejects duplicate SNS cache ids with a typed ambiguity error and directs the
  caller to the root principal, rather than selecting a cache according to
  filesystem order.
- Adds exhaustive current-contract tests for snapshot completeness metadata,
  routing-range order independence, ASCII terminal-control escaping, and temp
  file cleanup after an atomic replacement failure.

## 0.8.1 - 2026-07-11

### Changed

- Restores the detailed `0.8.x` release ledger that was omitted from the
  0.8.0 commit.
- Requires the changelog gate to verify the detailed ledger and root version
  entry for the target version from `HEAD`, preventing untracked or merely
  staged documentation from authorizing a bump.
- Runs the complete `make ci` gate inside the version-bump script before any
  release metadata is edited. The clean-tree check includes untracked files,
  cargo-package retry preserves the failing exit status, composite release
  targets remain sequential under parallel Make, and tagging cannot follow a
  failed commit.
- Verifies coordinated workspace packages before a bump by checking the
  packaged CLI against the extracted library package, rather than resolving an
  older published library release from the registry.
- Adds an executable release-guard check to local and GitHub CI for those
  fail-closed invariants.
- Resets every current text and JSON report schema to version 1. Pre-1.0 schema
  numbers describe only the current hard-cut shape, not an upgrade lineage.
- Requires SNS proposal and neuron identifiers at the live conversion and
  complete-snapshot boundaries. Proposal pagination derives its cursor from
  the validated final row, and complete snapshots reject inconsistent row
  counts, duplicate identifiers, invalid neuron identifiers, and mismatched
  embedded identity.
- Validates refresh locks and attempt sidecars for the exact current field set,
  schema, network, identity, status, and progress invariants. SNS attempts now
  carry their list id, so numeric cache status finds a failed first refresh
  even when no complete snapshot exists.
- Treats the atomic snapshot replacement as the publication commit. A later
  attempt-sidecar finalization error remains visible in the refresh report but
  no longer relabels the successfully published snapshot as failed.
- Preserves raw `icrc1:logo` metadata in JSON while keeping large logo payloads
  compact in text, escapes terminal control characters across human-facing
  scalar, proposal, and table values, and preserves typed family errors through
  top-level CLI dispatch for correct usage and broken-pipe handling.
- Rejects overlapping subnet routing ranges and issues independent ICRC token,
  capability, and registry subnet-record reads concurrently.

### Removed

- Removes positional `version` shortcuts from command families. Version output
  is exposed only through `-V` and `--version`; the concrete
  `nns registry version` query remains a supported subcommand.
- Removes the redundant public per-report request and refresh-attempt status
  aliases. SNS lookup builders use `SnsLookupRequest`, topology read builders
  use `NnsTopologyReadRequest`, and SNS cache status reports use
  `SnsRefreshAttemptStatus` directly.

## 0.8.0 - 2026-07-11

### Changed

- Makes live host builders safe to call from an existing Tokio runtime by
  isolating their synchronous query runtime instead of nesting `block_on` on a
  runtime worker.
- Treats duplicate-only pages with continuation cursors as incomplete refreshes
  and validates public NNS/SNS refresh page sizes before source calls.
- Preserves page, row, cursor, and current update-time metadata when NNS or SNS
  proposal refreshes fail.
- Reports stale refresh locks for explicit operator cleanup instead of deleting
  them automatically, avoiding cross-process stale-lock replacement races.
- Preserves Clap diagnostics for invalid CLI values and makes top-level help
  after global options exit successfully.
- Makes malformed refresh-attempt sidecars visible to cache status commands,
  validates calendar dates strictly, and uses Unicode-aware table widths and
  proposal text matching.
- Removes the unused `time` dependency and keeps registry-only `prost` and
  `sha2` dependencies behind the `host` feature.
- Updates the native live-call stack to `ic-agent` 0.48.1 and refreshes its
  locked transitive dependencies.

### Removed

- Removes all compatibility with identity-less NNS and SNS complete snapshots.
  The current complete snapshot schema is reset to version 1 and requires
  `domain`, `entity`, `collection`, and `scope`; files outside that current
  shape must be refreshed.
- Removes the legacy `catalog_path` and `cache_path` refresh-lock field names;
  refresh-lock JSON accepts only `target_path`.
- Removes SNS proposal cache field detection and automatic upgrade branches.
- Provides no deprecated wrappers, compatibility aliases, or automatic cache
  migrations for the breaking contracts.
