# 0.42 Changelog

## 0.42.0 - Unreleased

### Stable snapshot authority and transient acquisition provenance

- Replaces `CatalogAuthorityEvidence` with the portable, serializable
  `CatalogSnapshotAuthorityEvidence`. Its identity contains only the validated
  catalog's Registry version, catalog digest, assurance, and canonically
  ordered source endpoints; cache disposition is not retained.
- Replaces `CatalogLoadOutcome::authority_evidence()` with
  `CatalogLoadOutcome::snapshot_authority()`. The outcome method delegates to
  `ValidatedSubnetCatalog::snapshot_authority()`, making the validated catalog
  the sole source of stable snapshot authority.
- Keeps `CatalogLoadOutcome::path` and `CatalogLoadOutcome::disposition` as
  transient acquisition provenance. Missing-cache refresh, invalid-cache
  repair, and a later cache hit report their truthful, different
  `CacheDisposition` values while returning exactly equal snapshot authority
  for identical validated content.
- Applies the same naming boundary to archive-bound certified catalog loads:
  `NnsCertifiedSubnetCatalogLoadOutcome::snapshot_authority()` returns the
  stable catalog identity, while `cache_evidence()` returns the combined
  archive, certificate, and cache-action diagnostics for that operation.

### Compatibility

- This is a source-breaking pre-1.0 hard cut. The removed
  `CatalogAuthorityEvidence` type and `authority_evidence()` methods are not
  retained as aliases, deprecated wrappers, or dual serialization shapes.
- Downstream callers replace `authority_evidence()` with
  `snapshot_authority()` and read `path` or `disposition` from the load outcome
  when operational provenance is needed. Persisted copies of the removed DTO
  require an explicit downstream hard cut; ic-query performs no migration.
- Existing `CatalogReadPolicy` behavior, cache validation, atomic refresh,
  cache-only source isolation, truthful dispositions, sync/async/custom-source
  entry points, and detailed typed failure provenance are unchanged.
- Registry routing selection remains modern-first and fail-closed. Modern
  family failures never fall back to legacy routing authority.
- Catalog, report, cache, sidecar, and lock schemas remain version 1. No cache
  path, network-call behavior, dependency, or CLI surface changes.

```rust
let loaded = load_subnet_catalog(&request)?;
let stable_authority: CatalogSnapshotAuthorityEvidence =
    loaded.snapshot_authority();

let cache_path = &loaded.path;
let acquisition_disposition = loaded.disposition;
```

### Validation

- Covers equal stable authority across missing-cache refresh and cache hit, and
  across invalid-cache repair and cache hit.
- Covers authority changes caused by Registry-version and catalog-digest
  changes, serializable stable evidence, truthful acquisition disposition,
  cache-only source isolation, and unchanged detailed failure provenance.
- Covers the new ordinary and certified methods through public API visibility
  tests and warning-denied Clippy.
