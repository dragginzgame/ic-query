# 0.81 release notes

## 0.81.1

### 🧹 Cleanup

- Cache inspection builds one status row and retains admitted header identity
  when timestamp evidence is absent, malformed or in the future. Byte budgets,
  confinement, recovery policy and timestamp precedence are unchanged.
- Complete collection publication shares its bounded atomic writer and error
  projection. NNS, SNS and ICRC retain family validation and independent attempt
  finalization, including warnings after a successful snapshot publication.
- SNS list and operational-status commands construct requests directly from CLI
  arguments. Preserve their defaults, format selection, cache roots and clocks.
- Registry inventory reads share typed protobuf decoding at the pinned version,
  retaining concurrency, diagnostic labels and missing-record errors. SNS Root
  projection explicitly pairs each inventory role with its matching health data;
  sorted SNS metrics and swap gaps retain uniqueness checks without extra sets.
- Topology gaps share one output vector. Catalog tables share their common cells,
  refresh reports share finalization text, and coverage rendering calls its
  existing table helper directly. Text order and escaping are unchanged.

Public Rust APIs, JSON fields, CLI behavior, protocol bytes and schema-1 cache
formats are unchanged. No consumer migration or reset is required.

## 0.81.0 - 2026-11-01

### ⚠️ Breaking

Rust callers use the shared records below. This is a pre-1.0 hard cut: update
field access, struct literals and custom source fixtures together. No deprecated
accessors or compatibility aliases are retained. The maintainer selects the
minor release; this work does not bump package versions or execute a release.

| Surface | Current Rust access |
| --- | --- |
| Live ICRC token, balance, allowance, index, history-page, block-type, archive, capability and tip-certificate reports | `report.provenance` contains schema, ledger id, timestamp, endpoint and collector through `IcrcReportProvenance` |
| NNS proposal list/detail and SNS instance-list, neuron-list and proposal list/detail acquisition | `report.provenance` carries `ReportProvenance` with data source, cache path and completeness |
| Catalog `SubnetInfo`, list rows and detail reports | `classification: SubnetClassification` owns raw Registry kind and classification annotations |
| Dashboard replica-version detail sources and reports | `release: IcReplicaVersionDetails` owns the release-election payload; provenance and derived Subnet count remain separate |
| Detailed catalog source/load failures | `evidence: SubnetCatalogFailureEvidence` carries pinned/returned versions, endpoint, assurance, completed records and subject; the original error remains `source` |

Report records serialize with flattened fields. JSON keys and values, external
protocol contracts, CLI output and existing schema-1 caches retain their current
shapes. No schema bump, cache reset or migration is required. Report-specific
collection clocks, subject charging decisions, provider enrichment, and original
failure errors remain separate from the shared records.

### 🧹 Cleanup

- NNS proposal, neuron, node-list and Subnet parsers construct public requests
  directly. Keep output format and text verbosity at the CLI boundary, with
  explicit cache roots and clocks. Argument defaults, filters, bounds and help
  retain their current behavior.
- Complete proposal-activity and neuron-distribution reports use one analytics
  header validation sequence. Keep their distinct payload checks, source trust
  boundaries, error projection and sequential-collection limitations.
- ICRC text renderers share escaped acquisition lines, preserving their position
  before tables and report-specific sections.
- Related topology request projections live with their common request owner.
