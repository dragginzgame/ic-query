## 0.47.0 - 2026-10-06

### Maintainer release workflow

- Replaces the separate bump, stage, commit, and push interface with one
  reviewed Shared Tooling runner for `make release-patch`, `make release-minor`,
  and `make release-major`. The selected immutable helpers and executable modes
  are verified from `.shared-tooling.snapshot` at revision
  `cb86188c5956866564de4fb6ec6be67b27981ab9` (Shared Tooling 0.1.4).
  [#3](https://github.com/dragginzgame/ic-query/issues/3).
- Breaking maintainer workflow change: the former `patch`, `minor`, `major`,
  `release-stage`, `release-commit`, and `release-push` Make targets are removed.
  Use the standard one-shot release commands; rerunning the same command
  reconciles retained intent, and `release-resume VERSION=X.Y.Z` permits explicit
  selection. Package publication remains separate.
- Updates only the directly owned workspace/dependency and lockfile versions.
  Prepared files must equal transformations of the inputs that passed the
  gate, including unchanged third-party lockfile identities and checksums.
  Missing offline dependencies fail before metadata changes without resolving
  upgrades. [#2](https://github.com/dragginzgame/ic-query/issues/2).
- Finalizes one numbered pending root heading and its detailed heading with the
  selected UTC date. Stages both changelogs with the explicit owned metadata.
  Preserves historical minor-line indexes and published notes.
- Checks candidate agreement in both pending headings during preflight, before
  validation and preparation intent. Inspects staged and unstaged paths
  independently and verifies each staged metadata file against the validated
  payload before commit, including when a working file hides a staged edit.
- CI and release validation use the pinned shared log runner with fail-fast
  ordering. Unique raw failed logs survive later attempts; unavailable log
  destinations preserve and report temporary logs instead of deleting evidence.
- Saves unique validation logs and before-files, source/selection identity,
  and schema-1 recovery intent. Rejects changed payloads, unrelated work, stale
  validation identities, concurrent releases, and conflicting local/remote tags.
  Lost preparation or push replies resume at the saved candidate; unavailable
  remote state stops recovery rather than replaying uncertain effects.
- Ordinary commands reconcile an older committed release after newer descendant
  fixes, then validate the requested next increment from the actual manifest.
  Unchanged same-kind retries finish only the saved release; exact resume starts
  no next increment. Late consumer callbacks validate files and evidence at the
  explicit `RELEASE_COMMIT`, preserving the original source, tree and tag.
  Adopts the committed correction for
  [Shared Tooling #5](https://github.com/dragginzgame/shared-tooling/issues/5).
- Pushes only the selected branch and exact annotated release tag with
  `--no-follow-tags --atomic`. Unsupported atomic push fails without fallback.
  Build outputs and evidence remain retained on success, failure, and retry.
- Rejects failed Git inventory before release or publication admission, including
  empty or partial output, adopting the canonical fix for
  [Shared Tooling #4](https://github.com/dragginzgame/shared-tooling/issues/4).
- Centralizes workspace-version reading and release-file ownership. Removes
  repeat commit/tag checks from consumer hooks; the shared runner owns those
  identities, while the hooks retain exact prepared-payload and evidence checks.
  Publication separately requires the current version's annotated tag at HEAD.
- Declares the native host matrix and configures the complete gate and MSRV
  checks on Ubuntu 24.04 plus macOS 15 on Apple Silicon and Intel. macOS release
  gate runs once using system Bash. Native qualification requires those
  workflow runs; macOS canister-network integration remains an explicit gap.
- Fixture coverage exercises all three increments, dependency preservation
  when newer choices exist, failure admission, exact staging/push scope,
  retained logs/artifacts, and interruption recovery through file-backed stubs.
  Actual Make callbacks cover older release recovery after committed fixes,
  fresh validation failure/retry, exact resume and historical payload conflicts.
  A real Git index/tree fixture supplements effect stubs and exercises the actual
  adapter's retention of raw failed validation logs across retries.
  It performs no real commit, tag, push, publication, or repository version bump.
- Publication fixtures clear inherited Make flags and overrides before their
  own Make invocations. A release candidate no longer overrides the simulated
  current-version tag and falsely fails the complete release gate.
- Real-Git release fixtures clear inherited logger checkout identity before
  invoking their own failing gate. Nested logger coverage verifies that gate
  execution stays in the fixture checkout and reports routing failures clearly.
- CLI grammar, Rust APIs, report/cache shapes, and schemas are unchanged;
  repository-owned schemas remain `1`.
