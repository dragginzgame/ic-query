# 0.74 release notes

## 0.74.0 - 2026-10-26

- **Breaking:** remove `proposed_at`, `deadline_at`, `decided_at`, `executed_at`
  and `failed_at` from `NnsProposalRow` and its serialized report/cache shape.
  Consumers use the corresponding raw Unix-second fields. Human-readable text
  keeps its existing labels, timestamp formatting and absent-value behavior.
  Before installing this hard cut, retain any required proposal snapshots and
  caller-retained collection evidence separately. Update custom sources and
  JSON consumers, then explicitly run `icq nns proposal refresh` to replace the
  local proposal snapshot. Schema identifiers remain 1; rejected files are not
  migrated, rewritten or removed by cache reads.
- **Breaking:** NNS proposal cache list and status share one inspection path.
  Both surface malformed or invalid refresh-attempt sidecars and preserve valid
  attempt evidence when no complete snapshot exists. Missing sidecars remain
  valid absence; invalid snapshots still appear as invalid summary rows.
- Resolve raw and validated canister routes through one borrowed match, avoiding
  an intermediate general report while retaining inclusive boundaries, typed
  errors and exact catalog authority evidence.
- Share NNS source/cache context construction and SNS cache context projection
  within their respective families, without changing report provenance.
- Share Governance analytics identity and source checks while retaining
  family-specific bounds, validation order and diagnostics.
- Derive Subnet classification annotations for assignment and independent
  validation without cloning Subnet records. Policy identities and digests are
  unchanged.
- Consolidate the fifteen one-argument SNS public-builder signature aliases into
  one parameterised alias, preserving lifetime and result-type checks.
- Prepare CLI subcommand display order without cloning command subtrees;
  generated help remains alphabetical and namespace help behavior is unchanged.
- Move owned proposal strings and selected cached neuron rows into reports
  instead of cloning them. Snapshot validation, row order, cursor boundaries and
  total counts are unchanged.
