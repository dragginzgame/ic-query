# 0.22 Changelog

Detailed release notes for the `0.22.x` release line.

Root summary: [../../CHANGELOG.md](../../CHANGELOG.md)

When a patch introduces any new CLI surface, include a fenced `bash` command
example here and in the root changelog. New CLI surface includes commands,
subcommands, options, option values, and new supported option combinations.
Cleanup-only patches without CLI behavior changes should not include command
examples.

## 0.22.0 - 2026-08-01

### Changed

- Establishes the `0.22.x` structural-consolidation design and its ordered
  validation gates for CLI composition, NNS Registry inventory orchestration,
  snapshot lifecycle sharing, and cohesive module ownership.
- Replaces the NNS neuron family's wildcard public re-export with an explicit
  current-contract export list, preventing future internal additions from
  silently expanding the family-root Rust API.
- Consolidates repeated non-mainnet topology command tests into one
  table-driven contract while retaining coverage for every supported topology
  view and refresh operation.
- Adds a focused `subnet-catalog-host` library feature for embedders that need
  live/cache Subnet catalog behavior without the Dashboard Reqwest transport or
  CBOR certification dependency. The existing `host` feature remains a strict
  superset and the CLI continues to use it.
- Makes every repository-document and changelog link in the README absolute to
  GitHub, so the same README remains navigable from the published library and
  CLI archives even though those archives do not contain the root `docs/` and
  changelog trees.
- Centralizes the cache-missing refresh driver and exact-or-unique-prefix row
  resolver used by node, node-provider, node-operator, and data-center reports.
  The same internal owner now enforces the network contract, constructs shared
  source provenance, and orders fetch before locked atomic cache publication.
  Family DTOs, errors, sources, projections, cache files, filters, and refresh
  reports remain distinct.
- Centralizes NNS Governance proposal/neuron refresh-attempt construction,
  strict sidecar reads, metadata validation, report-status projection, and
  failed-progress recovery. The existing generic snapshot owner continues to
  own locking, paging progress, completeness, atomic publication, and attempt
  finalization; proposal and neuron public errors and cache contracts remain
  distinct.
- Centralizes SNS proposal/neuron target lookup, network validation, refresh
  locking, resolved context, complete-cache provenance and completeness,
  atomic publication, page-progress evidence, and attempt finalization. The
  family-specific proposal and neuron cursor logic, row validation, source
  traits, cache schemas, public reports, and errors remain separate; four
  redundant context/progress leaf modules are removed.

### Compatibility

- This cleanup does not change public Rust paths or types, CLI grammar or
  output, report JSON, cache paths or schemas, network calls, refresh policy,
  or source-adapter behavior.
- Enabling `subnet-catalog-host` exposes the same Subnet catalog API available
  under `host`; it does not introduce a second implementation or behavior
  branch.
- No compatibility aliases, fallback readers, deprecated wrappers, mutation
  behavior, or hidden live calls are added.
